# Platform & operations

> Operate workflows, Sandboxes, Online Evals, and Realtime together from one Inngest account.

Run durable functions, Sandboxes, Online Evals, and Realtime in one account. Separate production from testing, connect the apps that run your code, and trace each run from its trigger through its outcome.
## Organize your work
An **environment** separates its apps, events, functions, and execution history from other environments. Use production for live traffic, a custom environment for shared staging or QA, and local development for work on your machine. Use **branch deploys** for preview deployments tied to a code branch. Branch deploys are deployment previews; Inngest Sandboxes are isolated microVMs that run code within your work.
An **app** groups the functions you deploy together. One environment can contain multiple apps. Keep each app ID stable so Inngest can track its functions across deployments.
Continue with [Apps and syncs](/docs/platform-and-operations/apps-and-syncs), [Environments and branch deploys](/docs/platform-and-operations/environments-and-branch-deploys), or [Local Development](/docs/local-development).
## Deploy and connect apps
Today, you can run Inngest function code on your infrastructure. Serve an HTTP endpoint with `serve()` on a compatible serverless or server runtime, or use Connect on a long-running worker. Your app can run on AWS, Google Cloud, Vercel, Cloudflare, or another compatible host. Inngest triggers runs and records their progress while your code runs in that app.
**Inngest compute is planned.** It will host an app's function code on Inngest-managed compute. Compute placement is per app: an environment can include apps on your infrastructure alongside apps on Inngest compute. This is one platform and one function model. Sandboxes provide isolated execution inside work; they are not a deployment target for Inngest functions.
Follow [Deploying functions](/docs/durable-execution/guides-and-advanced/deploying-functions) for setup, sync, host requirements, and the differences between HTTP serving and Connect.
To operate the Inngest server in your own infrastructure, follow [Self-host Inngest](/docs/platform-and-operations/self-host-inngest). Check its feature scope before assuming managed-platform capabilities are available.
## Manage keys and access
Use an **event key** when an app sends events to an environment. Use its **signing key** to secure communication between Inngest and your deployed app. Use an **API key** for the Inngest REST API. These credentials serve different requests; give each deployment the credential it needs and keep secrets out of source control and browser code.
Use [Keys and access](/docs/platform-and-operations/keys-and-access) to choose a credential and [Rotate event and signing keys](/docs/platform-and-operations/rotate-event-and-signing-keys) to replace it safely. [Cloud architecture and security](/docs/platform-and-operations/cloud-architecture-and-security) explains where Inngest coordinates runs and how it protects the connection. Check your plan and account settings for available access controls.
## See what happened
Open an app to check its registered functions. Use function metrics to find changes in volume or failures, then open a run trace to see its steps, waits, timings, and retries. Inngest captures workflow traces without extra instrumentation. Sandbox operations appear alongside durable steps in the run trace. Online Evals connect sessions and scores to runs so you can compare outcomes after execution.
Start with [Inspect events and runs](/docs/platform-and-operations/inspect-events-and-runs). Use [Traces](/docs/platform-and-operations/traces) for one run, [Metrics](/docs/platform-and-operations/metrics) for workload health, and [Insights](/docs/platform-and-operations/insights) for historical SQL analysis. [Online Evals](/docs/online-evals) covers outcome scores.
## Control load and recover
Set concurrency, throttling, rate limiting, or other [flow controls](/docs/durable-execution/flow-control) on the functions that need them. Check [Limits](/docs/durable-execution/limits), your host's limits, and the [pricing page](https://www.inngest.com/pricing) before production deployment. Pricing is the source for the current Free, Pro, Business, and Enterprise plan allowances.
When a run fails or an app does not sync, inspect the app and run trace first. Then use the relevant [Troubleshooting](/docs/durable-execution/troubleshooting) guide. [Rerun a run](/docs/platform-and-operations/rerun-a-run) recovers one run. [Replay runs in bulk](/docs/platform-and-operations/replay-runs-in-bulk) recovers a selected set. [Pause and resume functions](/docs/platform-and-operations/pause-and-resume-functions) stops new runs during maintenance or an incident. Read each action's scope before using it on live work.
