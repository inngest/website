# Limits

> Plan your client connections and message volume before you stream updates to users.

## Realtime plan limits

Estimate the number of clients online at once and the updates your app will publish each day. The pricing page lists concurrent Realtime connections and daily messages by plan. Check both before you add Realtime to a high-volume job.

| Plan | Concurrent Realtime connections | Realtime messages per day |
| --- | --- | --- |
| Free | 50 | 250,000 |
| Pro | 1,000 | 1,000,000 |
| Business | 5,000 | 5,000,000 |
| Enterprise | Custom | Custom |

See [pricing](https://www.inngest.com/pricing) for the current plan comparison.  These connection limits apply to Realtime subscribers.  Do not confuse them with Inngest worker connections or concurrent workflow steps, which have separate limits.

## Client-side message history and buffering

In TypeScript SDK v4, `useRealtime()` keeps the latest **100 received messages** in `messages.all` by default.  Set `historyLimit` to change how many messages that React hook keeps in memory, or set it to `null` for unbounded local history.  This setting does not increase your plan's daily message allowance or define a server-side replay window.

By default, `bufferInterval` is **0 ms**, so incoming messages update the hook immediately.  Set a larger interval to group UI updates when you stream many small messages.  Buffering changes when React renders; it does not change the published plan allowance.

The hook also reconnects automatically by default.  It pauses when the browser tab is hidden and closes when the associated run reaches a terminal state, unless you change those options.

## Keep message volume predictable

Publish meaningful state changes as Realtime messages.  If you stream model output token by token, estimate the daily message volume for your expected run count.  Use `bufferInterval` to reduce UI render work, and use `historyLimit` to bound browser memory.  For an important final result or state transition inside a function, `step.realtime.publish()` is durable and memoized on retry.
