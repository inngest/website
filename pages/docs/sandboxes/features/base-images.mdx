# Base images

> Start isolated work with Node.js, Python, Ruby, and common command-line tools already installed.

> **Open beta.** Sandboxes are available on Pro plans and above. The Sandbox API, image, and limits may change. Use this beta for evaluation and feedback.

Run generated code or inspect a repository without building an image first. The beta Sandbox image includes Node.js, Python, Ruby, and common command-line tools. Check installed versions inside the Sandbox when your task depends on a specific version.

## What the beta image includes

New Sandboxes use the default image unless you select a published image. A Sandbox cloned from a snapshot starts with the captured image and filesystem changes.

| Tool | Included |
| --- | --- |
| Node.js | Latest release as `node`, `npm`, and `npx`; LTS release as `node-lts`, `npm-lts`, and `npx-lts` |
| Python | Python 3.14 |
| Ruby | Ruby 4.0 |
| Repository and network tools | Git, curl, OpenSSH, and CA certificates |
| Operating system and utilities | Debian 13 slim with GNU `grep`, `sed`, `awk`, `find`, `diff`, `tar`, and `gzip`, plus `ripgrep` and `jq` |

The default image does **not** currently include Go, Rust, Java, Bun, or Deno. Exact installed versions can change when Inngest rebuilds the image. Check versions in the Sandbox if your task depends on them.

## Select a published image

In SDK 4.25 or newer, import `image` from `inngest/experimental` and set
`from: image.custom("my-image:v1")` when creating a Sandbox. Use
`from: image.inngest("base")` to select the platform base image explicitly.
With REST, set `"image": "my-image:v1"` on `POST /v2/sandboxes`.

An untagged name uses `latest`. To pin an exact artifact, use
`my-image@sha256:<digest>` with its 64-character lowercase hexadecimal digest.
Tags can move; existing Sandboxes keep their resolved image. Snapshot clones
inherit the captured image and cannot override it.

To build and publish your own application code, dependencies, or runtimes,
follow [Custom images](/docs/sandboxes/features/custom-images).

## Inspect the image

Run commands after the Sandbox reaches `RUNNING`. This example assumes you already have a Sandbox object from `inngest.sandboxes.create()`:

<CodeGroup>
```typescript {{ title: "TypeScript" }}
const result = await sandbox.commands.run(
  "node --version && python3 --version && ruby --version && git --version",
  { timeout: "30s" },
);

console.log(result.stdout);
console.error(result.stderr);
console.log(result.exitCode);
```

## Add dependencies for a task

Install packages inside a running Sandbox when the task needs them. For example, create a project directory and install a Node package:

<CodeGroup>
```typescript {{ title: "TypeScript" }}
await sandbox.commands.run(
  "mkdir -p /tmp/project && cd /tmp/project && npm init -y && npm install lodash",
  { timeout: "5m" },
);
```

<SdkUnsupported title="Python" feature="Sandboxes" />
<SdkUnsupported title="Go" feature="Sandboxes" />
</CodeGroup>

This changes **that Sandbox**, not the fixed base image. The files remain in the Sandbox across pause and resume. A snapshot captures its disk, so clones start with the installed files. Destroying the Sandbox removes its filesystem. User snapshots expire and are not permanent storage. For files shared across different Sandboxes, use S3-backed persistent filesystem mounts.

## Choose a supported size

Fresh Sandboxes accept 1, 2, or 4 vCPU with 1, 2, or 4 GiB of memory per vCPU. `memoryMb` is measured in MiB:

| `vcpu` | Allowed `memoryMb` values |
| --- | --- |
| 1 | 1024, 2048, 4096 |
| 2 | 2048, 4096, 8192 |
| 4 | 4096, 8192, 16384 |

Other sizes are not available. The API does not accept a size profile name. A snapshot clone inherits the snapshot's CPU and memory. Access or available capacity can still prevent a supported size from starting; missing capacity returns `503 compute_unavailable`.
