# Managed lifecycle

> Create a Sandbox, run several statements in it, and have it cleaned up without writing cleanup code.

A Sandbox you create inside a function belongs to that run. Use `await using` or `group.sandbox()` to end it exactly where you want, and leave the rest to the run: whatever is still alive when the run ends is destroyed, however the run ends. There is no `onFailure` handler to write and no Sandbox ID to store.

<AnnotatedCode>

```typescript {{ title: "inngest/functions/build-check.ts" }}
import { image } from "inngest";

export const buildCheck = inngest.createFunction(
  { id: "build-check", triggers: { event: "repo/pushed" } },
  async ({ event, step }) => {
    await using sb = await step.sandbox.create("check", {
      from: image.inngest("node-22"),
      vcpu: 4,
      secrets: ["NPM_TOKEN"],
    });

    await sb.$`git clone --depth 1 ${event.data.url} /work/repo`;
    await sb.$`cd /work/repo && npm ci`.timeout("5m");

    const tests = await sb.$`cd /work/repo && npm test`.exitCodes("any");

    return { passed: tests.ok, tail: tests.stdout.slice(-2000) };
  },
);
```

## Create options

`step.sandbox.create(id, options?)` takes:

| Option | Default | Does |
| --- | --- | --- |
| `from` | Base image | The [image](/docs/sandboxes/features/base-images?ref=docs-sandboxes-managed-lifecycle) to start from, such as `image.inngest("node-22")`. |
| `vcpu`, `memoryMb` | `2`, `2048` | Machine size, from a [supported pair](/docs/sandboxes/limits?ref=docs-sandboxes-managed-lifecycle). |
| `timeout` | `"30s"` | Default time limit per command, up to `"5m"`. |
| `env` | None | Environment variables. |
| `secrets` | None | Workspace [secret](/docs/sandboxes/features/secrets?ref=docs-sandboxes-managed-lifecycle) names that Inngest injects. |
| `owner` | The current run | Who [cleans the Sandbox up](/docs/sandboxes/features/run-owned?ref=docs-sandboxes-managed-lifecycle). |

## End it where you want

`step.sandbox.create()` returns a handle that works with `await using`.

| You write | The Sandbox is destroyed |
| --- | --- |
| `await using sb = await step.sandbox.create(...)` | When the scope ends. |
| `const sb = await step.sandbox.create(...)` | When the run ends. Call `await sb.destroy("done")` to end it sooner. |
| `step.sandbox.create(..., { owner: "persistent" })` | Only when you destroy it. See [Run-owned Sandboxes](/docs/sandboxes/features/run-owned?ref=docs-sandboxes-managed-lifecycle). |

Forgetting `await using` is safe, because the run still cleans up. Use it to give a Sandbox a precise lifetime, and use a block to end it before the function carries on:

```typescript {{ title: "TypeScript" }}
async ({ step, event }) => {
  const repo = await step.run("resolve", () => resolveRepo(event.data.repoId));
  let files: string[];

  {
    await using sb = await step.sandbox.create("review", { from: image.inngest("node-22") });
    await sb.$`git clone --depth 1 ${repo.url} /work/r`;
    await sb.$`cd /work/r && npx eslint .`.exitCodes("any");
    files = (await sb.$`cd /work/r && git diff --name-only`.text()).split("\n");
  }

  await step.run("notify", () => notify(repo.id, files));
  return { files };
}
```

The Sandbox is gone at the closing brace, before `notify` runs.

<Info>
  `await using` needs `lib: ["esnext.disposable"]` (or `esnext`) in your `tsconfig.json` and Node.js 20.5 or newer. Without it, use `group.sandbox()` below.
</Info>

## Group a callback

`group.sandbox()` runs a callback with a Sandbox and destroys it when the callback returns or throws. It works in every runtime, and it renders as one `SANDBOX` group in the [trace](/docs/sandboxes/features/traces?ref=docs-sandboxes-managed-lifecycle).

```typescript {{ title: "TypeScript" }}
const out = await group.sandbox("run", (sb) => sb.python("main", "return 6 * 7"));

const report = await group.sandbox(
  { id: "build-check", from: image.inngest("node-22"), vcpu: 4, secrets: ["NPM_TOKEN"] },
  async (sb) => {
    await sb.$`git clone --depth 1 ${url} /work/repo`;
    const tests = await sb.$`cd /work/repo && npm test`.exitCodes("any");
    return { passed: tests.ok, tail: tests.stdout.slice(-2000) };
  },
);
```

- The first argument is an ID, or an object with the ID plus the [create options](#create-options).
- The callback's return value is the value of the whole call.
- A `step.run` inside the callback lands in the same group.

## What cleanup does for you

- **Success.** The Sandbox is destroyed when the scope ends.
- **A failure that ends the run.** The Sandbox is destroyed at once, so a failed build doesn't hold a machine.
- **A failure that will be retried.** The Sandbox stays, and the retry finds its files where it left them.
- **Cancellation, timeouts, or a crashed deploy.** The Sandbox is destroyed when the run ends. You don't register anything.

The same applies to [snapshots](/docs/sandboxes/features/snapshots-and-restore?ref=docs-sandboxes-managed-lifecycle) you take inside a function. [Run-owned Sandboxes](/docs/sandboxes/features/run-owned?ref=docs-sandboxes-managed-lifecycle) explains the guarantee and how to opt out.

Destroying removes the filesystem, processes, and retained output. Save anything you need before the scope ends.

## Retries and uncertain outcomes

Let unexpected `step.sandbox` errors escape the function. Inngest retries the operations that are safe to repeat and records a failure when retries run out or an operation can't be repeated. A retry repeats only the step that failed, in the same Sandbox, so earlier statements don't run again.

An `operation_ambiguous` error means a command, process start, or signal may have happened without a confirmed response. Inspect the Sandbox or the command's external effect before repeating it. A command's exit code is not an infrastructure error: see [Exit codes and errors](/docs/sandboxes/features/exit-codes?ref=docs-sandboxes-managed-lifecycle).

A durable step records the operation's result. It doesn't keep a guest process or file alive if the Sandbox itself is lost, so call Get when work resumes after a long wait.

## Pause, resume, and reuse state

Pause releases the live runtime into a private checkpoint. Resume returns the **same** Sandbox ID with its filesystem, memory, and remaining runtime. A snapshot keeps a copy of the Sandbox while it keeps running, and a clone starts a **new** Sandbox from it. See [Pause and resume](/docs/sandboxes/features/pause-and-resume?ref=docs-sandboxes-managed-lifecycle) and [Snapshots and restore](/docs/sandboxes/features/snapshots-and-restore?ref=docs-sandboxes-managed-lifecycle).

Outside a function, `inngest.sandboxes` makes immediate calls and has no run to own anything, so you manage the lifecycle: destroy in `finally`.

Deployment previews are called **branch deploys**. This page is about isolated microVM Sandboxes.
