# Cloning

> Prepare a Sandbox once and start separate jobs from the same snapshot.

- **Prepare once.** Install dependencies a single time. [Snapshots →](/docs/sandboxes/features/snapshots-and-restore?ref=docs-sandboxes-cloning)
- **Fan out.** One clone per job, each with its own ID.
- **Clean up for free.** Clones and snapshots belong to the run. [Run-owned →](/docs/sandboxes/features/run-owned?ref=docs-sandboxes-cloning)
- **Share a mount.** Clones attach the same S3-backed path. [Durable filesystems →](/docs/sandboxes/features/durable-filesystems?ref=docs-sandboxes-cloning)

<AnnotatedCode>

```typescript {{ title: "inngest/functions/fan-out.ts" }}
await using builder = await step.sandbox.create("builder");

await builder.sh("deps", "npm ci");

const snapshot = await builder.snapshot("snap", {});

const clone = await snapshot.clone("clone-a", {
  name: `worker-${event.data.jobId}`,
  runningTimeout: "2m",
});

const out = await clone.commands.run("check", "npm test");
```

With the direct client, destroy every clone and delete the snapshot yourself.

```typescript {{ title: "TypeScript" }}
const snapshot = await builder.snapshot({}, { timeout: "5m" });

try {
  const clone = await snapshot.clone({ name: `worker-${id}` });

  try {
    await clone.commands.run("npm test");
  } finally {
    await clone.destroy();
  }
} finally {
  await snapshot.delete();
}
```

## How it works

- A clone inherits the snapshot's resources and environment. It cannot override them.
- Snapshots are crash-consistent, so flush databases first. They expire at `expiresAt`.
- A readiness timeout does not destroy the clone. Track and clean it up.
- Need the same Sandbox back instead? [Pause and resume →](/docs/sandboxes/features/pause-and-resume?ref=docs-sandboxes-cloning)
