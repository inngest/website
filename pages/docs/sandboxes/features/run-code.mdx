# Run code

> Run Python, TypeScript, or shell in a Sandbox with one statement, and get the result back as a value.

The runners create a Sandbox, run your code in it, return the result, and destroy the Sandbox, all in one call. Use them for short jobs, such as running generated code or a quick computation, where you don't need to keep the Sandbox.

- **One statement.** Create, run, and destroy a Sandbox in a single call. See [The runners](#the-runners).
- **Data in, value out.** Each `input` key becomes a variable, and `return` sends JSON back. See [Pass data in](#pass-data-in).
- **Typed results.** Validate the returned value with Zod, Valibot, or ArkType. See [Type the result](#type-the-result).
- **Pick the runtime.** Run Node, Deno, Bun, or Python, at an exact version. See [Choose a runtime](#choose-a-runtime).
- **Safe commands.** Values you interpolate into a command never reach a shell unquoted. See [The `$` template](#the-template).

## The runners

```typescript {{ title: "TypeScript" }}
const total = await step.sandbox.python<number>("sum", "return sum(range(10))");
const listing = await step.sandbox.sh("ls", "ls -la /work");
const count = await step.sandbox.typescript<number>("count", "return JSON.parse(raw).items.length", {
  input: { raw: payload },
});

await using sb = await step.sandbox.create("many");
await sb.python("a", "return 1");
```

`python` and `typescript` return the value of `return`, `sh` returns `stdout`, and `run` returns the [full result](#the-full-result). A Sandbox you create with `step.sandbox.create()` has methods with the same names.

## Pass data in

```typescript {{ title: "TypeScript" }}
const label = await step.sandbox.python<string>(
  "label",
  `return f"{name} has {len(items)} items"`,
  { input: { name: user.name, items: cart.items } },
);
```

- Values must be JSON. A `Date` or a `Map` throws an error before any Sandbox starts.
- `input` appears in the trace. Use [`secrets`](/docs/sandboxes/features/secrets) for sensitive values.

## Return a value

```typescript {{ title: "TypeScript" }}
await step.sandbox.typescript("a", `const total = rows.length; return { total };`, { input: { rows } });
await step.sandbox.python("b", `total = len(rows)\nreturn {"total": total}`, { input: { rows } });
```

Top-level `await` works. Code with no `return` returns `undefined`.

## Type the result

```typescript {{ title: "TypeScript" }}
const stats = await step.sandbox.python(
  "stats",
  `return {"mean": sum(xs) / len(xs), "n": len(xs)}`,
  {
    input: { xs },
    schema: { output: z.object({ mean: z.number(), n: z.number() }) },
  },
);

stats.mean;
```

Any [Standard Schema](https://standardschema.dev) library works. A value that doesn't match fails the step, and the error lists the problems.

## Choose a runtime

```typescript {{ title: "TypeScript" }}
await step.sandbox.typescript("node", code, { runtime: "node@22" });
await step.sandbox.typescript("edge", code, { runtime: "deno" });
await step.sandbox.typescript("fast", code, { runtime: "bun" });
await step.sandbox.python("ml", code, { runtime: "python@3.13" });
```

Other versions include `node@20`, `node@24`, `python@3.11`, and `python@3.12`. Each is a [runtime image](/docs/sandboxes/features/base-images).

## The `$` template

```typescript {{ title: "TypeScript" }}
await using sb = await step.sandbox.create("repo");

await sb.$`git clone --depth 1 ${url} /work/repo`;
const files = await sb.$.sh`ls /work/repo | head -5`.text();
const pkg = await sb.$`cat /work/repo/package.json`.json();
const tests = await sb.$.sh({ exitCodes: [0, 1], timeout: "4m" })`cd /work/repo && npm test`;
```

- `` sb.$`…` `` runs the command directly, without a shell. Each `${value}` is passed as one argument.
- `` sb.$.sh`…` `` runs the command with `/bin/sh -c`, with values quoted. Use it for pipes and `&&`.
- To set options, call `$` with them first: `timeout`, `env`, `cwd`, `retries`, `exitCodes`, `id`, and `quiet`. Save the configured tag to reuse it: `const repo$ = sb.$({ cwd: "/work/repo" })`.
- A non-zero exit code fails the step. See [Exit codes](/docs/sandboxes/features/exit-codes).

## The full result

```typescript {{ title: "TypeScript" }}
type SandboxResult = {
  ok: boolean;
  exitCode: number;
  stdout: string;
  stderr: string;
  result?: unknown;
  truncated: boolean;
  durationMs: number;
};
```

Shell commands have no `result`. `ok` is `false` only for an [allowed exit code](/docs/sandboxes/features/exit-codes).

## Options

```typescript {{ title: "TypeScript" }}
type RunnerOptions = {
  input?: Record<string, JSONValue>;
  runtime?: string;
  from?: SandboxImage;
  vcpu?: number;
  memoryMb?: number;
  files?: Record<string, string | Uint8Array>;
  env?: Record<string, string>;
  secrets?: string[];
  cwd?: string;
  timeout?: SandboxDuration;
  exitCodes?: number[] | "any";
  schema?: { input?: StandardSchemaV1; output?: StandardSchemaV1 };
  tools?: SandboxTools;
  toolOptions?: SandboxToolOptions;
  owner?: "persistent" | { runId: string };
};
```

- The defaults are 2 `vcpu`, 2048 `memoryMb`, and a `timeout` of `"30s"`, which you can raise to `"5m"`. See [limits](/docs/sandboxes/limits).
- `from` is [`image.inngest()` or `image.custom()`](/docs/sandboxes/features/base-images#choose-an-image).
- [`tools`](/docs/sandboxes/features/tools) and [`owner`](/docs/sandboxes/features/run-owned) are covered on their own pages.

## How it works

- Each runner is a group of durable steps, so a retry repeats only the phase that failed.
- Each call is one row in the [trace](/docs/sandboxes/features/traces), with create, run, and destroy phases.
