# Pause and resume

> Pause a Sandbox while work waits, then resume the same environment.

- **Wait for a human.** Pause while a job waits for review.
- **Same ID, same state.** Filesystem, memory, processes, and environment return.
- **Pay for active time only.** Paused time does not use the one-hour runtime. [Limits →](/docs/sandboxes/limits?ref=docs-sandboxes-pause-and-resume)
- **Stay owned.** The paused Sandbox is cleaned up when the run ends. [Run-owned →](/docs/sandboxes/features/run-owned?ref=docs-sandboxes-pause-and-resume)

<AnnotatedCode>

```typescript {{ title: "inngest/functions/review.ts" }}
const sandbox = await step.sandbox.create("create", {
  name: `work-${event.data.jobId}`,
});

await sandbox.commands.run("write", "echo progress > /tmp/progress.txt");

const paused = await sandbox.pause("pause", { timeout: "5m" });
const running = await paused.resume("resume", { timeout: "5m" });

const out = await running.commands.run("read", "cat /tmp/progress.txt");
```

The direct client has the same calls without step IDs.

```typescript {{ title: "TypeScript" }}
const paused = await sandbox.pause({ timeout: "5m" });
const running = await paused.resume({ timeout: "5m" });

console.log(running.id === paused.id);
```

## How it works

- The path is `RUNNING`, `PAUSING`, `PAUSED`, `RESUMING`, `RUNNING`.
- Commands, files, and processes need `RUNNING`.
- Pause is a cold checkpoint, so reconnect network clients after resume.
- A `timeout` bounds the SDK wait. Get the Sandbox to see the real state.
- The runtime limit triggers an automatic pause. [Runtime expiry →](/docs/sandboxes/limits#runtime-expiry)
- Pause is not a backup. Need a reusable copy? [Snapshots →](/docs/sandboxes/features/snapshots-and-restore?ref=docs-sandboxes-pause-and-resume)
