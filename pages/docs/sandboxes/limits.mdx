# Sandboxes limits

> Choose a supported size and plan around the limits.

| Limit | Value | If you reach it |
| --- | --- | --- |
| Access | Inngest Cloud account on Pro or above. | `403 access_denied` means the plan does not include Sandboxes. [Upgrade your plan](https://app.inngest.com/billing/plans). |
| Size | **1, 2 or 4 vCPU** with **1, 2 or 4 GiB per vCPU**. [Sizes →](/docs/sandboxes/features/base-images?ref=docs-sandboxes-limits#choose-a-size) Clones inherit. | Other sizes are refused. Capacity can still reject. |
| Custom images | One `linux/amd64` image per upload, up to **5 GiB** uploaded and **5 GiB** expanded. At most **10** unfinished builds per workspace. | [Custom images →](/docs/sandboxes/features/custom-images?ref=docs-sandboxes-limits) |
| Active name | 1-255 characters, unique per workspace. | Same config returns the Sandbox. Else `409 sandbox_name_taken`. |
| Create readiness wait | **120 s** default. `runningTimeout` changes it. `false` skips it. | Timeout does not destroy the Sandbox. Get it and clean up. |
| Captured command | **30 s** default, **5 min** max. | Effects may be uncertain. Use a managed process for longer work. |
| Captured output | Direct and REST: **4 MiB**. `step.sandbox`: **2 MiB** tail. | `413 sandbox_exec_output_too_large`. Write to a file. |
| Process wait | **30 s** default, **5 min** max. | The process keeps running. Wait again. |
| Process output | About **512 KiB** per process. Newest **32** kept. `tailBytes` 0-524,288. | Old output is evicted. Save it elsewhere. |
| File transfer | **100 MiB** per file, direct client or REST. Runners accept `files`. | `413 sandbox_file_too_large`. Split it. |
| Snapshot wait | Up to **5 min** for `READY`. | Polling stops, creation continues. List before retrying. |
| Snapshot quota | Account-specific, unpublished. Each has `expiresAt`. | `403 sandbox_snapshot_limit_exceeded`. Delete old snapshots. |
| Runner code and input | **8 MiB** combined. | Fails before create. Pass big data with `files`. |
| Tool calls | **100** per command (`maxCalls`), **8** parallel. Request **256 KiB**, reply **1 MiB**, **30 s** `toolTimeout`. | The Sandbox gets a `ToolError`. |
| Owned resources | Sandboxes and snapshots a run owns are cleaned up when it ends. | [Run-owned](/docs/sandboxes/features/run-owned?ref=docs-sandboxes-limits) |
| Runtime | **1 hour** of active runtime per Sandbox. Paused time is free. | Automatic pause. [Runtime expiry](#runtime-expiry) |
| Disk and concurrency | Unpublished. No configurable lifetime, disk, or resizing. | Ask Inngest about your entitlement. |

Argument, environment, process spec, and JSON body sizes are also capped.

## Runtime expiry

- At the limit, Inngest requests an automatic **Pause**: `RUNNING`, `PAUSING`, `PAUSED`.
- The Sandbox is not destroyed or `FAILED`. Resume while its checkpoint is retained.
- The pause is asynchronous, so the change may lag the exact second.
- `commands.run()` can be cut off with no exit code. Check a marker after resume before repeating.
- `processes.start()` survives, but waits, streams, and network connections break. Reconnect.
- Wait for `RUNNING` before commands, files, logs, or processes. [Pause and resume →](/docs/sandboxes/features/pause-and-resume?ref=docs-sandboxes-limits)
- Save lasting artifacts elsewhere. Destroy when done.
