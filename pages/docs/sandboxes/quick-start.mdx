# Sandboxes quick start
> Run your first Sandbox from a durable function and inspect it in the run trace.

Run Python in an isolated Linux Sandbox, get its result back as a value, and see the run in the trace. Inngest creates the Sandbox, destroys it, and cleans up if the run fails.

## Before you start

You need:

- An existing server-side TypeScript Inngest app connected to an Inngest Cloud environment. If you need an app, start with the [Node.js quick start](/docs/durable-execution/quick-start/typescript-quick-start).
- Node.js 20.5 or newer.
- Your environment's signing key set as `INNGEST_SIGNING_KEY` in your **server** environment. Keep it out of browser code and source control.

## 1. Install the SDK

> **Upgrading from SDK v3?** Sandboxes require the TypeScript SDK v4. Follow the [v3 to v4 migration guide](/docs/reference/typescript/v4/migrations/v3-to-v4) first.

```bash
npm install inngest@latest
```

## 2. Enable Sandbox steps

Add the Sandbox middleware to your shared Inngest client. This makes `step.sandbox` available inside functions.

`inngest/client.ts`

<CodeGroup>
```typescript {{ title: "TypeScript" }}
import { Inngest } from "inngest";
import { sandboxMiddleware } from "inngest/experimental";

export const inngest = new Inngest({
  id: "sandbox-demo",
  middleware: [sandboxMiddleware()],
});
```

Keep your existing app ID if you're adding this to an app you already use.

## 3. Run code in a Sandbox

This function runs a Python snippet on data from the event and returns the result. The `input` keys become variables in the code, and a top-level `return` sends the value back.

`inngest/functions/run-in-sandbox.ts`

<CodeGroup>
```typescript {{ title: "TypeScript" }}
import { inngest } from "../client";

export const runInSandbox = inngest.createFunction(
  { id: "run-in-sandbox", triggers: { event: "sandbox/demo.requested" } },
  async ({ event, step }) => {
    const stats = await step.sandbox.python<{ mean: number; n: number }>(
      "stats",
      `return {"mean": sum(values) / len(values), "n": len(values)}`,
      { input: { values: event.data.values } },
    );

    const listing = await step.sandbox.sh("list", "uname -a && ls /");

    return { stats, listing };
  },
);
```

Register `runInSandbox` in the `functions` array of your `serve()` handler. Each statement boots its own Sandbox, runs, and destroys it. There's nothing to clean up.

## 4. Trigger your function

Send this event to the same environment from the Inngest dashboard or your app:

```json
{
  "name": "sandbox/demo.requested",
  "data": { "values": [3, 5, 10] }
}
```

## 5. Inspect the result

Open the function run in Inngest. It returns a result like this:

```json
{
  "stats": { "mean": 6, "n": 3 },
  "listing": "Linux ... \nbin\ndev\netc\n..."
}
```

Open the trace. Each statement is one **SANDBOX** group, collapsed to a row with its runtime, exit code, and duration. Expand `stats` to see `create`, `run`, and `destroy`. See [Traces](/docs/sandboxes/features/traces).

Now make a command fail. Change the second statement to `step.sandbox.sh("list", "ls /missing")`. The row turns red, the exit code is on it, and the function ends. [Exit codes and errors](/docs/sandboxes/features/exit-codes) shows how to allow codes that are information.

## Keep one Sandbox for several statements

To install something once and use it in later statements, create a Sandbox. With `await using`, it's destroyed when the function leaves the scope, and if you leave that off it's destroyed when the run ends:

```typescript {{ title: "TypeScript" }}
await using sb = await step.sandbox.create("work");

await sb.$`npm init -y && npm install lodash`;
const version = await sb.$`node -p "require('lodash').VERSION"`.text();
```
