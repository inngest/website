## What you can do

- **Run code in one statement.** Python, TypeScript, or shell, with a typed value back. [Run code →](/docs/sandboxes/features/run-code?ref=docs-sandboxes-overview)
- **Fail loudly.** A non-zero exit fails its step and shows red. [Exit codes →](/docs/sandboxes/features/exit-codes?ref=docs-sandboxes-overview)
- **Call your functions from the Sandbox.** Tools run as durable steps with your credentials. [Tools →](/docs/sandboxes/features/tools?ref=docs-sandboxes-overview)
- **Reuse sandbox code.** A plain function over a runner, typed in and out. [Reusable functions →](/docs/sandboxes/features/sandbox-functions?ref=docs-sandboxes-overview)
- **Never leak one.** Whatever your run creates is cleaned up when it ends. [Run-owned →](/docs/sandboxes/features/run-owned?ref=docs-sandboxes-overview)
- **Snapshot and clone.** Files persist across pause, snapshot, and clone. [Snapshots →](/docs/sandboxes/features/snapshots-and-restore?ref=docs-sandboxes-overview)

## How it works

- A Sandbox is a Linux microVM, separate from where your functions are hosted.
- Each operation is a step in the durable run, so one trace shows both.
- Anything still alive when the run ends is cleaned up.

[Inngest CI →](/docs/labs/ci) runs each pipeline job on its own Sandbox.
