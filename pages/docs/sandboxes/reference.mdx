# Sandboxes reference

> Calls and options for running code, creating Sandboxes, and managing their lifecycle. Bounds are in [Limits](/docs/sandboxes/limits).

## Before you call

- Use trusted server-side Node.js 20.5+ with the `inngest` v4 package.
- `await using` needs `lib: ["esnext.disposable"]` in `tsconfig.json`.
- Enable Sandboxes and set `INNGEST_SIGNING_KEY`. `403 access_denied` means not enabled.
- Fresh Sandboxes start from `base` unless you set `from`. Sizes are `1 / 1024`, `2 / 2048`, `4 / 4096`. Clones inherit.

## Choose the TypeScript surface

- `step.sandbox`: a durable step per call, with a stable step ID. Memoized and retry-classified.
- `inngest.sandboxes`: immediate calls from routes and workers. You own retries and cleanup. No middleware.

### Durable call shape

Step ID first. Keep IDs stable across replays and deployments.

- `from` is `image.inngest("base")` (default) or `image.custom(ref)`, imported from `inngest`. [Choose an image →](/docs/sandboxes/features/base-images?ref=docs-sandboxes-reference#choose-an-image)

## Runners

```typescript {{ title: "TypeScript" }}
step.sandbox.python<T>(id, code, options?); // T, the `return` value
step.sandbox.ts<T>(id, code, options?); // T, the `return` value
step.sandbox.sh(id, command, options?); // stdout string
step.sandbox.run(id, spec); // SandboxResult
```

The same methods exist on a handle from `step.sandbox.create()` or `group.sandbox()`. A handle also has `` sb.$`…` `` (direct argv) and `` sb.$.sh`…` `` (`/bin/sh -c`, values quoted), and takes options as a call, `` sb.$({ id, exitCodes, timeout, retries, env, cwd, quiet })`…` ``. Results have `.text()` and `.json()`. A bare `$` from `inngest/experimental` runs on the enclosing `group.sandbox()` Sandbox and throws outside one. [Run code →](/docs/sandboxes/features/run-code?ref=docs-sandboxes-reference)

```typescript {{ title: "TypeScript" }}
type CreateOptions = {
  name?: string;
  from?: SandboxImage;
  vcpu?: number;
  memoryMb?: number;
  timeout?: SandboxDuration;
  runningTimeout?: SandboxDuration | false;
  env?: Record<string, string>;
  secrets?: string[];
  owner?: "persistent" | { runId: string };
  tools?: SandboxTools;
  toolOptions?: SandboxToolOptions;
};

type GroupSandboxOptions = CreateOptions & { id: string };

type RunnerOptions = {
  input?: Record<string, JSONValue>;
  runtime?: string;
  from?: SandboxImage;
  vcpu?: number;
  memoryMb?: number;
  files?: Record<string, string | Uint8Array>;
  env?: Record<string, string>;
  secrets?: string[];
  cwd?: string;
  timeout?: SandboxDuration;
  exitCodes?: number[] | "any";
  schema?: { input?: StandardSchemaV1; output?: StandardSchemaV1 };
  tools?: SandboxTools;
  toolOptions?: SandboxToolOptions;
  owner?: "persistent" | { runId: string };
};

type SandboxResult = {
  ok: boolean;
  exitCode: number;
  stdout: string;
  stderr: string;
  result?: unknown;
  truncated: boolean;
  durationMs: number;
};
```

- `create(id, CreateOptions?)`. `group.sandbox()` takes an ID or `GroupSandboxOptions`. Runners take `RunnerOptions`.
- CI jobs use `machine` instead. [Machines →](/docs/labs/ci/machines)
- `runtime` and `from` are exclusive. `runtime` maps to an [image Inngest maintains](/docs/sandboxes/features/base-images#runtime-images).
- `exitCodes` defaults to `[0]`. [Exit codes →](/docs/sandboxes/features/exit-codes?ref=docs-sandboxes-reference)
- `owner` defaults to the current run. [Run-owned →](/docs/sandboxes/features/run-owned?ref=docs-sandboxes-reference)
- `tools` exposes host functions to the code. [Tools →](/docs/sandboxes/features/tools?ref=docs-sandboxes-reference)
- `getCommandError(err)` returns `{ command, exitCode, stdoutTail, stderrTail, truncated }`. `getSandboxError(err)` returns the `SandboxError` fields.

## Functions and tools

```typescript {{ title: "TypeScript" }}
tool.step({ description?, input?, output?, run }); // one durable step; run receives (input, ctx)
tool.group({ description?, input?, output?, run }); // runs as a group; use step from "inngest"
sandbox.codeTool({ language, timeout?, tools }); // one LLM tool that writes code against your tools
describeTools(tools, language); // typed declaration the code sees
agentLoop({ adapter, tools, model, messages, maxTurns? }); // model and tool loop in your function
```

- Adapters in `@inngest/sandbox-tools`: `toAiSdk`, `toAnthropic`, `toOpenAI`, `toMcp`.
- `ctx` is `{ idempotencyKey, sandbox: { id }, signal }`. [Tools →](/docs/sandboxes/features/tools?ref=docs-sandboxes-reference)

## Operation index

Durable steps take a stable step ID first. The direct client does not.

```typescript {{ title: "TypeScript" }}
inngest.sandboxes.create(options);
inngest.sandboxes.list(options?);
inngest.sandboxes.get(id);

sandbox.waitUntilRunning({ timeout });
sandbox.destroy();
sandbox.pause(options?);
sandbox.resume(options?);
sandbox.commands.run(command, options?);
sandbox.processes.start / list / get; // process: getOutput / signal / wait
sandbox.snapshot(options?, waitOptions?);
snapshot.clone(options); // snapshots: list / get / delete

sandbox.files.upload / download; // direct client only
sandbox.logs.stream; // direct client only
process.streamOutput; // direct client only

await step.sandbox.get("lookup", sandboxId);
await sandbox.pause("pause", options);
```

## Sandbox lifecycle

- Pause path: `PENDING`, `STARTING`, `RUNNING`, `PAUSING`, `PAUSED`, `RESUMING`, `RUNNING`.
- Destroy goes `TERMINATING`, `TERMINATED`. A Sandbox can also be `FAILED`.
- Commands, files, logs, and processes need `RUNNING`.
- Create waits up to 120 s. `runningTimeout: false` returns the ID at once. Then call `waitUntilRunning`.
- A readiness timeout does not cancel Create or destroy the Sandbox.
- SDK objects are views. Get or a lifecycle call returns a fresh one.
- Pause and Resume keep ID, filesystem, memory, environment, and remaining runtime. [Runtime expiry →](/docs/sandboxes/limits#runtime-expiry)
- There is no in-place restore from a user snapshot.

## Commands, processes, and files

- `commands.run` returns `stdout`, `stderr`, `exitCode`, and truncation metadata. Strings run via `/bin/sh -c`. Arrays keep argument boundaries.
- Through `step.sandbox`, an exit code outside `exitCodes` fails the step. Through the direct client it is a result.
- `processes.start` returns a process with a UUID. Use `list`, `get`, `getOutput`, `signal`, and `wait`. A wait timeout does not stop it.
- Retained output is bounded. Live streams can miss or replay chunks.
- The direct client uploads or downloads one regular file at an absolute path. Upload replaces. There is no list, append, rename, or recursive transfer.
- Files survive pause and resume, and end at destroy.
- `secrets: ["NAME"]` injects workspace secrets as env vars. Clones cannot select new ones. [Secrets →](/docs/sandboxes/features/secrets?ref=docs-sandboxes-reference)

## Snapshots and clones

- `sandbox.snapshot({ name })` names a snapshot. `snapshots.list({ name })` returns exact matches, newest first.
- A held name fails with `sandbox_snapshot_name_taken`. [Name a snapshot →](/docs/sandboxes/features/snapshots-and-restore?ref=docs-sandboxes-reference#name-a-snapshot)
- Snapshots capture memory, disk, environment, image, and resources. The SDK waits up to five minutes for `READY`.
- `snapshot.clone()` makes a new Sandbox ID with the captured state.
- Snapshots are crash-consistent and expire. A private pause checkpoint is not a user snapshot and cannot be cloned.

## Errors and cleanup

- `SandboxError` has `action`, `code`, `ambiguous`, `retryable`, `requestId`, and resource IDs. Branch on those, not the message.
- The direct client never retries. Durable middleware retries retryable failures only.
- `operation_ambiguous` may have completed. Reconcile before repeating:

```typescript {{ title: "TypeScript" }}
// exec:             inspect external effects or a completion marker
// process.start:    list processes, compare command and start time
// process.signal:   get or wait for the process first
// snapshot.create:  list recent snapshots first
```

- Create, Destroy, Pause, Resume, snapshot Delete, and identical file upload are safe to repeat.
- Command timeouts and output-limit errors may also mean the command ran.
- In a function, the run owns Sandboxes and snapshots. Directly, use `finally` or `owner: { runId }`.
