# Sandbox REST API v2

The Sandbox REST API creates isolated Linux runtimes, executes commands,
transfers files, streams logs, manages background processes, and creates
restorable snapshots.

Cloud API origin:

```text
https://api.inngest.com
```

Every route below includes its `/v2` prefix.

## Authentication

Use an Inngest signing key. Set `X-Inngest-Env` when you need to target an
environment explicitly:

```text
Authorization: Bearer <INNGEST_SIGNING_KEY>
X-Inngest-Env: production
```

```sh
curl https://api.inngest.com/v2/sandboxes \
  --header "Authorization: Bearer $INNGEST_SIGNING_KEY" \
  --header "X-Inngest-Env: production"
```

Find the signing key in the Inngest dashboard. Keep it in server-side code and
secret stores. Without `X-Inngest-Env`, the signing key's workspace is used.
The header is particularly useful for branch environments that share a parent
signing key.

The TypeScript `inngest.sandboxes` client uses the signing key and environment
configuration attached to its `Inngest` client. See the
[TypeScript SDK reference](/docs/reference/typescript/v4/sandboxes).

## JSON conventions

JSON requests:

- use `Content-Type: application/json`;
- reject unknown fields;
- reject trailing or multiple JSON values; and
- are capped at 1 MiB for Create, captured Exec, process Start, and Signal.

Snapshot Create is capped at 4 KiB.

Most successful responses use:

```json
{
  "data": {},
  "metadata": {
    "fetchedAt": "2026-07-28T19:00:00.123456789Z"
  }
}
```

List responses also include a top-level `page`.

Errors use:

```json
{
  "errors": [
    {
      "code": "invalid_field_format",
      "message": "command must contain at least one argument"
    }
  ]
}
```

Branch on `code`, not `message`. Live responses set
`Cache-Control: no-store`. RFC 3339 timestamps can include nanosecond
precision.

## Sandbox resource

```json
{
  "id": "b066bdf7-a57b-4d8b-a1a7-76eab1f91273",
  "name": "agent_job-42",
  "status": "RUNNING",
  "vpcId": "5f82a217-9d54-4fa8-a9be-d1dbba8a8db2",
  "imageRef": "default",
  "resources": {
    "vcpu": 1,
    "memoryMb": 1024
  },
  "createdAt": "2026-07-28T19:00:00.123456789Z",
  "startedAt": "2026-07-28T19:00:00.500000000Z"
}
```

| Field                | Meaning                                                                             |
| -------------------- | ----------------------------------------------------------------------------------- |
| `id`                 | Public sandbox UUID                                                                 |
| `name`               | Workspace-scoped active name                                                        |
| `status`             | Uppercase lifecycle state                                                           |
| `vpcId`              | Resolved workspace VPC; informational                                               |
| `imageRef`           | Resolved image reference; do not assume it is always `default`                      |
| `imageDigest`        | Optional pinned artifact digest, in `sha256:<hex>` form; absent on legacy sandboxes |
| `resources.vcpu`     | Allocated virtual CPUs                                                              |
| `resources.memoryMb` | Allocated memory in MiB                                                             |
| `createdAt`          | Resource creation time                                                              |
| `startedAt`          | Runtime start time; omitted until present                                           |
| `endedAt`            | Terminal time; omitted until present                                                |
| `error`              | Optional terminal error information                                                 |

Possible statuses:

```text
PENDING
STARTING
PAUSING
RUNNING
PAUSED
RESUMING
TERMINATING
TERMINATED
FAILED
```

Create returns only `STARTING` or `RUNNING`. Pause can return `PAUSING` or
`PAUSED`; Resume can return `RESUMING` or `RUNNING`. Runtime operations require
`RUNNING`.

## Process resource

```json
{
  "id": "45cef567-a28c-4109-b464-bc9c504ea900",
  "command": ["/bin/sh", "-c", "while :; do sleep 1; done"],
  "pid": 87,
  "state": "RUNNING",
  "startedAt": "2026-07-28T19:00:02.123456789Z"
}
```

Possible states:

```text
STARTING
RUNNING
EXITED
KILLED
FAILED
LOST
```

`exitCode` is included only for `EXITED`. `terminationSignal` is included only
for `KILLED`. Process metadata is held in memory and disappears with the
sandbox.

## Create a sandbox

```text
POST /v2/sandboxes
Content-Type: application/json
```

```json
{
  "name": "agent_job-42",
  "vcpu": 1,
  "memoryMb": 1024,
  "environment": {
    "CI": "true"
  },
  "secrets": ["OPENAI_API_KEY", "GITHUB_TOKEN"]
}
```

| Field         | Validation                                                                                   |
| ------------- | -------------------------------------------------------------------------------------------- |
| `name`        | Required; 1–255 Unicode code points, no control characters or surrounding whitespace         |
| `vcpu`        | Required positive unsigned 32-bit integer for a new sandbox                                  |
| `memoryMb`    | Required positive unsigned 32-bit integer for a new sandbox                                  |
| `environment` | Optional sandbox-level environment variables                                                 |
| `secrets`     | Optional array of exact workspace secret names for a new sandbox                             |
| `image`       | Optional published image reference for a fresh sandbox; cannot be combined with `snapshotId` |
| `snapshotId`  | Optional READY snapshot UUID to clone                                                        |

New sandboxes currently support these exact resource configurations:

| `vcpu` |          `memoryMb` |
| -----: | ------------------: |
|      1 |    1024, 2048, 4096 |
|      2 |    2048, 4096, 8192 |
|      4 |   4096, 8192, 16384 |
|      8 |  8192, 16384, 32768 |
|     16 | 16384, 32768, 65536 |

Choose one memory value from the CPU's row. Unsupported combinations return
`400 invalid_field_format`, even when both values are positive. Supported
sizes can still fail with `503 compute_unavailable` when capacity is
unavailable. The API does not accept a profile name or resize an existing
sandbox.

The API resolves the workspace's default egress-only VPC. Omitting `image`
selects the default image. There is no `vpcId` or `template` request field, and
no user-configurable TTL or idle timeout. When `snapshotId`
is present, `vcpu` and `memoryMb` can be omitted and otherwise must match the
snapshot. The clone restores the snapshot's image, resources, environment,
memory, and disk; a clone request cannot include `environment` or `secrets`.

For a fresh sandbox, every `secrets` entry selects an active secret in the
authenticated workspace. Each value is injected under the same name and is
inherited by commands and managed processes. The request and sandbox resource
contain names only; secret values are not returned by this API.

Secret names are exact and case-sensitive. Each name must be unique, at most
256 UTF-8 bytes, free of leading or trailing Unicode whitespace, and contain
no `=`, carriage return, line feed, or NUL. A selected name cannot also appear
in `environment`. Literal environment keys and selected secret names share a
maximum of 256 entries and 64 KiB of resolved `KEY=value` data. Invalid,
missing, or archived selections return HTTP 400 with `invalid_field_format`.
See [Secrets](/docs/features/sandboxes/secrets) for delivery, rotation,
snapshot, and redaction behavior.

The current beta image includes Node.js latest and LTS, Python 3.14, Ruby 4.0,
Git, curl, OpenSSH, CA certificates, BusyBox `sh`, and common command-line
tools. Go, Rust, Java, Bun, and Deno are not currently installed. Exact runtime
versions may change when the image is rebuilt.

### Select a published image

For a fresh sandbox, `image` can select a published image visible to the
workspace. Accepted reference forms are:

- `name` or `name:tag`;
- `name@sha256:<64 lowercase hex characters>`; or
- `sha256:<64 lowercase hex characters>`.

Omit `image` to use the default. An empty string or the literal `default` is
not a valid explicit selection. Do not combine `image` with `snapshotId`.
A missing or inaccessible image returns `404 sandbox_image_not_found`; an
image that is not ready returns `409 sandbox_image_not_ready`.

Published tags can move. Existing sandboxes keep their resolved image; changing
a tag does not update them. Use a digest when you need to pin an artifact.

<Callout variant="info">
  Image selection is available through REST and SDK 4.25 or newer. Select an
  image published to your workspace; this API does not pull directly from a
  container registry.
</Callout>

See [Custom images](/docs/features/sandboxes/custom-images) for the Docker build,
signed upload, Commit, and readiness-polling workflow.

### Create response

Response:

- HTTP 200 with the matching active sandbox when an identical Create is
  repeated;
- HTTP 201 with a full `RUNNING` sandbox; or
- HTTP 202 with a full `STARTING` sandbox.

```json
{
  "data": {
    "id": "b066bdf7-a57b-4d8b-a1a7-76eab1f91273",
    "name": "agent_job-42",
    "status": "STARTING",
    "vpcId": "5f82a217-9d54-4fa8-a9be-d1dbba8a8db2",
    "imageRef": "default",
    "resources": {
      "vcpu": 1,
      "memoryMb": 1024
    },
    "createdAt": "2026-07-28T19:00:00.123456789Z"
  },
  "metadata": {
    "fetchedAt": "2026-07-28T19:00:00.200000000Z"
  }
}
```

Important errors:

| HTTP | Code                                        | Meaning                                                             |
| ---: | ------------------------------------------- | ------------------------------------------------------------------- |
|  400 | `invalid_request` or `invalid_field_format` | Invalid JSON, name, resources, environment, or snapshot combination |
|  403 | `access_denied`                             | Sandbox access is not enabled                                       |
|  409 | `sandbox_name_taken`                        | Active sandbox already uses the name                                |
|  429 | `rate_limited`                              | Rejected before Create                                              |
|  503 | `compute_unavailable`                       | Compute could not accept Create                                     |

Create is idempotent for an active sandbox with the same name and resource
request. Repeating the exact request returns that sandbox instead of creating a
second one. Reusing the name with different resources returns
`sandbox_name_taken`.

## List sandboxes

```text
GET /v2/sandboxes?limit=50&cursor=<opaque>
```

| Parameter | Default | Validation                           |
| --------- | ------: | ------------------------------------ |
| `limit`   |      50 | Integer from 1 through 250           |
| `cursor`  |    None | Opaque cursor from the previous page |

```json
{
  "data": [
    {
      "id": "b066bdf7-a57b-4d8b-a1a7-76eab1f91273",
      "name": "agent_job-42",
      "status": "RUNNING",
      "vpcId": "5f82a217-9d54-4fa8-a9be-d1dbba8a8db2",
      "imageRef": "default",
      "resources": {
        "vcpu": 1,
        "memoryMb": 1024
      },
      "createdAt": "2026-07-28T19:00:00.123456789Z",
      "startedAt": "2026-07-28T19:00:00.500000000Z"
    }
  ],
  "metadata": {
    "fetchedAt": "2026-07-28T19:00:03.000000000Z"
  },
  "page": {
    "cursor": "eyJjcmVhdGVkQXQiOi...",
    "hasMore": true,
    "limit": 50
  }
}
```

List is scoped to the authenticated workspace, includes retained terminal
resources, and orders by `createdAt DESC`, then `id DESC`. It uses keyset
pagination. Do not decode or construct cursors.

## Get a sandbox

```text
GET /v2/sandboxes/{sandboxId}
```

Returns HTTP 200 with the full resource. A missing or workspace-hidden
resource returns:

```text
404 sandbox_not_found
```

While Pause or Resume is in progress, Get and List can currently serialize the
transient lifecycle as `STARTING`. Treat it as a non-running state and continue
polling until `PAUSED` or `RUNNING`.

## Pause a sandbox

```text
POST /v2/sandboxes/{sandboxId}/pause
```

Send no request body. The source sandbox must be `RUNNING`, already `PAUSING`,
or already `PAUSED`. Repeating Pause continues or returns the same lifecycle
transition instead of creating another checkpoint.

Success returns HTTP 200 with the full sandbox resource. The response can be
`PAUSING` while the private checkpoint is uploaded or `PAUSED` when it has
finished. Poll Get until `PAUSED` before attempting runtime operations.

Pause creates a private memory-and-disk checkpoint, stops the live runtime,
and clears its node placement. The checkpoint is hidden from snapshot List and
does not count against user snapshot quotas. Time spent paused does not consume
the sandbox's remaining runtime.

## Resume a sandbox

```text
POST /v2/sandboxes/{sandboxId}/resume
```

Send no request body. The sandbox must be `PAUSED`, already `RESUMING`, or
already `RUNNING`. Success returns HTTP 200 with the full resource. The response
can be `RESUMING` or `RUNNING`; poll Get before using runtime operations.

Resume restores the private checkpoint with the same sandbox UUID, name, VPC,
MAC address, IP address, image, resources, environment, filesystem, and
remaining runtime. Repeating Resume continues or returns the same transition.

Pause and Resume return `409 invalid_request` from an incompatible state,
`404 sandbox_not_found` for a missing or workspace-hidden sandbox, and
`503 compute_unavailable` for a temporary compute or snapshot-storage failure.
Repeating either transition after `compute_unavailable` is safe.

## Destroy a sandbox

```text
DELETE /v2/sandboxes/{sandboxId}
```

- HTTP 202 returns the full `TERMINATING` resource.
- HTTP 204 has no body when teardown completed synchronously.
- A missing or hidden resource returns `404 sandbox_not_found`.

The destroy intent is persisted before node teardown. After the intent is
stored, temporary node unavailability can still return the durable
`TERMINATING` resource.

## Run a captured command

```text
POST /v2/sandboxes/{sandboxId}/exec
Content-Type: application/json
```

```json
{
  "command": ["/bin/sh", "-c", "printf 'tests passed\n'"],
  "environment": {
    "CI": "true"
  },
  "cwd": "/",
  "timeout": "5m"
}
```

| Field         |   Default | Meaning                                           |
| ------------- | --------: | ------------------------------------------------- |
| `command`     |  Required | Argument vector executed directly                 |
| `environment` | Inherited | Overrides sandbox and guest environment variables |
| `cwd`         |       `/` | Working directory                                 |
| `timeout`     |     `30s` | Go duration greater than zero and at most `5m`    |

The API does not shell-parse the command or accept a command string. Use
`["/bin/sh", "-c", "..."]` when you need shell syntax. A bare executable name
is resolved with the effective guest `PATH`; a value containing `/` is used as
supplied, relative to `cwd` when it is not absolute.

```json
{
  "data": {
    "stdout": "dGVzdHMgcGFzc2VkCg==",
    "stderr": "",
    "encoding": "base64",
    "exitCode": 0
  },
  "metadata": {
    "fetchedAt": "2026-07-28T19:01:00.000000000Z"
  }
}
```

`stdout` and `stderr` are base64. A non-zero exit code still returns HTTP 200.
Combined raw output is limited to 4 MiB.

| HTTP | Code                            | Meaning                                                         |
| ---: | ------------------------------- | --------------------------------------------------------------- |
|  409 | `operation_ambiguous`           | The command may have executed, but its result was not confirmed |
|  413 | `sandbox_exec_output_too_large` | Output exceeded 4 MiB; command may have executed                |
|  504 | `sandbox_exec_timed_out`        | Observation timed out; command may have executed                |

`operation_ambiguous` is an error about the Exec outcome, not a sandbox state.
Do not retry these automatically. Inspect the command's external effects or an
application-defined completion marker before deciding what to do next.

## Stream sandbox logs

```text
GET /v2/sandboxes/{sandboxId}/logs?follow=false
Accept: application/x-ndjson
```

`follow` defaults to `false` and accepts only `true` or `false`.

```json
{"type":"log","stream":"STDOUT","data":"c3RhcnRlZAo=","encoding":"base64","at":"2026-07-28T19:00:00Z"}
{"type":"log","stream":"STDERR","data":"d2FybmluZwo=","encoding":"base64","at":"2026-07-28T19:00:01Z"}
```

The endpoint opens the upstream stream before committing HTTP 200, so an
admission failure returns an ordinary non-200 JSON error. A live failure after
HTTP 200 is terminal:

```json
{
  "type": "error",
  "errors": [
    {
      "code": "compute_unavailable",
      "message": "Compute is temporarily unavailable"
    }
  ]
}
```

Parse every frame. HTTP 200 alone does not mean the stream completed
successfully.

## Upload or replace a file

```text
PUT /v2/sandboxes/{sandboxId}/files?path=/tmp/input.bin&mode=0640
Content-Type: application/octet-stream
```

The body is the raw file. URL-encode query values.

| Parameter |  Default | Validation                        |
| --------- | -------: | --------------------------------- |
| `path`    | Required | Absolute path, at most 4096 bytes |
| `mode`    |   `0644` | Octal `0001` through `0777`       |

Files are capped at 100 MiB. Upload cannot replace `/`, a directory, symlink,
device, socket, or FIFO. A successful write uses an atomic replacement.

```json
{
  "data": {
    "path": "/tmp/input.bin",
    "bytesWritten": 2
  },
  "metadata": {
    "fetchedAt": "2026-07-28T19:00:05.000000000Z"
  }
}
```

Success is HTTP 200. If the response cannot be confirmed after replacement,
the API returns retryable `503 compute_unavailable`. Repeating the same PUT
with the same path, bytes, and mode is safe.

## Download a file

```text
GET /v2/sandboxes/{sandboxId}/files?path=/tmp/output.bin
```

```text
HTTP/1.1 200 OK
Content-Type: application/octet-stream
Content-Length: 1234
Cache-Control: no-store
X-Sandbox-File-Mode: 0640
Last-Modified: Tue, 28 Jul 2026 19:00:00 GMT
```

The body is the raw file. Only regular files up to 100 MiB are downloadable.
Missing sandboxes and files use `404 sandbox_file_not_found`.

A failure after HTTP 200 cannot become JSON. Treat a body shorter than
`Content-Length` as failed.

## Start a managed process

```text
POST /v2/sandboxes/{sandboxId}/processes
Content-Type: application/json
```

```json
{
  "command": ["/bin/sh", "-c", "while :; do sleep 1; done"],
  "environment": {
    "PORT": "8080"
  },
  "cwd": "/"
}
```

`command` is required and follows the captured Exec argument-vector and PATH
rules. `environment` overrides the sandbox and guest environment for this
process.

Response: HTTP 201.

```json
{
  "data": {
    "id": "45cef567-a28c-4109-b464-bc9c504ea900",
    "command": ["/bin/sh", "-c", "while :; do sleep 1; done"],
    "pid": 87,
    "state": "RUNNING"
  },
  "metadata": {
    "fetchedAt": "2026-07-28T19:00:02.500000000Z"
  }
}
```

The platform generates the UUID before dispatch and never exposes internal
guest handles. Start is not HTTP-idempotent. `409 operation_ambiguous` means a
process may be running even though the caller did not receive its UUID and PID.
Do not retry Start automatically. List processes and compare command and start
time. If the process cannot be identified confidently, require application-level
or operator reconciliation.

## Get a managed process

```text
GET /v2/sandboxes/{sandboxId}/processes/{processId}
```

Returns HTTP 200 with one process resource. A missing process returns:

```text
404 sandbox_process_not_found
```

## Signal a managed process

```text
POST /v2/sandboxes/{sandboxId}/processes/{processId}/signals
Content-Type: application/json
```

```json
{
  "signal": 15,
  "includeChildren": false
}
```

| Field             |  Default | Validation                |
| ----------------- | -------: | ------------------------- |
| `signal`          | Required | Integer from 1 through 64 |
| `includeChildren` |  `false` | Boolean                   |

Success returns HTTP 204. An already-terminal process accepts Signal as a
no-op. `409 operation_ambiguous` means the signal may have been delivered. Get
or wait for the process, and resend only when duplicate delivery is safe for
that signal and application. Currently,
`includeChildren: true` should be used only with signal 9 (`SIGKILL`);
descendant delivery with other signals can make terminal state unobservable.

## Wait for a managed process

```text
POST /v2/sandboxes/{sandboxId}/processes/{processId}/wait?timeout=30s
```

There is no request body. `timeout` defaults to `30s`, uses Go duration syntax,
must be positive, and cannot exceed `5m`.

```json
{
  "data": {
    "id": "45cef567-a28c-4109-b464-bc9c504ea900",
    "state": "EXITED",
    "exitCode": 0
  },
  "metadata": {
    "fetchedAt": "2026-07-28T19:01:00.000000000Z"
  }
}
```

`KILLED` includes `terminationSignal` instead of `exitCode`.

`504 sandbox_process_wait_timed_out` stops only the observation. It does not
stop or signal the process.

## Read retained process output

```text
GET /v2/sandboxes/{sandboxId}/processes/{processId}/output?tailBytes=65536
```

`tailBytes` defaults to 0, meaning all retained output. It accepts 0 through
524,288 bytes across stdout and stderr.

```json
{
  "data": {
    "chunks": [
      {
        "stream": "STDOUT",
        "data": "c2VydmVyIHN0YXJ0ZWQK",
        "encoding": "base64",
        "at": "2026-07-28T19:00:03.000000000Z"
      },
      {
        "stream": "STDERR",
        "data": "d2FybmluZwo=",
        "encoding": "base64",
        "at": "2026-07-28T19:00:04.000000000Z"
      }
    ]
  },
  "metadata": {
    "fetchedAt": "2026-07-28T19:00:05.000000000Z"
  }
}
```

Chunks preserve observed ordering and arbitrary bytes. They are not lines.
Tail selection preserves whole chunks.

The endpoint distinguishes:

```text
404 sandbox_process_not_found
404 sandbox_process_output_not_retained
```

## Tail and follow process output

```text
GET /v2/sandboxes/{sandboxId}/processes/{processId}/output/stream?tailBytes=8192
Accept: application/x-ndjson
```

The endpoint always sends the retained tail and then follows live output.
There is no `follow` parameter.

It confirms the process and retained-output ring and opens the upstream stream
before committing HTTP 200. Admission failures therefore return an ordinary
non-200 JSON error.

```json
{"type":"log","stream":"STDOUT","data":"c3RhcnRlZAo=","encoding":"base64","at":"2026-07-28T19:00:03Z"}
{"type":"log","stream":"STDERR","data":"d2FybmluZwo=","encoding":"base64","at":"2026-07-28T19:00:04Z"}
```

A failure after HTTP 200 sends:

```json
{
  "type": "error",
  "errors": [
    {
      "code": "compute_unavailable",
      "message": "Compute is temporarily unavailable"
    }
  ]
}
```

Fail the stream when `type` is `error`.

The stream is best effort. A slow consumer can miss chunks, and frames have no
sequence number or loss marker.

## Create a snapshot

```text
POST /v2/sandboxes/{sandboxId}/snapshots
Content-Type: application/json
```

The body can be empty, `{}`, or an object with an optional snapshot name:

```json
{ "name": "prepared-runtime" }
```

The body is capped at 4 KiB and unknown fields are rejected. Names use the
same validation as sandbox names and are case-sensitive within the workspace.
A `CREATING` or unexpired `READY` snapshot holds its name. Reusing that name
returns `409 sandbox_snapshot_name_taken`, not the existing resource. This
endpoint does not provide an idempotency key, even when a name is supplied.

Snapshot creation is crash-consistent: it captures the sandbox's memory,
disk, environment, image, and resource allocation without coordinating
application-level flushes. The source sandbox must be `RUNNING` and continues
running after the snapshot is taken.

Success returns HTTP 202 with a `CREATING` snapshot. Artifact upload and
readiness continue asynchronously after the response; the request does not stay
open until the snapshot becomes `READY`.

```json
{
  "data": {
    "id": "2a02e0b4-d4c8-4a94-9068-e92399627e83",
    "sourceImageId": "default",
    "status": "CREATING",
    "resources": {
      "vcpu": 1,
      "memoryMb": 1024
    },
    "memoryPackCount": 0,
    "diskPackCount": 0,
    "storedBytes": 0,
    "createdAt": "2026-09-02T12:00:00Z",
    "updatedAt": "2026-09-02T12:00:00Z",
    "expiresAt": "2026-09-03T12:00:00Z"
  },
  "metadata": {
    "fetchedAt": "2026-09-02T12:00:00Z"
  }
}
```

Possible statuses are `CREATING`, `READY`, `DELETING`, `DELETED`, `FAILED`,
and `LOST`. A `READY` snapshot includes `compatibilityId`. Failed snapshots
can include `error`. Poll Get with bounded backoff until the snapshot is `READY`
before cloning it. A client-side polling timeout does not cancel snapshot
creation or its background upload.

Count and storage quotas are account-specific. Exceeding either returns
`403 sandbox_snapshot_limit_exceeded`. An uncertain mutation can return
`409 operation_ambiguous`; read the snapshot before deciding whether to retry.

## List snapshots

```text
GET /v2/snapshots?limit=50&cursor=<opaque>
```

`limit` defaults to 50 and accepts 1 through 250. Results are scoped to the
authenticated workspace and ordered by `createdAt DESC`, then `id DESC`.
Pass the opaque `page.cursor` value unchanged to fetch the next page.

An optional `name` query parameter filters by exact snapshot name. It does
not change ordering or pagination. Named snapshots also include their `name`
in the resource returned by Create, List, and Get.

## Get a snapshot

```text
GET /v2/snapshots/{snapshotId}
```

Returns the full snapshot resource. Missing or workspace-hidden snapshots
return `404 sandbox_snapshot_not_found`.

## Clone a snapshot

Clone through the ordinary Create endpoint:

```json
{
  "name": "agent_job-42-copy",
  "snapshotId": "2a02e0b4-d4c8-4a94-9068-e92399627e83"
}
```

The snapshot must be `READY`. Omit `vcpu` and `memoryMb` to inherit them; if
supplied, they must match the snapshot. The clone restores the captured
environment together with memory, disk, and the source image. A requested
`environment` does not override it. The new sandbox receives its own UUID and
follows the normal Create response and active-name idempotency rules.

## Delete a snapshot

```text
DELETE /v2/snapshots/{snapshotId}
```

Success returns HTTP 204. Deletion is permanent. A snapshot also exposes its
server-defined `expiresAt`; do not depend on it after that time.

Inngest SDK 4.20 or newer exposes the same lifecycle through
`sandbox.snapshot()`, `snapshot.clone()`, and the direct and durable snapshot
collections. See [Sandbox snapshots](/docs/features/sandboxes/snapshots).

## Output retention

- Approximately 512 KiB is retained per process.
- Only the newest 32 process output rings are retained.
- Output can be evicted while process metadata remains.
- All output disappears with the sandbox.
- Output is not a durable log store.

See [Managed processes](/docs/features/sandboxes/managed-processes) for
application guidance and [Sandbox errors and retries](/docs/features/sandboxes/errors-and-retries)
for the full error and retry model.
