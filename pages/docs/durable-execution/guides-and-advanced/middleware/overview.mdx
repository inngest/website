# Overview

> Add shared behavior across functions without repeating code in each handler.

Give several functions the same typed client or error reporting behavior without copying setup into each handler. Middleware runs at defined points around requests, handlers, steps, and event sends.
## Where middleware runs
A middleware can act around a request, a function handler, a step, or an event send. Register it on an Inngest client to apply it to that app's functions, or on one function for a narrower scope. In TypeScript v4, a middleware extends `Middleware.BaseMiddleware` and defines only the hooks it needs. The SDK creates a fresh instance for each request.
Wrapping hooks must call `next()` so the wrapped work continues. Code before and after `next()` runs on either side of that work. With multiple wrappers, the hooks nest. Check the hook order and arguments before changing retries, step output, or event data.
## Common tasks
- [Creating middleware](/docs/durable-execution/guides-and-advanced/middleware/creating-middleware) shows how to write and register a TypeScript v4 class.
- [Dependency injection](/docs/durable-execution/guides-and-advanced/middleware/dependency-injection) adds a shared database or API client to typed function context.
- [Encryption middleware](/docs/durable-execution/guides-and-advanced/middleware/encryption-middleware) protects selected event data, step data, and function output.
- [Sentry middleware](/docs/durable-execution/guides-and-advanced/middleware/sentry-middleware) sends function errors and trace context to Sentry.
## SDK versions
TypeScript v4 replaced the earlier middleware API with classes. Use v4 middleware classes for new TypeScript code; v3 `InngestMiddleware` registration does not work in a v4 app. Python has its own middleware lifecycle and versioned hooks.
Use middleware for behavior shared across runs. Observable hooks are best for logging and metrics: the SDK logs their errors without failing the run. `onRunError` can run on each errored attempt; use a function's `onFailure` handler for work that should happen only after final failure. Put business actions that must be durable in named steps, so a retry can reuse completed work.
