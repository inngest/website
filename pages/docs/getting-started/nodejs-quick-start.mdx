# Get started

> Build a durable support workflow and inspect its progress locally in about 10 minutes.

Build a durable support workflow and inspect its run in about 10 minutes. A ticket starts a function, Inngest records each step, and the function resumes after a wait. You will also group the run by ticket so you can connect later feedback to the same work.

This tutorial uses the TypeScript SDK v4 and runs entirely on your machine. You do not need an Inngest Cloud account for the first run.

## Before you start

You need Node.js, npm, and a terminal. The example uses Express to expose an HTTP endpoint to the local Inngest Dev Server. Use the platform and language tab to find setup for another framework.

## 1. Create the app

Run these commands in a new directory.

```bash
mkdir inngest-first-run
cd inngest-first-run
npm init -y
npm install inngest@latest express
npm install -D tsx @types/express
```

Create `index.ts` with the following code.

```typescript
import express from "express";
import { serve } from "inngest/express";
import { Inngest } from "inngest";

const inngest = new Inngest({ id: "support-demo" });

const handleTicket = inngest.createFunction(
  { id: "handle-ticket", triggers: { event: "support/ticket.created" } },
  async ({ event, step }) => {
    const category = await step.run("classify-ticket", () =>
      event.data.message.toLowerCase().includes("invoice")
        ? "billing"
        : "general"
    );

    await step.sleep("wait-for-review", "2s");

    const reply = await step.run("draft-reply", () =>
      category === "billing"
        ? "We will check your invoice."
        : "We will review your request."
    );

    return { category, reply };
  }
);

const app = express();
app.use(express.json());
app.use("/api/inngest", serve({ client: inngest, functions: [handleTicket] }));

app.post("/tickets", async (req, res, next) => {
  try {
    const { ticketId, message } = req.body;
    if (typeof ticketId !== "string" || typeof message !== "string") {
      res.status(400).json({ error: "ticketId and message must be strings" });
      return;
    }

    const { ids } = await inngest.send({
      name: "support/ticket.created",
      data: { ticketId, message },
      meta: { sessions: { ticket_id: ticketId } },
    });

    res.status(202).json({ ticketId, eventIds: ids });
  } catch (error) {
    next(error);
  }
});

app.listen(3000, () => {
  console.log("App listening on http://localhost:3000");
});
```

The `/tickets` route sends an event and returns without waiting for the workflow. The `/api/inngest` route lets Inngest discover and invoke the function. The function's two `step.run()` calls and `step.sleep()` create the execution history you will inspect.

## 2. Start the app and Dev Server

In one terminal, start the app in local development mode.

```bash
INNGEST_DEV=1 npx tsx index.ts
```

In a second terminal, start the Inngest Dev Server and point it at the app.

```bash
npx --ignore-scripts=false inngest-cli@latest dev -u http://localhost:3000/api/inngest
```

Open `http://localhost:8288/functions`. You should see `handle-ticket`. If it does not appear, check that the app is listening on port `3000` and that both terminals are still running.

## 3. Send a ticket

In a third terminal, send a request.

```bash
curl -X POST http://localhost:3000/tickets \
  -H "Content-Type: application/json" \
  -d '{"ticketId":"ticket-123","message":"My invoice looks wrong"}'
```

The app returns a `202` response with `ticketId` and `eventIds`. Open `http://localhost:8288/runs`, then open the new `handle-ticket` run. You should see `classify-ticket`, `wait-for-review`, and `draft-reply`. The run returns `billing` as the category and `We will check your invoice.` as the reply. The event also has the `ticket_id` session key, which groups later work for this ticket.

## 4. Record a known-answer score

The workflow has finished, but a finished run does not prove the reply helped the customer. When you know a correct answer during the run, the current TypeScript v4 scoring API can record it. Add this call immediately before the function's `return`.

```typescript
if (event.data.knownCategory) {
  await inngest.score({
    name: "ticket-category-accuracy",
    value: category === event.data.knownCategory ? 1 : 0,
  });
}
```

Scoring is currently a beta API. To test this call, invoke `handle-ticket` from the Dev Server with `{"data":{"ticketId":"ticket-124","message":"My invoice looks wrong","knownCategory":"billing"}}`. This records a score of `1` for the known category. A real outcome, such as whether a customer resolves a ticket, often arrives later. Use a deferred scorer or score the original run by its ID when that signal arrives. Keep the ticket's session key on related events, and use `group.experiment()` when you want to compare changes to a step or an entire workflow. See [Online Evals](/docs/online-evals).
