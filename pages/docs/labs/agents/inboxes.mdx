# Inboxes

> Your agent keeps listening while it works.

Whatever is sent to a thread while its run works waits in the run's inbox, in order. Each section changes the PR helper from [Threads](/docs/labs/agents/threads?ref=docs-labs-agents-inboxes) by one step.

## While it works

To let a CI failure that arrives mid-run reach that run, read the run's `inbox`.

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

const ciRun = z.object({ pr: z.number(), prUrl: z.string() });

export const ciFailed = eventType("ci/run.failed", { schema: ciRun });

export const ciPassed = eventType("ci/run.passed", { schema: ciRun });

export const deployed = eventType("deploy/finished", {
  schema: z.object({ env: z.string(), pull: z.object({ url: z.string() }) }),
});
```

<AnnotatedCode>

{/* not type-checked: inbox.next() in an agent handler with per-trigger thread keys */}
```typescript {{ title: "inngest/agents/prHelper.ts" }}
import { github } from "inngest/experimental/agents";
import { agents } from "../client";
import { ciFailed, deployed } from "../events";

const triggers = [
  github.thread({ repos: ["acme/web"] }),
  { event: ciFailed, thread: "event.data.prUrl" },
  { event: deployed, thread: "event.data.pull.url" },
];

export const prHelper = agents.agent(
  { id: "pr-helper", triggers },
  async ({ inbox, step }) => {
    await step.sleep("read the diff", "5s");

    await inbox.next();

    const arrived = await inbox.next();

    return `While I read, ${arrived?.name} arrived`;
  },
);
```

## Heard, never a start

To let CI passing reach a working run without ever starting one, list it in `inbox`.

{/* not type-checked: the inbox option with a source that sets its own thread */}
```typescript
export const prHelper = agents.agent(
  {
    id: "pr-helper",
    triggers,
    inbox: [{ event: ciPassed, thread: "event.data.prUrl" }],
  },
  async ({ inbox, step }) => {
    await step.sleep("read the diff", "5s");

    await inbox.next();

    const arrived = await inbox.next();

    return `While I read, ${arrived?.name} arrived`;
  },
);
```

Only `triggers` start a run. Sources, and messages from people and [other agents](/docs/labs/agents/agent-teams?ref=docs-labs-agents-inboxes), reach a live one. A source's `if` compares the arriving event, `async`, with the run's trigger, `event`.

## Waiting

To wait for the next thing on the PR, call `next()` with nothing unread.

{/* not type-checked: a second inbox.next() that waits in an agent handler */}
```typescript
async ({ inbox }) => {
  await inbox.next();

  const comment = await inbox.next();

  return `Next on the PR: ${comment?.name}`;
},
```

The run uses nothing while it waits. Without a `timeout`, `idle` doesn't end the wait.

## Pull the plug

To trust that waiting survives anything, stop the app while a run waits, start it again, then comment: the run carries on where it was. Inngest holds the wait, not your app. [Deploys →](/docs/labs/agents/reliability?ref=docs-labs-agents-inboxes#deploys-and-long-runs)

## Answer every message

To reply on the PR to everything that happens to it, loop over the `inbox`.

{/* not type-checked: for await over an agent's inbox with me.post() */}
```typescript
async ({ inbox, me }) => {
  for await (const message of inbox) {
    await me.post(`Seen: ${message.name}`);
  }
},
```

`me.post()` writes where the thread lives, here the pull request. A read takes the message, so each one is seen once.

## Batches

To handle comments that land together as one, loop over `inbox.batches()`.

{/* not type-checked: inbox.batches({ max }) in an agent handler */}
```typescript
async ({ inbox, me }) => {
  for await (const batch of inbox.batches({ max: 20 })) {
    await me.post(`Seen ${batch.length} things`);
  }
},
```

One reply covers the batch, a plain array. `max` caps a flood and leaves the rest unread, oldest first.

## Going quiet

To stop when the PR goes quiet and come back when it doesn't, set `idle` on the agent.

<AnnotatedCode>

{/* not type-checked: idle on an agent definition with inbox.batches({ max }) */}
```typescript
export const prHelper = agents.agent(
  {
    id: "pr-helper",
    triggers,
    inbox: [{ event: ciPassed, thread: "event.data.prUrl" }],
    idle: "1h",
  },
  async ({ inbox, me }) => {
    for await (const batch of inbox.batches({ max: 20 })) {
      await me.post(`Seen ${batch.length} things`);
    }
  },
);
```

<Annotation id="idle" lines="6" tease="quiet before it ends" title="idle" href="/docs/labs/agents/reference?ref=docs-labs-agents-inboxes#idle" linkText="Reference">
After this much quiet both `for await` forms end. The default is ten minutes.
</Annotation>

</AnnotatedCode>

The next message starts a new run. A run opened with `start()` ends once it has answered. [Call it from code →](/docs/labs/agents/agent-teams?ref=docs-labs-agents-inboxes#call-it-from-code)

## Give up waiting

To stop waiting for a review that never comes, give `next()` a `timeout`.

{/* not type-checked: inbox.next({ timeout }) in an agent handler */}
```typescript
async ({ inbox, me }) => {
  const next = await inbox.next({ timeout: "1m" });

  if (next === null) {
    await me.post("No reviews for a minute, so I'm moving on.");
  }
},
```

[`nextBatch({ timeout })`](/docs/durable-execution/primitives/step-subscribe?ref=docs-labs-agents-inboxes#read-in-batches) gives `null` the same way.

## Check without waiting

To see what queued up between two steps without stopping, `drain()` the inbox.

{/* not type-checked: inbox.drain() in an agent handler */}
```typescript
async ({ inbox, step }) => {
  await step.sleep("read the diff", "5s");

  const waiting = await inbox.drain();
},
```

It never waits: `waiting` is `[]` when nothing came.

## A second inbox

To watch a PR's checks after it pushes a fix, and only from now on, open a second inbox with `step.subscribe`.

<AnnotatedCode>

{/* not type-checked: step.subscribe with if in an agent handler beside the agent's inbox */}
```typescript
const mine = `async.data.prUrl == "${me.key}"`;

const checks = step.subscribe("checks", [
  { event: ciPassed, if: mine },
  { event: ciFailed, if: mine },
]);

const result = await checks.next();
```

<Annotation id="mine" lines="1" tease="only this PR" title="if" href="/docs/labs/agents/reference?ref=docs-labs-agents-inboxes#thread-keys-and-inbox-sources" linkText="Reference">
An inbox you open isn't tied to the thread, so filter it. `async` is the arriving event.
</Annotation>

<Annotation id="subscribe" lines="3" tease="beside the agent's own" title="step.subscribe" href="/docs/durable-execution/primitives/step-subscribe?ref=docs-labs-agents-inboxes#more-inboxes" linkText="More inboxes">
Your agent's own `inbox` is one of these, opened for you.
</Annotation>

</AnnotatedCode>

Checks that ran before it opened aren't in it, and `result` is a check and nothing else. Agents run with `optimizeParallelism: false`, so a read beside your steps needs none of the [background-reader remedy](/docs/durable-execution/primitives/step-subscribe?ref=docs-labs-agents-inboxes#read-in-the-background) on the core page.

## Stop watching

To stop watching and know nothing was lost, `close()` the inbox.

{/* not type-checked: close() on a second inbox in an agent handler */}
```typescript
const result = await checks.next();

const missed = await checks.close();
```

`missed` holds the unread messages. [Close an inbox →](/docs/durable-execution/primitives/step-subscribe?ref=docs-labs-agents-inboxes#close-an-inbox)

## Clean up for you

To close it even if the code throws, open it with `await using`.

{/* not type-checked: await using on a second inbox in an agent handler */}
```typescript
await using checks = step.subscribe("checks", [
  { event: ciPassed, if: mine },
  { event: ciFailed, if: mine },
]);
```
