# Reliability

> Leave an agent running. It retries what fails, caps its own spend and picks up after a crash or a deploy.

Every model call and tool call is a durable step, so a retry never repeats finished work.

- **Cap spend.** A budget for each thread. [Budget →](#cap-spend)
- **Cap turns and reach.** No runaway loops or chains. [Turns →](#cap-turns-and-reach)
- **Ride out model errors.** Rate limits wait. [Model errors →](#model-errors)
- **Pick up after a failure.** One line, then the message again. [Recovery →](#recover-a-failed-run)
- **Run long.** Deploys, `idle` and the step limit. [Long runs →](#deploys-and-long-runs)

```typescript {{ title: "inngest/agents/support.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const support = agents.agent(
  {
    id: "support",
    triggers: [slack.thread()],
    model: claude,
    system: "You answer support questions.",
    budget: { usd: 2, tokens: 500_000 },
    limits: { depth: 2, mayCall: ["support/researcher"] },
    recovery: true,
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches()) {
      const result = await loop(batch);

      if (result.end === "budget") {
        await me.post(result.reason);

        return;
      }

      await me.post(result.text);
    }
  },
);
```

## Retries and replay

A failed step retries; tune it with `retries`. After a crash or a deploy the function runs again from the top and finished steps return their saved results, so keep side effects in tools. [Handlers →](/docs/labs/agents/handlers?ref=docs-labs-agents-reliability#gotchas)

## Cap spend

`budget` limits what one thread may spend, in `usd`, `tokens` or both, across all its runs. The model prices its own calls; `price` overrides the rates:

{/* not type-checked: price as a per-million-token table */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/summariser.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const summariser = agents.agent({
  id: "summariser",
  triggers: [slack.thread()],
  model: claude,
  system: "Summarise the thread in three lines.",
  budget: { usd: 1 },
  price: {
    "*": { input: 2.5, output: 12.5 },
  },
});
```

<Annotation id="price" lines="11-13" tease="dollars per million tokens" title="Price" href="/docs/labs/agents/reference?ref=docs-labs-agents-reliability#the-definition" linkText="Reference: the definition">
`"*"` is the rate for any model not named. A function of the call's usage works too.
</Annotation>

</AnnotatedCode>

## Cap turns and reach

A loop that keeps calling tools stops after `maxTurns` (40 by default) with `end: "maxTurns"`. A handler sets it per call:

{/* not type-checked: maxTurns as a per-call loop option */}
```typescript
const result = await loop(batch, { maxTurns: 10 });
```

An agent with no handler swaps the loop:

{/* not type-checked: loop: agent.loop({ maxTurns }) on a definition with no handler */}
```typescript {{ title: "inngest/agents/lookup.ts" }}
import { agent, slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const lookup = agents.agent({
  id: "lookup",
  triggers: [slack.thread()],
  model: claude,
  system: "Answer from the docs, in three turns or fewer.",
  loop: agent.loop({ maxTurns: 10 }),
});
```

`limits` caps chains of agents that start agents. `depth` defaults to 1, so agents you start can't start more until you raise it, and `mayCall` lists the addresses the model may start. A start past a limit throws in code, and the model gets an error result. [Teams of agents →](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-reliability)

## Model errors

A rate limit waits for the provider's `retry-after`, for any model. A final error such as a rejected request isn't retried. [Models and the loop →](/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-reliability)

## Recover a failed run

Every run that fails for good posts one line where the thread lives. With `recovery: true` it also hands the message it was handling to a fresh run on the thread.

{/* not type-checked: recovery, previousRun and restarts in the handler's argument */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/releaser.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const releaser = agents.agent(
  {
    id: "releaser",
    triggers: [slack.thread()],
    model: claude,
    system: "You run releases.",
    recovery: true,
  },
  async ({ inbox, me, loop, score, previousRun, restarts }) => {
    await score("after-failure", previousRun?.status === "failed");

    await score("restarts", restarts);

    for await (const batch of inbox.batches()) {
      const { text } = await loop(batch);

      await me.post(text);
    }
  },
);
```

<Annotation id="recovery" lines="11" tease="opt in" title="Recovery" href="/docs/labs/agents/reference?ref=docs-labs-agents-reliability#the-definition" linkText="Reference: the definition">
Off unless you turn it on. `{ resume: false }` skips the resend; `message` writes the line yourself.
</Annotation>

<Annotation id="previous" lines="14" tease="how the last run ended" title="previousRun" href="/docs/labs/agents/reference?ref=docs-labs-agents-reliability#the-handler" linkText="Reference: the handler">
Every run gets it, with or without `recovery`.
</Annotation>

<Annotation id="restarts" lines="16" tease="moved between processes" title="restarts" href="/docs/labs/agents/reference?ref=docs-labs-agents-reliability#the-handler" linkText="Reference: the handler">
How many times this run continued in another process.
</Annotation>

</AnnotatedCode>

The resend can't loop: the same error is never sent twice, a `NonRetriableError` is never sent, and one message gets at most three kinds of error. It is never a Rerun or a Replay, which would repeat the whole conversation.

## Deploys and long runs

A run that is live when you deploy replays on the code you deployed. Every model call, tool call, KV call, awaited post and inbox message counts toward the step limit of 1,000. [Limits →](/docs/durable-execution/limits?ref=docs-labs-agents-reliability#platform-limits)

Keep `idle` at its 10-minute default. The thread keeps the history, the sandbox and the shell's place, so a run that ends loses only the handler's variables. [Threads and memory →](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-reliability#how-long-a-run-waits)

{/* not type-checked: idle as a duration string on an agent that waits for GitHub events */}

```typescript {{ title: "inngest/agents/babysitter.ts" }}
export const babysitter = agents.agent({

```

<Annotation id="idle" lines="10" tease="one run for a week" title="A long idle" href="/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-reliability#how-long-a-run-waits" linkText="Threads and memory">

A run that takes in more messages than the limit allows ends with the usual step-limit error.

## Gotchas

- **A spent budget stays spent.** A later message ends at once with `end: "budget"`. With no handler, the agent posts that the budget is spent; a handler checks `end` itself.
- **A cancelled run isn't recovered.** A stopped run posts no line and is not resent.
- **A model with no built-in prices needs `price`.**

## How it works

- Steps are saved by ID, so a replay never repeats a finished call.
- A thread's spend lives in thread state, so it outlasts a run.
