# Reliability

> Leave an agent running. It retries what fails, caps its own spend and picks up after a crash or a deploy.

Every model call and tool call is a [durable step](/docs/labs/agents/handlers?ref=docs-labs-agents-reliability#gotchas), so a retry never repeats finished work.

- **Cap spend and turns.** No runaway loops. [Caps →](#cap-spend)
- **Recover.** Rate limits wait; a failed run picks up. [Recovery →](#recover-from-failures)
- **Run long.** Deploys, `idle` and the step limit. [Long runs →](#deploys-and-long-runs)

<AnnotatedCode>

{/* not type-checked: budget, limits and recovery on an agent definition, result.end and result.reason */}
```typescript {{ title: "inngest/agents/support.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const support = agents.agent(
  {
    id: "support",
    triggers: [slack.thread()],
    model: claude,
    system: "You answer support questions.",
    budget: { usd: 2, tokens: 500_000 },
    limits: { depth: 2, mayCall: ["support/researcher"] },
    recovery: true,
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches()) {
      const result = await loop(batch);

      if (result.end === "budget") {
        await me.post(result.reason);

        return;
      }

      await me.post(result.text);
    }
  },
);
```

## Cap spend

`budget` caps what one thread spends across all its runs. The model prices its own calls; `price` overrides its rates.

<AnnotatedCode>

{/* not type-checked: price as a per-million-token table */}
```typescript {{ title: "inngest/agents/summariser.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const summariser = agents.agent({
  id: "summariser",
  triggers: [slack.thread()],
  model: claude,
  system: "Summarise the thread in three lines.",
  budget: { usd: 1 },
  price: {
    "*": { input: 2.5, output: 12.5 },
  },
});
```

<Annotation id="price" lines="11-13" tease="dollars per million tokens" title="Price" href="/docs/labs/agents/reference?ref=docs-labs-agents-reliability#budget-and-price" linkText="Reference: budget and price">
`"*"` is the rate for any model not named.
</Annotation>

</AnnotatedCode>

## Cap turns

A loop that keeps calling tools stops after `maxTurns` (40 by default). A handler sets it per call; an agent with no handler sets `loop: { maxTurns: 10 }` on its definition.

<AnnotatedCode>

{/* not type-checked: maxTurns as a per-call loop option and end: "maxTurns" */}
```typescript {{ title: "inngest/agents/lookup.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const lookup = agents.agent(
  {
    id: "lookup",
    triggers: [slack.thread()],
    model: claude,
    system: "Answer from the docs.",
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches()) {
      const result = await loop(batch, { maxTurns: 10 });

      if (result.end === "maxTurns") {
        await me.post("I ran out of turns before I finished.");

        continue;
      }

      await me.post(result.text);
    }
  },
);
```

<Annotation id="turns" lines="14" tease="for this call" title="maxTurns" href="/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-reliability" linkText="Models and the loop">
A loop option, so each call can have its own.
</Annotation>

</AnnotatedCode>

## Recover from failures

A rate limit waits for the provider's `retry-after`, for any model; a final error such as a rejected request isn't retried. A run that fails for good posts one line where the thread lives, and with `recovery` hands the message it was handling to a fresh run.

<AnnotatedCode>

{/* not type-checked: recovery with a message function */}
```typescript {{ title: "inngest/agents/releaser.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const releaser = agents.agent({
  id: "releaser",
  triggers: [slack.thread()],
  model: claude,
  system: "You run releases.",
  recovery: {
    message: (failure) => {
      return `That run failed: ${failure.error}`;
    },
  },
});
```

<Annotation id="message" lines="10-14" tease="opt in" title="Recovery" href="/docs/labs/agents/reference?ref=docs-labs-agents-reliability#recovery" linkText="Reference: recovery">
`message` writes the line; `{ resume: false }` skips the resend.
</Annotation>

</AnnotatedCode>

The same error is never resent, and neither is a `NonRetriableError`. A handler's [`previousRun`](/docs/labs/agents/reference?ref=docs-labs-agents-reliability#the-handler) says how the last run ended.

## Deploys and long runs

A live run replays on the code you deployed. Every model call, tool call, KV call, awaited post and inbox message counts toward the 1,000-step limit. [Limits →](/docs/durable-execution/limits?ref=docs-labs-agents-reliability#platform-limits)

An agent that waits on something slow, such as a pull request, can raise `idle` to stay live across deploys.

<AnnotatedCode>

{/* not type-checked: idle as a duration string on an agent that waits for GitHub events */}
```typescript {{ title: "inngest/agents/babysitter.ts" }}
import { github } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const babysitter = agents.agent({
  id: "babysitter",
  triggers: [github.thread()],
  model: claude,
  system: "Watch the pull request until it merges.",
  idle: "7d",
});
```

<Annotation id="idle" lines="10" tease="a week-long run" title="A long idle" href="/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-reliability#how-long-a-run-waits" linkText="Threads and memory">
Live across every deploy; all it does adds to the step count.
</Annotation>

</AnnotatedCode>

## Gotchas

- **A spent budget stays spent.** Later messages end at once.
- **A cancelled run isn't recovered.**
- **A long `idle` can reach the step limit.**

## How it works

- Steps are saved by ID, so a replay reuses finished calls.
- A thread's spend lives in thread state, so it outlasts runs.
