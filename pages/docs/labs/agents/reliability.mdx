# Reliability

> Leave an agent running. It retries what fails, caps its own spend and picks up after a crash or a deploy.

Agents run for a long time and call things that fail. Every model call and tool call is a durable step, so a retry never repeats finished work.

- **Survive crashes and deploys.** Finished calls never run twice. [Retries and replay →](#retries-and-replay)
- **Cap spend.** A dollar or token budget for each thread. [Budget →](#cap-spend)
- **Cap turns and reach.** Stop runaway loops and chains of agents. [Turns →](#cap-turns-and-reach)
- **Ride out model errors.** Rate limits wait; rejected requests fail once. [Model errors →](#model-errors)
- **Pick up after a failure.** The message in flight is tried again. [Recovery →](#recover-a-failed-run)
- **Run long.** The step limit, deploys and `idle`. [Deploys and long runs →](#deploys-and-long-runs)

```typescript {{ title: "inngest/agents/support.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const support = agents.agent(
  {
    id: "support",
    triggers: [slack.thread()],
    model: claude,
    system: "You answer support questions.",
    budget: { usd: 2, tokens: 500_000 },
    limits: { depth: 2, mayCall: ["support/*"] },
    recovery: true,
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches()) {
      const result = await loop(batch);

      if (result.end === "budget") {
        await me.post(result.reason);

        return;
      }

      await me.post(result.text);
    }
  },
);
```

## Retries and replay

A failed step retries; tune it with the function's `retries` option. When a run crashes or a deploy restarts it, the function runs again from the top and finished steps return their saved results. Code outside a step runs again too, so keep side effects in tools. [Handlers →](/docs/labs/agents/handlers?ref=docs-labs-agents-reliability#gotchas)

## Cap spend

`budget` limits what one thread may spend, in `usd`, `tokens` or both. It applies to every loop, with a handler or without one, and the thread keeps its spend across runs. A thread that another agent starts gets the budget of its own agent.

The model prices its own calls, so a dollar budget needs no price table. `price` overrides the built-in rates.

## Model errors

A rate limit waits for the `retry-after` the provider sends and tries again, for any model, including one you write yourself. A final error such as a rejected request fails the step for good and is not retried. [Models and the loop →](/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-reliability)

## Recover a failed run

With `recovery: true`, a run that fails for good doesn't strand the thread. One line goes where the thread lives, and the message the run was handling goes to a fresh run on the thread.

{/* not type-checked: recovery, previousRun and restarts in the handler's argument */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/releaser.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const releaser = agents.agent(
  {
    id: "releaser",
    triggers: [slack.thread()],
    model: claude,
    system: "You run releases.",
    recovery: true,
  },
  async ({ inbox, me, loop, score, previousRun, restarts }) => {
    await score("after-failure", previousRun?.status === "failed");

    await score("restarts", restarts);

    for await (const batch of inbox.batches()) {
      const { text } = await loop(batch);

      await me.post(text);
    }
  },
);
```

<Annotation id="recovery" lines="11" tease="opt in" title="Recovery" href="/docs/labs/agents/reference?ref=docs-labs-agents-reliability#the-definition" linkText="Reference: the definition">
Off unless you turn it on. `{ resume: false }` posts the line and sends nothing again; `message` writes the line yourself.
</Annotation>

<Annotation id="previous" lines="14" tease="how the last run ended" title="previousRun" href="/docs/labs/agents/reference?ref=docs-labs-agents-reliability#the-handler" linkText="Reference: the handler">
Every run gets it, with or without `recovery`.
</Annotation>

<Annotation id="restarts" lines="16" tease="moved between processes" title="restarts" href="/docs/labs/agents/reference?ref=docs-labs-agents-reliability#the-handler" linkText="Reference: the handler">
How many times this run continued in another process. `depth` is how many agent starts led to the run, and `0` when none did.
</Annotation>

</AnnotatedCode>

The resend can't loop: the same error is never sent twice, a `NonRetriableError` is never sent, and one message gets at most three kinds of error. The fresh run reads the thread's saved history. It is not a Rerun or a Replay, which would start from the original trigger and repeat the whole conversation.

## Deploys and long runs

A run that is live when you deploy replays on the code you deployed. Every step it takes counts toward the step limit of 1,000: model calls, tool calls, KV calls, awaited posts and each message the inbox takes in. A fifty-minute chat can take a few hundred. [Limits →](/docs/durable-execution/limits?ref=docs-labs-agents-reliability#platform-limits)

Keep `idle` at its 10-minute default. The thread keeps the model's history, the sandbox and the shell's place, so a run that ends loses only the handler's own variables. [Threads and memory →](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-reliability#how-long-a-run-waits)

A long `idle` is a choice, for a handler that must hold its own variables for days:

## Gotchas

- **A spent budget stays spent.** The thread keeps its spend, so a later message ends at once with `end: "budget"`.
- **A cancelled run isn't recovered.** A run you stop or cancel is neither reported nor resent.
- **A model with no built-in prices needs `price`.** A dollar budget can't count calls it can't price.

## How it works

- Steps are saved by ID, so a replay returns finished calls instead of making them again.
- A thread's spend lives in thread state, so it outlasts a run and a handler's variables don't.
