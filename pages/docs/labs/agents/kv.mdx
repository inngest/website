# KV

> Keep state across turns, runs and agents without running a database.

- **Remember across turns.** `kv.thread` keeps a value for the life of a thread. [Remember →](#remember-across-turns)
- **Choose how long a value lives.** Six scopes, from one run to the whole environment. [Scopes →](#choose-a-scope)
- **Type your keys.** A schema checks every read. [Typed keys →](#type-your-keys)
- **Update without losing writes.** `update`, `setIfAbsent` and `take` are atomic. [Updates →](#update-safely)
- **Keep sorted lists.** Indexes order ids by score. [Indexes →](#keep-a-sorted-index)
- **Bring your own store.** Redis, D1 or memory. [Stores →](#choose-a-store)

## Remember across turns

Store the conversation once and every later turn, in any run, reads it back.

```typescript {{ title: "inngest/keys.ts" }}
import { kvKey } from "inngest/experimental/agents";
import type { AgentMessage } from "inngest/experimental/agents";

export const history = kvKey<AgentMessage[]>("history");
```

<AnnotatedCode>

```typescript {{ title: "inngest/agents/support.ts" }}
import { agent, kv } from "inngest/experimental/agents";
import { agents } from "../client";
import { history } from "../keys";
import { claude } from "../models/claude";

export const support = agents.agent(
  { id: "support" },
  async ({ inbox, control }) => {
    for await (const message of inbox) {
      const result = await agent.loop({
        model: claude,
        prompt: message.content ?? "",
        history: (await kv.thread.get(history)) ?? [],
        tools: {},
        ...control,
      });

      await kv.thread.set(history, result.history);
    }
  },
);
```

</Annotation>

<Annotation id="set" lines="18" tease="JSON only" title="Write" href="/docs/labs/agents/structure?ref=docs-labs-agents-kv" linkText="Structure">

</Annotation>

## Choose a scope

A scope says who sees a value and when it goes away.

<AnnotatedCode>

```typescript {{ title: "inngest/scopes.ts" }}
import { kv } from "inngest/experimental/agents";

export async function remember(threadKey: string) {
  await kv.env.set("flag:beta", true);

  await kv.app.set("model", "claude");

  await kv.function.set("last-deploy", Date.now());

  await kv.run.set("scratch", { files: ["a.ts"] });

  await kv.session.set("customer", "acme");

  await kv.thread.set("topic", "refunds");

  await kv.scope("thread", threadKey).set("topic", "billing");

  return kv.get("scratch");
}
```

## Type your keys

`kvKey` ties a name to a value type. Add a schema and every read is checked.

```typescript {{ title: "inngest/keys.ts" }}
import { kvKey } from "inngest/experimental/agents";
import { z } from "zod";

export const plan = kvKey(
  "plan",
  z.object({
    steps: z.array(z.string()),
    done: z.number(),
  }),
);
```

```typescript {{ title: "inngest/agents/planner.ts" }}
import { kv } from "inngest/experimental/agents";
import { agents } from "../client";
import { plan } from "../keys";

export const planner = agents.agent({ id: "planner" }, async ({ inbox }) => {
  for await (const message of inbox) {
    await kv.thread.set(plan, {
      steps: [message.content ?? ""],
      done: 0,
    });

    const found = await kv.thread.get(plan);

    await kv.thread.set("progress", found?.steps.length ?? 0);
  }
});
```

A stored value that fails the schema throws a `NonRetriableError` that names the key. Schemas must read back what they wrote, so no transforms or defaults.

## Update safely

Two runs can touch the same key. These calls never lose a write.

<AnnotatedCode>

```typescript {{ title: "inngest/update.ts" }}
import { kv, kvKey } from "inngest/experimental/agents";

const spent = kvKey<number>("spent");

export async function charge(runId: string, cents: number) {
  const total = await kv.thread.update(spent, (current) => {
    return (current ?? 0) + cents;
  });

  const owns = await kv.env.setIfAbsent(`card:${runId}`, runId, {
    ttl: 600,
  });

  const review = await kv.thread.take("review");

  await kv.thread.delete("scratch");

  return { total, owns, review };
}

export async function reset() {
  const everything = await kv.thread.all();

  await kv.thread.clear();

  return Object.keys(everything);
}
```

<Annotation id="update" lines="6-8" tease="read, change, write" title="update" href="/docs/labs/agents/kv?ref=docs-labs-agents-kv#how-it-works" linkText="How it works">
Runs again if another run wrote first, so the function must be pure.
</Annotation>

<Annotation id="claim" lines="10-12" tease="first caller wins" title="setIfAbsent" href="/docs/labs/agents/kv?ref=docs-labs-agents-kv#how-it-works" linkText="How it works">
Returns `true` for the first caller until `ttl` seconds pass.
</Annotation>

<Annotation id="take" lines="14" tease="read once" title="take" href="/docs/labs/agents/threads?ref=docs-labs-agents-kv" linkText="Threads">
Reads a key and deletes it, for flags used once.
</Annotation>

<Annotation id="all" lines="22-24" tease="whole scope" title="all and clear" href="/docs/labs/agents/threads?ref=docs-labs-agents-kv" linkText="Threads">
`all` lists every key of the instance; `clear` removes them.
</Annotation>

</AnnotatedCode>

## Keep a sorted index

An index orders ids by a number, such as a start time.

<AnnotatedCode>

```typescript {{ title: "inngest/index.ts" }}
import { kv } from "inngest/experimental/agents";

const improve = kv.env.index("improve");

export async function track(id: string, oldest: string) {
  await improve.add(id, Date.now());

  await improve.remove(oldest);

  const newest = await improve.range({ order: "desc", limit: 20 });

  const recent = await improve.range({ min: Date.now() - 86_400_000 });

  return { newest, recent };
}
```

<Annotation id="add" lines="6" tease="adds or moves" title="add" href="/docs/labs/agents/kv?ref=docs-labs-agents-kv#how-it-works" linkText="How it works">
Adds the member, or moves it to the new score.
</Annotation>

<Annotation id="range" lines="10-12" tease="min, max, limit, order" title="range" href="/docs/labs/agents/kv?ref=docs-labs-agents-kv#how-it-works" linkText="How it works">
Returns `{ member, score }` entries, lowest score first unless `order` is `"desc"`.
</Annotation>

</AnnotatedCode>

## Choose a store

By default KV uses the Redis at `INNGEST_EXPERIMENTAL_KV_URL`. Pass a `store` to `createAgents` to change it.

```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { createAgents, redisKvAdapter } from "inngest/experimental/agents";

export const inngest = new Inngest({ id: "support" });

export const agents = createAgents(inngest, {
  store: redisKvAdapter("rediss://default:secret@redis.example.com:6379"),
});
```

On Cloudflare, a D1 database holds the same data. A Worker gets its bindings per request, so `d1KvAdapter` also takes a function and calls it on every operation.

```typescript {{ title: "inngest/db.ts" }}
import type { D1KvDatabase } from "inngest/experimental/agents";

let database: D1KvDatabase | undefined;

export function useDatabase(db: D1KvDatabase) {
  database = db;
}

export function getDatabase() {
  if (!database) {
    throw new Error("The D1 binding is not set yet.");
  }

  return database;
}
```

```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { createAgents, d1KvAdapter } from "inngest/experimental/agents";
import { getDatabase } from "./db";

export const inngest = new Inngest({ id: "support" });

export const agents = createAgents(inngest, {
  store: d1KvAdapter(getDatabase),
});
```

Create the tables in a migration. `d1KvAdapter(db, { createTables: true })` creates them on first use, for local development.

```typescript {{ title: "inngest/migrate.ts" }}
import { d1KvSchema } from "inngest/experimental/agents";

console.log(`${d1KvSchema.join(";\n")};`);
```

Tests use `memoryKvAdapter()`.

```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { createAgents, memoryKvAdapter } from "inngest/experimental/agents";

export const inngest = new Inngest({ id: "support" });

export const agents = createAgents(inngest, { store: memoryKvAdapter() });
```

## Give one agent its own KV

The `kv` option of an agent takes a KV, or a function that returns one. The function is called at each use and must return the same data every time.

```typescript {{ title: "inngest/agents/own.ts" }}
import { agent, createKv, d1KvAdapter, kv } from "inngest/experimental/agents";
import { agents } from "../client";
import { getDatabase } from "../db";
import { claude } from "../models/claude";

export const own = agents.agent(
  {
    id: "own",
    kv: () => {
      return createKv({ adapter: d1KvAdapter(getDatabase) });
    },
  },
  async ({ inbox, control }) => {
    for await (const message of inbox) {
      await agent.loop({
        model: claude,
        prompt: message.content ?? "",
        tools: {},
        ...control,
      });

      await kv.thread.set("seen", message.seq);
    }
  },
);
```

## Read it outside a function

In a script or a test there is no current run. `kv.with(client)` gives the store for your client.

```typescript {{ title: "inngest/outside.ts" }}
import { kv } from "inngest/experimental/agents";
import { inngest } from "./client";

export async function peek(threadKey: string) {
  const store = kv.with(inngest);

  return store.scope("thread", threadKey).get("topic");
}
```

## How it works

- Inside a function, every call is a memoized step, so a replay sees the values the first run saw. Outside one, calls go straight to the store.
- Values are JSON. `ttl` is whole seconds, and `update` results never expire.
- `update` retries up to 25 times, then throws. A custom store implements `KvAdapter`, which the types in the reference describe.
- `session` and `thread` come from the agent's thread. Using them elsewhere throws.
