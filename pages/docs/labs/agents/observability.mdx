# Observability

> See what an agent did, what it cost and how well it worked.

Every statement of a run is a row in its trace. Scores add numbers to those rows.

- **A row per statement.** Calls, posts and inbox reads. [Read a trace →](#read-a-trace)
- **Scores you don't write.** Time, tokens and failures. [Automatic scores →](#automatic-scores)
- **Scores you do.** From a handler or a tool. [Score outcomes →](#score-outcomes)
- **Progress as it happens.** A hook after each turn. [Show progress →](#show-progress)

```typescript {{ title: "inngest/agents/support.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const support = agents.agent(
  {
    id: "support",
    triggers: [slack.thread()],
    model: claude,
    system: "You answer support questions.",
  },
  async ({ inbox, me, loop, score }) => {
    for await (const batch of inbox.batches()) {
      const result = await loop(batch);

      await me.post(result.text);

      await score("answered", result.text.length > 0);

      await score("cost", result.usage.usd ?? 0);
    }
  },
);
```

## Read a trace

A run has one row for each:

- model call, tool call and awaited `me.post()`;
- inbox, with a tick for every message that arrived, read or not;
- inbox read, expanding to the messages it took, with arrived and read times.

An unread message still shows, so "why didn't it react?" has an answer. [Inboxes →](/docs/labs/agents/inboxes?ref=docs-labs-agents-observability)

Screenshot needed: an inbox row with three ticks, and the read row expanded to its messages.

## Automatic scores

Every agent writes these, with nothing to turn on:

- **Each model call:** its time, tokens in and out, tools called and messages folded in.
- **Each tool call:** its time and whether it failed.

Query them in [Insights](/docs/platform-and-operations/insights?ref=docs-labs-agents-observability) or compare variants with [agent evals](/docs/agent-evals/overview?ref=docs-labs-agents-observability).

## Score outcomes

`score(name, value)` records a number or a boolean. From a tool's context, it lands on that tool call's row.

{/* not type-checked: score in a tool's context */}
```typescript {{ title: "inngest/tools/escalate.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";

export const escalate = tool.step({
  description: "Hands the thread to a person",
  input: z.object({ reason: z.string() }),
  run: async ({ reason }, { score }) => {
    await score("escalated", true);

    return `escalated: ${reason}`;
  },
});
```

Await it or don't: an un-awaited score is still written before the run ends. A refused score logs a warning and the run goes on.

## Track usage and cost

Each loop result carries the `usage` of its own model calls. The model prices its own calls, so `usd` needs no price table. [Reliability →](/docs/labs/agents/reliability?ref=docs-labs-agents-observability#cap-spend)

{/* not type-checked: the usage fields of a loop result */}
```typescript
const { input, output, usd } = result.usage;
```

## Show progress

`onTurn` runs after each turn's tool calls. The loop doesn't wait for it between turns, and an error in it never fails the run.

{/* not type-checked: loop(batch, { onTurn }) with an un-awaited me.post() */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/builder.ts" }}
import { sandbox, slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const builder = agents.agent(
  {
    id: "builder",
    triggers: [slack.thread()],
    model: claude,
    system: "Run the build and fix what fails.",
    sandboxes: { work: sandbox({ id: "work" }) },
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches()) {
      const { text } = await loop(batch, {
        onTurn: (turn) => {
          me.post(`Turn ${turn.turn}: ${turn.toolCalls.length} tool calls.`);
        },
      });

      await me.post(text);
    }
  },
);
```

## Warnings

These never fail a run, so they show as warnings on its trace:

- a `me.post()` on a thread with no home;
- a Slack configuration error from a write you didn't await;
- a `thread` expression with nothing at its path.

## Gotchas

- **A score in handler code is a step.** In a tool or the loop it adds none.
- **Keep score names stable.** A changed name is a separate series. [Scores →](/docs/agent-evals/scores?ref=docs-labs-agents-observability)

## How it works

- A score on a call rides on its result, so replay never writes it again.
- Each inbox message is saved as it arrives, read or not.
