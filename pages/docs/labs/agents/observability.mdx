# Observability

> See what an agent did, what it cost and how well it worked.

Every statement of a run is a row in its trace, and scores add numbers to those rows.

- **A row per statement.** Calls, posts, reads. [Read a trace →](#read-a-trace)
- **Scores you don't write.** Time, tokens, failures. [Automatic scores →](#automatic-scores)
- **Scores you do.** From a handler or a tool. [Score outcomes →](#score-outcomes)
- **Progress as it happens.** `onTurn` after each turn. [Show progress →](/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-observability#watch-progress)

```typescript {{ title: "inngest/agents/support.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const support = agents.agent(
  {
    id: "support",
    triggers: [slack.thread()],
    model: claude,
    system: "You answer support questions.",
  },
  async ({ inbox, me, loop, score }) => {
    for await (const batch of inbox.batches()) {
      const result = await loop(batch);

      await me.post(result.text);

      await score("answered", result.text.length > 0);

      await score("cost", result.usage.usd ?? 0);
    }
  },
);
```

## Automatic scores

Every agent records model time, tokens, tool calls, folded messages, tool time and tool errors. They show on the trace and in function dashboards, and [agent evals](/docs/agent-evals/overview?ref=docs-labs-agents-observability) compare variants with them. ## Score outcomes

`score(name, value)` from a tool's context lands on that tool call's row.

{/* not type-checked: score in a tool's context */}
```typescript {{ title: "inngest/tools/escalate.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";

export const escalate = tool.step({
  description: "Hands the thread to a person",
  input: z.object({ reason: z.string() }),
  run: async ({ reason }, { score }) => {
    await score("escalated", true);

    return `escalated: ${reason}`;
  },
});
```

An un-awaited score is still written before the run ends. Names can't start with `agent.`, which the automatic scores use.

## Gotchas

- **A score in handler code is a step.** In a tool or the loop it adds none.
- **Keep score names stable.** A changed name is a separate series. [Scores →](/docs/agent-evals/scores?ref=docs-labs-agents-observability)
- **Some problems are only warnings.** A `me.post()` on a thread with no home shows on the trace and fails nothing.

## How it works

- A score on a call rides on its result, so replay never writes it twice.
