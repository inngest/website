# Observability

> See what an agent did, what it cost and how well it worked.

Every statement of a run is a row in its trace. Scores add timing, tokens and your own measures to those rows.

- **A row per statement.** Model calls, tool calls, posts and inbox reads. [Read a trace →](#read-a-trace)
- **Scores you don't write.** Model time, tokens, tool calls and failures. [Automatic scores →](#automatic-scores)
- **Scores you do.** One call, from a handler or a tool. [Score outcomes →](#score-outcomes)
- **Usage and cost.** On every loop result. [Usage →](#track-usage-and-cost)
- **Progress as it happens.** A hook after each turn. [Show progress →](#show-progress)
- **Warnings in place.** Mistakes that can't fail a run show on its trace. [Warnings →](#warnings)

```typescript {{ title: "inngest/agents/support.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const support = agents.agent(
  {
    id: "support",
    triggers: [slack.thread()],
    model: claude,
    system: "You answer support questions.",
  },
  async ({ inbox, me, loop, score }) => {
    for await (const batch of inbox.batches()) {
      const result = await loop(batch);

      await me.post(result.text);

      await score("answered", result.text.length > 0);

      await score("cost", result.usage.usd ?? 0);
    }
  },
);
```

## Read a trace

Open a run in the Dev Server or in Inngest Cloud. The trace has one row for each:

- model call and tool call, with its own timing and retries;
- awaited `me.post()`;
- inbox, with a tick for every message that arrived, read or not;
- read of an inbox, which expands to the messages it took, with when each arrived and when it was read.

A message the agent never read still shows as a tick, so "why didn't it react?" has an answer. [Inboxes →](/docs/labs/agents/inboxes?ref=docs-labs-agents-observability)

## Automatic scores

Every agent writes these, with nothing to turn on:

- **On each model call:** its time, the tokens in and out, how many tools it called and how many messages were folded in.
- **On each tool call:** its time and whether it failed.

They sit on the row of the call. Query them over time in [Insights](/docs/platform-and-operations/insights?ref=docs-labs-agents-observability), and compare variants with [agent evals](/docs/agent-evals/overview?ref=docs-labs-agents-observability).

## Score outcomes

`score(name, value)` records a number or a boolean on the run. Call it from a handler, as above, or from a tool's context, where it lands on that tool call's row.

{/* not type-checked: score in a tool's context */}
```typescript {{ title: "inngest/tools/escalate.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";

export const escalate = tool.step({
  description: "Hands the thread to a person",
  input: z.object({ reason: z.string() }),
  run: async ({ reason }, { score }) => {
    await score("escalated", true);

    return `escalated: ${reason}`;
  },
});
```

Await a score or don't: one you didn't await is still written before the run ends. Scoring is best effort, so a refused score logs a warning and the run goes on.

## Track usage and cost

Each loop result carries the `usage` of its own model calls. The model prices its own calls, so `usd` is there with no price table. [Reliability →](/docs/labs/agents/reliability?ref=docs-labs-agents-observability#cap-spend)

## Show progress

`onTurn` runs after each turn's tool calls, with the turn's reply, tool runs and usage. The loop doesn't wait for it between turns, and an error in it is logged and never fails the run. The last one is waited for before `loop` returns.

{/* not type-checked: loop(batch, { onTurn }) with an un-awaited me.post() */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/builder.ts" }}
import { sandbox, slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const builder = agents.agent(
  {
    id: "builder",
    triggers: [slack.thread()],
    model: claude,
    system: "Run the build and fix what fails.",
    sandboxes: { work: sandbox({ id: "work" }) },
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches()) {
      const { text } = await loop(batch, {
        onTurn: (turn) => {
          me.post(`Turn ${turn.turn}: ${turn.toolCalls.length} tool calls.`);
        },
      });

      await me.post(text);
    }
  },
);
```

## Warnings

These can't fail a run, so they show as a warning on its trace:

- a `me.post()` on a thread with no home, such as one opened by `start()`;
- a Slack configuration error, such as a bad token or a missing scope, from a write you didn't await;
- a `thread` expression that finds nothing at its path: a trigger then starts a fresh thread, and an `inbox` source reaches no thread.

## Gotchas

- **A score in handler code is a step.** It gets its own row and counts toward the step limit. In a tool or the loop it rides on the call's row.
- **Keep score names stable.** Changing a name starts a separate series. [Scores →](/docs/agent-evals/scores?ref=docs-labs-agents-observability)
- **The automatic scores have no switch.** They are always written.

## How it works

- A score on a model or tool call rides on that call's result, so it adds no step and is never written again on replay.
- Each inbox message is saved as it arrives, which is why its tick shows before anything reads it.
