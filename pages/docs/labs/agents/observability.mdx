# Observability

> See what an agent did, what it cost, how well it worked.

Every model call and tool call is a step in the run's trace. Built-in scores add timing and cost to each, and you can add your own.

<AnnotatedCode>

```typescript {{ title: "inngest/agents/support.ts" }}
import { agent } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const support = agents.agent(
  { id: "support" },
  async ({ inbox, control, scores }) => {
    for await (const message of inbox) {
      const result = await agent.loop({
        model: claude,
        prompt: message,
        ...control,
      });

      await scores.score("support.answered", result.text.length > 0);

      await scores.score("support.turns", result.turns);
    }
  },
);
```

## Read a trace

Open the run in the Dev Server or in Inngest Cloud. Each model call is a step named `<id>:model:<turn>`, each tool call is `<id>:<turn>.<n>:<name>`, and a tool with a `displayName` shows it.

Screenshot needed: the trace of one turn, with the model step, a tool step and their scores.

The scores on those steps come free:

- `agent.model_ms`, `agent.input_tokens`, `agent.output_tokens`, `agent.tool_calls` and `agent.steers` on each model step. Cache scores join them when the model reports cache use, as `agent.anthropic()` does.
- `agent.tool_ms` and `agent.tool_error` on each tool step. `agent.tool_error` is `1` when the tool threw or returned an error.
- `agent.first_output_ms` and `agent.output_gap_ms` on `report()` posts.
- `agent.stopped` on the step that records a stop request.

## Follow a thread

`state()` reads a thread without a run: its status, turn, summary, usage and how the last run ended.

```typescript {{ title: "app/state.ts" }}
import { support } from "../inngest/agents/support";

const ticket = support.thread("ticket-42");

const { status, turn, summary, usage, keys, lastRun } = await ticket.state();

console.log(status, turn, summary, keys, lastRun);
```

`status` is `running`, `waiting`, `stopped` or `idle`.

## Track usage and cost

`usage` sums every model call of the thread. It has `usd` when the agent has a `limits.price`.

```typescript {{ title: "app/usage.ts" }}
import { support } from "../inngest/agents/support";

const { usage } = await support.thread("ticket-42").state();

console.log(usage.input, usage.output, usage.usd);
```

Each loop result carries the `usage` of that loop. Set prices in [Reliability](/docs/labs/agents/reliability?ref=docs-labs-agents-observability#limit-turns-and-spend).

## Score outcomes

Call `scores.score(name, value)` from the agent body or from a tool. Inside a tool it lands on that tool's step.

```typescript {{ title: "inngest/tools/escalate.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";

export const escalate = tool.step({
  description: "Hands the thread to a person",
  input: z.object({ reason: z.string() }),
  run: async ({ reason }) => {
    return `escalated: ${reason}`;
  },
});
```

Query scores over time in [Insights](/docs/platform-and-operations/insights?ref=docs-labs-agents-observability), and compare variants with [agent evals](/docs/agent-evals/overview?ref=docs-labs-agents-observability).

## When to use what

- Find out why a turn was slow or costly: the trace and the built-in scores.
- Check a thread from a script or a dashboard: `thread.state()`.
- Measure your own outcome: `scores.score()`.
- Compare variants or roll scores into averages: Insights and agent evals.

## Options

```typescript {{ title: "inngest/agents/quiet.ts" }}
import { agents } from "../client";

export const quiet = agents.agent({ id: "quiet", scores: false }, async () => {
  return undefined;
});
```

`scores: false` turns the built-in scores off. `scores.score()` still works in the body.

## Gotchas

- A group from `tool.group()` is not one step, so it is not scored.
- Outside a step, `scores.score` sets a score on the run. Call it with values that do not change between replays.
- A score never fails a run. If the server refuses it, one warning is logged and the run goes on.

## How it works

- A score rides in the metadata of a step that is already running, so none adds a step.
- It is written once, when the step really runs, never on replay.
- Averages, percentiles and rates are left to Insights.
