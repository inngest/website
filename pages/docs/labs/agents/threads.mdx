# Threads

> Say which events belong together, and their runs share one thread.

A run is thrown away when it ends; a thread is what its runs share.

The sections below grow a PR helper for `acme/web`, the agent after [`hello`](/docs/labs/agents/agents?ref=docs-labs-agents-threads); after the first block, a block shows only what changes, and [the last section](#a-trigger-with-its-own-key) has the whole file.

## Three events, three strangers

You want one helper for everything that happens to a PR. List its events as triggers.

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

const ciRun = z.object({ pr: z.number(), prUrl: z.string() });

export const ciFailed = eventType("ci/run.failed", { schema: ciRun });

export const deployed = eventType("deploy/finished", {
  schema: z.object({ env: z.string(), pull: z.object({ url: z.string() }) }),
});
```

{/* not type-checked: github.thread({ repos }) and plain event triggers on an agent */}
```typescript {{ title: "inngest/agents/prHelper.ts" }}
import { github } from "inngest/experimental/agents";
import { agents } from "../client";
import { ciFailed, deployed } from "../events";

export const prHelper = agents.agent(
  {
    id: "pr-helper",
    triggers: [github.thread({ repos: ["acme/web"] }), ciFailed, deployed],
  },
  async ({ event }) => {
    return `Saw ${event.name}`;
  },
);
```

Open a PR, fail its CI and deploy it: three runs on three threads, because CI and deploy name no thread. None of them knows about the others.

## Which conversation is this?

You want CI on #42 to be part of #42's thread. Give its trigger a `thread`: an [expression](/docs/durable-execution/guides-and-advanced/writing-expressions?ref=docs-labs-agents-threads) over the `event`.

<AnnotatedCode>

{/* not type-checked: a trigger with its own thread expression */}
```typescript
triggers: [
  github.thread({ repos: ["acme/web"] }),
  { event: ciFailed, thread: "event.data.prUrl" },
  deployed,
],
```

<Annotation id="thread" lines="3" tease="the PR's URL" title="thread" href="/docs/labs/agents/reference?ref=docs-labs-agents-threads#thread-keys-and-inbox-sources" linkText="Thread keys">
The CI event carries the PR's URL. GitHub's trigger keys on the same URL, so both land on one thread.
</Annotation>

</AnnotatedCode>

Fail CI on #42 and the run joins its thread, after the runs already there. To name the thread for every trigger at once, set `thread` on the agent's [definition](/docs/labs/agents/reference?ref=docs-labs-agents-threads#the-definition); a trigger's own `thread` wins.

## What a conversation keeps

You want to know what joining a thread gets you. Leave a note for the next run.

{/* not type-checked: kv.thread.get and set in an agent handler */}
```typescript
import { kv } from "inngest/experimental/agents";

async ({ event }) => {
  const note = await kv.thread.get("note");

  await kv.thread.set("note", `saw ${event.name}`);

  return note;
},
```

The first run returns nothing, and the second returns the first's note. The thread keeps its [state](/docs/labs/agents/memory?ref=docs-labs-agents-threads#thread-state), the model's [history](/docs/labs/agents/models?ref=docs-labs-agents-threads#it-remembers), its [sandbox](/docs/labs/agents/sandboxes?ref=docs-labs-agents-threads#it-belongs-to-the-thread) and its [budget](/docs/labs/agents/models?ref=docs-labs-agents-threads#a-budget).

## No key is fine

You want an agent for one-off jobs. It needs no key.

{/* not type-checked: an agent with a handler and no thread */}
```typescript {{ title: "inngest/agents/summarize.ts" }}
import { agents } from "../client";

export const summarize = agents.agent(
  { id: "summarize" },
  async ({ event }) => {
    return event.data.content.slice(0, 80);
  },
);
```

Each `start()` is its own thread, with nothing to set up. Its answer stays in the run's output, since there is nowhere to post it.

## Two conversations

You want to follow two pull requests at once. The agent needs no change; send CI failures for #42 and #43.

```typescript {{ title: "scripts/failBoth.ts" }}
import { inngest } from "../inngest/client";

const pulls = "https://github.com/acme/web/pull";

await inngest.send([
  { name: "ci/run.failed", data: { pr: 42, prUrl: `${pulls}/42` } },
  { name: "ci/run.failed", data: { pr: 43, prUrl: `${pulls}/43` } },
]);
```

`me` is the handle to the run's own thread, so `me.key` names the one a run is on.

{/* not type-checked: me.key in an agent handler */}
```typescript
async ({ event, me }) => {
  return `Saw ${event.name} on ${me.key}`;
},
```

Each pull request has its own thread, with its own runs and state.

## A trigger with its own key

You want deploys in the thread too, though they carry the PR's URL somewhere else. Give their trigger its own `thread`.

{/* not type-checked: three triggers on an agent, each with its thread */}
```typescript
import { github } from "inngest/experimental/agents";
import { agents } from "../client";
import { ciFailed, deployed } from "../events";

export const prHelper = agents.agent(
  {
    id: "pr-helper",
    triggers: [
      github.thread({ repos: ["acme/web"] }),
      { event: ciFailed, thread: "event.data.prUrl" },
      { event: deployed, thread: "event.data.pull.url" },
    ],
  },
  async ({ event, me }) => {
    return `Saw ${event.name} on ${me.key}`;
  },
);
```

All three kinds of event land on #42's thread.
