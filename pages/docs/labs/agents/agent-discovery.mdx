# Agent discovery

> Let models find the right agent at run time, by what it does, with no wiring in code.

<Info>
  Inngest Agents is an Inngest Labs project: early, moving fast, and shaped by your feedback. [What's Labs?](/docs/labs?ref=docs-labs-agents-agent-discovery)
</Info>

Every agent publishes a card that says what it does and what input it takes. An agent with a model can list the cards it's allowed to see, read one in full, and start the agent it needs. You decide which agents each card is visible to, and which agents each model may start.

## Give an agent a card

<AnnotatedCode>

```typescript {{ title: "inngest/agents/securityReviewer.ts" }}
import { invoke } from "inngest";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";

export const securityReviewer = agents.agent({
  id: "security-reviewer",
  triggers: [invoke(z.object({ pr: z.number() }))],
  model: claude,
  system: "You review pull requests for security problems.",
  card: {
    description: "Reviews a pull request for security problems",
    capabilities: ["security review", "vulnerability triage"],
    share: "team",
  },
});
```

In an app with the ID `platform`, this agent's address is `platform/security-reviewer`. `start_agent` and discovery settings refer to agents by address.

## Write capabilities

`capabilities` tells a model when to pick the agent. Name the problems it handles, not the tools it has:

```typescript
// Hard to choose by: a model can't tell when this agent fits.
card: { description: "General helper", capabilities: ["helps with stuff"] },

// Easy to choose by: it names the problems, in a caller's words.
card: { description: "Investigates failed deploys", capabilities: ["pipeline failures", "deployment readiness"] },
```

If you leave out `capabilities`, the card uses `tags` instead and logs a warning. Write them yourself.

## How a model finds agents

Every agent with a model has `list_agents`, `describe_agent`, and `start_agent` tools by default:

```text {{ title: "What the model calls" }}
list_agents()
  agents: [
    {
      address: "platform/security-reviewer",
      description: "Reviews a pull request for security problems",
      capabilities: ["security review", "vulnerability triage"],
      effects: "write",
    },
    ...
  ]

describe_agent({ address: "platform/security-reviewer" })
  input: { type: "object", properties: { pr: { type: "number" } } }
  instructions: "Give it a pull request number. It reports its findings to whoever started it."

start_agent({ address: "platform/security-reviewer", input: { pr: 42 } })
  { thread: "a1b2c3" }
```

- **`list_agents`** takes no input and returns every agent the caller can see. There's no search: the model reads the list and picks. An agent never lists itself.
- **`describe_agent`** returns the full card, including the input schema, `instructions`, and the agent's skills.
- **`start_agent`** checks the input against the card and starts the agent. Its result comes back as an `agent/finished` message. See [Agent teams](/docs/labs/agents/agent-teams?ref=docs-labs-agents-agent-discovery#let-the-model-start-agents).

An agent that isn't visible to the caller gets the same error as one that doesn't exist, so a model can't probe for agents it isn't allowed to see.

## Fill in the rest of the card

```typescript
card: {
  description: "Reviews a pull request for security problems",
  capabilities: ["security review", "vulnerability triage"],
  instructions: "Give it a pull request number. It reports its findings to whoever started it.",
  tags: ["security", "review"],
  owner: "platform",
  effects: "read",
  speed: "minutes",
  share: "team",
},
```

| Field | What it's for |
| --- | --- |
| `instructions` | How to work with the agent once it's chosen. Only `describe_agent` returns it. |
| `tags` | Labels that discovery filters match exactly. They don't help a model find the agent. |
| `owner` | The team that owns the agent. Filters can match it. |
| `effects` | What calling the agent does to the world. See [Describe what a call does](#describe-what-a-call-does). |
| `speed` | Roughly how long a call takes: `"seconds"` or `"minutes"`. |

The card also lists the agent's own tools, and a paused agent shows `paused: true`.

## Describe what a call does

`effects` has three values:

- **`"read"`** looks something up or computes an answer, and changes nothing outside its own thread.
- **`"write"`**, the default, can send, post, charge, or otherwise change something.
- **`"destructive"`** deletes data, or does something that can't be undone, such as closing an account.

A discovery filter for `{ effects: "write" }` matches read and write agents, but never destructive ones. To allow a destructive agent, name it, or write `{ effects: "destructive" }` in the filter on purpose. `effects` doesn't add an approval step: put one around the call if you need it.

## Choose who can find it

`share` sets who can see an agent's card:

- **`"private"`**, the default, shows it to agents in its own app.
- **`"team"`** shows it to every app in the environment.

Agents in the same app see each other's cards as soon as they're defined. Other apps see a card after that app's next announcement, which happens every six hours. On the Dev Server, invoke the announce function to send one now. Cards are signed with the app's signing key, and unsigned cards are dropped.

`share` isn't access control. Code in your app can start any agent it imports, and anyone with an event key can send an agent's trigger event.

## Limit who it may start

`discovery.agents` limits which agents a model can find and start. This is experimental.

```typescript
discovery: {
  agents: [securityReviewer, "platform/linter", { tags: ["docs"] }],
},
```

An entry is an imported agent, an address, or a filter over card fields: `app` (`"self"` for the agent's own app), `tags` (all must match), `owner`, and `effects`. An agent is allowed if any entry matches it. `list_agents` and `describe_agent` show only allowed agents, and `start_agent` refuses the rest.

Without `discovery.agents`, a model may use every agent in its own app, and read-only agents in other apps: `[{ app: "self" }, { effects: "read" }]`. `share` still applies.

- **Leave an agent out of filters.** `card: { explicit: true }` means filters never match it. Only its address or an import does.
- **Started agents inherit the limit.** An agent started by a model never sees more than its starter was allowed, however deep the chain.
- **Shared tools work the same way.** `discovery.tools` limits the [shared tools](/docs/labs/agents/tools?ref=docs-labs-agents-agent-discovery#share-a-tool-between-apps) a model can use, with the same default.
- **Your code isn't limited.** `agent.start()` in your code starts any agent it imports.

## Turn discovery off

```typescript
discovery: false,
```

The model loses `list_agents`, `describe_agent`, and the tools that start and message agents, in its own calls and in sandbox scripts. It keeps `reply`, and the agent's card is still published.
