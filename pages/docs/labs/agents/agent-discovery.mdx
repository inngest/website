# Agent discovery

> Agents find each other at run time, by what they do.

Every agent publishes a card. A model agent reads the cards it can see and starts the one it needs, with nothing wired in code.

## A card

You want other agents to find yours. Give it a card that says what it does.

<AnnotatedCode>

```typescript {{ title: "inngest/agents/securityReviewer.ts" }}
import { invoke } from "inngest";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";

export const securityReviewer = agents.agent({
  id: "security-reviewer",
  triggers: [invoke(z.object({ pr: z.number() }))],
  model: claude,
  system: "You review pull requests for security problems.",
  card: {
    description: "Reviews a pull request for security problems",
    share: "team",
  },
});
```

In an app named `platform`, its address is `platform/security-reviewer`. `start_agent` and [`discovery.agents`](#who-it-may-start) take that address.

## Finding

You want the [PR helper](/docs/labs/agents/agent-teams?ref=docs-labs-agents-agent-discovery)'s model to use an agent nobody wired in. A model agent has the discovery tools by default, so the PR helper needs no change.

```text {{ title: "What the model calls" }}
list_agents({ query: "security" })
  agents: [
    {
      address: "platform/security-reviewer",
      description: "Reviews a pull request for security problems",
      effects: "write",
    },
  ]

describe_agent({ address: "platform/security-reviewer" })
  input: { type: "object", properties: { pr: { type: "number" } }, ... }

start_agent({
  address: "platform/security-reviewer",
  input: { pr: 42 },
})
  { thread: "a1b2c3" }
```

An agent never lists itself. `describe_agent` and `start_agent` still take its own address, since starting another run of itself can be meant.

`start_agent` checks the input against the card first, and the review returns as `agent/finished`. [The model calls agents →](/docs/labs/agents/agent-teams?ref=docs-labs-agents-agent-discovery#the-model-calls-agents)

## Keeping to itself

You want an agent to stop reaching for others. Switch discovery off.

```typescript
discovery: false,
```

That removes `list_agents`, `describe_agent` and the [agent tools](/docs/labs/agents/agent-teams?ref=docs-labs-agents-agent-discovery#the-model-calls-agents) except `reply`, from the model and from the code it runs in a sandbox. Its card is still published.

## What a card says

You want to tell the model more about an agent. Fill in the rest of the card.

```typescript
card: {
  description: "Reviews a pull request for security problems",
  tags: ["security", "review"],
  share: "team",
  owner: "platform",
  effects: "read",
  speed: "minutes",
},
```

```text {{ title: "What describe_agent returns" }}
{
  address: "platform/security-reviewer",
  description: "Reviews a pull request for security problems",
  input: { type: "object", properties: { pr: { type: "number" } }, ... },
  tags: ["security", "review"],
  share: "team",
  owner: "platform",
  effects: "read",
  speed: "minutes",
}
```

`input` comes from the `invoke()` trigger, and the card lists the agent's skills. `list_agents` matches `tags` like words of the description. A paused agent shows `paused: true`.

An agent with tools of its own also lists them, as `tools`: each by the name its model sees, with its description. A `tools` written as a function of the run and an MCP server's tools aren't listed. In dev mode the card says where the agent and each tool were defined, as `source`. Both are experimental, and `list_agents` leaves them out.

## Who can find it

You want to choose who finds an agent. `share: "private"`, the default, shows it to its own app; `share: "team"` to every app in the environment.

An agent of your own app is found at once, from its definition. Another app's agent appears after that app's next announce, every six hours. On the Dev Server, invoke the announce function by hand.

Announced cards are signed with the app's signing key, and a reader drops one that isn't. `share` still isn't access control: code in your app can import and start any of its agents, and anyone with an event key can send an agent's trigger.

## Who it may start

You want to limit what the PR helper's model may find and start. List the agents in `discovery.agents`. This is experimental.

```typescript
discovery: {
  agents: [securityReviewer, "platform/linter", { tags: ["docs"] }],
},
```

An entry is an imported agent, an exact address, or a filter over card fields: `app` (`"self"` is the agent's own app), `tags` (all must match), `owner` and `effects`. Any entry may match, and every field of one filter must. `list_agents` and `describe_agent` show only what matches, and `start_agent` refuses the rest.

With no list, an agent may use the agents of its own app and the read-only agents of other apps: `[{ app: "self" }, { effects: "read" }]`. A card without `effects` counts as `"write"`. `share` still applies on top.

- **Keep an agent out of filters.** `card: { explicit: true }` means no filter object matches it; only an imported agent or its exact address does.
- **Started agents inherit it.** An agent started by the model never sees more than its starter allowed, at every level of the chain.
- **Shared tools too.** `discovery.tools` filters [shared tools](/docs/labs/agents/tools?ref=docs-labs-agents-agent-discovery) the same way, with the same default.
- **Code isn't filtered.** `agent.start()` in your code starts any agent it imports.

`limits.depth` (default 1) says how deep chains of started agents go. The lowest `depth` in a chain wins.
