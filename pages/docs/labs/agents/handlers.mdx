# Handlers

> Write the code around the model: what it sees, what gets posted, and what happens next.

An agent with no handler answers every message the same way. A handler is plain code that decides instead: when to run the model, with which tools, and what to post.

- **The run's trigger, typed.** `event` is exactly what was sent. [Event →](#read-the-event)
- **The inbox in batches.** Everything sent to the thread, in order. [Inbox →](#read-the-inbox)
- **The loop when you want it.** Set up from the definition, and it posts nothing. [Loop →](#run-the-loop)
- **Tools from your own scope.** The model and sandbox code call them by name. [Tools →](#give-the-model-a-tool)
- **Posts that never slow you down.** Await one, or don't. [Post →](#post-in-the-thread)
- **A result for the caller.** Whatever the handler returns. [Return →](#return-a-result)

{/* not type-checked: the handler argument (event, inbox, me, loop) and an un-awaited me.post() */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/triage.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const triage = agents.agent(
  {
    id: "triage",
    triggers: [slack.thread()],
    model: claude,
    system: "You triage support threads.",
  },
  async ({ event, inbox, me, loop }) => {
    me.post(`Looking at it, <@${event.data.user}>.`);

    for await (const batch of inbox.batches()) {
      const { text } = await loop(batch);

      await me.post(text);
    }
  },
);
```

## Read the event

`event` is the event that started the run, exactly as it was sent: a Slack message, a webhook, the input to `start()`. With several triggers, `event.is()` narrows it to one.

{/* not type-checked: event.is() on an agent's trigger */}
```typescript {{ title: "inngest/agents/deploys.ts" }}
import { eventType } from "inngest";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";

const deploy = z.object({ service: z.string(), log: z.string() });

export const deployFailed = eventType("deploy/failed", { schema: deploy });

export const rollbackFailed = eventType("deploy/rollback.failed", {
  schema: deploy,
});

export const deploys = agents.agent(
  {
    id: "deploys",
    triggers: [deployFailed, rollbackFailed],
    model: claude,
    system: "Explain why a deploy failed, and what to try next.",
  },
  async ({ event, inbox, loop }) => {
    if (event.is(rollbackFailed)) {
      return { page: true, service: event.data.service };
    }

    const batch = await inbox.nextBatch();
    const { text } = await loop(batch ?? []);

    return { page: false, advice: text };
  },
);
```

The event is also the first message in the inbox, so a handler can read it either way. [Narrow an event with `is()` →](/docs/durable-execution/guides-and-advanced/events-and-triggers/event-payloads-and-schemas?ref=docs-labs-agents-handlers#narrow-an-event-with-is)

## Read the inbox

The inbox holds what is sent to the thread while the run works: the trigger, more messages from people, and messages from other agents. `inbox.batches()` gives every unread message at once, as an array.

{/* not type-checked: inbox.batches({ max }) and for await over the inbox */}
```typescript {{ title: "inngest/agents/notes.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const notes = agents.agent(
  {
    id: "notes",
    triggers: [slack.thread()],
    model: claude,
    system: "Summarise what the thread asked for.",
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches({ max: 20 })) {
      const { text } = await loop(batch);

      await me.post(text);
    }
  },
);
```

`max` caps a batch and leaves the rest unread, oldest first. To take one message at a time, loop over `inbox` itself. Both loops end after the agent's `idle` quiet time (ten minutes by default), or at once on a run opened by `start()`. [When the handler returns →](#when-the-handler-returns)

## Run the loop

`loop(batch)` runs the model with the agent's prompt and tools until it answers, and posts nothing. You decide what to do with the result.

{/* not type-checked: the loop result's end and reason */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/support.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const support = agents.agent(
  {
    id: "support",
    triggers: [slack.thread()],
    model: claude,
    system: "You answer support questions.",
    budget: { usd: 2 },
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches()) {
      const result = await loop(batch);

      if (result.end === "budget") {
        await me.post("I've reached my budget for this thread.");

        return;
      }

      await me.post(result.text);
    }
  },
);
```

<Annotation id="budget" lines="11" tease="per thread" title="Budget" href="/docs/labs/agents/reliability?ref=docs-labs-agents-handlers" linkText="Reliability">
The loop stops when this thread has spent it.
</Annotation>

<Annotation id="end" lines="17" tease="why it stopped" title="end" href="/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-handlers" linkText="Models and the loop">
`"done"`, `"maxTurns"`, `"stop"` or `"budget"`.
</Annotation>

</AnnotatedCode>

The loop saves the model's history on the thread. It is in the argument only when the agent has a `model`. [Models and the loop →](/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-handlers)

## Give the model a tool

A tool made inside the handler can use everything in its scope: `me`, the event, your variables. Pass it to a loop call with `tools`.

{/* not type-checked: loop(batch, { tools }) with a tool closing over me, called from sandbox code */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/prHelper.ts" }}
import { tool } from "inngest/experimental";
import { github } from "inngest/experimental/agents";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";
import { work } from "../sandboxes/work";

export const prHelper = agents.agent(
  {
    id: "pr-helper",
    triggers: [github.thread()],
    model: claude,
    system: "Fix what the pull request comment asks for.",
    sandboxes: { work },
  },
  async ({ inbox, me, loop }) => {
    const progress = tool.step({
      description: "Tells the person on the pull request how it's going",
      input: z.object({ note: z.string() }),
      run: async ({ note }) => {
        await me.post(note);

        return "posted";
      },
    });

    for await (const batch of inbox.batches()) {
      const { text } = await loop(batch, { tools: { progress } });

      await me.post(text);
    }
  },
);
```

<Annotation id="tool" lines="17-25" tease="closes over me" title="A tool in the handler" href="/docs/labs/agents/tools?ref=docs-labs-agents-handlers" linkText="Tools">
It runs as a durable step, like any tool.
</Annotation>

<Annotation id="tools" lines="28" tease="for this call" title="Per-call tools" href="/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-handlers#let-code-call-your-tools" linkText="Let code call your tools">

</Annotation>

</AnnotatedCode>

## Post in the thread

`me` is the handle to the run's own thread. `me.post(text)` writes where the thread lives: the Slack thread or the pull request it came from, in that place's own markup.

```typescript
await me.post("Merged. <https://github.com/acme/api/pull/42|The PR> is in.");

me.post("Still running the tests.");
```

- **Awaited**, it waits until the post landed, and throws if it still fails after retries.
- **Not awaited**, the agent carries on at once and the post lands before the run ends. A failure is logged, and a bad token or missing scope warns on the trace.

The agent posts a status line while it works and a notice when a run fails. A thread with no home, such as one opened by `start()` or a schedule, posts nothing, and the trace says so.

## Message yourself

`me.message(content)` puts a message in the agent's own inbox. It's how work you didn't wait for reports back.

{/* not type-checked: an un-awaited function that reports through me.message() */}
```typescript {{ title: "inngest/agents/releaser.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const releaser = agents.agent(
  {
    id: "releaser",
    triggers: [slack.thread()],
    model: claude,
    system: "You run releases. Say when the smoke tests are back.",
  },
  async ({ inbox, me, loop, step }) => {
    const smokeTest = async () => {
      const passed = await step.run("smoke-test", async () => {
        return true;
      });

      await me.message({ smokeTest: passed ? "passed" : "failed" });
    };

    void smokeTest();

    for await (const batch of inbox.batches()) {
      const { text } = await loop(batch);

      await me.post(text);
    }
  },
);
```

## Score the run

`score(name, value)` records how well the run went, as a number or a boolean. It's written once, however often the run replays.

```typescript
await score("resolved", true);
```

Await it or don't. The agent records its own scores too. [Observability →](/docs/labs/agents/observability?ref=docs-labs-agents-handlers)

## Return a result

What the handler returns is the run's output. A caller's `result()` gets it, typed. [Teams of agents →](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-handlers)

{/* not type-checked: a handler's return value as the run's output */}
```typescript {{ title: "inngest/agents/labeller.ts" }}
import { invoke } from "inngest";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";

export const labeller = agents.agent(
  {
    id: "labeller",
    triggers: [invoke(z.object({ title: z.string(), body: z.string() }))],
  },
  async ({ event, step }) => {
    return await step.run("pick-labels", async () => {
      const { output } = await claude({
        system: "Pick labels for this issue.",
        prompt: `${event.data.title}\n\n${event.data.body}`,
        output: z.object({ labels: z.array(z.string()) }),
      });

      return output;
    });
  },
);
```

The model's one-shot call takes an `output` schema and returns a typed value. It isn't a step by itself, so it goes in one.

## When the handler returns

The run ends, and work you started and didn't await is stopped, so a run never acts after it decided it was done. Un-awaited `me.post()` and `score()` calls land first.

On a run opened through a handle (`start()`, `message()`, `start_agent`, `message_agent`), both `for await` forms behave as if `idle` were zero: they end the moment they would have to wait, so a looping handler normally returns after its first batch. The run stays open while the runs it started with `start_agent` are open, and the answer after the last one is the output. [Wait for the result →](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-handlers#wait-for-the-result)

## Gotchas

- **Code outside steps runs again.** A handler re-runs from the top on every replay, and finished steps return their saved results. Put side effects in steps or tools.

## How it works

- `inbox` is one `step.subscribe` the agent opens with its triggers, its `inbox` sources and the messages agents send each other. [`step.subscribe` →](/docs/durable-execution/primitives/step-subscribe?ref=docs-labs-agents-handlers)
- Each model call, tool call and post is a step with its own trace row. The run waits for un-awaited posts before it ends.
