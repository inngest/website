# Subscribe

> Give any function a durable inbox, so no event is lost while it works.

- **Collect events as they arrive.** Loop over an inbox with `for await`. [Collect →](#collect-events)
- **Wait with a timeout.** `next({ timeout })` returns `undefined` when nothing comes. [Timeouts →](#wait-and-catch-up)
- **Catch up between steps.** `unread()` takes what arrived while you worked. [Catch up →](#wait-and-catch-up)
- **Listen to several events.** Messages narrow by event name. [Several events →](#listen-to-several-events)
- **Add and remove sources.** `listen()` and `of()` change what an inbox hears. [Sources →](#add-sources-and-read-by-kind)
- **Let a model listen.** `inboxTools` lets an agent start its own listeners. [Model tools →](#let-a-model-listen)

## Collect events

Events that arrive while the function is busy are saved in the run. The loop reads them in order.

<AnnotatedCode>

```typescript {{ title: "inngest/functions/collect.ts" }}
import { inngest } from "../client";
import { item } from "../events";

export const collect = inngest.createFunction(
  { id: "collect", triggers: [{ event: "batch/started" }] },
  async ({ event, step }) => {
    await using inbox = await step.subscribe("items", {
      event: item,
      if: `async.data.batch == ${JSON.stringify(event.data.batch)}`,
    });

    let total = 0;

    for await (const message of inbox) {
      total += message.data.n;

      if (total > 100) {
        break;
      }
    }

    return total;
  },
);
```

export const item = eventType("batch/item", {
  schema: z.object({ batch: z.string(), n: z.number() }),

## Wait and catch up

`next` waits for one message. `unread` takes everything that arrived while you worked.

<AnnotatedCode>

```typescript {{ title: "inngest/functions/patient.ts" }}
import { inngest } from "../client";

export const patient = inngest.createFunction(
  { id: "patient", triggers: [{ event: "work/started" }] },
  async ({ step }) => {
    await using inbox = await step.subscribe("updates", {
      event: "work/update",
    });

    await step.run("long-task", async () => {
      return "done";
    });

    const waiting = await inbox.unread();

    const next = await inbox.next({ timeout: "30s" });

    if (next === undefined) {
      return { waiting: waiting.length, next: null };
    }

    return { waiting: waiting.length, next: next?.seq };
  },
);
```

<Annotation id="unread" lines="14" tease="never waits" title="unread" href="/docs/labs/agents/loop?ref=docs-labs-agents-subscribe" linkText="Loop">
Returns the messages after your position and moves past them.
</Annotation>

<Annotation id="timeout" lines="16" tease="undefined on timeout" title="Timeout" href="/docs/labs/agents/threads?ref=docs-labs-agents-subscribe" linkText="Threads">
A late message is kept for the next read. `{ timeout: 0 }` never waits.
</Annotation>

</AnnotatedCode>

`current()` lists every message so far without moving your position. `putBack(messages)` returns messages so the next reads give them first.

## Listen to several events

Several events share one ordered sequence. `is` narrows a message to its event.

```typescript {{ title: "inngest/functions/watch.ts" }}
import { inngest } from "../client";
import { order, refund } from "../events";

export const watch = inngest.createFunction(
  { id: "watch", triggers: [{ event: "shop/watch" }] },
  async ({ step }) => {
    await using inbox = await step.subscribe("shop", {
      events: [
        { event: order },
        { event: refund, if: "async.data.amount > 100" },
      ],
    });

    const first = await inbox.next();

    if (first?.is(refund)) {
      return first.data.amount;
    }

    return first?.seq;
  },
);
```

Each message carries `seq`, `id`, `name`, `data`, `ts`, and `user`.

## Add sources and read by kind

`step.inbox` starts with no sources. `listen` adds one, and `of` reads one event with a position of its own.

```typescript {{ title: "inngest/functions/grow.ts" }}
import { inngest } from "../client";
import { refund } from "../events";

export const grow = inngest.createFunction(
  { id: "grow", triggers: [{ event: "shop/open" }] },
  async ({ step }) => {
    const inbox = await step.inbox("desk");

    const listener = await inbox.listen({
      event: refund,
      if: "async.data.amount > 100",
    });

    const refunds = inbox.of(refund);

    const big = await refunds.next({ timeout: "1h" });

    const everything = await inbox.current();

    await listener.stop();

    const left = await inbox.close();

    return {
      big: big?.data.order,
      seen: everything.length,
      left: left.length,
    };
  },
);
```

`listen` only captures events sent after it. `close()` returns the messages nobody read.

## Let a model listen

Set `inboxTools` on an agent and the model can start listeners and wait for events. It can only use the events you list, and each is tied to the thread by your `thread` expression.

```typescript {{ title: "inngest/agents/watcher.ts" }}
import { agent } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const watcher = agents.agent(
  {
    id: "watcher",
    inboxTools: {
      listen: [
        {
          event: "github/check_run",
          thread: "event.data.thread",
          maxPerRun: 2,
        },
      ],
      maxListeners: 3,
      maxWait: "20m",
      maxTotalWait: "1h",
    },
  },
  async ({ inbox, control, inboxTools }) => {
    for await (const message of inbox) {
      await agent.loop({
        model: claude,
        prompt: message.content ?? "",
        tools: { ...inboxTools },
        ...control,
      });
    }
  },
);
```

The tools are `inbox_listen`, `inbox_wait`, `inbox_read` and `inbox_stop`. `createInboxTools(inbox, config)` builds them for your own inbox.

## How it works

- The executor keeps a pause per source and saves each matching event as a step of the run. Saving does nothing else.
- A message already saved is read without a step. When none is, the run parks and wakes when one arrives.
- Reads on one inbox run in call order. Do not race `next()` with `Promise.race`; use `next({ timeout: 0 })` or `group.parallel({ mode: "race" })`.
- An agent's `inbox` is this API, with thread messages.
