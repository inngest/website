# MCP assistant

> An agent that works in each person's own account on a remote MCP server.

Each person signs in once, and the model never sees the link or a token.

```text
task/assigned   31   maya   What's in my Notion roadmap page?
To maya         Sign in to notion: https://mcp.notion.com/authorize?...
Run output      I sent Maya a link to connect Notion. Send the task again
                once she has.

(Maya signs in with Notion in the browser, and the task is sent again)
task/assigned   31   maya   What's in my Notion roadmap page?
Run output      Your roadmap has three items: ...
```

Screenshot needed: the sign-in message as your app delivers it, then the run's output.

## The code

Your app sends `task/assigned` with `inngest.send` when a task goes to a person.

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

export const taskAssigned = eventType("task/assigned", {
  schema: z.object({ task: z.string(), user: z.string(), text: z.string() }),
});
```

```typescript {{ title: "inngest/lib/chat.ts" }}
const api = "https://chat.acme.test/api";

export const chat = {
  send: async (user: string, text: string) => {
    const response = await fetch(`${api}/users/${user}/messages`, {
      method: "POST",
      headers: {
        authorization: `Bearer ${process.env.CHAT_TOKEN}`,
        "content-type": "application/json",
      },
      body: JSON.stringify({ text }),
    });

    if (!response.ok) {
      throw new Error(`Message to ${user}: ${response.status}`);
    }
  },
};
```

## What it shows off

- [Per-person sign-in](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-mcp-assistant#per-user-o-auth) lets each person work as themselves.
- [A hook for the link](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-mcp-assistant#deliver-the-link) sends the sign-in link through your own code, never through the model.
- [A one-line callback](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-mcp-assistant#the-callback-route) finishes the sign-in.

## Run it

Set the project up as in the [quick start](/docs/labs/agents/quick-start?ref=docs-labs-agents-recipes-mcp-assistant#install), in a Next.js app.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export INNGEST_EXPERIMENTAL_KV_URL=redis://localhost:6379
export MCP_OAUTH_ENCRYPTION_KEY=$(openssl rand -base64 32)
export CHAT_TOKEN=...
npm run dev
```

```bash
npx inngest-cli@latest dev -u http://localhost:3000/api/inngest
```

Set `redirectUri` to your app's public address; a tunnel works for local runs. Send a task from the Dev Server's **Send event** button at [localhost:8288](http://localhost:8288), or from code:

```typescript {{ title: "scripts/assignTask.ts" }}
import { inngest } from "../inngest/client";

await inngest.send({
  name: "task/assigned",
  data: {
    task: "31",
    user: "maya",
    text: "What's in my Notion roadmap page?",
  },
});
```

The first run sends the link through `chat.send`. With no chat service yet, swap the `fetch` in `chat.send` for a `console.log` and open the link from the app's output. Sign in, then send the task again.

## Variations

- [A shared token](/docs/labs/agents/tools?ref=docs-labs-agents-recipes-mcp-assistant#secrets-stay-home) serves a server that has one: `auth: { bearer: secret("TOKEN") }`.
- [Disconnecting](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-mcp-assistant#mcp) revokes one person's connection with `notion.disconnect(user)`.
- [A reply tool](/docs/labs/agents/recipes/support-assistant?ref=docs-labs-agents-recipes-mcp-assistant) like the Support assistant's `sendReply` sends the answer to the person instead of leaving it in the run's output.
