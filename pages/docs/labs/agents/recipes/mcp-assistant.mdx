# MCP assistant

> An agent that works in each person's own account on a remote MCP server.

```text
Maya   What's in my Notion roadmap page?
Bot    I sent you a link to connect Notion. Ask again once you've connected.
Maya   (signs in with Notion in the browser)
Maya   What's in my roadmap page?
Bot    Your roadmap has three items: ...
```

## The code

The server is one tool. `user` names the person from the Slack message that started the run, so every person gets their own token.

<AnnotatedCode>

{/* not type-checked: tool.mcp with auth.oauth.user reading { event }, the default OAuth store */}
```typescript {{ title: "inngest/tools/notion.ts" }}
import { tool } from "inngest/experimental";

export const notion = tool.mcp({
  id: "notion",
  url: "https://mcp.notion.com/mcp",
  auth: {
    oauth: {
      user: ({ event }) => {
        return event.data.user;
      },
      redirectUri: "https://app.acme.test/api/mcp/callback",
    },
  },
});
```

Tokens are stored under this id, so two servers never share one.
</Annotation>

Gets the event and thread that started the run. Any ID that is stable for the person works.
</Annotation>

<Annotation id="redirect" lines="11" tease="your callback route" title="Redirect" href="/docs/labs/agents/tools?ref=docs-labs-agents-recipes-mcp-assistant" linkText="Tools">

The agent has no handler; listing the tool is enough.

<AnnotatedCode>

{/* not type-checked: agents.agent with an MCP tool and no handler */}
```typescript {{ title: "inngest/agents/assistant.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";
import { notion } from "../tools/notion";

export const assistant = agents.agent({
  id: "assistant",
  triggers: [slack.thread()],
  model: claude,
  system: "You help people with their Notion workspace.",
  tools: { notion },
});
```

<Annotation id="tools" lines="11" tease="sign-in, handled for you" title="The sign-in link" href="/docs/labs/agents/tools?ref=docs-labs-agents-recipes-mcp-assistant" linkText="Tools">
A person who hasn't connected gets the link from the SDK. The model learns only that a link was sent, and never sees the link or a token.
</Annotation>

</AnnotatedCode>

The rest is wiring: the client, then three routes for Inngest, Slack and the server's redirect.

{/* not type-checked: createAgents with the store from the environment */}
```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { createAgents } from "inngest/experimental/agents";

export const inngest = new Inngest({ id: "mcp-assistant" });

export const agents = createAgents(inngest);
```

{/* not type-checked: agents.functions() in a Next.js route */}
```typescript {{ title: "app/api/inngest/route.ts" }}
import { serve } from "inngest/next";
import { agents, inngest } from "../../../inngest/client";
import "../../../inngest/agents/assistant";

export const { GET, POST, PUT } = serve({
  client: inngest,
  functions: agents.functions(),
});
```

{/* not type-checked: slack.bridge as a Web handler */}
```typescript {{ title: "app/api/slack/route.ts" }}
import { secret } from "inngest/experimental";
import { slack } from "inngest/experimental/agents";
import { inngest } from "../../../inngest/client";

export const POST = slack.bridge({
  client: inngest,
  signingSecret: secret("SLACK_SIGNING_SECRET"),
});
```

{/* not type-checked: completeMcpAuthorization with the default store */}
```typescript {{ title: "app/api/mcp/callback/route.ts" }}
import { completeMcpAuthorization, kvOAuthStore } from "inngest/experimental";

export const GET = async (request: Request) => {
  const { searchParams } = new URL(request.url);

  await completeMcpAuthorization({
    store: kvOAuthStore(),
    code: searchParams.get("code") ?? "",
    state: searchParams.get("state") ?? "",
    error: searchParams.get("error") ?? undefined,
  });

  return new Response("Connected. You can close this tab.");
};
```

## What it shows off

- Each person signs in once and works as themselves. [Tools](/docs/labs/agents/tools?ref=docs-labs-agents-recipes-mcp-assistant)
- The model never sees a sign-in link or a token. [Tools](/docs/labs/agents/tools?ref=docs-labs-agents-recipes-mcp-assistant)
- A Slack agent with no handler, and a Slack route that checks the signature. [Slack and GitHub](/docs/labs/agents/slack-and-github?ref=docs-labs-agents-recipes-mcp-assistant)

## Run it

You need the setup from the [quick start](/docs/labs/agents/quick-start?ref=docs-labs-agents-recipes-mcp-assistant#install), a Slack app and a Next.js app.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export INNGEST_EXPERIMENTAL_KV_URL=redis://localhost:6379
export MCP_OAUTH_ENCRYPTION_KEY=$(openssl rand -base64 32)
export SLACK_BOT_TOKEN=xoxb-...
export SLACK_SIGNING_SECRET=...
npm run dev
```

```bash
npx inngest-cli@latest dev -u http://localhost:3000/api/inngest
```

Set your Slack app's Events API request URL to `https://<your-host>/api/slack`, and set `redirectUri` to your app's public address. Mention the bot and ask about Notion. The run shows each model turn and tool call.

## Variations

- Use a server with one shared token: `auth: { bearer: secret("TOKEN") }`. [Tools](/docs/labs/agents/tools?ref=docs-labs-agents-recipes-mcp-assistant)
- Revoke one person's connection with `notion.disconnect(user)`. [Tools](/docs/labs/agents/tools?ref=docs-labs-agents-recipes-mcp-assistant)
- Add a second server to `tools`. Its own `id` keeps its tokens apart. [Tools](/docs/labs/agents/tools?ref=docs-labs-agents-recipes-mcp-assistant)
