# Slack assistant

> An agent that answers in a Slack thread and learns from what the team tells it.

A trigger, a model, a prompt and two tools. The thread, its memory and the status line come with the agent.

```text
Maya      @Support Where is order 7?
Support   Order 7 shipped with UPS and arrives Friday.
Maya      Remember: always give the carrier first.
Support   Saved. UPS, arriving Friday.

(a new thread, an hour later)
Dan       @Support Where is order 9?
Support   UPS (carrier first, as asked), arriving Friday.
```

Screenshot needed: the same exchange in Slack, and the first run's trace in the Dev Server.

## The code

<AnnotatedCode>

{/* not type-checked: slack.thread, system as an async function, kv.app and kv.key read in a run-time field */}
{/* TODO(spec): may a run-time field's function call kv? The spec says the function is pure and runs again on replay; a kv read is a memoized step. */}
```typescript {{ title: "inngest/agents/support.ts" }}
import { kv, slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { notes } from "../lib/notes";
import { claude } from "../models/claude";
import { lookupOrder } from "../tools/lookupOrder";
import { saveNote } from "../tools/saveNote";

export const support = agents.agent({
  id: "support",
  triggers: [slack.thread({ in: ["C0123ABC"] })],
  model: claude,
  system: async () => {
    const known = (await kv.app.get(notes)) ?? [];

    return `Answer support questions. Team notes: ${known.join("; ")}`;
  },
  tools: { lookupOrder, saveNote },
});
```

Slack calls a route in your app. It is a Web handler, so any framework that gives you a `Request` can mount it.

<AnnotatedCode>

{/* not type-checked: slack.bridge as a Web handler with the client and a secret */}
```typescript {{ title: "app/api/slack/route.ts" }}
import { secret } from "inngest/experimental";
import { slack } from "inngest/experimental/agents";
import { inngest } from "../../../inngest/client";

export const POST = slack.bridge({
  client: inngest,
  signingSecret: secret("SLACK_SIGNING_SECRET"),
});
```

The tools are two steps the model can call, and one key the notes live under.

```typescript {{ title: "inngest/tools/lookupOrder.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";

export const lookupOrder = tool.step({
  description: "Find an order by ID",
  input: z.object({ id: z.string() }),
  run: async ({ id }) => {
    return { id, status: "shipped", carrier: "UPS", eta: "Friday" };
  },
});
```

{/* not type-checked: kv.app.update with a typed kv.key */}
```typescript {{ title: "inngest/tools/saveNote.ts" }}
import { tool } from "inngest/experimental";
import { kv } from "inngest/experimental/agents";
import { z } from "zod";
import { notes } from "../lib/notes";

export const saveNote = tool.step({
  description: "Save something the team asked you to remember",
  input: z.object({ fact: z.string() }),
  run: async ({ fact }) => {
    await kv.app.update(notes, (current) => {
      return [...(current ?? []), fact];
    });

    return { saved: fact };
  },
});
```

{/* not type-checked: kv.key with a type argument */}
```typescript {{ title: "inngest/lib/notes.ts" }}
import { kv } from "inngest/experimental/agents";

export const notes = kv.key<string[]>("notes");
```

`inngest/client.ts` and `inngest/models/claude.ts` are the ones from the [quick start](/docs/labs/agents/quick-start?ref=docs-labs-agents-recipes-slack-assistant).

## What it shows off

- [Threads](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-recipes-slack-assistant) pick up where they stopped, after a restart, a deploy or a day.
- [An agent with no handler](/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-recipes-slack-assistant) answers in the thread, with a status line, from a definition alone.
- [App-wide memory](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-recipes-slack-assistant) lets one thread teach every other.
- [Slack](/docs/labs/agents/slack-and-github?ref=docs-labs-agents-recipes-slack-assistant) reaches the agent through one signed route.
- [Retried steps](/docs/labs/agents/reliability?ref=docs-labs-agents-recipes-slack-assistant) make every model call and tool call visible in the trace.

## Run it

Set the project up as in the quick start, in a Next.js app. Start the Dev Server, pointed at the app:

```bash
npx inngest-cli@latest dev -u http://localhost:3000/api/inngest
```

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export INNGEST_EXPERIMENTAL_KV_URL=redis://localhost:6379
export SLACK_BOT_TOKEN=xoxb-...
export SLACK_SIGNING_SECRET=...
npm run dev
```

Point your Slack app's Event Subscriptions at `https://<your-host>/api/slack`; a tunnel works for local runs. Invite the app to `C0123ABC`, mention it, and open the run in the Dev Server at [localhost:8288](http://localhost:8288).
