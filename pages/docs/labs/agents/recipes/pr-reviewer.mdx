# PR reviewer

> An agent that checks out a pull request, runs its tests and reviews it in a comment.

Opening a pull request starts the review, and nothing the agent runs can push.

```text
pr/opened   #42   maya

reviewer    comment on #42
  The tests pass (42 passed). Two problems:
  1. src/pagination.ts:31 skips the last page when `total` % `limit` is 0.
  2. src/pagination.test.ts has no case for an empty list.
```

Screenshot needed: the review comment on a pull request.

## The code

Your own webhook route sends `pr/opened` with `inngest.send` when a pull request opens.

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

export const prOpened = eventType("pr/opened", {
  schema: z.object({ pr: z.number(), author: z.string() }),
});
```

<AnnotatedCode>

```typescript {{ title: "inngest/sandboxes/review.ts" }}
import { secret } from "inngest/experimental";
import { sandbox } from "inngest/experimental/agents";

const { run, read, search } = sandbox.tools;

export const review = sandbox({
  id: "review",
  repo: ({ event }) => {
    const { pr } = event.data as { pr: number };

    return {
      url: "https://github.com/acme/web",
      ref: `refs/pull/${pr}/head`,
      auth: secret("GITHUB_READ_TOKEN"),
      push: false,
    };
  },
  tools: { run, read, search },
});
```

<Annotation id="repo" lines="8-13" tease="the pull request's head" title="Check out the pull request" href="/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-pr-reviewer#repos" linkText="Reference: repos">
The head of the pull request that opened. A sandbox is defined apart from any agent, so `event.data` is `unknown` until you say its shape.
</Annotation>

<Annotation id="readonly" lines="14-15" tease="nothing can push" title="Read only" href="/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-pr-reviewer#repos" linkText="Reference: repos">
One read-only secret serves the checkout, and `push: false` leaves out the push tool. A changed tracked file would block the next checkout, so the prompt forbids it.
</Annotation>

```typescript {{ title: "inngest/tools/comment.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";
import { gh } from "../lib/github";

export const comment = tool.step({
  description: "Comments on a pull request",
  input: z.object({ pr: z.number(), body: z.string() }),
  run: async ({ pr, body }) => {
    return await gh.comment(pr, body);
  },
});
```

```typescript {{ title: "inngest/lib/github.ts" }}
const api = "https://api.github.com/repos/acme/web";

export const gh = {
  comment: async (pr: number, body: string) => {
    const response = await fetch(`${api}/issues/${pr}/comments`, {
      method: "POST",
      headers: {
        accept: "application/vnd.github+json",
        authorization: `Bearer ${process.env.GITHUB_TOKEN}`,
      },
      body: JSON.stringify({ body }),
    });

    if (!response.ok) {
      throw new Error(`Comment on #${pr}: ${response.status}`);
    }

    return await response.json();
  },
};
```

The client adds `sandboxMiddleware()`.

```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { sandboxMiddleware } from "inngest/experimental";
import { createAgents } from "inngest/experimental/agents";

export const inngest = new Inngest({
  id: "pr-reviewer",
  middleware: [sandboxMiddleware()],
});

export const agents = createAgents(inngest);
```

The [model](/docs/labs/agents/quick-start?ref=docs-labs-agents-recipes-pr-reviewer#pick-a-model) is the quick start's. The serve route is the [Support assistant's](/docs/labs/agents/recipes/support-assistant?ref=docs-labs-agents-recipes-pr-reviewer), importing `inngest/agents/reviewer`.

## What it shows off

- [Your own event](/docs/labs/agents/threads?ref=docs-labs-agents-recipes-pr-reviewer#which-conversation-is-this) starts the agent on the pull request's thread.
- [A repository in the sandbox](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-pr-reviewer#repos) is checked out at the event's ref.
- [The built-in tools](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-pr-reviewer#code-tools), listed one by one, limit the model to a shell, `read` and `search`.
- [A comment tool](/docs/labs/agents/tools?ref=docs-labs-agents-recipes-pr-reviewer#your-own-git-hub-tools) posts the review, so the token that posts stays in your app.
- [Reports](#reporting-findings-instead-of-one-comment) are the structured alternative to a comment, for a caller that can wait and read findings as they're made.

## Run it

Set the project up as in the [quick start](/docs/labs/agents/quick-start?ref=docs-labs-agents-recipes-pr-reviewer#install), in a Next.js app with Sandboxes.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export GITHUB_READ_TOKEN=ghp_...
export GITHUB_TOKEN=ghp_...
npm run dev
```

```bash
npx inngest-cli@latest dev -u http://localhost:3000/api/inngest
```

`GITHUB_READ_TOKEN` only reads `acme/web`, and `GITHUB_TOKEN` posts the review. Send a pull request from the Dev Server's **Send event** button at [localhost:8288](http://localhost:8288), or from code, with the number of an open pull request:

```typescript {{ title: "scripts/openPr.ts" }}
import { inngest } from "../inngest/client";

await inngest.send({
  name: "pr/opened",
  data: { pr: 42, author: "maya" },
});
```

## Reporting findings instead of one comment

The `comment` tool is the right choice here because nothing is waiting on the reviewer — a webhook started it, and posting to the pull request *is* the output. But a reviewer started by another agent (a [lead](/docs/labs/agents/recipes/agent-teams?ref=docs-labs-agents-recipes-pr-reviewer), a CI orchestrator) has a caller that can wait and read structured findings, not just a final comment. Give it a report type and the model gets a `report` tool alongside `comment`, with no change to how it's triggered:

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

export const findingSchema = z.object({
  file: z.string(),
  line: z.number(),
  problem: z.string(),
});

export const finding = eventType("review/finding", { schema: findingSchema });
```

The schema is exported beside the type because a caller reading these reports parses with it.

A caller that starts this agent with `start()` and asks for that report type gets each finding as the model writes it, not one comment at the end:

```typescript
const review = await reviewer.start(
  { pr: 42 },
  { reports: [{ event: finding, required: true }] },
);

for await (const batch of inbox.batches()) {
  for (const message of batch) {
    const named: { name: string; data: unknown } = message;

    if (named.name === finding.name) {
      const found = findingSchema.parse(named.data);

      console.log(`${found.file}:${found.line} - ${found.problem}`);
    }
  }
}
```

`message.is(finding)` can't narrow to a report, so the name is matched and the data parsed with the report's own schema. [Reading a report's type →](/docs/labs/agents/agent-teams?ref=docs-labs-agents-recipes-pr-reviewer#reading-a-reports-type)

Nothing about the webhook-triggered path above changes — `reports` only exists for a run that was started with it, so the plain `pr/opened` trigger still just gets a comment. [Reports along the way →](/docs/labs/agents/agent-teams?ref=docs-labs-agents-recipes-pr-reviewer#reports-along-the-way)
