# PR reviewer

> An agent that checks out a pull request, runs its tests and reviews it in a comment.

<Info>
  Inngest Agents is an Inngest Labs project: early, moving fast, and shaped by your feedback. [What's Labs?](/docs/labs?ref=docs-labs-agents-recipes-pr-reviewer)
</Info>

Opening a pull request starts the review, and nothing the agent runs can push.

```text
pr/opened   #42   maya

reviewer    comment on #42
  The tests pass (42 passed). Two problems:
  1. src/pagination.ts:31 skips the last page when `total` % `limit` is 0.
  2. src/pagination.test.ts has no case for an empty list.
```

## The code

Your own webhook route sends `pr/opened` with `inngest.send` when a pull request opens.

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

export const prOpened = eventType("pr/opened", {
  schema: z.object({ pr: z.number(), author: z.string() }),
});
```

```typescript {{ title: "inngest/agents/reviewer.ts" }}
import { agents } from "../client";
import { prOpened } from "../events";
import { claude } from "../models/claude";
import { review } from "../sandboxes/review";
import { comment } from "../tools/comment";

export const reviewer = agents.agent({
  id: "reviewer",
  triggers: [prOpened],
  thread: "event.data.pr",
  model: claude,
  system:
    "Run the tests, list problems with file and line, change no tracked " +
    "files, then post the review with comment.",
  sandboxes: { review },
  tools: { comment },
});
```

<AnnotatedCode>

```typescript {{ title: "inngest/sandboxes/review.ts" }}
import { secret } from "inngest/experimental";
import { sandbox } from "inngest/experimental/agents";

const { run, read, search } = sandbox.tools;

export const review = sandbox({
  id: "review",
  repo: ({ event }) => {
    const { pr } = event.data as { pr: number };

    return {
      url: "https://github.com/acme/web",
      ref: `refs/pull/${pr}/head`,
      auth: secret("GITHUB_READ_TOKEN"),
      push: false,
    };
  },
  tools: { run, read, search },
});
```

<Annotation id="repo" lines="8-13" tease="the pull request's head" title="Check out the pull request" href="/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-pr-reviewer#repos" linkText="Reference: repos">
Checks out the head of the pull request. A sandbox is defined apart from any agent, so `event.data` is `unknown` until you state its shape.
</Annotation>

<Annotation id="readonly" lines="14-15" tease="nothing can push" title="Read only" href="/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-pr-reviewer#repos" linkText="Reference: repos">
A read-only token clones the repository, and `push: false` leaves out the push tool. The prompt tells the model not to change tracked files, because a changed file would block the next checkout.
</Annotation>

<Annotation id="tools" lines="18" tease="three tools only" title="Only these tools" href="/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-pr-reviewer#code-tools" linkText="Reference: built-in tools">
Only these built-in tools. The model gets `review_run`, `review_read`, and `review_search`, with no `edit` and no push.
</Annotation>

</AnnotatedCode>

```typescript {{ title: "inngest/tools/comment.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";
import { gh } from "../lib/github";

export const comment = tool.step({
  description: "Comments on a pull request",
  input: z.object({ pr: z.number(), body: z.string() }),
  run: async ({ pr, body }) => {
    return await gh.comment(pr, body);
  },
});
```

```typescript {{ title: "inngest/lib/github.ts" }}
const api = "https://api.github.com/repos/acme/web";

export const gh = {
  comment: async (pr: number, body: string) => {
    const response = await fetch(`${api}/issues/${pr}/comments`, {
      method: "POST",
      headers: {
        accept: "application/vnd.github+json",
        authorization: `Bearer ${process.env.GITHUB_TOKEN}`,
      },
      body: JSON.stringify({ body }),
    });

    if (!response.ok) {
      throw new Error(`Comment on #${pr}: ${response.status}`);
    }

    return await response.json();
  },
};
```

The client adds `sandboxMiddleware()`.

```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { inboxMiddleware, sandboxMiddleware } from "inngest/experimental";
import { createAgents } from "inngest/experimental/agents";

export const inngest = new Inngest({
  id: "pr-reviewer",
  middleware: [inboxMiddleware(), sandboxMiddleware()],
});

export const agents = createAgents(inngest);
```

The [model](/docs/labs/agents/quick-start?ref=docs-labs-agents-recipes-pr-reviewer#3-choose-a-model) is the quick start's. The serve route is the [Support assistant's](/docs/labs/agents/recipes/support-assistant?ref=docs-labs-agents-recipes-pr-reviewer), importing `inngest/agents/reviewer`.

## How it works

- [Your own event](/docs/labs/agents/threads?ref=docs-labs-agents-recipes-pr-reviewer#name-a-thread) starts the agent on the pull request's thread.
- [A repository in the sandbox](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-pr-reviewer#repos) is checked out at the event's ref.
- [The built-in tools](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-recipes-pr-reviewer#code-tools), listed one by one, limit the model to a shell, `read` and `search`.
- [A comment tool](/docs/labs/agents/tools?ref=docs-labs-agents-recipes-pr-reviewer#give-tools-to-an-agent) posts the review, so the token that posts stays in your app.
- [Reports](#report-findings-to-a-caller) send structured findings to a caller that started the reviewer.

## Run it

Set the project up as in the [quick start](/docs/labs/agents/quick-start?ref=docs-labs-agents-recipes-pr-reviewer#1-install-the-packages), in a Next.js app with Sandboxes.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export GITHUB_READ_TOKEN=ghp_...
export GITHUB_TOKEN=ghp_...
npm run dev
```

```bash
npx inngest-cli@latest dev -u http://localhost:3000/api/inngest
```

`GITHUB_READ_TOKEN` only reads `acme/web`, and `GITHUB_TOKEN` posts the review. Send a pull request from the Dev Server's **Send event** button at [localhost:8288](http://localhost:8288), or from code, with the number of an open pull request:

```typescript {{ title: "scripts/openPr.ts" }}
import { inngest } from "../inngest/client";

await inngest.send({
  name: "pr/opened",
  data: { pr: 42, author: "maya" },
});
```

## Report findings to a caller

When a webhook starts the reviewer, nothing waits for its result, so posting a comment is the right output. When another agent starts it, such as a [lead](/docs/labs/agents/recipes/agent-teams?ref=docs-labs-agents-recipes-pr-reviewer), that caller can read structured findings as they're made. Define a report type, and the model gets a `report` tool beside `comment`:

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

export const findingSchema = z.object({
  file: z.string(),
  line: z.number(),
  problem: z.string(),
});

export const finding = eventType("review/finding", { schema: findingSchema });
```

Export the schema beside the type, because a caller parses reports with it.

A caller that starts the agent and asks for the report type gets each finding as the model writes it:

```typescript
const review = await reviewer.start(
  { pr: 42 },
  { reports: [{ event: finding, required: true }] },
);

for await (const batch of inbox.batches()) {
  for (const message of batch) {
    const named: { name: string; data: unknown } = message;

    if (named.name === finding.name) {
      const found = findingSchema.parse(named.data);

      console.log(`${found.file}:${found.line} - ${found.problem}`);
    }
  }
}
```

`message.is(finding)` can't narrow to a report type, so the caller compares the name and parses the data with the report's schema. See [Receive reports while an agent works](/docs/labs/agents/agent-teams?ref=docs-labs-agents-recipes-pr-reviewer#receive-reports-while-an-agent-works).

A run started by `pr/opened` isn't asked for reports, so it still posts a comment.
