# PR reviewer

> An agent that checks out a pull request, runs its tests and reviews it in a comment.

A comment asks for the review. The repository is checked out for the agent, and nothing it runs can push.

```text
maya     @review-bot please review

review-bot
  The tests pass (42 passed). Two problems:
  1. src/pagination.ts:31 skips the last page when `total` % `limit` is 0.
  2. src/pagination.test.ts has no case for an empty list.
```

## The code

<AnnotatedCode>

{/* not type-checked: github.thread with repos, events and if */}
{/* TODO(spec): github.thread({ repos?, events? }) has no way to keep only comments that ask for a review and skip the bot's own. This page assumes an if option and the event.data fields body and author. */}
```typescript {{ title: "inngest/agents/reviewer.ts" }}
import { github } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";
import { review } from "../sandboxes/review";

export const reviewer = agents.agent({
  id: "reviewer",
  triggers: [
    github.thread({
      repos: ["acme/app"],
      events: ["issue_comment"],
      if: [
        'event.data.body.contains("@review-bot please review")',
        'event.data.author != "review-bot[bot]"',
      ].join(" && "),
    }),
  ],
  model: claude,
  system: [
    "Review the pull request checked out in the sandbox.",
    "Run its tests and read the changed files.",
    "Report problems first, with file and line.",
  ].join(" "),
  sandboxes: { review },
});
```

The sandbox holds the repository, and the repository is a function of the comment that started the run.

<AnnotatedCode>

{/* TODO(spec): the checkout leaves an existing checkout alone when a paused sandbox resumes, so a second request on the same pull request would review the old head. Which option or call gives it a clean checkout of the current head? */}
{/* not type-checked: repo as a function of the event, repo auth as a function, push: false */}
```typescript {{ title: "inngest/sandboxes/review.ts" }}
import { sandbox } from "inngest/experimental/agents";

export const review = sandbox({
  id: "review",
  repo: ({ event }) => {
    return {
      url: "https://github.com/acme/app",
      ref: `refs/pull/${event.data.number}/head`,
      auth: () => {
        return process.env.GITHUB_READ_TOKEN ?? "";
      },
      push: false,
    };
  },
  tools: sandbox.tools.code({ only: ["run", "read", "search"] }),
});
```

<Annotation id="repo" lines="5-8" tease="the pull request's head" title="Check out the pull request" href="/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-recipes-pr-reviewer" linkText="Sandboxes and code">
A function of the event, so the checkout is the head of the pull request that asked.
</Annotation>

<Annotation id="readonly" lines="9-12" tease="nothing can push" title="Read only" href="/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-recipes-pr-reviewer" linkText="Sandboxes and code">
Checkout uses a read token, and `push: false` leaves out the push tool. `run` can still change files, but only inside the sandbox.
</Annotation>

<Annotation id="tools" lines="15" tease="the shell plus two" title="Code tools" href="/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-recipes-pr-reviewer" linkText="Sandboxes and code">
`run` is a shell. `read` and `search` are opt-in, and `edit` stays out.
</Annotation>

import { Inngest } from "inngest";
import { sandboxMiddleware } from "inngest/experimental";
import { createAgents } from "inngest/experimental/agents";

`inngest/models/claude.ts` is the one from the [quick start](/docs/labs/agents/quick-start?ref=docs-labs-agents-recipes-pr-reviewer). `app/api/inngest/route.ts` serves the agents as in the [Slack assistant](/docs/labs/agents/recipes/slack-assistant?ref=docs-labs-agents-recipes-pr-reviewer), importing `inngest/agents/reviewer`.

## What it shows off

- [A GitHub comment](/docs/labs/agents/slack-and-github?ref=docs-labs-agents-recipes-pr-reviewer) starts the agent on the pull request's own thread, and the answer comes back there.
- [A repository in the sandbox](/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-recipes-pr-reviewer) is checked out for you, at a ref the event names.
- [Read-only by construction](/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-recipes-pr-reviewer) means a read token, no push tool and no write token in the sandbox.
- [Tools you pick](/docs/labs/agents/tools?ref=docs-labs-agents-recipes-pr-reviewer) limit the model to a shell, `read` and `search`.

## Run it

Set the project up as in the quick start, in a Next.js app. It needs an environment with Sandboxes. Start the Dev Server, pointed at the app:

```bash
npx inngest-cli@latest dev -u http://localhost:3000/api/inngest
```

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export INNGEST_EXPERIMENTAL_KV_URL=redis://localhost:6379
export GITHUB_READ_TOKEN=ghp_...
export GITHUB_TOKEN=ghp_...
export GITHUB_WEBHOOK_SECRET=...
npm run dev
```

`GITHUB_READ_TOKEN` only needs read access to the repository's contents. `GITHUB_TOKEN` posts the review.

{/* TODO(spec): which token does the answer's post to GitHub use by default? This page assumes GITHUB_TOKEN. */}

Add a webhook to `acme/app` for **Issue comments**, pointing at `https://<your-host>/api/github` with `GITHUB_WEBHOOK_SECRET` as its secret; a tunnel works for local runs. Comment `@review-bot please review` on a pull request and watch the run in the Dev Server at [localhost:8288](http://localhost:8288).
