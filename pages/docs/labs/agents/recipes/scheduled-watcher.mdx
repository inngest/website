# Scheduled watcher

> A weekday digest that speaks up only when there is news.

<Info>
  Inngest Agents is an Inngest Labs project: early, moving fast, and shaped by your feedback. [What's Labs?](/docs/labs?ref=docs-labs-agents-recipes-scheduled-watcher)
</Info>

It's a plain Inngest function with one model call, not an agent: it needs no thread, inbox, or card. Use this shape for scheduled work that doesn't hold a conversation.

```text
Mon 09:00   Watcher
            Stale pull requests in acme/app:
            #301 Add retries to webhooks, maya, idle 5 days
            #288 Bump vitest, dan, idle 4 days

Tue 09:00   (nothing posted: no pull request went stale)
```

## The code

The function remembers which pull requests it already reported, so it doesn't repeat itself. A plain function has no thread state, so keep that list in your own storage. `reportedStore` below is the smallest version that works. Replace it with a table or a Redis key you already use.

<AnnotatedCode>

```typescript {{ title: "inngest/functions/watcher.ts" }}
import { inngest } from "../client";
import { claude } from "../models/claude";
import { findStalePulls } from "./findStalePulls";
import { postToSlack } from "./postToSlack";
import { reportedStore } from "./reportedStore";

export const watcher = inngest.createFunction(
  { id: "watcher", triggers: [{ cron: "TZ=UTC 0 9 * * 1-5" }] },
  async ({ step }) => {
    const seen = await step.run("seen", async () => {
      return await reportedStore.get();
    });

    const stale = await step.run("find-stale", async () => {
      return await findStalePulls(seen);
    });

    if (stale.length === 0) {
      return;
    }

    const digest = await step.run("digest", async () => {
      const { text } = await claude({
        system: "One line per pull request, oldest first, for the team.",
        prompt: JSON.stringify(stale),
      });

      return text ?? "";
    });

    await step.run("post", async () => {
      await postToSlack(digest);
    });

    const numbers = stale.map((pull) => {
      return pull.number;
    });

    await step.run("mark-reported", async () => {
      await reportedStore.add(numbers);
    });
  },
);
```

```typescript {{ title: "inngest/functions/reportedStore.ts" }}
// The smallest thing that works. Swap this for your own database or cache:
// anything that can remember a set of numbers across invocations.
const reported = new Set<number>();

export const reportedStore = {
  get: async (): Promise<number[]> => {
    return [...reported];
  },
  add: async (numbers: number[]): Promise<void> => {
    for (const number of numbers) {
      reported.add(number);
    }
  },
};
```

```typescript {{ title: "inngest/functions/findStalePulls.ts" }}
export const findStalePulls = async (seen: number[]) => {
  const token = process.env.GITHUB_TOKEN;

  if (!token) {
    throw new Error("Set GITHUB_TOKEN");
  }

  const query = "state=open&sort=updated&direction=asc";

  const response = await fetch(
    `https://api.github.com/repos/acme/app/pulls?${query}`,
    { headers: { authorization: `Bearer ${token}` } },
  );

  if (!response.ok) {
    throw new Error(`GitHub ${response.status}: ${await response.text()}`);
  }

  const pulls = (await response.json()) as {
    number: number;
    title: string;
    updated_at: string;
    user: { login: string };
  }[];

  const cutoff = Date.now() - 3 * 86_400_000;

  return pulls
    .filter((pull) => {
      const stale = Date.parse(pull.updated_at) < cutoff;

      return stale && !seen.includes(pull.number);
    })
    .map((pull) => {
      return {
        number: pull.number,
        title: pull.title,
        author: pull.user.login,
        updated: pull.updated_at,
      };
    });
};
```

```typescript {{ title: "inngest/functions/postToSlack.ts" }}
export const postToSlack = async (text: string) => {
  const webhook = process.env.SLACK_WEBHOOK_URL;

  if (!webhook) {
    throw new Error("Set SLACK_WEBHOOK_URL");
  }

  const response = await fetch(webhook, {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify({ text }),
  });

  if (!response.ok) {
    throw new Error(`Slack answered ${response.status}`);
  }
};
```

## How it works

- **A plain function** runs on a schedule, with steps and no agent.
- [One model call](/docs/labs/agents/models?ref=docs-labs-agents-recipes-scheduled-watcher#call-a-model-directly) writes the digest inside a step.
- **Your own storage** keeps what was reported. An agent would use [`kv.thread`](/docs/labs/agents/threads?ref=docs-labs-agents-recipes-scheduled-watcher#keep-your-own-state), which a plain function doesn't have.
- [Retried steps](/docs/labs/agents/reliability?ref=docs-labs-agents-recipes-scheduled-watcher) keep a failed post from being marked reported.

## Run it

Set the project up as in the [quick start](/docs/labs/agents/quick-start?ref=docs-labs-agents-recipes-scheduled-watcher#1-install-the-packages), plus a GitHub token and a Slack incoming webhook.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export GITHUB_TOKEN=ghp_...
export SLACK_WEBHOOK_URL=https://hooks.slack.com/services/...
npx tsx inngest/serve.ts
```

```bash
npx inngest-cli@latest dev -u http://localhost:3000/api/inngest
```

Invoke `watcher` from the Functions page at [localhost:8288](http://localhost:8288) to run it before 09:00. A second invoke in the same process posts nothing. The in-memory `Set` in `reportedStore` is only for this walkthrough. In production, back it with storage that survives a restart.

## Variations

- [Add triggers](/docs/labs/agents/agents?ref=docs-labs-agents-recipes-scheduled-watcher#add-triggers): run it hourly with `{ cron: "TZ=UTC 0 * * * *" }`.
- Expire old entries in `reportedStore`, so a pull request that's still open weeks later is reported again.
