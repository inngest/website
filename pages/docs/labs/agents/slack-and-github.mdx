# Slack and GitHub

> Talk to your agent in Slack, and work with it on issues and pull requests, right in the thread.

Slack is one route, one trigger and a set of tools. GitHub works the same way.

- **One route.** Signatures are checked; only messages meant for the agent get through. [Route →](#add-the-route)
- **DMs, mentions and replies.** No channel list to keep. [Trigger →](#start-from-slack)
- **Post, ask and show progress.** Three tools, for the model and for scripts. [Tools →](#post-ask-and-show-progress)
- **Post anywhere.** A channel, a person or a message link. [Destinations →](#post-somewhere-else)
- **Your own rules.** Replace the default, or feed the bridge from Socket Mode. [Rules →](#set-your-own-rules)
- **Pull requests too.** The same pieces on GitHub. [GitHub →](#work-on-github)

## Add the route

`slack.bridge()` is the route Slack sends messages to. It's a Web handler, so it mounts in any framework.

{/* not type-checked: slack.bridge({ client, signingSecret }) as a Web handler */}
<AnnotatedCode>

```typescript {{ title: "app/api/slack/route.ts" }}
import { secret } from "inngest/experimental";
import { slack } from "inngest/experimental/agents";
import { inngest } from "../../../inngest/client";

export const POST = slack.bridge({
  client: inngest,
  signingSecret: secret("SLACK_SIGNING_SECRET"),
});
```

<Annotation id="bridge" lines="5" tease="Request in, Response out" title="The bridge" href="#how-it-works" linkText="How it works">
Checks the signature, then sends an event only for a direct message, a mention in any channel the agent is in, or a reply in a thread it already answered. A redelivery is one event. Bots, including the agent itself, are ignored unless the bridge sets `allowBots: true`.
</Annotation>

<Annotation id="secret" lines="7" tease="read inside the call" title="Signing secret" href="/docs/labs/agents/tools?ref=docs-labs-agents-slack-and-github#keep-secrets-on-the-host" linkText="Keep secrets on the host">
Kept on the host.
</Annotation>

</AnnotatedCode>

In your Slack app, point Event Subscriptions and Interactivity at the route's URL, so buttons and forms arrive at the bridge too. Then add:

- **Events:** `app_mention`, `message.im`, `message.channels`, `message.groups`, `reaction_added` and `assistant_thread_started`.
- **Scopes:** `chat:write`, `app_mentions:read`, `channels:history`, `groups:history`, `im:history`, `reactions:read` and `assistant:write`.

## Start from Slack

`slack.thread()` covers every channel the app is in, plus DMs. `in` limits it, and `token` replaces `SLACK_BOT_TOKEN` for the SDK's own writes: [`me.post()`](/docs/labs/agents/handlers?ref=docs-labs-agents-slack-and-github#post-in-the-thread), the status line and the default answer.

```typescript
triggers: [
  slack.thread({
    in: ["C0123ABC", "C0456DEF"],
    token: secret("ACME_SLACK_TOKEN"),
  }),
],
```

The model reads a message as `[Ana] can you check order 7?`, not as JSON. Each event carries `threadKey`, a plain field that `waitForEvent` and `cancelOn` can match on. Besides `slack/message`, the bridge sends `slack/reaction`, `slack/action`, `slack/view` and `slack/stop`. [Threads and memory →](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-slack-and-github)

## Post, ask and show progress

`slack.tools()` gives the model three tools, and [sandbox code](/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-slack-and-github#let-code-call-your-tools) calls the same ones by name. They post in the Slack thread the run came from.

<AnnotatedCode>

```js {{ title: "ship.js" }}
const { tools } = require("inngest_tools");

const main = async () => {
  await tools.slack_progress({
    id: "ship",
    title: "Shipping",
    status: "running",
  });

  const answer = await tools.slack_ask({
    question: "Ship it?",
    options: ["yes", "no"],
  });

  await tools.slack_post({ text: `You said ${answer}.` });
};

main();
```

<Annotation id="progress" lines="4-8" tease="a task that updates" title="slack_progress">
The same `id` updates the task.
</Annotation>

<Annotation id="ask" lines="10-13" tease="waits in a script" title="slack_ask" href="/docs/labs/agents/inboxes?ref=docs-labs-agents-slack-and-github" linkText="Inboxes">
In a script the call waits and gives the answer as a string. When the model calls it, the model carries on, and the answer arrives later in its inbox.
</Annotation>

<Annotation id="post" lines="15" tease="plain text" title="slack_post" href="/docs/labs/agents/handlers?ref=docs-labs-agents-slack-and-github#post-in-the-thread" linkText="Post in the thread">
Lands in the same thread as `me.post()`. Posts use Slack's markup, so links and mentions work; broadcast mentions such as `<!channel>` do nothing.
</Annotation>

</AnnotatedCode>

```typescript
await sandboxes.work.commands.run("ship", "node ship.js", {
  tools: { ...slack.tools() },
});
```

## Post somewhere else

Every Slack tool takes an optional `to`: `#channel`, `@person` or a Slack message link.

{/* not type-checked: slack.tools({ to }) on an agent with a cron trigger */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/digest.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const digest = agents.agent({
  id: "digest",
  triggers: [{ cron: "TZ=UTC 0 9 * * 1-5" }],
  model: claude,
  system: "Summarise yesterday's deploys and post it with slack_post.",
  tools: { ...slack.tools({ to: "#deploys" }) },
});
```

<Annotation id="to" lines="10" tease="a default destination" title="to" href="#gotchas" linkText="Gotchas">
Used when a call gives no `to`. A cron run has no Slack thread, so it needs one. The model can still pass its own.
</Annotation>

</AnnotatedCode>

## Set your own rules

A `gate` replaces the default rule, and a message it rejects never becomes an event. For your own Socket Mode connection, give each payload to `bridge.handle()`.

{/* not type-checked: slack.bridge({ gate }) and bridge.handle(payload) */}
<AnnotatedCode>

```typescript {{ title: "app/slack/socket.ts" }}
import { secret } from "inngest/experimental";
import { slack } from "inngest/experimental/agents";
import { inngest } from "../../inngest/client";

const bridge = slack.bridge({
  client: inngest,
  signingSecret: secret("SLACK_SIGNING_SECRET"),
  gate: ({ message, bot }) => {
    return message.text.includes(`<@${bot.userId}>`);
  },
});

export const onSocketEvent = async (payload: unknown) => {
  await bridge.handle(payload);
};
```

<Annotation id="gate" lines="8-10" tease="replaces the default rule" title="gate">
Gets the message, the thread (`key` and `history()`) and the bot's own `userId`, and returns a boolean or a promise of one. This one passes only mentions, so direct messages stop reaching the agent.
</Annotation>

<Annotation id="handle" lines="13-15" tease="no signature check" title="handle" href="#how-it-works" linkText="How it works">
For a connection you already trust; the SDK never opens a socket. The gate and thread key behave as over HTTP.
</Annotation>

</AnnotatedCode>

## Work on GitHub

`github.bridge()` verifies `X-Hub-Signature-256` and sends `github/<event>` events, such as `github/issue_comment`. A redelivered webhook is dropped, and so are the app's own comments and other bots', so an agent never triggers itself.

{/* not type-checked: github.bridge({ client, secret }) as a Web handler */}
```typescript {{ title: "app/api/github/route.ts" }}
import { secret } from "inngest/experimental";
import { github } from "inngest/experimental/agents";
import { inngest } from "../../../inngest/client";

export const POST = github.bridge({
  client: inngest,
  secret: secret("GITHUB_WEBHOOK_SECRET"),
});
```

`github.thread()` is the trigger. Each issue or pull request is one thread, keyed by its URL.

{/* not type-checked: github.thread({ repos, events }), a plain event source with a thread override, and ...github.tools() */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/prHelper.ts" }}
import { github } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const prHelper = agents.agent({
  id: "pr-helper",
  triggers: [
    github.thread({
      repos: ["acme/api"],
      events: ["issue_comment"],
      if: 'event.data.comment.body.contains("@pr-helper")',
    }),
    { event: "ci/run.failed", thread: "event.data.prUrl" },
  ],
  model: claude,
  system: "Answer reviewers and explain failing CI runs.",
  tools: { ...github.tools() },
});
```

<Annotation id="thread" lines="8-12" tease="a thread per PR" title="github.thread()" href="/docs/labs/agents/agents-and-triggers?ref=docs-labs-agents-slack-and-github#start-a-run" linkText="Start a run">
`repos` and `events` limit it, and `events` takes GitHub's event names. Without `events` it triggers on `issues`, `issue_comment`, `pull_request`, `pull_request_review` and `pull_request_review_comment`. `if` works as on any trigger, over GitHub's webhook payload plus `threadKey`.
</Annotation>

<Annotation id="plain" lines="13" tease="a plain event joins" title="Join by URL">
An event that carries the URL lands on the same thread. The pull request is that thread's home, even when this event opened it, so its run posts there.
</Annotation>

<Annotation id="tools" lines="17" tease="comment and ask" title="Tools">
`github_comment` and `github_ask`. They use `GITHUB_TOKEN`; `github.tools({ token })` takes a string, a function, `secret()` or `githubApp()`.
</Annotation>

</AnnotatedCode>

## Gotchas

- **Anyone in the thread can answer an ask.** Nothing checks who.
- **`to` is needed without a Slack thread.** A cron run, `start()` or a GitHub thread has none, so the model gets an error that names `to`.
- **Messages travel with their full text.** Not as a pointer, and not encrypted.
- **Misconfigured writes warn.** A bad token or missing scope on a write you didn't await becomes a warning on the trace and never fails the run. An awaited write throws.
- **GitHub has no status line.** A call with no GitHub form warns once.

## How it works

- The agent marks a Slack thread as its own when it first posts there. The bridge reads that mark to accept replies without a mention, and the SDK sets Slack's status line while the agent works.
- On GitHub, `me.post()` and `github_comment` comment on the issue or pull request, and the model reads a comment as `[ana-dev] please review`.
