# Events and triggers

> Start threads from events, schedules and other agents.

- **Start from an event.** The event's data names the thread. [Events →](#start-a-thread-from-an-event)
- **On a schedule.** A cron starts the agent. [Cron →](#run-on-a-schedule)
- **Several triggers.** One agent, many sources. [List →](#combine-triggers)
- **Call another agent.** `agent.invoke()` returns its result. [Invoke →](#call-another-agent)
- **Cancel children with the parent.** One `cancelOn` entry. [Cancel →](#cancel-with-the-caller)
- **Limit sub-agents.** Depth, count, who and how much. [Limits →](#limit-sub-agents)
- **Reach a live run.** Events that never start one. [Inbox →](#inbox-sources)

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

export const ticketOpened = eventType("support/ticket.opened", {
  schema: z.object({
    ticketId: z.string(),
    subject: z.string(),
    priority: z.enum(["low", "high"]),
  }),
});

export const prCommented = eventType("github/pr.commented", {
  schema: z.object({
    repo: z.string(),
    number: z.number(),
    body: z.string(),
  }),
});
```

## Start a thread from an event

The first matching event starts a run. Later ones with the same key reach it as messages.

Send a message to the same key from anywhere and it joins that thread.

```typescript {{ title: "app/send.ts" }}
import { agentMessage } from "inngest/experimental/agents";
import { inngest } from "../inngest/client";

await inngest.send(
  agentMessage.create({
    agent: "support/support",
    thread: "ticket:T-1",
    kind: "user",
    content: "Any news?",
  }),
);
```

## Run on a schedule

A cron tick is one thread per agent, unless the trigger sets `thread`.

```typescript {{ title: "inngest/agents/digest.ts" }}
import { agents } from "../client";

export const digest = agents.agent(
  { id: "digest", on: { cron: "0 9 * * 1-5", jitter: "30s" } },
  async ({ trigger }) => {
    return trigger?.data.cron;
  },
);
```

## Combine triggers

Give `on` a list. Each trigger types its own `message` from its own event.

```typescript {{ title: "inngest/agents/watcher.ts" }}
import { agents } from "../client";
import { prCommented, ticketOpened } from "../events";

export const watcher = agents.agent(
  {
    id: "watcher",
    on: [
      {
        event: ticketOpened,
        thread: '"ticket:" + event.data.ticketId',
        message: (event) => event.data.subject,
      },
      {
        event: prCommented,
        thread: '"pr:" + string(int(event.data.number))',
        message: (event) => event.data.body,
      },
      { cron: "0 * * * *", thread: '"hourly"' },
    ],
  },
  async ({ trigger }) => {
    if (trigger?.name === "support/ticket.opened") {
      return trigger.data.subject;
    }

    if (trigger?.name === "github/pr.commented") {
      return trigger.data.body;
    }

    return "tick";
  },
);
```

## Call another agent

`on: invoke(schema)` types the input. `agent.invoke()` starts the agent on a new thread in the caller's session and returns its result.

```typescript {{ title: "inngest/agents/researcher.ts" }}
import { invoke } from "inngest";
import { z } from "zod";
import { agents } from "../client";

export const researcher = agents.agent(
  {
    id: "researcher",
    on: invoke(z.object({ question: z.string() })),
    limits: { price: { "*": { input: 3, output: 15 } } },
  },
  async ({ trigger, depth }) => {
    return { answer: `Looked into: ${trigger?.data.question}`, depth };
  },
);
```

```typescript {{ title: "inngest/agents/lead.ts" }}
import { agent, AgentLimitError } from "inngest/experimental/agents";
import { agents } from "../client";
import { researcher } from "./researcher";

export const lead = agents.agent(
  {
    id: "lead",
    limits: {
      depth: 1,
      spawn: 3,
      mayCall: ["support/researcher", "support/helper"],
      budget: { usd: 5 },
      price: { "*": { input: 3, output: 15 } },
    },
  },
  async () => {
    try {
      const found = await agent.invoke(
        researcher,
        { question: "What changed in v3?" },
        { thread: "research-1", timeout: "10m" },
      );

      return found.answer;
    } catch (error) {
      if (error instanceof AgentLimitError) {
        return `refused by ${error.limit}`;
      }

      throw error;
    }
  },
);
```

Pass `"appId/functionId"` for an agent without a handle. The result is untyped.

```typescript {{ title: "inngest/agents/untyped.ts" }}
import { agent } from "inngest/experimental/agents";
import { agents } from "../client";

export const untyped = agents.agent({ id: "untyped" }, async () => {
  return agent.invoke<{ input: unknown }>("support/helper", { topic: "v3" });
});
```

An agent body reads how deep it is as `depth`: 1 when a function that is not an agent invoked it, 2 for the next, `0` when anything else started the run. Its `trigger.data` is already the caller's input.

A plain function an agent invokes uses `agentInvokeDepth(event)` and `agentInvokeInput(event)` instead.

```typescript {{ title: "inngest/helper.ts" }}
import { invoke } from "inngest";
import {
  agentInvokeDepth,
  agentInvokeInput,
} from "inngest/experimental/agents";
import { z } from "zod";
import { inngest } from "./client";

export const helper = inngest.createFunction(
  { id: "helper", triggers: [invoke(z.object({ topic: z.string() }))] },
  async ({ event }) => {
    const input = agentInvokeInput(event);

    return { input, depth: agentInvokeDepth(event) };
  },
);
```

## Cancel with the caller

A cancelled callee makes `agent.invoke()` throw `AgentCancelledError`. Cancelling the caller cancels the callee only if the callee lists `agentInvokeCancelOn`.

```typescript {{ title: "inngest/agents/worker.ts" }}
import { invoke } from "inngest";
import { agentInvokeCancelOn } from "inngest/experimental/agents";
import { z } from "zod";
import { agents } from "../client";

export const worker = agents.agent(
  {
    id: "worker",
    on: invoke(z.object({ task: z.string() })),
    cancelOn: [agentInvokeCancelOn],
  },
  async ({ trigger }) => {
    return { done: trigger?.data.task };
  },
);
```

```typescript {{ title: "inngest/agents/boss.ts" }}
import { agent, AgentCancelledError } from "inngest/experimental/agents";
import { agents } from "../client";
import { worker } from "./worker";

export const boss = agents.agent({ id: "boss" }, async () => {
  try {
    return await agent.invoke(worker, { task: "audit" });
  } catch (error) {
    if (error instanceof AgentCancelledError) {
      return { done: null, cancelledRun: error.runId };
    }

    throw error;
  }
});
```

Use the entry only on an agent that `agent.invoke()` starts. `agents.agent()` throws if `on` has any other trigger.

## Limit sub-agents

`limits` apply to `agent.invoke()`. A refused call throws `AgentLimitError`, whose `limit` is `depth`, `spawn`, `mayCall` or `budget`.

Sub-agents inherit the limits, narrowed, and `depth` defaults to 1. A dollar budget needs the sub-agent's own `limits.price`, since a price does not travel. A raw `step.invoke` or `sendEvent` is not checked.

## Inbox sources

An inbox source delivers events to a live run and never starts one.

```typescript {{ title: "inngest/agents/reviewer.ts" }}
import { agents } from "../client";
import { prCommented } from "../events";

export const reviewer = agents.agent(
  {
    id: "reviewer",
    inbox: [
      {
        event: prCommented,
        thread: '"pr:" + string(int(event.data.number))',
      },
    ],
  },
  async ({ inbox }) => {
    const comments = inbox.of(prCommented);
    const latest = await comments.next({ timeout: "1h" });

    return latest?.data.body;
  },
);
```

Add a source mid-run with `inbox.listen()`. Disposing it stops listening.

```typescript {{ title: "inngest/agents/listener.ts" }}
import { agents } from "../client";
import { prCommented } from "../events";

export const listener = agents.agent({ id: "listener" }, async ({ inbox }) => {
  await using _comments = await inbox.listen(prCommented, {
    thread: '"pr:" + string(int(event.data.number))',
  });

  const message = await inbox.next({ timeout: "1h" });

  return message?.name;
});
```

Set `inboxTools` to let the model listen too: [Subscribe](/docs/labs/agents/subscribe?ref=docs-labs-agents-events-and-triggers).

## How it works

- A thread key is a CEL expression over `event`. The backend reads it as written, so a JavaScript function cannot be one.
- It supports literals, `event.data.x` paths, `has()`, `+`, comparisons, `&&`, `||`, `!`, `a ? b : c` and `string()`. Use `string(int(...))` for numeric IDs.
- Equal keys are the same thread, whichever event made them. Prefix keys to keep sources apart.
- A trigger for a thread with a live run starts nothing. The run reads it from its inbox.
- One trigger per event name. `agent/message` is reserved.
