# Agents and triggers

> Define an agent once. It starts from an event, a schedule, a Slack thread or another agent.

An agent is a function that holds conversations. Give it a model and it answers on its own; give it a handler and your code decides.

- **Start from anything.** Events, schedules, Slack and GitHub threads. [Triggers →](#start-a-run)
- **No code for a model agent.** A model, a prompt and tools make a whole agent. [No handler →](#let-the-model-answer)
- **A typed input.** Callers send checked input and get a typed result. [Typed input →](#take-a-typed-input)
- **Decide per run.** Pick the prompt or the model from the event. [Per run →](#decide-per-run)
- **Plain functions too.** A scheduled job with one model call needn't be an agent. [Agent or function →](#agent-or-plain-function)

## Start a run

Start a run from any event, and say which thread it lands on.

<AnnotatedCode>

{/* not type-checked: two event triggers on an agent, the agent-wide thread expression */}
```typescript {{ title: "inngest/agents/deploys.ts" }}
import { eventType } from "inngest";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";

const deploy = z.object({ service: z.string(), log: z.string() });

export const deployFailed = eventType("deploy/failed", { schema: deploy });

export const rollbackFailed = eventType("deploy/rollback.failed", {
  schema: deploy,
});

export const deploys = agents.agent({
  id: "deploys",
  triggers: [deployFailed, rollbackFailed],
  thread: "event.data.service",
  model: claude,
  system: "Explain why a deploy failed, and what to try next.",
});
```

<Annotation id="triggers" lines="16" tease="several at once" title="More than one trigger" href="/docs/labs/agents/handlers?ref=docs-labs-agents-agents-and-triggers" linkText="Handlers">
In a handler, `event.is(deployFailed)` tells them apart.
</Annotation>

<Annotation id="thread" lines="17" tease="which thread" title="Thread" href="/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-agents-and-triggers" linkText="Threads and memory">
Events with the same key share a thread, so a failed rollback joins the failed deploy. Without `thread`, each event opens a new one.
</Annotation>

</AnnotatedCode>

A schedule is a trigger too: `{ cron: "TZ=UTC 0 9 * * 1-5" }`.

`slack.thread()` and `github.thread()` name their own threads, so they need no `thread`. [Slack and GitHub →](/docs/labs/agents/slack-and-github?ref=docs-labs-agents-agents-and-triggers)

An agent can also have no triggers at all. Code and other agents start it with `start()`. [Teams of agents →](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-agents-and-triggers)

## Let the model answer

An agent with a `model` and no handler answers on its own. For each batch of messages it:

1. runs the model with its tools until the model stops calling them, folding in messages that arrive meanwhile;
2. posts the answer where the thread lives, such as the Slack thread it came from;
3. saves the model's history on the thread, so the next run picks it up.

Then it waits for more messages and ends after ten quiet minutes. A run opened with `start()` ends after its first answer. [Threads and memory →](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-agents-and-triggers#how-long-a-run-waits)

## Take a typed input

An `invoke()` trigger declares what callers send. Code that starts the agent gets a typed input and a typed result.

<AnnotatedCode>

{/* not type-checked: invoke() trigger on an agent, start().result() from a plain function */}
```typescript {{ title: "inngest/agents/reviewer.ts" }}
import { invoke } from "inngest";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";

export const reviewer = agents.agent({
  id: "reviewer",
  triggers: [invoke(z.object({ pr: z.string() }))],
  model: claude,
  system: "Review the pull request at the URL you are given.",
});
```

<Annotation id="invoke" lines="8" tease="the input schema" title="invoke()" href="/docs/labs/agents/discovery?ref=docs-labs-agents-agents-and-triggers" linkText="Discovery">
Checks what callers send, and goes on the agent's card.
</Annotation>

</AnnotatedCode>

{/* not type-checked: start().result() from a plain function */}
```typescript {{ title: "inngest/functions/nightlyReview.ts" }}
import { inngest } from "../client";
import { reviewer } from "../agents/reviewer";

export const nightlyReview = inngest.createFunction(
  { id: "nightly-review", triggers: [{ cron: "TZ=UTC 0 2 * * *" }] },
  async () => {
    const pr = "https://github.com/acme/api/pull/42";

    return await reviewer.start({ pr }).result();
  },
);
```

`result()` waits for the answer. Without an `invoke()` trigger, `start()` takes text or JSON. [Teams of agents →](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-agents-and-triggers)

## Decide per run

Pick the prompt, the model or the budget from the event. `model`, `system`, `tools`, `sandboxes`, `skills`, `budget`, `limits`, `idle` and `remember` take a value or an async function of the event and thread, run once per run.

{/* not type-checked: system as an async function of { event } */}
```typescript {{ title: "inngest/agents/accounts.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";
import { lookupAccount } from "../lib/accounts";

export const accounts = agents.agent({
  id: "accounts",
  triggers: [slack.thread()],
  model: claude,
  system: async ({ event }) => {
    const account = await lookupAccount(event.data.user);

    return `You help ${account.name} with their ${account.plan} plan.`;
  },
});
```

```typescript {{ title: "inngest/lib/accounts.ts" }}
export const lookupAccount = async (user: string) => {
  return { name: `Customer ${user}`, plan: "team" };
};
```

The function runs again on replay, so keep it free of side effects. `id`, `triggers`, `thread`, `inbox`, `card`, `discovery` and `listen` take values only, because Inngest needs them before a run starts.

## Write a handler

To decide what the model sees and what gets posted, pass a handler as the second argument.

{/* not type-checked: a handler with inbox.batches(), loop(batch) and me.post() */}
```typescript {{ title: "inngest/agents/triage.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const triage = agents.agent(
  {
    id: "triage",
    triggers: [slack.thread()],
    model: claude,
    system: "You triage support threads.",
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches()) {
      const { text } = await loop(batch);

      await me.post(text);
    }
  },
);
```

[Handlers →](/docs/labs/agents/handlers?ref=docs-labs-agents-agents-and-triggers)

## Agent or plain function

Work that needs no thread, inbox or card is a plain function: cheaper, and never discoverable.

{/* not type-checked: the anthropic() one-shot call */}
```typescript {{ title: "inngest/functions/digest.ts" }}
import { inngest } from "../client";
import { claude } from "../models/claude";

export const digest = inngest.createFunction(
  { id: "digest", triggers: [{ cron: "TZ=UTC 0 9 * * 1-5" }] },
  async ({ step }) => {
    const pulls = await step.run("find-stale", async () => {
      return [{ number: 42, title: "Retry webhooks", days: 5 }];
    });

    return await step.run("summarise", async () => {
      const { text } = await claude({
        system: "Write one line per pull request, oldest first.",
        prompt: JSON.stringify(pulls),
      });

      return text;
    });
  },
);
```

A plain function can still start agents with `start()`. [Scheduled watcher →](/docs/labs/agents/recipes/scheduled-watcher?ref=docs-labs-agents-agents-and-triggers)

## Gotchas

- **Import agents before serving.** `agents.functions()` lists only imported agents. [Project structure →](/docs/labs/agents/structure?ref=docs-labs-agents-agents-and-triggers)
- **A thread with no home posts nothing.** One opened by a schedule, `start()` or a plain event with no GitHub URL keeps the answer in the run's output, and the trace warns.
- **Function options still apply.** `retries`, `concurrency`, `throttle` and the rest pass through.

## How it works

- Each model call and tool call is a step, so a retry or a deploy never repeats finished work.
- At most one run is live per thread. A message for a quiet thread starts one.
- Every agent publishes a card when your app syncs. With no `card` it is private to its own app.
