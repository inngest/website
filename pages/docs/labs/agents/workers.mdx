# Run on Workers

> Bindings exist only while a request runs, so an agent reads them when a run needs them.

A Worker has no secrets or database at import time. Fields that take a function are called when a run starts, and that is when a binding exists.

- **Keep state in D1.** The store reads its binding on each use. [Store →](#store-state-in-d1)
- **Read secrets at run time.** The model, tokens and repo access are functions. [Run-time fields →](#read-bindings-at-run-time)
- **Serve from `fetch`.** One export for Inngest and the Slack route. [Serve →](#serve-from-fetch)

  },

});

## Declare the bindings

`env.ts` holds the bindings of the latest request. A Worker's bindings don't change within a deployment, so the latest are the right ones.

{/* not type-checked: D1Database from @cloudflare/workers-types */}
```typescript {{ title: "inngest/env.ts" }}
import type { D1Database } from "@cloudflare/workers-types";

export type Env = {
  DB: D1Database;
  ANTHROPIC_API_KEY: string;
  SLACK_BOT_TOKEN: string;
  SLACK_SIGNING_SECRET: string;
  GITHUB_TOKEN: string;
};

let current: Env | undefined;

export const useEnv = (env: unknown) => {
  current = env as Env;
};

export const getEnv = () => {
  if (!current) {
    throw new Error("No request has reached the Worker yet.");
  }

  return current;
};
```

## Store state in D1

The store keeps each thread's history, spend and sandbox. `d1KvAdapter` takes a function, which it calls on every operation, so it never holds a binding past a request. Add `sandboxMiddleware()` when an agent lists sandboxes.

{/* not type-checked: d1KvAdapter with a function, sandboxMiddleware() */}
```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { sandboxMiddleware } from "inngest/experimental";
import { createAgents, d1KvAdapter } from "inngest/experimental/agents";
import { getEnv } from "./env";

export const inngest = new Inngest({
  id: "support",
  middleware: [sandboxMiddleware()],
});

export const agents = createAgents(inngest, {
  store: d1KvAdapter(() => {
    return getEnv().DB;
  }),
});
```

The store needs two tables. `d1KvSchema` holds the statements, so write them into a wrangler migration. `agents-db` is the name of your D1 database.

{/* not type-checked: d1KvSchema as a list of SQL statements */}
```typescript {{ title: "inngest/printSchema.ts" }}
import { d1KvSchema } from "inngest/experimental/agents";

console.log(`${d1KvSchema.join(";\n\n")};`);
```

```bash
npx wrangler d1 migrations create agents-db agents
npx tsx inngest/printSchema.ts > migrations/0001_agents.sql
npx wrangler d1 migrations apply agents-db
```

## Read bindings at run time

`model`, `system`, `tools`, `sandboxes`, `skills`, `budget`, `price`, `limits`, `idle` and `remember` take a function of the event and thread, which may be async and runs once when a run starts. A sandbox's `repo` does too, and its `auth` can be a function of its own.

{/* not type-checked: repo.auth as a function reading a Worker binding */}
```typescript {{ title: "inngest/sandboxes/work.ts" }}
import { sandbox } from "inngest/experimental/agents";
import { getEnv } from "../env";

export const work = sandbox({
  id: "work",
  repo: {
    url: "https://github.com/acme/web",
    auth: () => {
      return getEnv().GITHUB_TOKEN;
    },
  },
});
```

## Serve from fetch

`useEnv(env)` runs first on every request, so every function that follows can read the bindings. The Slack bridge reads its signing secret when it is built, so build it inside `fetch`, where the binding exists.

{/* TODO(spec): how does a Worker pass `secret()` values and the SLACK_SIGNING_SECRET, and which option carries the Slack bot token for the SDK's own writes (status line, me.post, final answer)? Used slack.tools({ token }) and a bridge built per request. */}
{/* not type-checked: serve() from inngest/cloudflare with slack.bridge() built per request */}
```typescript {{ title: "inngest/serve.ts" }}
import { serve } from "inngest/cloudflare";
import { slack } from "inngest/experimental/agents";
import { agents, inngest } from "./client";
import { getEnv, useEnv } from "./env";
import "./agents/triage";

const handler = serve({
  client: inngest,
  functions: agents.functions(),
  servePath: "/api/inngest",
});

export default {
  fetch: (request: Request, env: Record<string, string | undefined>) => {
    useEnv(env);

    if (new URL(request.url).pathname === "/api/slack") {
      return slack.bridge({
        client: inngest,
        signingSecret: getEnv().SLACK_SIGNING_SECRET,
      })(request);
    }

    return handler(request, env);
  },
};
```

Set up the Worker itself as in [Serving Inngest functions](/docs/learn/serving-inngest-functions?ref=docs-labs-agents-workers#framework-cloudflare-workers), including the `nodejs_compat` flag.

## Gotchas

- **Import time has no bindings.** Read them inside a function. A value computed at the top of a file runs before the first request.
- **Sync-time fields stay values.** `id`, `triggers`, `thread`, `inbox`, `card`, `discovery` and `listen` are read when your app syncs, so keep bindings out of them.
- **Run-time functions must be pure.** They run again when the run replays.
- **Other entry points call `useEnv`.** Code outside `fetch` that sends messages, such as a scheduled handler, calls `useEnv(env)` first so the store has its binding.

## How it works

- A run-time field's function is called once when a run starts, and a token function at each use.
- The store's function is called on every operation, so nothing keeps a binding past its request.
- Everything else about agents is the same as on any host. [Project structure →](/docs/labs/agents/structure?ref=docs-labs-agents-workers)
