# Run on Workers

> Run your agents on Cloudflare Workers, with state in D1 and secrets read as each run starts.

A Worker has no secrets or database at import time, so fields that take a function read them when a run starts.

- **Keep state in D1.** The store reads its binding on each use. [Store →](#store-state-in-d1)
- **Read secrets at run time.** The model, tokens and repo access are functions. [Bindings →](#read-bindings-at-run-time)
- **Serve from `fetch`.** One export for Inngest and the Slack route. [Serve →](#serve-from-fetch)

## Declare the bindings

`env.ts` keeps the bindings of the latest request, which are the same for the whole deployment.

{/* not type-checked: D1Database from @cloudflare/workers-types */}
```typescript {{ title: "inngest/env.ts" }}
import type { D1Database } from "@cloudflare/workers-types";

export type Env = {
  DB: D1Database;
  ANTHROPIC_API_KEY: string;
  SLACK_BOT_TOKEN: string;
  SLACK_SIGNING_SECRET: string;
  GITHUB_READ_TOKEN: string;
};

let current: Env | undefined;

export const setEnv = (env: unknown) => {
  current = env as Env;
};

export const getEnv = () => {
  if (!current) {
    throw new Error("No request has reached the Worker yet.");
  }

  return current;
};
```

## Store state in D1

`d1KvAdapter` takes a function and calls it on every operation, so the store never holds a binding past a request. Add `sandboxMiddleware()` when an agent lists sandboxes.

{/* not type-checked: d1KvAdapter with a function, sandboxMiddleware() */}
```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { sandboxMiddleware } from "inngest/experimental";
import { createAgents, d1KvAdapter } from "inngest/experimental/agents";
import { getEnv } from "./env";

export const inngest = new Inngest({
  id: "support",
  middleware: [sandboxMiddleware()],
});

export const agents = createAgents(inngest, {
  store: d1KvAdapter(() => {
    return getEnv().DB;
  }),
});
```

`d1KvSchema` holds the statements for the store's two tables. Write them into a migration; `agents-db` is your D1 database's name.

{/* not type-checked: d1KvSchema as a list of SQL statements */}
```typescript {{ title: "inngest/printSchema.ts" }}
import { d1KvSchema } from "inngest/experimental/agents";

console.log(`${d1KvSchema.join(";\n\n")};`);
```

```bash
npx wrangler d1 migrations create agents-db agents
npx tsx inngest/printSchema.ts > migrations/0001_agents.sql
npx wrangler d1 migrations apply agents-db
```

## Read bindings at run time

Fields that take a function (`model`, `tools`, `sandboxes` and the rest) get the event and thread. So does a sandbox's `repo`, whose `auth` can be a function of its own. [The definition →](/docs/labs/agents/reference?ref=docs-labs-agents-workers#the-definition)

{/* not type-checked: repo.auth as a function reading a Worker binding */}
```typescript {{ title: "inngest/sandboxes/work.ts" }}
import { sandbox } from "inngest/experimental/agents";
import { getEnv } from "../env";

export const work = sandbox({
  id: "work",
  repo: {
    url: "https://github.com/acme/web",
    auth: () => {
      return getEnv().GITHUB_READ_TOKEN;
    },
    push: false,
  },
});
```

## Serve from fetch

`setEnv(env)` runs first on every request, so everything after it can read the bindings. Workers require a default export for the entry point.

{/* not type-checked: serve() from inngest/cloudflare with slack.bridge() and a secret function */}
```typescript {{ title: "inngest/serve.ts" }}
import { serve } from "inngest/cloudflare";
import { secret } from "inngest/experimental";
import { slack } from "inngest/experimental/agents";
import { agents, inngest } from "./client";
import { getEnv, setEnv } from "./env";
import "./agents/triage";

const handler = serve({
  client: inngest,
  functions: agents.functions(),
  servePath: "/api/inngest",
});

const slackBridge = slack.bridge({
  client: inngest,
  signingSecret: secret(() => {
    return getEnv().SLACK_SIGNING_SECRET;
  }),
});

export default {
  fetch: (request: Request, env: Record<string, string | undefined>) => {
    setEnv(env);

    if (new URL(request.url).pathname === "/api/slack") {
      return slackBridge(request);
    }

    return handler(request, env);
  },
};
```

Set up the Worker as in [Serving Inngest functions](/docs/learn/serving-inngest-functions?ref=docs-labs-agents-workers#framework-cloudflare-workers), including the `nodejs_compat` flag.

## Gotchas

- **Import time has no bindings.** Read them inside a function.
- **Some fields stay values.** Inngest reads them when the app syncs or an event is routed, so keep bindings out of them. [The definition →](/docs/labs/agents/reference?ref=docs-labs-agents-workers#the-definition)
- **Field functions have no side effects.** They run again on replay, and may read `kv`.
- **Other entry points call `setEnv`.** A scheduled handler that sends messages calls `setEnv(env)` first.

## How it works

- A field's function runs once when a run starts, a token function at each use and the store's on every operation.
- Everything else is the same as on any host. [Project structure →](/docs/labs/agents/structure?ref=docs-labs-agents-workers)
