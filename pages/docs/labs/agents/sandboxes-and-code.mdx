# Sandboxes and code

> Give an agent a machine of its own that is still there on its next message.

A sandbox is the machine for one [thread](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-sandboxes-and-code). List it on an agent and the model gets a shell on it.

- **A shell for the model.** Listing a sandbox gives the model `work_run`. [Give the agent a sandbox →](#give-the-agent-a-sandbox)
- **Files that stay.** One machine per thread, paused when unused. [Keep files between runs →](#keep-files-between-runs)
- **Your code on the same machine.** Run commands from a handler. [Use it from a handler →](#use-it-from-a-handler)
- **Scripts that call your tools.** Each call is a durable step in your app. [Let code call your tools →](#let-code-call-your-tools)
- **Credentials stay with you.** A shim runs a program with a token only your app holds. [Hand a program a credential →](#hand-a-program-a-credential)
- **Pushes checked by your policy.** Your app pushes, so the sandbox never holds a write token. [Check out and push →](#check-out-a-repo)

```typescript {{ title: "inngest/agents/coder.ts" }}
  triggers: [slack.thread()],

  sandboxes: { work },
```


## Give the agent a sandbox

A `sandbox()` creates nothing until it's used. An app whose agents list sandboxes adds `sandboxMiddleware()` to its client, or the first use throws an error that says so.

{/* not type-checked: sandboxMiddleware() on the client */}
```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { sandboxMiddleware } from "inngest/experimental";
import { createAgents } from "inngest/experimental/agents";

export const inngest = new Inngest({
  id: "coder",
  middleware: [sandboxMiddleware()],
});

export const agents = createAgents(inngest);
```

`sandbox()` also takes an `image`, a size and a `setup` step. [Reference: sandbox() →](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-sandboxes-and-code#sandbox)

## Keep files between runs

The thread owns its sandbox.

```text {{ title: "One thread, two runs" }}
09:00  work_run  npm install   the sandbox starts
09:04  the run ends
09:14  ten minutes unused      the sandbox pauses
11:30  work_run  npm test      the sandbox resumes, node_modules is there
```

## Work in a shell

The model works in a shell, not file by file: `work_run` keeps `cd` and `export` from one call to the next, and into the thread's next run. A heredoc in `work_run` writes a file.

`read`, `search` and `edit` are off until you ask for them.

{/* not type-checked: sandbox.tools.code with only and timeout */}
<AnnotatedCode>

```typescript {{ title: "inngest/sandboxes/editor.ts" }}
import { sandbox } from "inngest/experimental/agents";

export const editor = sandbox({
  id: "editor",
  tools: sandbox.tools.code({
    only: ["run", "read", "search", "edit"],
    timeout: "10m",
  }),
});
```

<Annotation id="only" lines="6" tease="editor_run, editor_edit" title="Only" href="/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-sandboxes-and-code#code-tools" linkText="Reference: code tools">
The tools the model gets. Without `only` it gets `run`, plus `run_code` once you give tools.
</Annotation>

<Annotation id="timeout" lines="7" tease="longest one command may run" title="Timeout" href="#run-long-commands" linkText="Run long commands">
The default is five minutes.
</Annotation>

</AnnotatedCode>

## Use it from a handler

A [handler](/docs/labs/agents/handlers?ref=docs-labs-agents-sandboxes-and-code) gets the same machine the model uses, opened on first use.

{/* not type-checked: sandboxes.work.commands.run in a handler, { sandbox, model: false } */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/tester.ts" }}
import { github } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";
import { work } from "../sandboxes/work";

export const tester = agents.agent(
  {
    id: "tester",
    triggers: [github.thread()],
    model: claude,
    system: "Explain the test results you are given.",
    sandboxes: { work: { sandbox: work, model: false } },
  },
  async ({ inbox, me, loop, sandboxes }) => {
    const tests = await sandboxes.work.commands.run("tests", "npm test", {
      cwd: "/work",
    });

    await me.message({ tests: tests.stdout.slice(-2000) });

    for await (const batch of inbox.batches()) {
      const { text } = await loop(batch);

      await me.post(text);
    }
  },
);
```

<Annotation id="code-only" lines="12" tease="the model gets none of its tools" title="Code only">
`model: false` keeps this sandbox for your code. Without it, the model would get `work_run` too.
</Annotation>

<Annotation id="commands" lines="15-17" tease="a command on the thread's machine" title="Run a command" href="/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-sandboxes-and-code#the-handler-s-sandbox" linkText="Reference">
Each call is a durable step, so a replay never runs the tests twice.
</Annotation>

<Annotation id="message" lines="19" tease="the model reads it next" title="Hand it over" href="/docs/labs/agents/handlers?ref=docs-labs-agents-sandboxes-and-code#message-yourself" linkText="Handlers">
The result lands in the agent's own inbox, and the loop shows it to the model.
</Annotation>

</AnnotatedCode>

`sandboxes.work` also has `files`, `recycle()`, `close()` and `repo.push()`. [Reference: the handler's sandbox →](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-sandboxes-and-code#the-handler-s-sandbox)

## Let code call your tools

A script on the machine can call your [tools](/docs/labs/agents/tools?ref=docs-labs-agents-sandboxes-and-code). They run in your app as durable steps, so the credentials they use stay out of the sandbox.

{/* not type-checked: sandbox.tools.code({ tools }), which gives the model analyst_run_code */}
<AnnotatedCode>

```typescript {{ title: "inngest/sandboxes/analyst.ts" }}
import { sandbox } from "inngest/experimental/agents";
import { getAccount } from "../tools/getAccount";

export const analyst = sandbox({
  id: "analyst",
  tools: sandbox.tools.code({
    tools: { getAccount },
  }),
});
```

<Annotation id="tools" lines="7" tease="adds analyst_run_code" title="Tools for scripts" href="/docs/labs/agents/tools?ref=docs-labs-agents-sandboxes-and-code" linkText="Tools">
Giving the code tools some tools adds `run_code`. The script calls each by its key in the record, as `tools.getAccount(...)`.
</Annotation>

</AnnotatedCode>

List `analyst` on an agent, and the model writes scripts that `analyst_run_code` runs:

```python {{ title: "A script the model runs" }}
account = await tools.getAccount(id="a-42")

print(account["plan"])
```

```typescript {{ title: "inngest/tools/getAccount.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";

export const getAccount = tool.step({
  description: "Find an account by ID",
  input: z.object({ id: z.string() }),
  run: async ({ id }) => {
    return { id, plan: "pro" };
  },
});
```

A tool declared with `waits: true` makes a script exit while it waits and run again from the top. Keep what it does outside tool calls safe to repeat. [Wait for a reply →](/docs/labs/agents/tools?ref=docs-labs-agents-sandboxes-and-code#wait-for-a-reply)

Your own code passes tools to a command with `tools`, as on [Tools](/docs/labs/agents/tools?ref=docs-labs-agents-sandboxes-and-code#use-it-from-both-sides), and the script imports them with `from inngest_tools import tools`. [Tools and code mode →](/docs/sandboxes/features/tools?ref=docs-labs-agents-sandboxes-and-code)

A tool passed with `loop(batch, { tools })` makes `run_code` appear for that call. [Give the model a tool →](/docs/labs/agents/handlers?ref=docs-labs-agents-sandboxes-and-code#give-the-model-a-tool)

## Hand a program a credential

A shim is a program on the shell's `PATH` that calls your app first. The model types `flyctl deploy` and never handles the token.

{/* not type-checked: tool.shim with only and a handle that adds a token */}
<AnnotatedCode>

```typescript {{ title: "inngest/tools/flyctl.ts" }}
import { tool } from "inngest/experimental";

export const flyctl = tool.shim("flyctl", {
  only: ["deploy"],
  handle: async ({ run }) => {
    const token = process.env.FLY_DEPLOY_TOKEN ?? "";

    return run({ env: { FLY_API_TOKEN: token } });
  },
});
```

<Annotation id="only" lines="4" tease="only deploy calls your app" title="Only">
Any other `flyctl` call runs the real program at once, with no trip to your app.
</Annotation>

<Annotation id="run" lines="8" tease="the real program, plus a token" title="Run it">
The token joins the environment of that one process and isn't saved in the run.
</Annotation>

</AnnotatedCode>

{/* not type-checked: a shim passed to sandbox.tools.code({ shims }) */}
<AnnotatedCode>

```typescript {{ title: "inngest/sandboxes/deployer.ts" }}
import { sandbox } from "inngest/experimental/agents";
import { flyctl } from "../tools/flyctl";

export const deployer = sandbox({
  id: "deployer",
  tools: sandbox.tools.code({
    shims: [flyctl],
  }),
});
```

<Annotation id="shims" lines="7" tease="on PATH for run and run_code" title="Shims">
The model's `run` and `run_code` find `flyctl` on `PATH`. It isn't a tool in the model's list.
</Annotation>

</AnnotatedCode>

A shim can also decline with `refuse()` or answer on its own with `reply()`. [Reference: shims →](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-sandboxes-and-code#shims)

## Run long commands

A `timeout` over five minutes works, even for a command that calls tools or uses shims. Your code passes it per command, here with the `flyctl` shim.

```typescript
await sandboxes.work.commands.run("deploy", "flyctl deploy", {
  shims: [flyctl],
  timeout: "15m",
});
```

## Check out a repo

`repo` on a sandbox checks a repository out when the sandbox starts. The read-only token goes to the one `git` process that clones and is never written into the checkout's config.

{/* not type-checked: githubApp() with a secret() private key */}
```typescript {{ title: "inngest/github.ts" }}
import { secret } from "inngest/experimental";
import { githubApp } from "inngest/experimental/agents";

export const githubAuth = githubApp({
  appId: process.env.GITHUB_APP_ID ?? "",
  privateKey: secret("GITHUB_APP_PRIVATE_KEY"),
});
```

{/* not type-checked: sandbox({ repo }) with auth, ref, path and author */}
<AnnotatedCode>

```typescript {{ title: "inngest/sandboxes/service.ts" }}
import { sandbox } from "inngest/experimental/agents";
import { githubAuth } from "../github";

export const service = sandbox({
  id: "service",
  repo: {
    url: "https://github.com/acme/api",
    auth: githubAuth,
    ref: "main",
    path: "/work/api",
    author: { name: "Acme Agent", email: "agent@acme.dev" },
  },
});
```

<Annotation id="auth" lines="8" tease="read at checkout, write at push" title="Auth">
`githubApp()` makes a read token to check out and a write token to push, each short-lived, on your host. A `secret()`, a function of `{ access }` or `{ read, write }` works too.
</Annotation>

<Annotation id="ref" lines="9" tease="the branch, tag or commit" title="Ref">
Each run starts on this ref. If the checkout is on another, the sandbox fetches and checks out this one, and changes to tracked files make that an error the run sees.
</Annotation>

<Annotation id="path" lines="10" tease="where it lands" title="Path">
The folder for the checkout, `/work` by default. The model's shell starts there.
</Annotation>

<Annotation id="author" lines="11" tease="who commits" title="Author">
The name and email on commits made in the sandbox. The default author is `inngest-agent`.
</Annotation>

</AnnotatedCode>

The checkout runs inside the sandbox, so a single `secret()` should be a read-only token. An agent that pushes uses `githubApp()` or `{ read, write }`, and the write token never enters the sandbox.

`repo` can also be a function of `{ event, thread }`, run once when the run starts, so a reviewer checks out the pull request it was triggered by.

{/* not type-checked: repo as a function of { event } */}
```typescript {{ title: "inngest/sandboxes/review.ts" }}
import { sandbox } from "inngest/experimental/agents";
import { githubAuth } from "../github";

export const review = sandbox({
  id: "review",
  repo: ({ event }) => {
    return {
      url: event.data.repo,
      ref: event.data.head,
      auth: githubAuth,
    };
  },
});
```

## Push a branch

The model commits in the sandbox and calls `work_push({ branch })`. Your app makes the push, after `policy` has seen it.

{/* not type-checked: repo.policy reading the push and returning refuse or notes */}
<AnnotatedCode>

```typescript {{ title: "inngest/sandboxes/guarded.ts" }}
import { sandbox } from "inngest/experimental/agents";
import { githubAuth } from "../github";

export const guarded = sandbox({
  id: "guarded",
  repo: {
    url: "https://github.com/acme/api",
    auth: githubAuth,
    policy: async (push) => {
      if (!push.branch?.startsWith("agent/")) {
        return { refuse: "Branches for the agent start with agent/" };
      }

      const touched = push.paths.filter((path) => {
        return path.startsWith(".github/");
      });

      if (touched.length > 0) {
        return { refuse: `Not allowed to change ${touched.join(", ")}` };
      }

      return { notes: [`${push.commits.length} commits to ${push.branch}`] };
    },
  },
});
```

<Annotation id="policy" lines="9" tease="runs on your host" title="Policy">
Sees `push.branch`, `push.commits` with their messages and `push.paths` before anything is pushed. It returns `{ refuse }`, `{ notes }` or nothing.
</Annotation>

<Annotation id="refuse" lines="11" tease="the model reads the reason" title="Refuse">
A refused push comes back to the model as an error it can read and fix.
</Annotation>

<Annotation id="paths" lines="14-16" tease="by path" title="Paths">
Every path the commits touch.
</Annotation>

<Annotation id="notes" lines="22" tease="kept with the result" title="Notes">
Returned in the push result, for an audit trail.
</Annotation>

</AnnotatedCode>

Your code pushes through the same policy, and a refusal throws `PushRefusedError`, which isn't retried.

{/* not type-checked: sandboxes.guarded.repo.push and PushRefusedError */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/nightly.ts" }}
import { PushRefusedError } from "inngest/experimental/agents";
import { agents } from "../client";
import { guarded } from "../sandboxes/guarded";

export const nightly = agents.agent(
  {
    id: "nightly",
    triggers: [{ cron: "TZ=UTC 0 3 * * *" }],
    sandboxes: { guarded },
  },
  async ({ sandboxes }) => {
    const guard = sandboxes.guarded;

    await guard.commands.run(
      "fix",
      "npm audit fix && git commit -am audit",
      { cwd: "/work" },
    );

    try {
      return await guard.repo.push("agent/audit-fix");
    } catch (error) {
      if (error instanceof PushRefusedError) {
        return { refused: error.reason };
      }

      throw error;
    }
  },
);
```

<Annotation id="push" lines="21" tease="the same push as work_push" title="Push from code">
Returns `{ branch, sha, notes }`.
</Annotation>

<Annotation id="refused" lines="23-24" tease="reason is a string" title="Refused">
`PushRefusedError` carries the policy's `reason`.
</Annotation>

</AnnotatedCode>

Set `push: false` on the repo to leave `work_push` out.

## Secrets

`sandbox({ secrets })` puts values into the sandbox, where any code running there can read them; [`secret()`](/docs/labs/agents/tools?ref=docs-labs-agents-sandboxes-and-code#keep-secrets-on-the-host) keeps a value on your host.

{/* not type-checked: sandbox({ environment, secrets }) */}
<AnnotatedCode>

```typescript {{ title: "inngest/sandboxes/builder.ts" }}
import { sandbox } from "inngest/experimental/agents";

export const builder = sandbox({
  id: "builder",
  environment: { NODE_ENV: "test" },
  secrets: ["NPM_TOKEN"],
});
```

<Annotation id="environment" lines="5" tease="plain values" title="Environment">
Set in the sandbox when it is created.
</Annotation>

<Annotation id="secrets" lines="6" tease="names of workspace secrets" title="Secrets" href="/docs/sandboxes/features/secrets?ref=docs-labs-agents-sandboxes-and-code" linkText="Secrets">

</Annotation>

</AnnotatedCode>

## Gotchas

- **The shell has limits.** The environment is capped at 256 entries or 64 KiB, and a command with its own `EXIT` trap or `exec` drops its `cd` and `export`.
- **Exports stay in run history.** Put credentials in `secrets` or behind a tool, never in an `export`.
- **A shim is a program on `PATH`.** Code that runs the real program by its full path skips the shim.
- **One repo per sandbox.** A push names the branch and opens no pull request; your app does that with its GitHub tools.

## How it works

- The sandbox starts in one durable step, so every call shares it, and a run that waits longer than ten minutes pauses it.
- Each `run` is its own shell process, and the SDK saves where it ended, so a replay on any machine starts the next one in the same place.
- A push bundles the new commits in the sandbox, lets `policy` see them on your host, then pushes with the write token, never forcing or deleting.
- A command over five minutes runs as a process that steps follow in windows of five minutes, one wait step each.
