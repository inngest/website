# Models and the loop

> Run a model with tools until it answers, and fold in the messages that arrive while it works.

The loop calls the model, runs the tools it asks for, and repeats until it has an answer. A model agent with no handler runs it for you; a handler runs it when it chooses.

- **One model, three uses.** The agent's model, a one-shot call with a typed `output`, and `.with()` variants. [Pick a model →](#pick-a-model)
- **Turns until done.** Every model and tool call is a durable step. [Run the loop →](#run-the-loop)
- **Messages reach the model.** Whatever arrives is folded in before the next call. [Fold in messages →](#fold-in-messages)
- **Progress as it works.** `onTurn` reports each turn and never slows the next. [Watch progress →](#watch-progress)
- **Long threads fit.** The history is saved, summarised and reused. [Remember and summarise →](#remember-and-summarise)
- **Cost and errors handled.** The model prices its own calls, and rate limits wait. [Cost and errors →](#cost-and-errors)

<AnnotatedCode>

{/* not type-checked: a handler with loop(batch), result.end and result.reason */}
```typescript {{ title: "inngest/agents/reviewer.ts" }}
import { github } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";
import { readSource } from "../tools/readSource";

export const reviewer = agents.agent(
  {
    id: "reviewer",
    triggers: [github.thread()],
    model: claude,
    system: "You review pull requests.",
    tools: { readSource },
  },
  async ({ inbox, loop, me }) => {
    for await (const batch of inbox.batches()) {
      const result = await loop(batch);

      if (result.end === "budget") {
        await me.post(result.reason ?? "Out of budget for this thread.");

        return;
      }

      await me.post(result.text);
    }
  },
);
```

## Pick a model

A model is what the loop calls each turn: the history in, the reply out. `anthropic()` reads `ANTHROPIC_API_KEY`.

<AnnotatedCode>

{/* not type-checked: anthropic() as a named export and .with() variants */}
```typescript {{ title: "inngest/models/claude.ts" }}
import { anthropic } from "inngest/experimental/agents";

export const claude = anthropic({ model: "claude-sonnet-5-5" });

export const claudeQuick = claude.with({ effort: "low", maxTokens: 500 });
```

<Annotation id="with" lines="5" tease="same model, other options" title=".with()" href="/docs/labs/agents/reference?ref=docs-labs-agents-models-and-the-loop#models" linkText="Reference">
Changes effort, thinking or the token cap for one agent or one call. The client stays.
</Annotation>

</AnnotatedCode>

Any function of the `AgentModel` shape is a model too. This one wraps another and times it:

<AnnotatedCode>

{/* not type-checked: a model function typed AgentModel */}
```typescript {{ title: "inngest/models/timed.ts" }}
import type { AgentModel } from "inngest/experimental/agents";
import { claude } from "./claude";

export const timed: AgentModel = async (request) => {
  const started = Date.now();
  const reply = await claude(request);

  console.log(`model took ${Date.now() - started}ms`);

  return reply;
};
```

## Call it once

The model also answers on its own. Pass `system`, `prompt` or `messages`, and a schema as `output` for a typed reply.

<AnnotatedCode>

{/* not type-checked: the anthropic() one-shot call with output */}
```typescript {{ title: "inngest/functions/label.ts" }}
import { z } from "zod";
import { inngest } from "../client";
import { claude } from "../models/claude";

export const label = inngest.createFunction(
  { id: "label", triggers: [{ event: "support/ticket.created" }] },
  async ({ event, step }) => {
    return await step.run("label", async () => {
      const { output } = await claude({
        system: "Label the ticket.",
        prompt: event.data.body,
        output: z.object({ label: z.enum(["bug", "billing", "question"]) }),
      });

      return output.label;
    });
  },
);
```

<Annotation id="step" lines="8" tease="not a step by itself" title="Wrap it in a step" href="/docs/labs/agents/handlers?ref=docs-labs-agents-models-and-the-loop#return-a-result" linkText="Handlers">
A one-shot call isn't a step on its own, so a retry would repeat it. Put it in `step.run`.
</Annotation>

<Annotation id="output" lines="12" tease="a schema in, a typed value out" title="output">
`output` comes back typed by the schema. Without one, the reply is `{ text }`.
</Annotation>

</AnnotatedCode>

## Run the loop

`loop(batch)` runs turns. A turn is one model call plus the tool calls it asked for. The result's `end` says why the loop stopped:

- **`"done"`.** The model stopped calling tools.
- **`"maxTurns"`.** It used all its turns.
- **`"stop"`.** The loop's `stop` option returned `true`. [Choose per call →](#choose-per-call)
- **`"budget"`.** The thread's budget is spent, and `reason` says which.

The result also has `turns`, `history`, `usage` and `toolCalls`. `loop` is in a handler's argument only when the agent has a `model`.

## Fold in messages

Before every model call, the first included, the loop takes everything new from the handler's inbox and shows it to the model, so a correction reaches the very next call.

Folded messages don't come back through your `for await`. One that arrives during the final model call stays in the inbox for your next read.

`steer` picks what to fold: it gets the messages the loop took and returns the ones to fold. The rest come back as `result.unread`.

<AnnotatedCode>

{/* not type-checked: loop(batch, { steer }) and result.unread, with agentQuestion and message.is() */}
```typescript {{ title: "inngest/agents/builder.ts" }}
import { agentQuestion, github } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const builder = agents.agent(
  {
    id: "builder",
    triggers: [github.thread()],
    model: claude,
    system: "You implement what the pull request asks for.",
  },
  async ({ inbox, loop, me }) => {
    for await (const batch of inbox.batches()) {
      const built = await loop(batch, {
        steer: (drained) => {
          return drained.filter((message) => {
            return !message.is(agentQuestion);
          });
        },
      });

      await me.post(built.text);

      if (built.unread.length > 0) {
        const answers = await loop(built.unread);

        await me.post(answers.text);
      }
    }
  },
);
```

<Annotation id="steer" lines="15-19" tease="choose what to fold" title="steer" href="/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-models-and-the-loop" linkText="Teams of agents">
Folds everything except questions from other agents, so the model finishes its work first.
</Annotation>

<Annotation id="unread" lines="24-25" tease="held back, not lost" title="result.unread" href="/docs/labs/agents/inboxes?ref=docs-labs-agents-models-and-the-loop" linkText="Inboxes">
What `steer` skipped comes back here, ready for the next loop.
</Annotation>

</AnnotatedCode>

## Choose per call

`loop(batch, options)` takes the loop's options for one call, such as `tools` ([Give the model a tool →](/docs/labs/agents/handlers?ref=docs-labs-agents-models-and-the-loop#give-the-model-a-tool)), `steer` and `onTurn`. [Reference: the loop →](/docs/labs/agents/reference?ref=docs-labs-agents-models-and-the-loop#the-loop)

An agent with no handler sets them on its definition, as in `loop: { maxTurns: 10 }`.

A handler derives a loop with `loop.with(options)`. It keeps the agent's model, prompt, tools and history, and your options override or add to them.

<AnnotatedCode>

{/* not type-checked: loop options on a no-handler agent, and loop.with() with another model and stop in a handler */}
```typescript {{ title: "inngest/agents/escalator.ts" }}
import { eventType } from "inngest";
import { kv } from "inngest/experimental/agents";
import { z } from "zod";
import { agents } from "../client";
import { claude, claudeQuick } from "../models/claude";

export const ticketOpened = eventType("support/ticket.opened", {
  schema: z.object({
    id: z.string(),
    priority: z.enum(["low", "high"]),
    text: z.string(),
  }),
});

export const quick = agents.agent({
  id: "quick",
  triggers: [ticketOpened],
  thread: "event.data.id",
  model: claudeQuick,
  system: "You answer support tickets.",
  loop: { maxTurns: 10 },
});

export const escalator = agents.agent(
  {
    id: "escalator",
    triggers: [ticketOpened],
    thread: "event.data.id",
    model: claudeQuick,
    system: "You answer support tickets.",
  },
  async ({ event, inbox, loop }) => {
    const careful = loop.with({
      model: claude.with({ effort: "high" }),
      stop: async () => {
        return (await kv.thread.get("paused")) === true;
      },
    });

    const run = event.data.priority === "high" ? careful : loop;
    const batch = await inbox.nextBatch();
    const { text } = await run(batch ?? []);

    return text;
  },
);
```

<Annotation id="swap" lines="21" tease="no handler, other limits" title="loop: { maxTurns }" href="/docs/labs/agents/reference?ref=docs-labs-agents-models-and-the-loop#the-loop" linkText="Reference">
The agent keeps its model, prompt and tools, and the loop stops after ten model calls.
</Annotation>

<Annotation id="careful" lines="33-38" tease="same agent, other model" title="loop.with()" href="/docs/labs/agents/reference?ref=docs-labs-agents-models-and-the-loop#the-loop" linkText="Reference">
Swaps the model and keeps the rest. `stop` is checked before each model call, and the loop ends with `end: "stop"` when it returns `true`.
</Annotation>

<Annotation id="pick" lines="40" tease="one loop per run" title="Pick at run time">
The quick model answers by default; high priority tickets get the careful one.

`agent.loop(options)`, from the `agent` export of `inngest/experimental/agents`, builds a standalone loop with only what its options give it, so it needs a `model`.

## Watch progress

`onTurn` runs after each turn's tool calls, so you can tell people what the agent is doing. It gets the turn: its `turn` number, `stepId`, `text`, `toolCalls` and `usage`.

<AnnotatedCode>

{/* not type-checked: loop(batch, { onTurn }) posting through me */}
```typescript {{ title: "inngest/agents/runner.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const runner = agents.agent(
  {
    id: "runner",
    triggers: [slack.thread()],
    model: claude,
    system: "Run the task. Say what you do before each tool call.",
  },
  async ({ inbox, loop, me }) => {
    for await (const batch of inbox.batches()) {
      await loop(batch, {
        onTurn: async (turn) => {
          if (turn.text) {
            await me.post(turn.text);
          }
        },
      });
    }
  },
);
```

<Annotation id="onturn" lines="15" tease="after each turn's tools" title="onTurn" href="/docs/labs/agents/reference?ref=docs-labs-agents-models-and-the-loop#on-turn" linkText="Reference">
Not awaited between turns, so a slow post never delays the next model call.
</Annotation>

<Annotation id="post" lines="17" tease="best effort" title="A failed post">
It is logged and the loop carries on.
</Annotation>

</AnnotatedCode>

## Remember and summarise

When the saved history nears the model's context window, the loop summarises the start once and reuses the summary. [Threads and memory →](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-models-and-the-loop#remember-the-history)

To change the threshold, set `compaction` on the definition's loop. `keep` is how many recent messages are always sent whole.

```typescript
loop: { compaction: { maxTokens: 150_000, keep: 8 } },
```

## Cost and errors

The model prices its own calls, so a dollar `budget` works with no price table. The budget belongs to each thread. [Reliability →](/docs/labs/agents/reliability?ref=docs-labs-agents-models-and-the-loop)

<AnnotatedCode>

{/* not type-checked: budget on an agent definition */}
```typescript {{ title: "inngest/agents/capped.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const capped = agents.agent({
  id: "capped",
  triggers: [slack.thread()],
  model: claude,
  system: "You answer support questions.",
  budget: { usd: 2 },
});
```

<Annotation id="budget" lines="10" tease="dollars per thread" title="budget" href="/docs/labs/agents/reliability?ref=docs-labs-agents-models-and-the-loop" linkText="Reliability">
The loop stops with `end: "budget"` when the thread has spent it.
</Annotation>

</AnnotatedCode>

On the agent, beside `budget`, `price` overrides what the model reports, for a model with no built-in prices. It's a table of dollars per million tokens, where `"*"` is the rate for any model not named, or a function that prices one call.

```typescript
price: { "*": { input: 3, output: 15 } },
```

When the default handler's loop ends on the budget, it posts that the thread's budget is spent. In a handler, `end: "budget"` is yours to handle.

For errors, any model gets the same treatment:

- A rate limit or an overloaded provider is retried, waiting for the provider's `retry-after` when it sends one.
- A final provider error, such as a request it rejects, fails the step for good and isn't retried.
- A failure the model can read and react to is `agent.toolError()`, from the same `agent` export. [Tools →](/docs/labs/agents/tools?ref=docs-labs-agents-models-and-the-loop)

## What the model sees

A message from another agent reaches the model as text. The loop words the four types like this:

- **`agent/message`.** `Message from <address> (thread <key>): <content>`. From a plain function, `Message from function <id> (thread <key>): <content>`.
- **`agent/question`.** The question with its id, who asked it, and a pointer to the `reply` tool.
- **`agent/finished`.** Which agent and thread finished, the outcome (completed, failed or stopped), then the output or the error.
- **`agent/answer`.** The answer, next to the question it answers, so several questions can be open at once. `refused` and `timed_out` show as a plain "no answer" line.

A Slack message reads `[Name] text` and a GitHub comment the same, with the login. Any other event shows as its name and data as JSON.

`format` words a message your own way. `formatEvent` is the default wording, so you only write what differs.

<AnnotatedCode>

{/* not type-checked: loop.with({ format }) with formatEvent and message.is() */}
```typescript {{ title: "inngest/agents/shipper.ts" }}
import { eventType } from "inngest";
import { formatEvent } from "inngest/experimental/agents";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";

export const releaseRequested = eventType("release/requested", {
  schema: z.object({ service: z.string(), branch: z.string() }),
});

export const shipper = agents.agent(
  {
    id: "shipper",
    triggers: [releaseRequested],
    thread: "event.data.service",
    model: claude,
    system: "You ship the branch you are asked to ship.",
  },
  async ({ inbox, loop }) => {
    const run = loop.with({
      format: (message) => {
        if (message.is(releaseRequested)) {
          return `Ship ${message.data.branch} of ${message.data.service}.`;
        }

        return formatEvent(message);
      },
    });

    const batch = await inbox.nextBatch();
    const { text } = await run(batch ?? []);

    return text;
  },
);
```

<Annotation id="format" lines="21-27" tease="your wording for a message" title="format" href="/docs/labs/agents/reference?ref=docs-labs-agents-models-and-the-loop#the-loop" linkText="Reference">
Gets every message the model is about to read, the trigger included, and returns text for it.
</Annotation>

## Gotchas

- **A question to a busy agent waits.** It is answered at the agent's next model call, so the asker's `ask()` waits through a long turn, within its one-hour timeout.

## How it works

- Each model call and tool call is a step. Reading the handler's inbox before a model call adds a round trip to the executor, not a step, and so does each inbox the model opened.
- The loop records model time, tokens, tool calls, folded messages, tool time and tool errors on every run. [Observability →](/docs/labs/agents/observability?ref=docs-labs-agents-models-and-the-loop)
