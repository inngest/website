# Models and the loop

> Run a model with tools until it is done, and never repeat a finished call.

`agent.loop()` calls the model, runs the tools it asks for, and repeats until it answers. Every model call and tool call is a durable step.

<AnnotatedCode>

```typescript {{ title: "inngest/agents/triage.ts" }}
import { agent } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";
import { getOrder } from "../tools/getOrder";

export const triage = agents.agent({ id: "triage" }, async ({ inbox }) => {
  const message = await inbox.next();

  const result = await agent.loop({
    model: claude,
    system: "You answer questions about orders.",
    prompt: message?.content ?? "",
    tools: { getOrder },
  });

  if (result.stopped !== "done") {
    return `stopped early: ${result.stopped}`;
  }

  return result.text;
});
```

</Annotation>

The result also has `turns`, `usage`, `toolCalls` and `history`. `tools` is optional: a loop without it is a plain conversation.

## Choose a model

`agent.anthropic()` calls the Anthropic Messages API with prompt caching, usage and error handling built in. It reads `ANTHROPIC_API_KEY`.

```typescript {{ title: "inngest/models/claude.ts" }}
import { agent } from "inngest/experimental/agents";

export const claude = agent.anthropic({ model: "claude-sonnet-5-5" });
```

For any other provider, `agent.model()` wraps one call. Return the assistant message, its text and any tool calls.

```typescript {{ title: "inngest/models/hosted.ts" }}
import { agent } from "inngest/experimental/agents";

export const hosted = agent.model(async (request) => {
  const response = await fetch("https://models.acme.test/chat", {
    method: "POST",
    body: JSON.stringify({ system: request.system, messages: request.messages }),
  });

  if (!response.ok) {
    throw Object.assign(new Error(await response.text()), {
      status: response.status,
    });
  }

  const reply = (await response.json()) as { text: string };

  return {
    message: { role: "assistant", content: reply.text },
    text: reply.text,
    toolCalls: [],
  };
});
```

Throw an error with a `status` and the loop retries what a retry can fix. The request and response types are in the [reference](/docs/labs/agents/reference?ref=docs-labs-agents-models-and-the-loop#model-types).

## Add tools

A tool is a typed function the model can call. Return `agent.toolError()` and the model sees an error it can react to.

```typescript {{ title: "inngest/tools/getOrder.ts" }}
import { tool } from "inngest/experimental";
import { agent } from "inngest/experimental/agents";
import { z } from "zod";

export const getOrder = tool.step({
  description: "Find an order by ID",
  input: z.object({ id: z.string() }),
  run: async ({ id }) => {
    if (id === "") {
      return agent.toolError({ message: "No such order", id });
    }

    return { status: "shipped", total: 42 };
  },
});
```

More in [Tools](/docs/labs/agents/tools?ref=docs-labs-agents-models-and-the-loop).

## Continue a conversation

Pass the last result's `history` to the next loop.

```typescript {{ title: "inngest/agents/followUp.ts" }}
import { agent } from "inngest/experimental/agents";
import type { AgentMessage } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";
import { getOrder } from "../tools/getOrder";

export const followUp = agents.agent(
  { id: "follow-up" },
  async ({ inbox }) => {
    let history: AgentMessage[] = [];

    for await (const message of inbox) {
      const result = await agent.loop({
        model: claude,
        prompt: message.content ?? "",
        tools: { getOrder },
        history,
      });

      history = result.history;
    }
  },
);
```

A variable lives only as long as the run. To keep it between runs, save it under the thread: [Threads and memory](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-models-and-the-loop).

## Keep long conversations in the window

Every call sends the whole conversation. `compaction` turns the start of it into one summary once it nears the window.

```typescript {{ title: "inngest/agents/long.ts" }}
import { agent } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const long = agents.agent({ id: "long" }, async ({ inbox }) => {
  const message = await inbox.next();

  const result = await agent.loop({
    model: claude,
    prompt: message?.content ?? "",
    compaction: { maxTokens: 700_000, keep: 8 },
  });

  return result.text;
});
```

Past `maxTokens` (an estimate of about three characters a token, so set it well inside the window), everything but the last `keep` messages becomes one summary. A tool result over `maxToolOutput` can be kept whole in a sandbox file with `spill`.

## When to use what

- Run a model with tools: `agent.loop()`.
- A Claude model with caching: `agent.anthropic()`. Any other: `agent.model()`.
- Keep the conversation within one run: `history`. Across runs: [Threads and memory](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-models-and-the-loop).
- Cap turns, tokens or dollars: [Reliability](/docs/labs/agents/reliability?ref=docs-labs-agents-models-and-the-loop).
- Let new messages reach a running turn: `...control`, in [Inboxes](/docs/labs/agents/inboxes?ref=docs-labs-agents-models-and-the-loop#steer-a-running-turn).

## Options

<AnnotatedCode>

```typescript {{ title: "inngest/agents/tuned.ts" }}
import { agent } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";
import { getOrder } from "../tools/getOrder";

export const tuned = agents.agent({ id: "tuned" }, async ({ inbox }) => {
  const message = await inbox.next();

  const result = await agent.loop({
    id: "orders",
    model: claude,
    prompt: message?.content ?? "",
    tools: { getOrder },
    maxTurns: 10,
    wrapUp: "Answer now with what you know.",
    maxToolOutput: 50_000,
    parallelTools: false,
    onToolResult: async (run) => {
      if (run.isError) {
        console.log(run.name, run.output, run.ms);
      }
    },
  });

  return result.toolCalls.length;
});
```

A second loop with the same `id` in one run gets `-2` after it, so a function can loop repeatedly without choosing IDs.

## Gotchas

- Keep `system` fixed. A change to the system prompt, the tools or an earlier message is a cache miss for everything after it. Put changing context in the adapter's `volatile` or in a message.
- A budget needs `...control`, or the loop runs unbudgeted.
- A loop outside an agent body takes your own `steer` and `stop` functions instead of `control`.

## How it works

- A model call is the step `<id>:model:<turn>`. A tool call is `<id>:<turn>.<n>:<name>`.
- `stopped` is `done` when the model made no tool call, `maxTurns` when it ran out, `stopped` on a stop message and `budget` when the budget is spent.
- Nothing is shortened unless you set `compaction`; `history` is never summarised.
