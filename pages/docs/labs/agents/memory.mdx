# Memory

> Keep your own values on a thread, across runs and deploys.

A run's variables are gone when it ends, but a thread's state lasts as long as the thread. Each section builds on the PR helper from [Inboxes](/docs/labs/agents/inboxes?ref=docs-labs-agents-memory), and after the first, a block shows only what changes.

## Your own values

You want to count CI failures on a PR. Start with a variable.

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

const ciRun = z.object({ pr: z.number() });

export const prOpened = eventType("pr/opened", {
  schema: z.object({ pr: z.number(), author: z.string() }),
});

export const prComment = eventType("pr/comment", {
  schema: z.object({ pr: z.number(), author: z.string(), body: z.string() }),
});

export const ciFailed = eventType("ci/run.failed", { schema: ciRun });

export const ciPassed = eventType("ci/run.passed", { schema: ciRun });

export const deployed = eventType("deploy/finished", {
  schema: z.object({ env: z.string(), pull: z.number() }),
});
```

The comment helper is `gh`, from [Inboxes](/docs/labs/agents/inboxes?ref=docs-labs-agents-memory#answer-every-message).

```typescript {{ title: "inngest/lib/github.ts" }}
const api = "https://api.github.com/repos/acme/web";

export const gh = {
  comment: async (pr: number, body: string) => {
    const response = await fetch(`${api}/issues/${pr}/comments`, {
      method: "POST",
      headers: {
        accept: "application/vnd.github+json",
        authorization: `Bearer ${process.env.GITHUB_TOKEN}`,
      },
      body: JSON.stringify({ body }),
    });

    if (!response.ok) {
      throw new Error(`Comment on #${pr}: ${response.status}`);
    }

    return await response.json();
  },
};
```

import { agents } from "../client";
import { ciFailed, ciPassed, deployed, prComment, prOpened } from "../events";
import { gh } from "../lib/github";

const triggers = [
  prOpened,
  prComment,
  ciFailed,
  { event: deployed, thread: "event.data.pull" },
];

export const prHelper = agents.agent(
  {
    id: "pr-helper",
    triggers,
    thread: "event.data.pr",
    inbox: [ciPassed],
    idle: "1h",
  },
  async ({ inbox, me, step }) => {
    let failures = 0;

    for await (const message of inbox) {
      if (message.is(ciFailed)) {
        failures += 1;

            `CI has failed ${failures} times`,

        });
      }
    }
  },
);

## Thread state

You want the count to survive after the run ends. Keep it in `kv.thread`.

```typescript
import { kv } from "inngest/experimental/agents";
import { ciFailed } from "../events";
import { gh } from "../lib/github";

async ({ inbox, me, step }) => {
  for await (const message of inbox) {
    if (message.is(ciFailed)) {
      const failures = Number((await kv.thread.get("failures")) ?? 0);

      await kv.thread.set("failures", failures + 1);

      await step.run("comment", async () => {
        return await gh.comment(
          Number(me.key),
          `CI has failed ${failures + 1} times`,
        );
      });
    }
  }
},
```

`kv.thread` is this thread's state: it survives runs, restarts and deploys. Its values are JSON. [Where it lives →](#where-it-lives)

## Typed keys

You want the editor to know the value's type. Define the key once with a schema.

```typescript {{ title: "inngest/keys.ts" }}
import { kv } from "inngest/experimental/agents";
import { z } from "zod";

export const failures = kv.key("failures", z.number());
```

```typescript
import { kv } from "inngest/experimental/agents";
import { ciFailed } from "../events";
import { failures } from "../keys";
import { gh } from "../lib/github";

async ({ inbox, me, step }) => {
  for await (const message of inbox) {
    if (message.is(ciFailed)) {
      const total = ((await kv.thread.get(failures)) ?? 0) + 1;

      await kv.thread.set(failures, total);

      await step.run("comment", async () => {
        return await gh.comment(
          Number(me.key),
          `CI has failed ${total} times`,
        );
      });
    }
  }
},
```

`kv.thread.set(failures, "3")` is a type error, and a stored value that breaks the schema fails the read.

## Shared by every PR

You want a list of flaky tests that every PR shares. Add a second key to `inngest/keys.ts` and keep it in `kv.app`.

```typescript
export const flaky = kv.key("flaky", z.array(z.string()));
```

```typescript
const found = (await kv.app.get(flaky)) ?? [];

await kv.app.set(flaky, [...found, "checkout.spec.ts"]);
```

Every PR sees the same list. Each call names its scope: `kv.thread` is one thread's state and `kv.app` is shared by the whole app. [KV →](/docs/labs/agents/reference?ref=docs-labs-agents-memory#kv)

## Where it lives

By default, state lives in functions that `agents.functions()` serves with your agents, so there is nothing else to run. This store is experimental, and it has limits:

- **Later write wins.** Every live run sees a write after a short lag. Two runs that read, change and write one key at once can lose one change. Give each key one writer, or send a message to one owner.
- **128 KB per thread.** The same cap holds for each `kv.app` and `kv.env`. The model's remembered history counts toward it.
- **Write between steps.** A write inside a step's callback (a tool or `step.run`) throws.
- **Read inside a function.** A script or a route can write with `kv.with(client)`, but not read.
- **One app.** `kv.env` is shared by the functions of one app, not across apps.

For atomic writes, give `createAgents` a store: `redisKvAdapter(url)` or `d1KvAdapter(db)`. Setting `INNGEST_EXPERIMENTAL_KV_URL` to a Redis URL does the same. A store adds `update`, `setIfAbsent` and `take`, which read and write together, so overlapping updates never lose one. [Store →](/docs/labs/agents/reference?ref=docs-labs-agents-memory#store)

```typescript
await kv.app.update(flaky, (found) => {
  return [...(found ?? []), "checkout.spec.ts"];
});
```
