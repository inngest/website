# Teams of agents

> Start another agent, talk to it while it works, and get its answer back.

One rule covers every call between agents: messages arrive in your [inbox](/docs/labs/agents/inboxes?ref=docs-labs-agents-teams-of-agents); results return to your call.

- **Call an agent like a function.** `start()` opens a thread and returns a handle at once. [Start an agent →](#start-an-agent)
- **Wait only when you choose.** `result()` waits for the answer; `message()` doesn't, unless you ask for its result too. [Wait for the result →](#wait-for-the-result)
- **Talk while it works.** Message, ask or stop a running agent. [Talk to it →](#talk-to-a-running-agent)
- **Fan out.** Review ten pull requests with one `Promise.all`. [Fan out →](#fan-out)
- **Any app.** Call an agent in another app by its address. [Another app →](#call-an-agent-in-another-app)
- **Let the model delegate.** It starts work and carries on; results arrive as messages. [The model →](#let-the-model-delegate)

## Start an agent

`start()` opens a new [thread](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-teams-of-agents), starts a run on it and returns a handle at once. Every call opens its own thread, so two starts run side by side. With an `invoke()` trigger, the input is typed from it. [Typed input →](/docs/labs/agents/agents-and-triggers?ref=docs-labs-agents-teams-of-agents#take-a-typed-input)

An agent with no `invoke()` trigger takes text or JSON and receives it as a message:

{/* not type-checked: an agent with no triggers started by start() */}
```typescript {{ title: "inngest/agents/summarizer.ts" }}
import { agents } from "../client";
import { claude } from "../models/claude";

export const summarizer = agents.agent({
  id: "summarizer",
  model: claude,
  system: "Summarise what you are given in two sentences.",
});
```

```typescript
const summary = await summarizer.start("Release 4.2 adds retries.").result();
```

## Wait for the result

`result()` waits for a run to end and returns its output: what the handler returned, or the model's last answer when the agent has no handler. On a handle from `start()` it is the run `start()` opened. `await reviewer.start({ pr }).result()` is both in one line, for when you don't need the handle.

A failed or stopped run makes `result()` throw. `timeout` stops the wait after a while.

{/* TODO(spec): what does result({ timeout }) do when the time runs out? messaging.md says only "no default timeout". */}
{/* not type-checked: result({ timeout }) throwing for a failed or stopped run */}
```typescript {{ title: "inngest/functions/reviewOrSkip.ts" }}
import { inngest } from "../client";
import { pullOpened } from "../events";
import { reviewer } from "../agents/reviewer";

export const reviewOrSkip = inngest.createFunction(
  { id: "review-or-skip", triggers: [pullOpened] },
  async ({ event }) => {
    try {
      return await reviewer
        .start({ pr: event.data.url })
        .result({ timeout: "30m" });
    } catch {
      return "No review. A person will look.";
    }
  },
);
```

A run opened by `start()` ends as soon as it has answered and nothing is unread, so `result()` returns promptly. With a handler, the run ends when the handler returns, and a loop over its inbox stops once nothing is waiting. [When the handler returns →](/docs/labs/agents/handlers?ref=docs-labs-agents-teams-of-agents#when-the-handler-returns)

## Carry on the conversation

`message()` returns the run that takes the message, so a second round is one more line. The thread keeps its history, so the reviewer sees its first review too.

{/* not type-checked: message().result() on the handle from start() */}
```typescript {{ title: "inngest/functions/reviewTwice.ts" }}
import { inngest } from "../client";
import { pullOpened } from "../events";
import { reviewer } from "../agents/reviewer";

export const reviewTwice = inngest.createFunction(
  { id: "review-twice", triggers: [pullOpened] },
  async ({ event }) => {
    const review = await reviewer.start({ pr: event.data.url });

    const first = await review.result();

    const second = await review
      .message("Now check the tests you skipped.")
      .result();

    return { first, second };
  },
);
```

The message lands in the run that's still working, or starts a new run on the thread once the first has ended. Either way, `result()` gives the answer of the run that took it.

## Talk to a running agent

A handle talks to the thread. `message()` sends without waiting for the agent, `ask()` waits for an answer and `stop()` cancels the run.

<AnnotatedCode>

```typescript {{ title: "inngest/functions/reviewWithChecks.ts" }}
import { inngest } from "../client";
import { pullOpened } from "../events";
import { reviewer } from "../agents/reviewer";

export const reviewWithChecks = inngest.createFunction(
  { id: "review-with-checks", triggers: [pullOpened] },
  async ({ event }) => {
    const review = await reviewer.start({ pr: event.data.url });

    await review.message("The author says the migration is safe to skip.");

    const worry = await review.ask("Which file worries you most?");

    if (worry === null) {
      await review.stop();

      return { worry: null, findings: null };
    }

    return { worry, findings: await review.result() };
  },
);
```

## Rebuild a handle

`review.key` names the thread. Code that has the key rebuilds the handle with `thread(key)`. It has everything a handle has except its own `result()`; the run its `message()` starts has one.

{/* not type-checked: reviewer.thread(key) rebuilding a handle and awaiting the run its message starts */}
```typescript {{ title: "inngest/functions/nudgeReview.ts" }}
import { eventType } from "inngest";
import { z } from "zod";
import { inngest } from "../client";
import { reviewer } from "../agents/reviewer";

const pullUpdated = eventType("pull/updated", {
  schema: z.object({ reviewKey: z.string() }),
});

export const nudgeReview = inngest.createFunction(
  { id: "nudge-review", triggers: [pullUpdated] },
  async ({ event }) => {
    const review = reviewer.thread(event.data.reviewKey);

    return await review.message("The author pushed a fix.").result();
  },
);
```

## Fan out

Every `start()` opens its own thread, so parallel work is `Promise.all`.

{/* not type-checked: Promise.all over start().result() */}
```typescript {{ title: "inngest/functions/reviewRelease.ts" }}
import { eventType } from "inngest";
import { z } from "zod";
import { inngest } from "../client";
import { reviewer } from "../agents/reviewer";

const releaseCut = eventType("release/cut", {
  schema: z.object({ pulls: z.array(z.string()) }),
});

export const reviewRelease = inngest.createFunction(
  { id: "review-release", triggers: [releaseCut] },
  async ({ event }) => {
    return await Promise.all(
      event.data.pulls.map(async (pr) => {
        return await reviewer.start({ pr }).result();
      }),
    );
  },
);
```

## Answer a question

An agent that gets an `agent/question` answers it with `msg.reply()`. `msg.from` says who asked: from an agent it is a handle, so `msg.from.message()` talks back; from a plain function it holds the function's `id` and `key` and can't be messaged.

{/* not type-checked: msg.is(agentQuestion), msg.reply() and inbox.drain() in a start()-opened run */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/deployer.ts" }}
import { invoke } from "inngest";
import { agentQuestion } from "inngest/experimental/agents";
import { z } from "zod";
import { agents } from "../client";

export const deployer = agents.agent(
  {
    id: "deployer",
    triggers: [invoke(z.object({ service: z.string() }))],
  },
  async ({ event, inbox, step }) => {
    for (const region of ["us-east", "eu-west"]) {
      await step.run(`roll-out-${region}`, async () => {
        return { service: event.data.service, region };
      });

      for (const msg of await inbox.drain()) {
        if (msg.is(agentQuestion)) {
          await msg.reply(`Finished ${region}.`);
        }
      }
    }

    return "deployed";
  },
);
```

`drain()` returns what has arrived and never waits.

## Let the model delegate

A model agent never waits on another agent. Its tools `start_agent`, `message_agent`, `ask_agent`, `stop_agent` and `reply` return at once, and what comes back arrives as a message in its inbox, batched with everything else. They are on by default, next to the agent's own [tools](/docs/labs/agents/tools?ref=docs-labs-agents-teams-of-agents). [Discovery →](/docs/labs/agents/discovery?ref=docs-labs-agents-teams-of-agents)

```
start_agent({
  address: "support/reviewer",
  input: { pr: "https://github.com/acme/api/pull/42" },
})
  { thread: "a1b2c3" }
```

The model carries on. Four message types come back, each in a default wording. [Models and the loop →](/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-teams-of-agents)

- **`agent/message`.** What `message()` or `message_agent` sent. The model sees `Message from <address> (thread <key>): <content>`.
- **`agent/question`.** From `ask()` or `ask_agent`. The model sees the question with its id, who asked, and a pointer to `reply`.
- **`agent/answer`.** The answer to the model's `ask_agent`, shown with the question it answers. A refusal or a timeout shows as a plain "no answer" line.
- **`agent/finished`.** Work the model started with `start_agent` ended. The model sees which agent and thread, the outcome (completed, failed or stopped), then the output or the error.

They are exported as `agentMessage`, `agentQuestion`, `agentAnswer` and `agentFinished`, and `msg.is()` narrows to one. [Narrow an event with `is()` →](/docs/events/event-payloads-and-schemas?ref=docs-labs-agents-teams-of-agents#narrow-an-event-with-is)

{/* not type-checked: msg.is(agentFinished) narrowing data.outcome in a handler */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/lead.ts" }}
import { agentFinished, slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const lead = agents.agent(
  {
    id: "lead",
    triggers: [slack.thread()],
    model: claude,
    system: "Hand pull request reviews to the reviewer agent.",
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches()) {
      for (const msg of batch) {
        if (msg.is(agentFinished) && msg.data.outcome === "failed") {
          await me.post(`A review failed: ${msg.data.error}`);
        }
      }

      const { text } = await loop(batch);

      await me.post(text);
    }
  },
);
```

Sandbox code is code, so it gets the same tools plus `agent_result`, which waits. A script can start several agents and wait for each, as `Promise.all` does. [Sandboxes and code →](/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-teams-of-agents)

## Background work

Work that runs beside a conversation is a plain function you don't await. It reports back with `me.message()`, and work still running when the handler returns is stopped. [Message yourself →](/docs/labs/agents/handlers?ref=docs-labs-agents-teams-of-agents#message-yourself)

## Limit the team

Put `limits` on the agent that delegates:

{/* TODO(spec): the default of limits.depth, and what a refused start looks like to code and to the model. */}
```typescript
limits: { depth: 2, mayCall: ["support/reviewer"] },
```

`depth` caps a chain of starts, where A starts B and B starts C. `mayCall` lists the agents the model may start.

Every thread spends from its own agent's `budget`, such as the reviewer's `budget: { usd: 2 }`, whoever started it. [Reliability →](/docs/labs/agents/reliability?ref=docs-labs-agents-teams-of-agents)

## Gotchas

- **Handle methods need a function.** They throw in a route or a script. Send the agent's trigger event from there.
- **`ask()` can return `null`.** It does after the timeout and when the other side refuses. Pick a default.
- **Code that waits can't be asked.** A question from the run behind your `result()` is refused at once. The agent's `ask()` returns `null` and your `result()` keeps waiting.
- **Every `start()` opens a thread.** To carry on a conversation, `message()` the same thread. [Carry on →](#carry-on-the-conversation)

## How it works

- A message for a thread with a live run lands in that run's inbox; a message for a quiet thread starts a run. [Threads and memory →](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-teams-of-agents)
- A run opened through a handle ends once it has answered and nothing is unread. The thread keeps the history for the next run.
- Answers to your `ask()` and outputs for your `result()` go only to the waiting call, so an inbox holds only what was sent to the agent.
- Every agent message shows in the run's trace, with who sent it.
