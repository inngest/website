# Discovery

> Agents find each other at run time, by what they do.

Every agent publishes a card. A model agent reads the cards and starts the one it needs, in any app, with nothing wired in code.

- **Be found with no code.** The SDK publishes a card for every agent. [Publish a card →](#publish-a-card)
- **Choose who sees it.** `share` keeps a card in your app or shows it to the environment. [Not access control →](#gotchas)
- **Models find agents.** `list_agents` and `describe_agent` are on by default. [Find agents →](#find-agents)
- **Keep an agent on its own.** One setting stops it reaching others. [Turn it off →](#turn-it-off)
- **Fill in what the model must not make up.** The host sets part of the input. [Prepare input →](#fill-in-input-from-the-host)

## Publish a card

Cards announce when your app syncs, and again every six hours. An agent is `app/agent` everywhere, as in `support/reviewer`: `start_agent`, `mayCall` and `agents.reference()` all take that address. [Teams of agents →](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-discovery)

## Find agents

A model hands a review to the reviewer like this, with no wiring:

```text
list_agents({ query: "review" })
  agents: [
    {
      address: "support/reviewer",
      description: "Reviews a pull request and returns findings.",
      effects: "read",
    },
  ]

describe_agent({ address: "support/reviewer" })
  input: { type: "object", properties: { pr: { type: "string" } }, ... }

start_agent({ address: "support/reviewer", input: { pr: "acme/api#42" } })
```

`list_agents` matches the query's words against each card's address, description and skills. `start_agent` checks the input against the card first, so a bad call fails with a readable error. [Teams of agents →](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-discovery#let-the-model-delegate)

## Turn it off

`discovery: false` removes `list_agents`, `describe_agent` and the tools that reach other agents. `reply` stays, and the card is still published.

## Fill in input from the host

`discovery: { prepare }` runs before `start_agent` sends its input and returns the input to send. The model never sets a field the host fills.

{/* not type-checked: discovery.prepare with { card, input, event, thread } returning the input to send */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/concierge.ts" }}
import { slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const concierge = agents.agent({
  id: "concierge",
  triggers: [slack.thread()],
  model: claude,
  system: "Find the right agent for the request and hand it over.",
  discovery: {
    prepare: ({ card, input, event }) => {
      if (card.address === "platform/auditor") {
        return { ...input, requester: event.data.user };
      }

      return input;
    },
  },
});
```

<Annotation id="prepare" lines="11-17" tease="runs before each start" title="prepare">
Gets the card, the model's input, the run's event and its `thread`. What it returns is what the other agent receives.
</Annotation>

<Annotation id="requester" lines="13" tease="who is asking" title="A host-set field">
The Slack user who asked, from the event. The model can't make it up.
</Annotation>

</AnnotatedCode>

## Gotchas

- **`share` is a discovery rule, not access control.** Anyone who knows an address can start the agent from code, and anyone with an event key can send its trigger. [Teams of agents →](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-discovery#call-an-agent-in-another-app)
- **Cards lag, and a run reads them once.** A new card takes a few minutes to show. The model passes `refresh: true` to `list_agents` to read again, which finds it only once it has landed. A failed read is an error it can read, never an empty list.
- **Paused and removed agents.** A paused agent is listed with `paused: true`, and `start_agent` refuses it with a reason. A removed agent drops out, and an unknown or unshared address gives an error that tells the model to list again.

## How it works

- Discovery keeps the newest card of each agent from the last 24 hours, so a rolling deploy never hides an agent. An app announces only its own agents.
- On Cloud the read is one Insights query that also checks each app's functions, which is how paused agents are marked. The Dev Server answers from its events, so discovery works locally.
