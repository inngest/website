## createAgents

Makes the agents of one client. [Quick start](/docs/labs/agents/quick-start?ref=docs-labs-agents-reference), [Structure](/docs/labs/agents/structure?ref=docs-labs-agents-reference).

```typescript {{ title: "Signature" }}
createAgents(client: Inngest, options?: CreateAgentsOptions): Agents

interface CreateAgentsOptions {
  store?: KvStore; // default: Redis at INNGEST_EXPERIMENTAL_KV_URL
}

interface Agents {
  agent(config: AgentFunctionConfig, body: AgentBody): AgentFunction;
  functions(): InngestFunction[];
  announce(): Promise<void>;
}
```

- `store`: where KV, thread state, and indexes live. One store per app ID. See [KV stores](#kv-stores).
- `agents.functions()`: every function to serve. For each agent: its run, cleanup, finished and (with `onArrival`) arrival functions. Once per client: a skills bake function when an agent may bake skills, and the `agents-announce` heartbeat. Call it after the agents are defined.
- `agents.announce()`: sends the cards of this client's agents in an `agents/registered` event, so [discovery](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-reference#publish-a-card) finds them. Call it once the app is up. The heartbeat sends it again daily at 06:00 UTC, and on an `agents/announce` event.
- `agents.agent()` registers the agent when its file is imported, so import each agent file before serving.

```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { sandboxMiddleware } from "inngest/experimental";
import { createAgents } from "inngest/experimental/agents";

export const inngest = new Inngest({
  id: "support",
  middleware: [sandboxMiddleware()],
});

export const agents = createAgents(inngest);
```

```typescript {{ title: "inngest/serve.ts" }}
import { createServer } from "inngest/node";
import { agents, inngest } from "./client";
import "./agents/support";

createServer({
  client: inngest,
  functions: agents.functions(),
}).listen(3000);
```

### AgentFunction

What `agents.agent()` returns.

| Member | Description |
| --- | --- |
| `fn` | The function that runs the body. |
| `cleanup` | Runs after every run ends and removes the run's run-scoped KV keys. |
| `finished` | Writes the thread's `lastRun` when a run ends; reports failures when `recovery` is on. |
| `arrival` | Runs `onArrival`. Present only when the config has `onArrival`. |
| `ref` | The agent's address, `"<appId>/<functionId>"`. |
| `thread(key, session?)` | The [handle](#thread-handles) of a thread. `session` defaults to the key. |
| `threads.list(options?)` | [Lists threads](#list-threads). |
| `"~types"` | Types only: the agent's input and output. |

## Agent config

The first argument of `agents.agent()`. [Events and triggers](/docs/labs/agents/agents-and-triggers?ref=docs-labs-agents-reference), [Threads](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-reference).

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | `string` | required | Function ID. The agent's address is `"<appId>/<id>"`. |
| `on` | [trigger](#triggers) or array | none | What starts the agent besides messages: events, event types, crons, `invoke()`. |
| `thread` | CEL `string` | the trigger's | Thread key expression for event triggers. Overrides the one a trigger supplies. |
| `session` | CEL `string` | the thread key | Session expression for event triggers. |
| `kv` | `Kv` or `() => Kv` | the `createAgents` store | KV for thread state. A function is called at each use. [KV](/docs/labs/agents/reference?ref=docs-labs-agents-reference#kv) |
| `requests` | `{ request, reply }` schemas | none | Types for `handle.request()` and `message.reply()`. A schema must not transform its input. [Threads](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-reference#ask-another-thread) |
| `onArrival` | `(ctx) => void` | none | Runs for each message that reaches a busy thread, in its own `<id>-arrival` function. [Threads](/docs/labs/agents/inboxes?ref=docs-labs-agents-reference#options) |
| `inbox` | `InboxSource[]` | none | Event sources that reach a live run and never start one. [Events](/docs/labs/agents/inboxes?ref=docs-labs-agents-reference#listen-to-other-sources) |
| `inboxTools` | [`InboxToolsConfig`](#inbox-tools) | off | Lets the model listen for events. [Subscribe](/docs/labs/agents/tools?ref=docs-labs-agents-reference#let-the-model-listen-for-events) |
| `foldMessages` | `"steer" \| "all"` | `"steer"` | Which messages that arrive during a turn `control.steer()` folds into the next model call. [Threads](/docs/labs/agents/inboxes?ref=docs-labs-agents-reference#steer-a-running-turn) |
| `sandboxes` | record, or function of `{ event }` | none | Sandboxes by name: definitions or `{ sandbox, start }`. [Sandboxes](/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-reference) |
| `channels` | record, or function of `{ event }` | none | Destinations by name. [Channels](/docs/labs/agents/reporting?ref=docs-labs-agents-reference) |
| `report` | channel name, channel, or list; or function of `{ event }` | channel named `main` | Where `report()` posts when not told. |
| `limits` | [`AgentLimits`](#agentlimits) | see type | What the agent may start and spend. [Events](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-reference#limit-sub-agents) |
| `share` | `"private" \| "team"` | `"private"` | Who may find and call the agent: agents of its own app, or of every app in the environment. [Teams](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-reference#publish-a-card) |
| `skills` | `{ id, description, examples }[]` | none | What the agent is good at. Models pick agents by these. |
| `scores` | `boolean` | `true` | Whether the agent scores itself. [Scores](/docs/labs/agents/observability?ref=docs-labs-agents-reference) |
| `recovery` | `boolean \| AgentRecovery` | off | What to do about a run that fails unexpectedly. [Recovery](#recovery) |

`description` also goes on the agent's card, where callers and models read it.

Function options an agent takes as they are: `name` (default: the `id`), `description`, `concurrency`, `retries`, `timeouts`, `cancelOn`, `onFailure`, `idempotency`, `rateLimit`, `throttle`, `priority`, `middleware`. [Flow control](/docs/guides/flow-control?ref=docs-labs-agents-reference)

Options an agent refuses (type `never`): `debounce`, `batchEvents`, `singleton`, `checkpointing`. The agent has its own singleton per thread.

`sandboxes`, `channels`, and `report` given as a function run again on every replay, so they must be pure.

```typescript {{ title: "inngest/agents/support.ts" }}
import { agent, slack } from "inngest/experimental/agents";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";
import { lookupOrder } from "../tools/lookupOrder";
import { workbench } from "../sandboxes/workbench";

export const support = agents.agent(
  {
    id: "support",
    on: slack.thread({ in: ["C0123ABC"] }),
    requests: {
      request: z.object({ orderId: z.string() }),
      reply: z.object({ refundable: z.boolean() }),
    },
    sandboxes: { work: workbench },
    limits: { depth: 1, budget: { usd: 2 } },
    recovery: true,
    concurrency: { limit: 10 },
  },
  async ({ inbox, control, sandboxTools, thread }) => {
    for await (const message of inbox) {
      if (message.name === "agent/message") {
        const result = await agent.loop({
          model: claude,
          prompt: message,
          tools: { ...sandboxTools, lookup_order: lookupOrder },
          ...control,
        });

        await thread.send(result.text);
      }
    }
  },
);
```

## Agent body

The second argument of `agents.agent()`. It receives the function context of the client (`step`, `group`, `defer`, `runId`, `logger`, `attempt`, and what middleware adds) with these fields beside it. There is no `events`. Types: `AgentBody`, `AgentBodyContext`, `AgentBodyFields`, `AgentFunctionInput`.

| Field | Type | Description |
| --- | --- | --- |
| `event` | `{ name, data: AgentStartData }` | The event that started the run. `data.event` is the trigger event. |
| `trigger` | trigger event or `undefined` | The `on` event that started the run, typed from `on`. `undefined` when a plain thread message started it. |
| `depth` | `number` | How many calls deep this run is: 1 for the first callee, 2 for its callees. `0` when no call started the run, including a later run of a called agent's thread. |
| `thread` | [`ThreadHandle`](#thread-handles) | The handle of this run's thread. |
| `inbox` | [`ThreadInbox`](#inbox) | The thread's messages, in order. |
| `sandboxes` | `Record<name, LazySandbox>` | The agent's sandboxes. [Sandboxes reference](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-reference#lazysandbox) |
| `sandboxTools` | tools | Every sandbox's tools, named `<sandbox>_<tool>` (`work_run`). Spread into `tools`. |
| `inboxTools` | tools | `inbox_listen`, `inbox_wait`, `inbox_read`, `inbox_stop` when the config has `inboxTools`; none without it. |
| `channels` | `Record<string, Channel>` | The agent's channels, resolved for this run. |
| `report` | [`Reporter`](#reporter) | Posts progress to the channels. |
| `scores` | [`AgentScores`](#scores) | Your own scores. |
| `previousRun` | [`LastRun`](#lastrun) or `undefined` | How the last ended run of the thread ended. |
| `restarts` | `number` | How many times this run continued in another process. |
| `control` | object | Spread into `agent.loop()`: `steer`, `stop`, `onTurn`, `budget`, `scores`, `price`. |

Name the types of a body with one bag, `AgentBody<{ event?, output?, request?, reply?, sandboxes?, client?, middleware?, inboxTools? }>`. A field left out takes its default (`AgentTypeDefaults`), so `AgentBody<{ output: null }>` names only the output. `agents.agent()` infers all of it, so you only write a bag for a body you define apart from its agent. Types: `AgentTypes`, `AgentTypesOf`, `AgentTypeDefaults`.

`control` fields:

| Field | Description |
| --- | --- |
| `steer()` | Returns the steering events that arrived during a turn, for the next model call. |
| `stop()` | Returns `true` when a stop message arrived. |
| `onTurn(turn)` | Records the turn, usage, and summary for `thread.state()`. If you pass your own `onTurn`, put `...control` first and call `control.onTurn(turn)` from yours. |
| `budget()` | The reason the budget is spent, or `undefined`. |
| `scores` | The agent's `scores` setting. |
| `price` | The agent's `limits.price`, if any. |

`limits.budget` only applies to a loop given `...control`. [Loop](/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-reference)

## Inbox

`inbox` is an async iterable of messages, one per delivery. The first message is the event that started the run. [Threads](/docs/labs/agents/inboxes?ref=docs-labs-agents-reference#read-messages)

```typescript {{ title: "Signature" }}
interface ThreadInbox extends AsyncIterable<ThreadInboxMessage> {
  next(): Promise<ThreadInboxMessage | null>;
  next(options: { timeout }): Promise<ThreadInboxMessage | null | undefined>;
  current(): Promise<ThreadInboxMessage[]>;
  unread(): Promise<ThreadInboxMessage[]>;
  of(type): View;
  listen(source: InboxSource): Promise<ThreadListener>;
  listen(event, options: { thread?: string; if?: string }): Promise<ThreadListener>;
  close(): Promise<ThreadInboxMessage[]>;
}
```

| Method | Description |
| --- | --- |
| `next()` | Waits for the next message. `null` once the inbox is closed and drained. |
| `next({ timeout })` | Waits at most `timeout` (durable). `undefined` on timeout, `null` at the end. Durations under a second round up to one; `0` never waits. |
| `current()` | Every message saved so far, read or not, stops included, but not the event that started the run. Moves no cursor. |
| `unread()` | Takes every message after the cursor without waiting, and advances the cursor. Stops are included. |
| `of(type)` | A `View` of one event's messages with a cursor of its own: `next`, `unread`, `current`, async iterable. |
| `listen(source)` | Adds an event source mid-run. One step. Needs a `thread` or an `if`. |
| `close()` | Ends the subscription and returns the unread messages. |

Stop messages are skipped while the agent waits for its next message.

### Thread messages

A `ThreadInboxMessage` is a plain event: `id`, `name`, `data`, `ts`, `seq`. `switch (message.name)` narrows `data`. Every thread event also has `agent` and `thread` in `data`.

| `name` | `data` | Meaning |
| --- | --- | --- |
| `agent/message` | `text` | Starts the next turn. |
| `agent/steer` | `text` | Folded into the turn that is running. |
| `agent/stop` | `when: "nextTurn"` | Asks the thread to stop. Never starts a run. |
| `agent/request` | `payload`, `replyTo`, `from?` | A question from another thread. |

Events from your triggers and inbox sources arrive as they were sent. `message.reply(data)` exists on `agent/request` messages only, and answers as a step.

Types: `AgentMessageData`, `AgentSteerData`, `AgentStopData`, `AgentRequestData`, `ThreadInbox`, `ThreadInboxMessage`.

### InboxSource

| Field | Type | Description |
| --- | --- | --- |
| `event` | `string \| EventType` | The event. |
| `thread` | CEL `string` | Maps the event to the thread key. |
| `if` | CEL `string` | The event must match. At least one of `thread` and `if` is required. |

`ThreadListener` has `stop()` and is `AsyncDisposable`.

## Thread handles

A thread is one conversation with an address, its key. [Threads](/docs/labs/agents/threads-and-memory?ref=docs-labs-agents-reference)

```typescript {{ title: "Signature" }}
agent.thread(key: string, session?: string): ThreadHandle
getThread(client, agent: string, key: string, options?: ThreadOptions): ThreadHandle

interface ThreadOptions {
  session?: string; // default: the thread key
  kv?: KvSource; // default: the createAgents store
  requests?: { request: Schema; reply: Schema };
}
```

| Member | Description |
| --- | --- |
| `agent`, `key`, `session` | Identity of the thread. |
| `send(text)` | Sends `agent/message`: starts the next turn, and a run if none is live. A step inside a function. |
| `steer(text)` | Sends `agent/steer`: folds into the turn that is running. |
| `stop({ when })` | Sends `agent/stop`. `"nextTurn"` stops before the next model call. `"now"` cancels the live run through the API. Returns `{ stopped }`; `false` when nothing was live. |
| `state()` | Returns `ThreadState`. Works when no run is live. |
| `request(payload, options?)` | Sends `agent/request` and waits for the reply. Inside a function only. `options.timeout` default `"1h"`. Resolves to the reply or `null` on timeout. |

```typescript {{ title: "inngest/threads.ts" }}
import { getThread, listThreads } from "inngest/experimental/agents";
import { inngest } from "./client";
import { support } from "./agents/support";

export const run = async () => {
  const handle = support.thread("t1");

  await handle.send("hello");
  await handle.stop({ when: "nextTurn" });

  const state = await handle.state();
  const other = getThread(inngest, "support/support", "t2", { session: "s" });
  const threads = await support.threads.list({ limit: 10 });
  const all = await listThreads(inngest, "support/support", { session: "s" });

  return [state.status, other.key, threads.length, all.length];
};
```

### ThreadState

| Field | Description |
| --- | --- |
| `status` | `"running"`, `"waiting"`, `"stopped"`, or `"idle"`. |
| `turn` | Turn of the latest model call; restarts at 1 with each loop. |
| `summary` | The latest non-empty model reply, cut to 500 characters. |
| `usage` | `{ input, output, usd? }` across runs. `usd` needs a `limits.price`. |
| `keys` | Keys your code set in the thread's KV scope. |
| `lastRun` | [`LastRun`](#lastrun) or `undefined`. |

Types: `ThreadHandle`, `ThreadOptions`, `ThreadState`, `ThreadStatus`, `ThreadRequests`, `RequestOptions`.

## Triggers

`on` takes the shapes the `triggers` of a function take. [Events and triggers](/docs/labs/agents/agents-and-triggers?ref=docs-labs-agents-reference)

| Trigger | Description |
| --- | --- |
| `"event/name"` | A plain event name (no wildcard, not `agent/message`). |
| `eventType(...)` | Types and validates the event data. |
| `{ event, if?, thread?, session? }` | `ThreadEventTrigger`. `if` filters. |
| `{ cron, jitter?, thread?, session? }` | `ThreadCronTrigger`. One thread per agent unless `thread` is set. |
| `invoke(schema)` | Puts the agent's input schema on its card, for [`callAgent()`](#calling-agents) and `call_agent`. Without it a call takes `{ message }`. |
| `slack.thread(...)`, `github.thread(...)` | [Channel triggers](#slack-and-github). |

- Use one trigger per event name.
- A trigger for a thread with a live run starts nothing; the run reads the event from its inbox.
- `thread` and `session` are CEL expressions, not functions, because the backend evaluates them.
- A `callAgent()` call runs on a thread of its own; any other invocation uses `thread` or the agent's own thread.

Types: `ThreadTrigger`, `ThreadTriggers`, `ThreadEventTrigger`, `ThreadCronTrigger`, `ThreadCronEvent`, `ThreadTriggerEvent`, `ThreadTriggerData`, `ThreadTriggerEventOf`, `ThreadTriggerEventSource`, `ThreadTriggerList`, `ThreadTriggerListEvent`, `ThreadKeyConfig`.

| --- | --- |

### agent.loop

```typescript {{ title: "Signature" }}
agent.loop(options: AgentLoopOptions): Promise<AgentLoopResult>
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `model` | `AgentModel` | required | Called once per turn. |
| `prompt` | `string \| AgentContentBlock[] \| AgentEvent` | required | The first user message. An event, such as an inbox message, goes through `format`. |
| `format` | `(event) => string \| AgentContentBlock[]` | `data.text` of `agent/message` and `agent/steer`; JSON of `{ event, data }` otherwise | What the model sees for an event. |
| `tools` | tools record | none | Tools the model can call. |
| `id` | `string` | `"agent"` | Prefix of step IDs. A second loop with the same prefix in one run gets `-2`, a third `-3`. |
| `system` | `string` | none | System prompt. |
| `maxToolOutput` | `number` | `100000` | Most characters of a tool result the model sees; longer keeps start and end and says how much is missing. |
| `spill` | `{ sandbox, dir? }` | none | Saves the whole of a longer result to `<dir>/tool-output-<hash>.txt` in the sandbox (`dir` default `/tmp`, must exist) and tells the model the path. |
| `parallelTools` | `boolean` | `true` | Run the tool calls of one reply at once. |
| `maxTurns` | `number` | `40` | Most model calls. |
| `history` | `AgentMessage[]` | none | History of an earlier result, to continue. |
| `steer` | `(turn) => Promise<AgentInput[] \| undefined>` | none | Text, blocks or events returned reach the model as user messages. |
| `stop` | `(turn) => Promise<boolean>` | none | `true` ends the loop with `stopped: "stopped"`. |
| `budget` | `(turn) => string \| undefined` | none | A reason ends the loop with `stopped: "budget"`. |
| `wrapUp` | `string` | none | Text for the last turn, with no tool use allowed. |
| `compaction` | `AgentCompactionOptions` | off | Summarises the start of the conversation near the window. Without it every call sends the whole conversation. [Details](#compaction) |
| `onToolResult` | `(run) => void` | none | Called when a tool call finishes. Put side effects in steps. |
| `onTurn` | `(turn) => void` | none | Called after each model call. |
| `price` | `AgentPrice` | none | What a model call costs. [Pricing](#pricing) |
| `scores` | `boolean` | `true` | Whether the loop scores itself. |

Spread `...control` from the agent body to take `steer`, `stop`, `budget`, `onTurn`, `price`, and `scores`.

`AgentLoopResult`:

| Field | Description |
| --- | --- |
| `text` | Text of the last model reply. |
| `stopped` | `"done"`, `"maxTurns"`, `"stopped"`, or `"budget"`. |
| `reason` | Why, for `"budget"`. |
| `turns` | Model calls made. |
| `history` | The whole conversation. Pass as `history` to continue. |
| `usage` | `{ input, output, usd?, cacheRead?, cacheWrite?, cacheWrite1h? }` of this loop. |
| `toolCalls` | Every tool call, in order, as `AgentToolRun`. |

### Model types

```typescript {{ title: "Signature" }}
type AgentModel = (request: AgentModelRequest) => Promise<AgentModelResponse>

interface AgentModelRequest {
  system?: string;
  messages: AgentMessage[];
  turn: number; // from 1
  maxTurns: number;
  toolChoice?: "none"; // last turn when wrapUp is set
  tools: ToolJsonDefinition[];
}

interface AgentModelResponse {
  message: { role: "assistant"; content: unknown };
  text?: string;
  toolCalls: AgentToolCall[]; // none means the final reply
  usage?: AgentUsage; // default: none counted
  model?: string; // given to price
}

type AgentMessage =
  | { role: "user"; content: string }
  | { role: "assistant"; content: unknown }
  | { role: "tool"; results: AgentToolResult[] }
```

| Type | Fields |
| --- | --- |
| `AgentToolCall` | `id`, `name`, `input` |
| `AgentToolResult` | `toolCallId`, `name`, `input`, `content`, `isError?` |
| `AgentUsage` | `input` (cached tokens included), `output`, `usd?`, `cacheRead?`, `cacheWrite?`, `cacheWrite1h?`. The cache fields are parts of `input`; `cacheWrite1h` is part of `cacheWrite`. |
| `AgentTurn` | `turn`, `stepId`, `text`, `toolCalls`, `usage` |
| `AgentToolRun` | `turn`, `name`, `call`, `output`, `isError`, `stepId`, `ms`. With typed tools, `name` narrows `call.input` and `output` once `isError` is false. |

A model function runs inside a step, so a failure is retried. The loop stops at once on a 4xx other than 408, 409, and 429. Throw `NonRetriableError` for anything else a retry cannot fix.

### agent.anthropic

[Loop](/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-reference#choose-a-model)

```typescript {{ title: "Signature" }}
agent.anthropic(options: AnthropicOptions): AgentModel
anthropic(options: AnthropicOptions): AgentModel // the same function

```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `model` | `string` | required | The model, such as `"claude-sonnet-5-5"`. It is also the name the call is priced under. |
| `client` | `AnthropicClient` | made on first call | Your `@anthropic-ai/sdk` client. Without it the adapter imports the SDK and reads `ANTHROPIC_API_KEY`. A bundled app must pass it. |
| `apiKey`, `baseURL` | `string` | none | For the client the adapter makes. Ignored with `client`. |
| `maxTokens` | `number` | `16000` | Most tokens of one reply, thinking included. A reply cut off by it fails the step for good. |
| `effort` | `"low" \| "medium" \| "high" \| "xhigh" \| "max"` | the model's | Sent as `output_config.effort`. |
| `thinking` | `Record<string, unknown>` | not sent | The `thinking` request field. Thinking blocks stay in the history untouched. |
| `cache` | `false \| { ttl?: "5m" \| "1h" }` | `{ ttl: "5m" }` | Prompt caching. `false` sends no breakpoints. A `1h` write costs 2x instead of 1.25x. |
| `volatile` | `string \| (request) => string \| undefined` | none | Text added to the last user message after the cache breakpoint, for what changes on every call. |
| `stream` | `boolean` | on above `maxTokens` 21,000 | Streams the reply and waits for the whole message. Needs a client with `messages.stream`. |
| `timeout` | `number` | 300000 on its own client | Milliseconds before a call times out. |
| `maxRetries` | `number` | `0` on its own client | Retries inside the SDK, before the step fails and Inngest retries it. |
| `params` | `Record<string, unknown>` | none | More request fields (`metadata`, `stop_sequences`, server tools). Applied last. |

- Keep `system` fixed per agent. Put context that changes on every call in `volatile` or in a message, and never rewrite earlier context: a changed prefix misses the cache.
- Breakpoints go on the system prompt (which caches the tools with it; on the last tool when there is no system prompt), on the end of the conversation, and where the previous call's conversation ended.
- The loop sends the whole conversation unchanged, so each call reads the cached prefix of the one before. Set `compaction` on `agent.loop()` to summarise only near the context limit.
- `usage` is `{ input, output, cacheRead, cacheWrite, cacheWrite1h }`. `input` includes the cached tokens.
- A 4xx, a `refusal`, a reply cut off by `maxTokens`, `model_context_window_exceeded` and `pause_turn` throw `NonRetriableError`. A 429, 529 or 5xx is retried, after the `retry-after` the API sent when it sent one.
- Not covered: forcing one tool with `tool_choice`, a model or effort that changes per call (make one adapter for each), and a loop without `tools` that continues a history with tool calls in it.
- It never uses `step.ai`. Use `anthropicPrices` (or your own table) as `limits.price` or `price`.

Types: `AnthropicOptions`; `AnthropicClient`, the part of an `@anthropic-ai/sdk` client it calls (`messages.create`, and `messages.stream` when streaming), so any SDK client or a fake fits; `AnthropicReply`, the part of a Messages response it reads.

### Model errors and untrusted text

```typescript {{ title: "Signature" }}
agent.classifyModelError(error: unknown): unknown
agent.untrusted(text: unknown, options?: { source?: string }): string
untrustedTag: "untrusted"
```

- `classifyModelError` returns `NonRetriableError` (with the original as `cause`) for a 4xx other than 408, 409, 429, for provider types such as `invalid_request_error`, and for `insufficient_quota`. Anything else comes back as is. The loop applies it to every model call. It reads `status`, `statusCode`, `response.status`, and `$metadata.httpStatusCode`.
- `untrusted` returns the text between `<untrusted source="...">` tags and breaks any closing tag in the text. A non-string is marked as its JSON. Nothing calls it for you.

The same functions are exported by name: `classifyModelError`, `untrusted`. Type: `UntrustedOptions`.

## Calling agents

[Teams of agents](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-reference)

```typescript {{ title: "Signature" }}

  address: string,
  input: Record<string, unknown>,
```

| Export | Description |
| --- | --- |
| `callAgent(address, input, options?)` | Calls the agent whose address is `"<app>/<agentId>"` and returns its result. Throws if the agent is not shared with the caller. An agent without `invoke(schema)` takes `{ message }`. `options.id` is the step ID, default `agent:invoke:<address>`. Repeats in one run are numbered. |
| `findAgents(query?)` | The cards of the agents the caller may use that match any word of `query`, best match first. Without a query it returns them all. The read is a step. |

| Export | Description |
| --- | --- |
| `agentInvokeCancelOn` | A `cancelOn` entry (`{ event: "inngest/function.cancelled", if: "event.data.run_id == async.data._agent.parent" }`) that ends the run when the run that called it is cancelled. |
| `AgentCancelledError` | Thrown by `callAgent()` for a cancelled callee. In a loop, `call_agent` hands it to the model as the tool's result. `functionId?` and `runId?` name the cancelled run. |

## Limits, pricing, and recovery

### AgentLimits

[Events and triggers](/docs/labs/agents/teams-of-agents?ref=docs-labs-agents-reference#limit-sub-agents)

| Field | Default | Description |
| --- | --- | --- |
| `depth` | `1` | Levels of sub-agents allowed below. A sub-agent gets this minus one at most. |
| `spawn` | none | Most agent calls (`callAgent()` or `call_agent`) one run may make. A refused call does not count. |
| `mayCall` | any | Agents it may call, as `"<app>/<agentId>"` patterns where `*` matches any text. |
| `budget` | none | What the thread may spend: `AgentBudget`. |
| `price` | none | What a model call costs. Needed for `budget.usd`. |

`AgentBudget`: `tokens` (input plus output), `input`, `output`, `usd`. A field left out is not limited. `usd` without `limits.price` throws when the agent is made. A `usd` budget handed down by a parent needs the sub-agent's own `limits.price` too, since a price does not travel; its run fails without one. The handed-down `usd` budget belongs to that run and is not kept on the thread.

Limits gate agent calls only; a raw `step.invoke` or `sendEvent` bypasses them. Sub-agents inherit the limits narrowed.

`AgentLimitError` has `limit`: `"depth"`, `"spawn"`, `"mayCall"`, or `"budget"`.

### Compaction

[Loop](/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-reference#keep-long-conversations-in-the-window)

| Option | Default | Description |
| --- | --- | --- |
| `maxTokens` | required | Summarise once the conversation is estimated past this many tokens (about three characters a token). |
| `keep` | `8` | Messages at the end that are always sent whole. |
| `summarise` | the loop's `model` | `({ messages, previous? }) => Promise<string>` writes the summary. The default model call has no tools and counts in `usage`. |

`AgentCompaction` is `{ upTo, summary }`: the first `upTo` messages are replaced by `summary` when the conversation is sent. It rides in the output of the model step that made it, so a replay restores it. The `history` of the result is never summarised. Types: `AgentCompaction`, `AgentCompactionOptions`.

### Pricing

[Loop](/docs/labs/agents/reliability?ref=docs-labs-agents-reference#limit-turns-and-spend)

```typescript {{ title: "Signature" }}
type AgentPriceFunction = (usage: AgentUsage, model: string | undefined) => number
type AgentPriceTable = Record<string, {
  input: number;
  output: number;
  cacheRead?: number; // default: input
  cacheWrite?: number; // 5-minute cache, default: input
  cacheWrite1h?: number; // default: cacheWrite, then input
}> // USD per million tokens
type AgentPrice = AgentPriceFunction | AgentPriceTable
```

- `"*"` is the rate for any model not named. A table with no rate for the model and no `"*"` throws `NonRetriableError`.
- A price that is not dollars from 0 up throws `NonRetriableError`.
- The cost is worked out once, inside the model call's step.
- `input` counts cached tokens too. A call is priced with `cacheRead`, `cacheWrite` and `cacheWrite1h` at their own rates and the rest of `input` at `input`.
- `anthropicPrices` is a table with the current Claude models, cache rates included. Spread it to add or replace an entry.
