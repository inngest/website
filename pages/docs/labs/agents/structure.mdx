# Project structure

> One file per agent, tool, sandbox and model, so everything is easy to find and share.

Agents, tools, sandboxes and models are plain exports. An agent imports what it uses, and code that calls an agent imports that agent.

```
inngest/
  client.ts
  serve.ts
  events.ts
  models/
    claude.ts
  agents/
    support.ts
    reviewer.ts
  functions/
    nightlyReview.ts
  tools/
    lookupOrder.ts
  sandboxes/
    work.ts
skills/
  refunds/
    SKILL.md
app/
  api/
    slack/
      route.ts
```

## The client

The client holds the Inngest app and the agents factory. Add `sandboxMiddleware()` when any agent lists sandboxes.

{/* not type-checked: createAgents with the store from the environment, sandboxMiddleware() */}
```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { sandboxMiddleware } from "inngest/experimental";
import { createAgents } from "inngest/experimental/agents";

export const inngest = new Inngest({
  id: "support",
  middleware: [sandboxMiddleware()],
});

export const agents = createAgents(inngest);
```

## One model per file

Agents import their model, so a different model for another environment is a change to this file.

{/* not type-checked: anthropic() as a named export */}
```typescript {{ title: "inngest/models/claude.ts" }}
import { anthropic } from "inngest/experimental/agents";

export const claude = anthropic({ model: "claude-sonnet-5-5" });
```

## Event types in one file

Agents trigger on these types, and the code that sends the events imports the same ones.

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

export const question = eventType("support/question", {
  schema: z.object({ customer: z.string(), text: z.string() }),
});
```

## One tool per file

```typescript {{ title: "inngest/tools/lookupOrder.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";

export const lookupOrder = tool.step({
  description: "Find an order by ID",
  input: z.object({ id: z.string() }),
  run: async ({ id }) => {
    return { id, status: "shipped", eta: "Friday" };
  },
});
```

## One sandbox per file

```typescript {{ title: "inngest/sandboxes/work.ts" }}
import { sandbox } from "inngest/experimental/agents";

export const work = sandbox({ id: "work" });
```

## One agent per file

An agent is a module-level export, not a function that builds one from a model. It imports the client, its model and the tools and sandboxes it uses.

{/* not type-checked: agents.agent with a thread expression, tools and skills.folder */}
```typescript {{ title: "inngest/agents/support.ts" }}
import { skills } from "inngest/experimental/agents";
import { agents } from "../client";
import { question } from "../events";
import { claude } from "../models/claude";
import { lookupOrder } from "../tools/lookupOrder";

export const support = agents.agent({
  id: "support",
  triggers: [question],
  thread: "event.data.customer",
  model: claude,
  system: "You answer questions about orders. Keep it short.",
  tools: { lookupOrder },
  skills: [skills.folder("./skills")],
});
```

{/* not type-checked: an invoke() trigger on an agent that lists a sandbox */}
```typescript {{ title: "inngest/agents/reviewer.ts" }}
import { invoke } from "inngest";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";
import { work } from "../sandboxes/work";

export const reviewer = agents.agent({
  id: "reviewer",
  triggers: [invoke(z.object({ pr: z.string() }))],
  model: claude,
  system: "Review the pull request at the URL you are given.",
  sandboxes: { work },
});
```

## Plain functions beside them

Work that holds no conversation is a plain function. It lives in `functions/`, and when it starts an agent it imports it. [Agents and triggers →](/docs/labs/agents/agents-and-triggers?ref=docs-labs-agents-structure#agent-or-plain-function)

{/* not type-checked: start().result() from a plain function */}
```typescript {{ title: "inngest/functions/nightlyReview.ts" }}
import { inngest } from "../client";
import { reviewer } from "../agents/reviewer";

export const nightlyReview = inngest.createFunction(
  { id: "nightly-review", triggers: [{ cron: "TZ=UTC 0 2 * * *" }] },
  async () => {
    const pr = "https://github.com/acme/api/pull/42";

    return await reviewer.start({ pr }).result();
  },
);
```

## Skills in a folder

Each skill is a folder with a `SKILL.md`. `skills.folder("./skills")` finds them from the directory you start the app in. [Skills →](/docs/labs/agents/skills?ref=docs-labs-agents-structure)

## A route for Slack

A Slack bridge is a route in your web framework. It imports the client with a relative path. [Slack and GitHub →](/docs/labs/agents/slack-and-github?ref=docs-labs-agents-structure)

{/* not type-checked: slack.bridge() as a Web handler */}
```typescript {{ title: "app/api/slack/route.ts" }}
import { secret } from "inngest/experimental";
import { slack } from "inngest/experimental/agents";
import { inngest } from "../../../inngest/client";

export const POST = slack.bridge({
  client: inngest,
  signingSecret: secret("SLACK_SIGNING_SECRET"),
});
```

## Serve them

Import every agent file before you call `agents.functions()`, then add your plain functions to the list.

{/* not type-checked: agents.functions() spread with a plain function */}
```typescript {{ title: "inngest/serve.ts" }}
import { createServer } from "inngest/node";
import { agents, inngest } from "./client";
import { nightlyReview } from "./functions/nightlyReview";
import "./agents/reviewer";
import "./agents/support";

createServer({
  client: inngest,
  functions: [...agents.functions(), nightlyReview],
}).listen(3000);
```

## Grow it

When a folder gets crowded, group by area. Imports stay relative.

```
inngest/
  agents/
    support/
      triage.ts
      refunds.ts
    release/
      watcher.ts
  tools/
    github/
      listIssues.ts
      commentOnIssue.ts
```

## How it works

- An agent registers when its file is imported, and `agents.functions()` returns what is registered, so `serve.ts` imports each agent.
- Tools, sandboxes and models are plain definitions with no client, so many agents share one.
- A plain function is served in the same list as the agents.
