# Agents

> Define an agent, choose what starts it, and decide whether the SDK runs the model loop or your own handler does.

<Info>
  Inngest Agents is an Inngest Labs project: early, moving fast, and shaped by your feedback. [What's Labs?](/docs/labs?ref=docs-labs-agents-agents)
</Info>

An agent is an Inngest function you define with `agents.agent()`. Inngest starts it from its triggers, retries what fails, and records every run. An agent adds three things to a plain function: a [thread](/docs/labs/agents/threads?ref=docs-labs-agents-agents) that keeps each conversation, an [inbox](/docs/labs/agents/inboxes?ref=docs-labs-agents-agents) that receives messages while it works, and a [model loop](/docs/labs/agents/models?ref=docs-labs-agents-agents) that calls the model and its tools.

## Define an agent

Pass a definition to `agents.agent()`. The `agents` object comes from `createAgents()` in your [client](/docs/labs/agents/quick-start?ref=docs-labs-agents-agents#2-create-the-client).

```typescript {{ title: "inngest/agents/support.ts" }}
import { agents } from "../client";
import { ticketOpened } from "../events";
import { claude } from "../models/claude";

export const support = agents.agent({
  id: "support",
  triggers: [ticketOpened],
  thread: "event.data.ticket",
  model: claude,
  system: "You answer support tickets.",
});
```

- `id` names the agent. Its address is `<app id>/<agent id>`, such as `acme/support`, which other agents use to start it.
- `triggers` says what starts a run. See [Add triggers](#add-triggers).
- `thread` names the conversation an event belongs to. See [Threads](/docs/labs/agents/threads?ref=docs-labs-agents-agents).
- `model` and `system` give the agent a model loop. With them and no handler, each message goes to the model, and the model's answer is the run's output.

Only `id` is required. The [Agents reference](/docs/labs/agents/reference?ref=docs-labs-agents-agents#the-definition) lists every field.

## Add triggers

An agent takes the same triggers as an Inngest function: event types, event names, cron schedules, and `invoke()`.

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

export const ticketOpened = eventType("ticket/opened", {
  schema: z.object({ ticket: z.string(), text: z.string() }),
});

export const ticketReplied = eventType("ticket/replied", {
  schema: z.object({ ticket: z.string(), text: z.string() }),
});
```

```typescript {{ title: "inngest/agents/support.ts" }}
import { agents } from "../client";
import { ticketOpened, ticketReplied } from "../events";
import { claude } from "../models/claude";

export const support = agents.agent({
  id: "support",
  triggers: [ticketOpened, ticketReplied, { cron: "0 9 * * 1-5" }],
  thread: "event.data.ticket",
  model: claude,
  system: "You answer support tickets.",
});
```

- **Events.** Each trigger types `event` in a handler. A trigger can set its own `thread` expression when its event names the conversation differently. See [Threads](/docs/labs/agents/threads?ref=docs-labs-agents-agents#give-a-trigger-its-own-key).
- **Schedules.** A `{ cron }` trigger starts a run on a schedule.
- **`invoke()`.** `invoke(schema)` from `inngest` types the input that your code or other agents pass to `start()`. See [Agent teams](/docs/labs/agents/agent-teams?ref=docs-labs-agents-agents).

An agent with no triggers can still be started from code with `start()`, or by another agent's model.

## Add a handler

Pass a function as the second argument to take control of the run. What it returns is the run's output.

<AnnotatedCode>

```typescript {{ title: "inngest/agents/support.ts" }}
import { agents } from "../client";
import { ticketOpened, ticketReplied } from "../events";
import { claude } from "../models/claude";

export const support = agents.agent(
  {
    id: "support",
    triggers: [ticketOpened, ticketReplied],
    thread: "event.data.ticket",
    model: claude,
    system: "You answer support tickets.",
  },
  async ({ event, inbox, loop }) => {
    if (event.is(ticketOpened)) {
      console.log(`New ticket: ${event.data.text}`);
    }

    let answer = "";

    for await (const batch of inbox.batches()) {
      const result = await loop(batch);

      answer = result.text;
    }

    return answer;
  },
);
```

<Annotation id="event" lines="14-16" tease="the event that started it" title="event" href="/docs/durable-execution/guides-and-advanced/events-and-triggers/event-payloads-and-schemas?ref=docs-labs-agents-agents#narrow-an-event-with-is" linkText="Narrow an event with is()">
The event that started the run. `event.is()` checks which trigger it was and types `event.data` to match.
</Annotation>

<Annotation id="inbox" lines="20" tease="messages on the thread" title="inbox" href="/docs/labs/agents/inboxes?ref=docs-labs-agents-agents" linkText="Inboxes">
The first batch includes the event that started the run. Later batches hold what arrived while the run worked. The loop ends when the inbox is empty.
</Annotation>

<Annotation id="loop" lines="21" tease="the model loop" title="loop()" href="/docs/labs/agents/models?ref=docs-labs-agents-agents#write-a-handler" linkText="Models and the loop">
Runs the model and its tool calls on a batch. `loop` is only in the handler's argument when the agent has a `model`.
</Annotation>

</AnnotatedCode>

The handler's argument has everything a function handler has, such as `step`, `group`, `runId`, and `logger`, plus:

| Field | What it is |
| --- | --- |
| `inbox` | The messages on this run's thread. See [Inboxes](/docs/labs/agents/inboxes?ref=docs-labs-agents-agents). |
| `loop` | Runs the model loop on a batch of messages. See [Models and the loop](/docs/labs/agents/models?ref=docs-labs-agents-agents). |
| `thread` | The run's thread: its `key`, and methods to message it or watch more events. See [Threads](/docs/labs/agents/threads?ref=docs-labs-agents-agents). |
| `kv.thread` | Values you keep on the thread between runs. See [Threads](/docs/labs/agents/threads?ref=docs-labs-agents-agents#keep-your-own-state). |
| `previousRun` | How the last run on this thread ended, or `undefined` on its first run. |
| `sandboxes` | The thread's sandboxes, for your own commands. See [Sandboxes](/docs/labs/agents/sandboxes?ref=docs-labs-agents-agents#run-commands-from-your-handler). |
| `score` | Records a score on the run. See [Observability](/docs/labs/agents/observability?ref=docs-labs-agents-agents). |

An agent with no model and no handler runs and ends with no output.

## Use steps

A handler is a durable function body. Wrap work that calls other services in `step.run()`, so a failure retries only that step and finished steps return their saved results.

<AnnotatedCode>

```typescript {{ title: "inngest/agents/support.ts" }}
import { agents } from "../client";
import { ticketOpened, ticketReplied } from "../events";
import { helpdesk } from "../lib/helpdesk";
import { claude } from "../models/claude";

export const support = agents.agent(
  {
    id: "support",
    triggers: [ticketOpened, ticketReplied],
    thread: "event.data.ticket",
    model: claude,
    system: "You answer support tickets.",
  },
  async ({ inbox, loop, step, thread }) => {
    for await (const batch of inbox.batches()) {
      const result = await loop(batch);

      await step.run("send-reply", async () => {
        return await helpdesk.reply(thread.key, result.text);
      });
    }
  },
);
```

<Annotation id="step" lines="18-20" tease="retried alone" title="step.run()" href="/docs/durable-execution/primitives/step-run?ref=docs-labs-agents-agents" linkText="step.run">
If the helpdesk API fails, only this step retries. The model calls before it aren't repeated.
</Annotation>

</AnnotatedCode>

The loop already makes each model call and tool call a step. Code outside a step runs again each time the run resumes, so keep side effects inside steps.

## Set function options

An agent accepts the [`createFunction` options](/docs/reference/typescript/v4/functions/create?ref=docs-labs-agents-agents) that apply to it, such as `name`, `retries`, `concurrency`, `throttle`, `cancelOn`, and `onFailure`. They're passed through to the function that runs the agent.

```typescript
export const support = agents.agent({
  id: "support",
  triggers: [ticketOpened, ticketReplied],
  thread: "event.data.ticket",
  model: claude,
  system: "You answer support tickets.",
  concurrency: { limit: 10 },
  retries: 5,
});
```

## Serve agents

`agents.functions()` returns every agent you defined, plus the functions that hold their threads and deliver their results. Import each agent file before you call it, and add your plain functions to the list.

```typescript {{ title: "inngest/serve.ts" }}
import { createServer } from "inngest/node";
import { agents, inngest } from "./client";
import { nightlyReport } from "./functions/nightlyReport";
import "./agents/support";

createServer({
  client: inngest,
  functions: [...agents.functions(), nightlyReport],
}).listen(3000);
```

Each agent is served as several functions, so the Dev Server lists more functions than you have agents. Serve all of them. [Project structure](/docs/labs/agents/structure?ref=docs-labs-agents-agents) shows where each file lives.

## Start an agent from code

Every agent has `start()`, which starts a run and returns a handle. Wait for the run's output with `result()`.

```typescript
const answer = await support.start("Where is order 7?").result();
```

`start()` opens a new thread unless you pass one: `support.start(input, { thread: "T-1" })`. The handle can also message the run and ask it questions while it works. See [Agent teams](/docs/labs/agents/agent-teams?ref=docs-labs-agents-agents).
