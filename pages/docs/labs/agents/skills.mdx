# Skills

> Teach an agent how your team does things in plain files: skills are read, tools are called.

A skill is a folder with a `SKILL.md`: a name, a description and instructions. This page adds one to the PR helper, built up through [Threads](/docs/labs/agents/threads?ref=docs-labs-agents-skills), [Inboxes](/docs/labs/agents/inboxes?ref=docs-labs-agents-skills), [Models](/docs/labs/agents/models?ref=docs-labs-agents-skills) and [Tools](/docs/labs/agents/tools?ref=docs-labs-agents-skills).

## A skill

To have the PR helper review the way your team does, write the checklist as a skill.

<AnnotatedCode>

```markdown {{ title: "skills/review-checklist/SKILL.md" }}
---
name: review-checklist
description: How we review a pull request. Use before reviewing any PR.
---

# Review checklist

1. Read the CI log first.
2. Check that every changed function has a test.
3. Run the linter.
4. Say what is fine as well as what is wrong.
```

<Annotation id="name" lines="2" tease="what the model opens" title="Name">
The model passes this name to `open_skill`.
</Annotation>

<Annotation id="description" lines="3" tease="always in the prompt" title="Description">
Say what the skill is for and when to open it. The model decides from this line.
</Annotation>

</AnnotatedCode>

List the folder on the agent.

<AnnotatedCode>

{/* not type-checked: skills.folder() on an agent */}
```typescript {{ title: "inngest/agents/prHelper.ts" }}
import { github, skills } from "inngest/experimental/agents";
import { agents } from "../client";
import { ciFailed, ciPassed, deployed } from "../events";
import { claude } from "../models/claude";
import { readLog } from "../tools/readLog";

const triggers = [
  github.thread({ repos: ["acme/web"] }),
  { event: ciFailed, thread: "event.data.prUrl" },
  { event: deployed, thread: "event.data.pull.url" },
];

export const prHelper = agents.agent(
  {
    id: "pr-helper",
    triggers,
    inbox: [{ event: ciPassed, thread: "event.data.prUrl" }],
    idle: "1h",
    model: claude,
    system: "You help with pull requests on acme/web.",
    budget: { usd: 0.5 },
    tools: { readLog, ...github.tools() },
    listen: [ciPassed, ciFailed],
    skills: [skills.folder("./skills")],
  },
  async ({ inbox, me, loop }) => {
    me.post("Looking at it.");

    for await (const batch of inbox.batches({ max: 20 })) {
      const result = await loop(batch);

      if (result.end === "budget") {
        await me.post("This PR is out of budget.");

        return;
      }

      await me.post(result.text);
    }
  },
);
```

<Annotation id="skills" lines="24" tease="ships with your deploy" title="Skills" href="/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-skills#skills" linkText="Reference: skills">
One folder per skill. The path resolves against the working directory when the agent is defined, so ship the folder with your app.
</Annotation>

</AnnotatedCode>

Asked for a review, the model opens the checklist with `open_skill`, and not before. A pack in a repo is listed the same way, `skills.repo("acme/skills")`; it changes without a deploy, and a private one takes `auth`.

The files it imports are as those pages left them:

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

const ciRun = z.object({ pr: z.number(), prUrl: z.string() });

export const ciFailed = eventType("ci/run.failed", { schema: ciRun });

export const ciPassed = eventType("ci/run.passed", { schema: ciRun });

export const deployed = eventType("deploy/finished", {
  schema: z.object({ env: z.string(), pull: z.object({ url: z.string() }) }),
});
```

```typescript {{ title: "inngest/lib/ci.ts" }}
export const fetchLog = async (pr: number) => {
  const response = await fetch(`https://ci.acme.test/prs/${pr}/log`);

  if (!response.ok) {
    throw new Error(`CI log for #${pr}: ${response.status}`);
  }

  return await response.text();
};
```

```typescript {{ title: "inngest/tools/readLog.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";
import { fetchLog } from "../lib/ci";

export const readLog = tool.step({
  description: "Reads the CI log of a pull request",
  input: z.object({ pr: z.number() }),
  run: async ({ pr }) => {
    return await fetchLog(pr);
  },
});
```

## Skills add no tools

To see what a skill can't do, look at step 3 of the checklist: "Run the linter". The PR helper has no tool for that, so the model says it can't.

{/* not type-checked: a lint tool listed beside readLog */}
```typescript
tools: { lint, readLog, ...github.tools() },
```

Listing a `lint` tool makes the step work. A skill names tools but never adds one, and its scripts, which land in the first sandbox the model can use at `/skills/<name>/`, act only by calling tools. [Sandboxes →](/docs/labs/agents/sandboxes?ref=docs-labs-agents-skills)
