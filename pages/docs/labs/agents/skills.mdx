# Skills

> Teach an agent how your team does things, in plain `SKILL.md` files from your app or a repo.

A skill is a folder with a `SKILL.md`: a name, a description and instructions. The model sees every name and description, and opens the instructions when they apply.

- **Plain files.** `SKILL.md` is a format other agent tools read too. [Write a skill →](#write-a-skill)
- **From your app or a repo.** A folder ships with a deploy; a repo changes without one. [Read a repo →](#read-a-repo)
- **Read on demand.** The prompt carries names and descriptions; instructions load when needed. [Open a skill →](#open-a-skill)
- **Scripts and files too.** They land in the first sandbox the model can use. [Ship files and scripts →](#ship-files-and-scripts)
- **Read, then call.** A skill never adds a tool. [Skills and tools →](#skills-and-tools)

```typescript {{ title: "inngest/agents/support.ts" }}
import { skills, slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const support = agents.agent({
  id: "support",
  triggers: [slack.thread()],
  model: claude,
  system: "You answer support questions.",
  skills: [

    skills.repo("inngest/inngest-skills"),
  ],
});
```

## Write a skill

`SKILL.md` carries the name and description in its front matter, then the instructions; scripts and files sit beside it.

```text {{ title: "Your app" }}
skills/
  refund-policy/
    SKILL.md
    check.py
  shipping/
    SKILL.md
```

<AnnotatedCode>

```markdown {{ title: "skills/refund-policy/SKILL.md" }}
---
name: refund-policy
description: When an order can be refunded. Use for any refund question.
---

# Refund policy

1. Look the order up with the `lookupOrder` tool.
2. Orders delivered under 30 days ago are refundable in full.
3. Older orders get store credit, never cash.
4. Run `python /skills/refund-policy/check.py <order-id>`.
```

<Annotation id="name" lines="2" tease="what the model opens" title="Name" href="#open-a-skill" linkText="Open a skill">
The model passes this name to `open_skill`. Each skill on an agent has its own.
</Annotation>

<Annotation id="description" lines="3" tease="always in the prompt" title="Description" href="#open-a-skill" linkText="Open a skill">
Say what the skill is for and when to open it. This line is how the model decides.
</Annotation>

## Read a repo

Public repos need no `auth`. A private repo is read with it on your host, and the token never reaches the sandbox or a snapshot of it.

{/* not type-checked: skills.repo with ref, path and auth from githubApp() */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/internal.ts" }}
import { secret } from "inngest/experimental";
import { githubApp, skills, slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";

export const internal = agents.agent({
  id: "internal",
  triggers: [slack.thread()],
  model: claude,
  system: "You answer questions about how we work.",
  skills: [
    skills.repo("acme/handbook", {
      ref: "main",
      path: "skills",
      auth: githubApp({
        appId: process.env.GITHUB_APP_ID ?? "",
        privateKey: secret("GITHUB_APP_PRIVATE_KEY"),
      }),
    }),
  ],
});
```

<Annotation id="ref" lines="13" tease="branch, tag or commit" title="ref">
Which version of the repo to read.
</Annotation>

<Annotation id="path" lines="14" tease="where the skills are" title="path">
The folder in the repo that holds the skill folders.
</Annotation>

<Annotation id="auth" lines="15-18" tease="a private repo" title="auth" href="/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-skills#check-out-a-repo" linkText="GitHub App credentials">
A `githubApp()` or a token, for a private repo.

## Open a skill

The model opens a skill's instructions with one fixed tool, and only an agent with skills has it.

```text {{ title: "What the model calls" }}
open_skill({ name: "refund-policy" })
```

## Ship files and scripts

Files beside `SKILL.md` go to the first sandbox the model can use, at `/skills/<name>/`. The model runs a script there like any other file.

{/* not type-checked: skills with tools and a sandbox on one agent */}
<AnnotatedCode>

```typescript {{ title: "inngest/agents/helpdesk.ts" }}
import { skills, slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";
import { work } from "../sandboxes/work";
import { lookupOrder } from "../tools/lookupOrder";

export const helpdesk = agents.agent({
  id: "helpdesk",
  triggers: [slack.thread()],
  model: claude,
  system: "You answer support questions about orders.",
  tools: { lookupOrder },
  sandboxes: { work },
  skills: [skills.folder("./skills")],
});
```

`refund-policy` names `lookupOrder`, so the agent lists it too.

`work` is the first sandbox the model can use, so the skill's files go there.

An app whose agents list sandboxes adds `sandboxMiddleware()` to its client. [Sandboxes and code →](/docs/labs/agents/sandboxes-and-code?ref=docs-labs-agents-skills)

```typescript {{ title: "inngest/tools/lookupOrder.ts" }}
import { tool } from "inngest/experimental";
import { z } from "zod";

export const lookupOrder = tool.step({
  description: "Find an order by ID",
  input: z.object({ id: z.string() }),
  run: async ({ id }) => {
    return { id, status: "delivered", deliveredDaysAgo: 12 };
  },
});
```

## Skills and tools

A skill can name a tool, and its scripts can run, but a skill never adds a tool. The agent has to list it, and anything a skill does in your app goes through that tool's credentials and checks. [Tools →](/docs/labs/agents/tools?ref=docs-labs-agents-skills)

## Gotchas

- **A repo is read once per run.** An edit shows up on the next run, not partway through one.
- **A failed read is logged, not raised.** The agent carries on without those skills, so check the logs if a skill goes missing.
- **Names can't repeat.** Two skills with one name among your folders are an error when the agent is defined. A repo is read at run time, so a clash with its skills gives a warning on the trace, and the first source listed wins.
- **No sandbox, no scripts.** Without a sandbox the model reads the instructions and nothing runs.

## How it works

- The instructions load through `open_skill`, one fixed tool for every skill, so the tool list at the front of the prompt never changes and prompt caching holds.
- A repo is read on your host with GitHub's tarball endpoint for its `ref` and `path`.
