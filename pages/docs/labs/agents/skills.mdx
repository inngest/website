# Skills

> Teach an agent how your team does things, in plain files you can change without a deploy.

A skill is a folder with a `SKILL.md`: a name, a description and instructions. The model sees every name and description, and opens the instructions when they apply.

- **Plain files.** `SKILL.md` is a format other agent tools read too. [Write a skill →](#write-a-skill)
- **From your app or a repo.** A folder ships with a deploy; a repo changes without one. [Add skills →](#add-skills-to-an-agent)
- **Read on demand.** The prompt carries names and descriptions; instructions load when needed. [Open a skill →](#open-a-skill)
- **Scripts and files too.** They land in the agent's sandbox. [Ship files and scripts →](#ship-files-and-scripts)
- **Read, then call.** A skill never adds a tool, so it can't widen what an agent may do. [Skills and tools →](#skills-are-read-tools-are-called)

## Write a skill

A skill is a folder. `SKILL.md` carries the name and description in its front matter, then the instructions. Scripts and files sit beside it.

```text {{ title: "Your app" }}
skills/
  refund-policy/
    SKILL.md
    check.py
  shipping/
    SKILL.md
```

<AnnotatedCode>

```markdown {{ title: "skills/refund-policy/SKILL.md" }}
---
name: refund-policy
description: When an order can be refunded. Use for any refund question.
---

# Refund policy

1. Look the order up with the `lookupOrder` tool.
2. Orders delivered under 30 days ago are refundable in full.
3. Older orders get store credit, never cash.
4. Run `python /skills/refund-policy/check.py <order-id>`.
```

## Add skills to an agent

`skills` takes a list of sources. List a folder, a repo or both.

- **`skills.folder(path)`** reads skills shipped with your app, so they change with a deploy. The path resolves against the working directory when the agent is defined, so ship the folder with your app.
- **`skills.repo("owner/name")`** reads skills from a repo, so a fix reaches every agent that lists it with no deploy.

```typescript
skills.repo("acme/skills", { ref: "main", path: "support" })
```

- **`ref`** picks the branch, tag or commit to read.
- **`path`** is the folder in the repo that holds the skill folders.
- **`auth`** reads a private repo. [Read a private repo →](#read-a-private-repo)

## Open a skill

The prompt carries each skill's name and description. When one applies, the model opens its instructions with one fixed tool.

```typescript
open_skill({ name: "refund-policy" })
```

It returns the skill's instructions as text. Only an agent with skills has `open_skill`, and it works with no sandbox.

## Ship files and scripts

Files beside `SKILL.md` go to the first sandbox the model can use among the agent's listed sandboxes, at `/skills/<name>/`. The model runs a script there like any other file. With no sandbox, the model gets the instructions only.

<AnnotatedCode>

{/* not type-checked: skills with tools and a sandbox on one agent */}
```typescript {{ title: "inngest/agents/helpdesk.ts" }}
import { skills, slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { claude } from "../models/claude";
import { work } from "../sandboxes/work";
import { lookupOrder } from "../tools/lookupOrder";

export const helpdesk = agents.agent({
  id: "helpdesk",
  triggers: [slack.thread()],
  model: claude,
  system: "You answer support questions about orders.",
  tools: { lookupOrder },
  sandboxes: { work },
  skills: [skills.folder("./skills")],
});
```

## Skills are read, tools are called

A skill can name a tool, and its scripts can run, but a skill never adds a tool. Anything it does in your app goes through a tool the agent already has, with that tool's credentials and checks.

So a skill can't widen what an agent may do. A skill that names a tool the agent doesn't list can't use it, and the model's tool list is the same whichever skills are listed. [Tools →](/docs/labs/agents/tools?ref=docs-labs-agents-skills)

## Read a private repo

Public repos need no token. For a private repo, pass `auth`: a `githubApp()` or a token. Your host reads the repo with it, and the token never reaches the sandbox or a snapshot of it.

{/* not type-checked: skills.repo with auth from githubApp() */}
```typescript {{ title: "inngest/agents/internal.ts" }}
import { skills, slack } from "inngest/experimental/agents";
import { agents } from "../client";
import { app } from "../github";
import { claude } from "../models/claude";

export const internal = agents.agent({
  id: "internal",
  triggers: [slack.thread()],
  model: claude,
  system: "You answer questions about how we work.",
  skills: [
    skills.repo("acme/handbook", {
      path: "skills",
      auth: app,
    }),
  ],
});
```

{/* not type-checked: githubApp() with a secret() private key */}
```typescript {{ title: "inngest/github.ts" }}
import { secret } from "inngest/experimental";
import { githubApp } from "inngest/experimental/agents";

export const app = githubApp({
  appId: process.env.GITHUB_APP_ID ?? "",
  privateKey: secret("GITHUB_APP_PRIVATE_KEY"),
});
```

## Skills on the card

The agent's card lists each skill's name and description, read from the `SKILL.md` files, so other agents can decide whether to call it. [Discovery →](/docs/labs/agents/discovery?ref=docs-labs-agents-skills)

## Gotchas

- **A repo is read once per run.** An edit shows up on the next run, not partway through one.
- **A failed read is logged, not raised.** The agent carries on without those skills, so check the logs if a skill goes missing.
- **Names can't repeat.** Two skills with the same name are an error when the agent is defined.
- **No sandbox, no scripts.** Without a sandbox the model reads the instructions and nothing runs.
- **The card can lag.** A card is announced when the app syncs, so it may list a skill from a repo that a run no longer sees.

## How it works

- The prompt carries each skill's name and description. The instructions load through `open_skill`, one fixed tool for every skill, so the tool list at the front of the prompt never changes and prompt caching holds.
- A skill is text and files, so anyone can write and share one, and no host code is involved.
- The card's skills are the agent's own, so you list a skill once and the card follows.
