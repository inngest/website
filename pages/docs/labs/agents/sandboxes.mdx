# Sandboxes

> Give each thread its own machine, so the model runs code there and not in your app.

<Info>
  Inngest Agents is an Inngest Labs project: early, moving fast, and shaped by your feedback. [What's Labs?](/docs/labs?ref=docs-labs-agents-sandboxes)
</Info>

A sandbox is an isolated [Inngest Sandbox](/docs/sandboxes/overview?ref=docs-labs-agents-sandboxes) microVM that belongs to one [thread](/docs/labs/agents/threads?ref=docs-labs-agents-sandboxes). List a sandbox on an agent, and the model gets tools to run commands and work with files on it. The sandbox starts the first time it's used, pauses when the run ends, and resumes with its files on the thread's next run.

## Give an agent a sandbox

Define a sandbox with `sandbox()`, then list it in the agent's `sandboxes`. Defining a sandbox creates nothing until a run uses it.

```typescript {{ title: "inngest/sandboxes/work.ts" }}
import { sandbox } from "inngest/experimental/agents";

export const work = sandbox({ id: "work" });
```

<AnnotatedCode>

```typescript {{ title: "inngest/agents/prHelper.ts" }}
import { agents } from "../client";
import { ciFailed, prComment, prOpened } from "../events";
import { claude } from "../models/claude";
import { work } from "../sandboxes/work";
import { comment } from "../tools/comment";

export const prHelper = agents.agent({
  id: "pr-helper",
  triggers: [prOpened, prComment, ciFailed],
  thread: "event.data.pr",
  model: claude,
  system: "You help with pull requests on acme/web. Run the failing test before you explain it.",
  tools: { comment },
  sandboxes: { work },
});
```

An app whose agents use sandboxes adds `sandboxMiddleware()` to its client, next to `inboxMiddleware()`:

```typescript {{ title: "inngest/client.ts" }}
import { Inngest } from "inngest";
import { inboxMiddleware, sandboxMiddleware } from "inngest/experimental";
import { createAgents } from "inngest/experimental/agents";

export const inngest = new Inngest({
  id: "acme-web",
  middleware: [inboxMiddleware(), sandboxMiddleware()],
});

export const agents = createAgents(inngest);
```

## A sandbox lasts as long as its thread

Each thread has its own sandbox, and each run on the thread uses the same one. For pull request 42:

```text {{ title: "Two runs on one thread" }}
09:00  ci/run.failed   work_run: npm install    the sandbox starts
09:04  the run ends                             the sandbox pauses
11:30  ci/run.failed   work_run: npm test       the sandbox resumes, node_modules is still there
```

The shell keeps its working directory and exported variables between calls, and between runs.

## Choose the model's tools

A sandbox gives the model `run` by default. Set `tools` to choose from the built-in tools in `sandbox.tools`, and use `.with()` to set their options.

```typescript {{ title: "inngest/sandboxes/work.ts" }}
import { sandbox } from "inngest/experimental/agents";

const { run, read, edit, search } = sandbox.tools;

export const work = sandbox({
  id: "work",
  cwd: "/work",
  tools: { run: run.with({ timeout: "10m" }), read, edit, search },
});
```

The model sees each tool as `<sandbox>_<tool>`: `work_run`, `work_read`, `work_edit`, and `work_search`.

| Tool | What it does |
| --- | --- |
| `run` | Runs a shell command. |
| `read` | Reads a file. |
| `edit` | Replaces text in a file. |
| `write` | Writes a file. |
| `search` | Searches file contents. |
| `runCode` | Runs a Python or JavaScript script that can call your tools. See [Call your tools from a sandbox](/docs/labs/agents/call-tools-from-sandboxes?ref=docs-labs-agents-sandboxes). |

A tool of your own listed in `tools` acts on the same machine: a `tool.group()` receives it as `context.sandbox`. See [Code tools](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-sandboxes#code-tools).

## Check out a repository

Give the sandbox a `repo`, and it's checked out when the sandbox starts. The model's shell starts in the checkout.

<AnnotatedCode>

```typescript {{ title: "inngest/sandboxes/work.ts" }}
import { secret } from "inngest/experimental";
import { sandbox } from "inngest/experimental/agents";

export const work = sandbox({
  id: "work",
  repo: {
    url: "https://github.com/acme/web",
    auth: {
      read: secret("GITHUB_READ_TOKEN"),
      write: secret("GITHUB_WRITE_TOKEN"),
    },
    policy: (push) => {
      if (push.branch === "main") {
        return { refuse: "Never push to main." };
      }
    },
  },
});
```

<Annotation id="repo" lines="6-7" tease="checked out at /work" title="repo" href="/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-sandboxes#repos" linkText="Repos">
A GitHub URL or `owner/name`. Set `ref` to check out a branch, tag, or commit.
</Annotation>

<Annotation id="auth" lines="8-11" tease="read in, write out" title="auth">
The read token goes into the sandbox to clone the repository. The write token stays in your app, which does the push.
</Annotation>

<Annotation id="policy" lines="12-16" tease="runs in your app" title="policy">
Sees each push's `branch`, `commits`, and `paths` before anything is pushed. A refusal goes back to the model as an error it can read.
</Annotation>

</AnnotatedCode>

With a `repo`, the model also gets `work_push`: it commits in the sandbox, and your app pushes. To keep the sandbox read-only, pass a single read-only `secret()` as `auth` and set `push: false`.

`repo` can also be a function of the run, for example to check out the pull request a thread is about:

```typescript
repo: ({ thread }) => {
  return {
    url: "https://github.com/acme/web",
    ref: `refs/pull/${thread.key}/head`,
    auth: secret("GITHUB_READ_TOKEN"),
    push: false,
  };
},
```

## Run commands from your handler

In a handler, `sandboxes.work` is the thread's machine. Each command you run is a durable step.

```typescript
async ({ inbox, sandboxes }) => {
  for await (const batch of inbox.batches()) {
    const tests = await sandboxes.work.commands.run("run-tests", "npm test");

    const sha = await sandboxes.work.$`git rev-parse HEAD`.text();
  }
},
```

- `commands.run()` returns the command's exit code and output, whatever the exit code.
- `` $`...` `` runs in the sandbox's `cwd`, and fails its step on a non-zero exit code.

To use a sandbox from your handler only, and keep it away from the model, list it with `model: false`:

```typescript
sandboxes: { work: work.with({ model: false }) },
```

The model then has no `work_` tools. See [The handler's sandbox](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-sandboxes#the-handler-s-sandbox) for every method.

## Size the machine

`sandbox()` also takes the machine's `image`, `vcpu`, `memoryMb`, `environment`, and `secrets`, and a `setup` function that runs when the sandbox first starts. Only the read token and the values in `secrets` enter the sandbox. See [sandbox()](/docs/labs/agents/reference-sandboxes?ref=docs-labs-agents-sandboxes#sandbox).
