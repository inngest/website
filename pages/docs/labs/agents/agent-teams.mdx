# Agent Teams

> Start another agent, talk to it while it works, and get its answer back.

Messages arrive in your [inbox](/docs/labs/agents/inboxes?ref=docs-labs-agents-agent-teams); results return to your call. Below, the PR helper from [Calling home](/docs/labs/agents/calling-home?ref=docs-labs-agents-agent-teams) gets a reviewer.

## A second agent

You want a reviewer the PR helper can hand pull requests to.

```typescript {{ title: "inngest/agents/reviewer.ts" }}
import { invoke } from "inngest";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";

export const reviewer = agents.agent({
  id: "reviewer",
  triggers: [invoke(z.object({ pr: z.number() }))],
  model: claude,
  system: "You review pull requests and list the problems.",
});
```

`invoke()` types the agent's input: `pr` is the pull request's number. With no handler, its output is the model's last answer.

## Call it from code

You want the review back in the PR helper's code, to comment on the PR once CI passes. `start()` the reviewer in the handler and wait for its `result()`.

<AnnotatedCode>

```typescript {{ title: "inngest/agents/prHelper.ts" }}
import { agents } from "../client";
import { ciFailed, ciPassed, deployed, prComment, prOpened } from "../events";
import { gh } from "../lib/github";
import { claude } from "../models/claude";
import { reviewer } from "./reviewer";

const triggers = [
  prOpened,
  prComment,
  ciFailed,
  { event: deployed, thread: "event.data.pull" },
];

export const prHelper = agents.agent(
  {
    id: "pr-helper",
    triggers,
    thread: "event.data.pr",
    inbox: [ciPassed],
    model: claude,
    system: "You help with pull requests on acme/web.",
  },
  async ({ inbox, loop, thread, step }) => {
    for await (const batch of inbox.batches({ max: 20 })) {
      const result = await loop(batch);

      await step.run("comment", async () => {
        return await gh.comment(Number(thread.key), result.text);
      });

      const passed = batch.some((message) => {
        return message.is(ciPassed);
      });

      if (passed) {
        const review = await reviewer.start({ pr: Number(thread.key) }).result();

        await step.run("comment review", async () => {
          return await gh.comment(Number(thread.key), review);
        });
      }
    }
  },
);
```

<Annotation id="result" lines="37" tease="waits for the answer" title="start() and result()">
`start()` returns at once. `result()` waits for the answer, a string here, and throws if the run fails or is stopped.
</Annotation>

</AnnotatedCode>

A run opened through a handle ends once it has answered, so `result()` returns promptly — the run itself is short-lived either way. It waits only for the runs its own model started with `start_agent`, never for `start()` calls your code made. [Short-lived runs →](/docs/labs/agents/reference?ref=docs-labs-agents-agent-teams#short-lived-runs)

`start()` opens a new thread each time. To keep one thread, and its sandbox and history, across runs, pass its key: `reviewer.start({ pr: 42 }, { thread: "42" })`. The input is still typed by the `invoke()` trigger.

The rest of the PR helper is as [Calling home](/docs/labs/agents/calling-home?ref=docs-labs-agents-agent-teams) left it. The events and the GitHub client are as [Threads](/docs/labs/agents/threads?ref=docs-labs-agents-agent-teams), [Inboxes](/docs/labs/agents/inboxes?ref=docs-labs-agents-agent-teams) and [Tools](/docs/labs/agents/tools?ref=docs-labs-agents-agent-teams#your-own-git-hub-tools) left them:

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

const ciRun = z.object({ pr: z.number() });

export const prOpened = eventType("pr/opened", {
  schema: z.object({ pr: z.number(), author: z.string() }),
});

export const prComment = eventType("pr/comment", {
  schema: z.object({ pr: z.number(), author: z.string(), body: z.string() }),
});

export const ciFailed = eventType("ci/run.failed", { schema: ciRun });

export const ciPassed = eventType("ci/run.passed", { schema: ciRun });

export const deployed = eventType("deploy/finished", {
  schema: z.object({ env: z.string(), pull: z.number() }),
});
```

```typescript {{ title: "inngest/lib/github.ts" }}
const api = "https://api.github.com/repos/acme/web";

export const gh = {
  comment: async (pr: number, body: string) => {
    const response = await fetch(`${api}/issues/${pr}/comments`, {
      method: "POST",
      headers: {
        accept: "application/vnd.github+json",
        authorization: `Bearer ${process.env.GITHUB_TOKEN}`,
      },
      body: JSON.stringify({ body }),
    });

    if (!response.ok) {
      throw new Error(`Comment on #${pr}: ${response.status}`);
    }

    return await response.json();
  },
};
```

## Talk while it works

You want to correct or question the reviewer while it works, and the handle `start()` returns lets you.

<AnnotatedCode>

```typescript
const review = await reviewer.start({ pr: Number(thread.key) });

await review.message("The author says the migration is safe to skip.");

const worry = await review.ask("Which file worries you most?");

await review.stop();
```

<Annotation id="message" lines="3" tease="doesn't wait" title="message()">
Lands in the reviewer's inbox and reaches its next model call.
</Annotation>

<Annotation id="ask" lines="5" tease="waits for the answer" title="ask()">
Gives `null` after an hour or when the reviewer refuses. `{ timeout }` changes the hour.
</Annotation>

<Annotation id="stop" lines="7" tease="cancels the run" title="stop()">
A `result()` waiting on this run throws.
</Annotation>

</AnnotatedCode>

Once the reviewer has answered, its run is over. `message()` and `ask()` then start a run on the same thread, which picks up its history:

```typescript
const second = await review.message("Now check the tests.").result();
```

## Being talked to

You want the reviewer to be able to ask the PR helper a question.

```typescript
import { agentQuestion } from "inngest/experimental/agents";

await reviewer.start({ pr: Number(thread.key) });

for await (const batch of inbox.batches()) {
  for (const message of batch) {
    if (message.is(agentQuestion)) {
      await message.reply("Yes, the author asked for the migration.");
    }
  }
}
```

The question arrives as `agent/question`, with who asked in `message.from`, and `reply()` answers it. A handle asks with `ask()`, a model with `ask_agent`.

## The model calls agents

You want the PR helper's model to hand off a review itself. It has the [agent tools](/docs/labs/agents/reference?ref=docs-labs-agents-agent-teams#agent-tools) `start_agent`, `message_agent`, `ask_agent`, `stop_agent` and `reply` by default. `start_agent` reaches agents in other apps too, as [Agent discovery](/docs/labs/agents/agent-discovery?ref=docs-labs-agents-agent-teams) shows.

```text {{ title: "What the model calls" }}
start_agent({
  address: "acme-web/reviewer",
  input: { pr: 42 },
})
  { thread: "a1b2c3" }
```

None of them waits, so the model can't deadlock. What comes back lands in its inbox as `agent/message`, `agent/question`, `agent/answer` or, for runs opened with `start_agent`, `agent/finished`. [How the model reads them →](/docs/labs/agents/reference?ref=docs-labs-agents-agent-teams#the-loop)

- **Who it can reach.** `message_agent`, `ask_agent` and `stop_agent` reach only the thread that started the agent, and threads it started. Thread keys from `start()` and `start_agent` are signed, so a guessed key is refused. There's no group of threads to reach beyond that — a "team" here is lineage (who started whom) plus discovery (what a model can find), not shared membership in anything.
- **Attached or not.** A started agent carries on by itself when the starter's run ends. `attach: true` cancels it when that run ends for good.
- **Ending a turn.** Every model agent also has a `wait` tool, which ends its turn until the next message arrives. It is experimental, and a tool of your own named `wait` replaces it. `reply` is only for answering a question by its ID; a run's result reaches whoever started it on its own.
- **Who sent it.** In a thread another agent started, a message with no sender, such as a person's steer, reads "Message from outside the agent team (not from an agent)", so the model doesn't take it for its starter's.

```typescript
import { agentFinished } from "inngest/experimental/agents";

if (message.is(agentFinished) && message.data.outcome === "failed") {
  const text = `The review failed: ${message.data.error}`;

  await step.run("comment", async () => {
    return await gh.comment(Number(thread.key), text);
  });
}
```

## From the sandbox

You want a script on the sandbox to start agents. Code the model runs with `runCode` calls `list_agents`, `describe_agent`, `start_agent`, `message_agent` and `stop_agent` there, plus `agent_result`, with no setup. The same discovery filters and reach rules apply, and `discovery: false` removes them.

```python {{ title: "A script the model runs" }}
started = await tools.start_agent(
    address="acme-web/reviewer",
    input={"pr": 42},
)

review = await tools.agent_result(thread=started["thread"])
```

`agent_result` waits: code can wait for an agent, where the model only reacts. [The model writes code →](/docs/labs/agents/calling-home?ref=docs-labs-agents-agent-teams#the-model-writes-code)

## Reports along the way

You want each finding as the reviewer finds it, not one answer at the end. Ask for typed reports when you start it. This is experimental.

<AnnotatedCode>

```typescript
import { eventType } from "inngest";
import { z } from "zod";

const findingSchema = z.object({ file: z.string(), problem: z.string() });

const finding = eventType("review/finding", { schema: findingSchema });

await reviewer.start(
  { pr: Number(thread.key) },
  { reports: [{ event: finding, required: true }] },
);

for await (const batch of inbox.batches()) {
  for (const message of batch) {
    const named: { name: string; data: unknown } = message;

    if (named.name === finding.name) {
      const found = findingSchema.parse(named.data);

      await step.run("comment finding", async () => {
        return await gh.comment(Number(thread.key), found.problem);
      });
    }
  }
}
```

<Annotation id="type" lines="4-6" tease="an ordinary event type" title="A report type">
Any `eventType()`. Its name can't start with `agent/` or `inngest/`.
</Annotation>

<Annotation id="reports" lines="8-11" tease="what it owes" title="reports">
A line is an event type, or `{ event, to, if, required }`. `to` sends it to other threads, such as `thread` or `agent.thread(key)`, and `if` is a CEL condition over `async.data`.
</Annotation>

<Annotation id="is" lines="15-18" tease="match, then parse" title="Reading a report" href="#reading-a-reports-type" linkText="Reading a report's type">
A report reaches your inbox under its type's name. `message.is(finding)` can't narrow to it, so match the name and parse the data.
</Annotation>

</AnnotatedCode>

### Reading a report's type

A report arrives under its own type's name with its own data, and **the runtime is right** - but `message.is(finding)` narrows to `never`, so nothing inside that `if` is usable. `is()` matches a message against the agent's triggers, its `inbox` sources and the `agent/*` messages, and an arriving report is none of those, so every intersection comes out empty.

Comparing the name directly doesn't work either: every name in that union is a literal, so `message.name === finding.name` is refused outright as a comparison with no overlap. Widen the message to the two fields you need, then parse the data with the report's own schema, as the example above does:

```typescript
const named: { name: string; data: unknown } = message;

if (named.name === finding.name) {
  const found = findingSchema.parse(named.data);
}
```

`found` is typed by the schema, and the parse is doing real work rather than quieting the compiler. **A report's data is whatever the sender wrote**, and validating it against the type's schema is a check `is()` was performing for you - it refuses the match when the data doesn't fit. So a bare `as` cast would be typed *and* trusted, which is worse than what you started with.

This is a known limitation of the types, not of reports. The fix is for an agent to declare the report types it accepts the way it declares its `inbox` sources, which would narrow exactly and weaken nothing; it is out of scope for now. `AgentMessage` in the SDK carries the full reasoning, including why a permissive union member would be the wrong repair.

The reviewer's model gets a `report` tool, and a handler gets `thread.report(finding, data)`. The data is checked against the schema before it is sent. A model that tries to finish while it owes a `required` report is reminded, and if it never sends one, its `agent/finished` lists the type in `missing`. A model can ask for reports too, with `start_agent`'s `reports`.

## Lend a sandbox

You want a fixer agent to work on the PR helper's checkout, not a fresh machine. Lend it the sandbox's tools. This is experimental.

```typescript
await fixer.start({ pr: Number(thread.key) }, { tools: sandboxes.work.tools });
```

The fixer's model gets `work_run`, `work_read` and the rest, and its run executes them as steps against the PR helper's machine. `sandboxes: { work: sandboxes.work }` lends the machine itself, for the fixer's code. Only the built-in tools can be lent, `push` never is, and both agents must be in the same app.

A child that borrows is attached: it is cancelled when the PR helper's run ends for good, so it never outlives the machine. `attach: false` with a lend is an error.

## Background work

You want to check with the reviewer without holding up the PR helper. Do it in a function you don't await.

```typescript
const reviewLater = async () => {
  const review = await reviewer.start({ pr: Number(thread.key) }).result();

  await thread.message({ review });
};

void reviewLater();
```

`thread.message()` puts the review in the PR helper's own inbox, for a later batch. A step the handler started and didn't await still runs, once, and the run ends after it. Nothing new starts after the handler returns.

## Not everything is an agent

You want a check of every open PR each morning. A plain function with a cron trigger does it.

```typescript {{ title: "inngest/lib/openPrs.ts" }}
import { z } from "zod";

const pulls = z.array(z.object({ number: z.number() }));

export const openPrs = async () => {
  const response = await fetch("https://api.github.com/repos/acme/web/pulls");

  if (!response.ok) {
    throw new Error(`Open PRs: ${response.status}`);
  }

  const open = pulls.parse(await response.json());

  return open.map((pull) => {
    return pull.number;
  });
};
```

```typescript {{ title: "inngest/functions/nightly.ts" }}
import { inngest } from "../client";
import { prHelper } from "../agents/prHelper";
import { openPrs } from "../lib/openPrs";

export const nightly = inngest.createFunction(
  { id: "nightly", triggers: [{ cron: "0 9 * * *" }] },
  async ({ step }) => {
    const prs = await step.run("open-prs", async () => {
      return await openPrs();
    });

    for (const pr of prs) {
      const thread = prHelper.thread(String(pr));

      await thread.message("Morning check: anything stuck?");
    }
  },
);
```

`thread(key)` gives the handle of that PR's thread, so each PR's thread gets the nudge. A plain function has no thread, inbox or card, and costs less.
