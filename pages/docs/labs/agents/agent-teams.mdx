# Agent Teams

> Start another agent, talk to it while it works, and get its answer back.

Messages arrive in your [inbox](/docs/labs/agents/inboxes?ref=docs-labs-agents-agent-teams); results return to your call. Below, the PR helper from [Calling home](/docs/labs/agents/calling-home?ref=docs-labs-agents-agent-teams) gets a reviewer.

## A second agent

To give the PR helper someone to hand reviews to, define a second agent.

{/* not type-checked: an agent with an invoke() trigger, a model and no handler */}
```typescript {{ title: "inngest/agents/reviewer.ts" }}
import { invoke } from "inngest";
import { z } from "zod";
import { agents } from "../client";
import { claude } from "../models/claude";

export const reviewer = agents.agent({
  id: "reviewer",
  triggers: [invoke(z.object({ pr: z.string() }))],
  model: claude,
  system: "You review pull requests and list the problems.",
});
```

`invoke()` makes the agent callable and types its input: `pr` is the pull request's URL. With no handler, its output is the model's last answer.

## Call it from code

To get a review once CI passes on the helper's fix, `start()` the reviewer in the handler and wait for its `result()`.

```typescript {{ title: "inngest/events.ts" }}
import { eventType } from "inngest";
import { z } from "zod";

const ciRun = z.object({ pr: z.number(), prUrl: z.string() });

export const ciFailed = eventType("ci/run.failed", { schema: ciRun });

export const ciPassed = eventType("ci/run.passed", { schema: ciRun });

export const deployed = eventType("deploy/finished", {
  schema: z.object({ env: z.string(), pull: z.object({ url: z.string() }) }),
});
```

<AnnotatedCode>

{/* not type-checked: start().result() on another agent inside an agent handler */}
```typescript {{ title: "inngest/agents/prHelper.ts" }}
import { github } from "inngest/experimental/agents";
import { agents } from "../client";
import { ciFailed, ciPassed, deployed } from "../events";
import { claude } from "../models/claude";
import { reviewer } from "./reviewer";

const triggers = [
  github.thread({ repos: ["acme/web"] }),
  { event: ciFailed, thread: "event.data.prUrl" },
  { event: deployed, thread: "event.data.pull.url" },
];

export const prHelper = agents.agent(
  {
    id: "pr-helper",
    triggers,
    inbox: [{ event: ciPassed, thread: "event.data.prUrl" }],
    idle: "1h",
    model: claude,
    system: "You help with pull requests on acme/web.",
  },
  async ({ inbox, me, loop }) => {
    for await (const batch of inbox.batches({ max: 20 })) {
      const answer = await loop(batch);

      await me.post(answer.text);

      const passed = batch.some((message) => {
        return message.is(ciPassed);
      });

      if (passed) {
        const review = await reviewer
          .start({ pr: me.key })
          .result({ timeout: "30m" });

        await me.post(review);
      }
    }
  },
);
```

<Annotation id="result" lines="33-35" tease="waits for the answer" title="start() and result()">
`start()` returns at once. `result()` waits for the answer, a string here.
</Annotation>

</AnnotatedCode>

The tools, skill and sandbox are left out. [Threads](/docs/labs/agents/threads?ref=docs-labs-agents-agent-teams#a-trigger-with-its-own-key) built the triggers, [Inboxes](/docs/labs/agents/inboxes?ref=docs-labs-agents-agent-teams) the `inbox` and `idle`, and [Models](/docs/labs/agents/models?ref=docs-labs-agents-agent-teams#the-loop) the loop.

A failed or stopped run makes `result()` throw, as does the `timeout` running out; the reviewer carries on.

A run opened through a handle ends once it has answered and nothing is unread, so `result()` returns promptly. If that agent has a handler, its `for await` loop ends the moment it would have to wait, not after `idle`.

A model that starts agents with `start_agent` holds its run open until they finish, for at most 24 hours. Agents you `start()` yourself are yours to await.

## Talk while it works

To correct or question the reviewer while it works, use the handle `start()` returns.

<AnnotatedCode>

{/* not type-checked: message(), ask() and stop() on a handle from start() */}
```typescript
const review = await reviewer.start({ pr: me.key });

await review.message("The author says the migration is safe to skip.");

const worry = await review.ask("Which file worries you most?");

await review.stop();
```

<Annotation id="message" lines="3" tease="doesn't wait" title="message()">
Lands in the reviewer's inbox and reaches its next model call.
</Annotation>

<Annotation id="ask" lines="5" tease="waits for the answer" title="ask()">
Gives `null` after an hour or when the reviewer refuses. `{ timeout }` changes the hour.
</Annotation>

<Annotation id="stop" lines="7" tease="cancels the run" title="stop()">
A `result()` waiting on this run throws.
</Annotation>

</AnnotatedCode>

Once the reviewer has answered, its run is over. `message()` and `ask()` then start a run on the same thread, which picks up its history:

{/* not type-checked: message().result() on a handle from start() */}
```typescript
const second = await review.message("Now check the tests.").result();
```

## Being talked to

To let the reviewer ask the PR helper something, read the question from the inbox and reply.

{/* not type-checked: agentQuestion, message.is() and message.reply() in a handler */}
```typescript
import { agentQuestion } from "inngest/experimental/agents";

for (const message of batch) {
  if (message.is(agentQuestion)) {
    await message.reply("Yes, the author asked for the migration.");
  }
}
```

`agent/question` says who asked in `message.from`, and gets one answer. A model agent has a `reply` tool for it.

Code waiting in `result()` isn't reading its inbox, so a question from that run is refused at once and the asker's `ask()` gives `null`.

## The model calls agents

To let the PR helper's model hand off a review itself, give it nothing: `start_agent` is on by default.

```text {{ title: "What the model calls" }}
start_agent({
  address: "support/reviewer",
  input: { pr: "https://github.com/acme/web/pull/42" },
})
  { thread: "a1b2c3" }
```

None of the agent tools waits. What comes back lands in the inbox as `agent/message`, `agent/question`, `agent/answer` or, for runs opened with `start_agent`, `agent/finished`, so the model can't deadlock. [How the model reads them →](/docs/labs/agents/reference?ref=docs-labs-agents-agent-teams#the-loop)

{/* not type-checked: message.is(agentFinished) narrowing data.outcome */}
```typescript
import { agentFinished } from "inngest/experimental/agents";

if (message.is(agentFinished) && message.data.outcome === "failed") {
  await me.post(`The review failed: ${message.data.error}`);
}
```

## From the sandbox

To start agents from a script on the sandbox, call the same tools there, plus `agent_result`.

```python {{ title: "A script the model runs" }}
started = await tools.start_agent(
    address="support/reviewer",
    input={"pr": "https://github.com/acme/web/pull/42"},
)

review = await tools.agent_result(thread=started["thread"])
```

`agent_result` waits: code can wait for an agent, where the model only reacts. [The model writes code →](/docs/labs/agents/calling-home?ref=docs-labs-agents-agent-teams#the-model-writes-code)

## Background work

To check with the reviewer without holding up the PR helper, do it in a function you don't await.

{/* not type-checked: an un-awaited function that reports back through me.message() */}
```typescript
const reviewLater = async () => {
  const review = await reviewer.start({ pr: me.key }).result();

  await me.message({ review });
};

void reviewLater();
```

`me.message()` puts the review in the PR helper's own inbox, for a later batch. Work still running when the handler returns is stopped.

## Not everything is an agent

To check every open PR each morning, use a plain function.

```typescript {{ title: "inngest/lib/openPrs.ts" }}
import { z } from "zod";

const pulls = z.array(z.object({ html_url: z.string() }));

export const openPrs = async () => {
  const response = await fetch("https://api.github.com/repos/acme/web/pulls");

  if (!response.ok) {
    throw new Error(`Open PRs: ${response.status}`);
  }

  const open = pulls.parse(await response.json());

  return open.map((pull) => {
    return pull.html_url;
  });
};
```

{/* not type-checked: prHelper.thread(key).message() from a plain function */}
```typescript {{ title: "inngest/functions/nightly.ts" }}
import { inngest } from "../client";
import { prHelper } from "../agents/prHelper";
import { openPrs } from "../lib/openPrs";

export const nightly = inngest.createFunction(
  { id: "nightly", triggers: [{ cron: "0 9 * * *" }] },
  async ({ step }) => {
    const urls = await step.run("open-prs", async () => {
      return await openPrs();
    });

    for (const url of urls) {
      await prHelper.thread(url).message("Morning check: anything stuck?");
    }
  },
);
```

`thread(url)` rebuilds a handle from a key, so `message()` reaches that PR's thread. With the cron on the agent, each tick would be a thread of its own, about no PR. A plain function has no thread, inbox or card, and costs less.

## An agent in another app

To call a reviewer another app owns, reference it by address.

{/* not type-checked: agents.reference() with schema and output */}
```typescript {{ title: "inngest/agents/platformReviewer.ts" }}
import { z } from "zod";
import { agents } from "../client";

export const platformReviewer = agents.reference("platform/reviewer", {
  schema: z.object({ pr: z.string() }),
  output: z.string(),
});
```

It has the `start()` and `thread()` of an import, by its [address](/docs/labs/agents/agent-discovery?ref=docs-labs-agents-agent-teams#a-card). Without `schema`, `start()` takes any JSON; without `output`, `result()` gives `unknown`.
