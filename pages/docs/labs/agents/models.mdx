# Models

> Give an agent a model and a prompt, and it runs the loop of turns for you.

The PR helper is the one from [Inboxes](/docs/labs/agents/inboxes?ref=docs-labs-agents-models), with the triggers [Threads](/docs/labs/agents/threads?ref=docs-labs-agents-models) gave it.

## Ask a model

You want a summary of the pull request, written by a model.

```typescript {{ title: "inngest/models/claude.ts" }}
import { anthropic } from "inngest/experimental/agents";

export const claude = anthropic({ model: "claude-sonnet-5-5" });
```

`gh` is the comment helper from [Inboxes](/docs/labs/agents/inboxes?ref=docs-labs-agents-models#answer-every-message):

```typescript {{ title: "inngest/lib/github.ts" }}
const api = "https://api.github.com/repos/acme/web";

export const gh = {
  comment: async (pr: number, body: string) => {
    const response = await fetch(`${api}/issues/${pr}/comments`, {
      method: "POST",
      headers: {
        accept: "application/vnd.github+json",
        authorization: `Bearer ${process.env.GITHUB_TOKEN}`,
      },
      body: JSON.stringify({ body }),
    });

    if (!response.ok) {
      throw new Error(`Comment on #${pr}: ${response.status}`);
    }

    return await response.json();
  },
};
```

A follow-up question gets an answer that knows nothing of the summary.

## The loop

You want follow-ups to work. A turn is one model call plus the tool calls it asked for.

<AnnotatedCode>

```typescript {{ title: "inngest/agents/prHelper.ts" }}
import { agents } from "../client";
import { ciFailed, ciPassed, deployed, prComment, prOpened } from "../events";
import { gh } from "../lib/github";
import { claude } from "../models/claude";

const triggers = [
  prOpened,
  prComment,
  ciFailed,
  { event: deployed, thread: "event.data.pull" },
];

export const prHelper = agents.agent(
  {
    id: "pr-helper",
    triggers,
    thread: "event.data.pr",
    inbox: [ciPassed],
    model: claude,
    system: "You help with pull requests on acme/web.",
  },
  async ({ inbox, loop, thread, step }) => {
    for await (const batch of inbox.batches({ max: 20 })) {
      const result = await loop(batch);

      await step.run("comment", async () => {
        return await gh.comment(Number(thread.key), result.text);
      });
    }
  },
);
```

## It remembers

You want the helper to pick the thread up after its run ends.

The loop saves the model's history in [the thread](/docs/labs/agents/threads?ref=docs-labs-agents-models#what-a-conversation-keeps) after each batch, so the next run — even a fresh, short-lived one on the same thread — sees it. When the history gets long, the loop summarizes it and reuses the summary. There's no option to turn this off: the thread is what makes a resumed run continuous, so remembering isn't something an agent opts out of.

## Corrections land

You want "focus on the tests" to count while the model works.

Before every model call the loop takes everything that arrived in the [inbox](/docs/labs/agents/inboxes?ref=docs-labs-agents-models#while-it-works), so the correction reaches the very next call.

## Delete the handler

You want the same agent with no code.

{/* not type-checked: a model agent with no handler */}
```typescript
export const prHelper = agents.agent({
  id: "pr-helper",
  triggers,
  thread: "event.data.pr",
  inbox: [ciPassed],
  model: claude,
  system: "You help with pull requests on acme/web.",
});
```

This is the handler the SDK writes: each batch goes through the loop. Its answer is only the run's output; to put it on the PR, the model needs a tool. [Your own GitHub tools →](/docs/labs/agents/tools?ref=docs-labs-agents-models#your-own-git-hub-tools)

The run itself is short-lived: it answers and ends as soon as its inbox is empty, there's no quiet period to wait out first. What feels continuous is the thread, not the run — a later message to the same PR resumes it with a fresh, equally short-lived run that reads the history back. [Reference: short-lived runs →](/docs/labs/agents/reference?ref=docs-labs-agents-models#short-lived-runs)

In a handler, `end` says why the loop stopped: `"done"`, `"maxTurns"`, `"stop"` or `"noToolCall"`. [Reference: the result →](/docs/labs/agents/reference?ref=docs-labs-agents-models#the-result)

  return claude;
},

## Any model, not just Anthropic

`anthropic()` is the one adapter the SDK ships, but `model` takes any function of the right shape — the loop doesn't know or care which provider answered. Writing your own adapter is how you use OpenAI, a local model, or anything else: the pattern is general on purpose, so the models Inngest ships with aren't a ceiling.

### The shape

A model is a function that takes the loop's request and returns a reply. That's the whole contract:

```typescript {{ title: "Signature" }}
interface AgentModel {
  (request: AgentModelRequest): Promise<AgentModelResponse>;
  contextWindow?: number;
  placesBriefing?: boolean;
}

interface AgentModelRequest {
  system?: string;
  messages: ModelMessage[]; // { role: "user" | "assistant" | "tool", ... }
  turn: number;
  maxTurns: number;
  toolChoice?: "auto" | "required" | "none" | { tool: string };
  tools: ToolJsonDefinition[]; // { name, description?, input_schema }
}

interface AgentModelResponse {
  message: { role: "assistant"; content: unknown }; // kept in history untouched
  text?: string;
  toolCalls: { id: string; name: string; input: unknown }[];
  usage?: { input: number; output: number; usd?: number };
  model?: string;
}
```

It runs inside a step, so a thrown error retries like any other step failure; throw `NonRetriableError` for one retrying can't fix (a 4xx the provider will never accept twice).

Putting it on an agent is no different from `anthropic()`: `model: myModel(options)` goes in the same slot, or a function of `{ event, thread }` that returns one.

```typescript
agents.agent({
  id: "triage",
  model: myModel({ apiKey: process.env.MY_PROVIDER_KEY }),
  // ...
});
```

The one thing a model function must do that an ordinary async function doesn't: mark itself with `agentModel()`, so the loop can tell "a model" apart from "a function of `{ event, thread }` that returns a model" — both are functions, and without the mark there's no way to know which you meant.

```typescript
import { agentModel } from "inngest/experimental/agents";

export const myModel = (options: MyOptions) => {
  return agentModel(async (request) => {
    // call your provider, return an AgentModelResponse
  });
};
```

### Worked example: OpenAI

The common case — another hosted chat API, its own tool-call format, but otherwise well-behaved. This maps `AgentModelRequest` onto the Chat Completions API and maps the reply back.

```typescript {{ title: "inngest/models/openai.ts" }}
import OpenAI from "openai";
import { agentModel } from "inngest/experimental/agents";
import type { AgentModelRequest, AgentModelResponse } from "inngest/experimental/agents";

interface OpenAiOptions {
  model: string;
  client?: OpenAI;
}

export const openaiModel = (options: OpenAiOptions) => {
  const client = options.client ?? new OpenAI();

  return agentModel(async (request: AgentModelRequest): Promise<AgentModelResponse> => {
    const messages = toOpenAiMessages(request);

    const reply = await client.chat.completions.create({
      model: options.model,
      messages: request.system
        ? [{ role: "system", content: request.system }, ...messages]
        : messages,
      tools: request.tools.map((tool) => {
        return {
          type: "function" as const,
          function: {
            name: tool.name,
            description: tool.description,
            parameters: tool.input_schema,
          },
        };
      }),
      tool_choice: toToolChoice(request.toolChoice),
    });

    const choice = reply.choices[0];
    const message = choice.message;

    const toolCalls = (message.tool_calls ?? []).map((call) => {
      return {
        id: call.id,
        name: call.function.name,
        // Untrusted JSON until the tool's own schema checks it.
        input: JSON.parse(call.function.arguments) as unknown,
      };
    });

    return {
      // Kept in history untouched, and fed back to this adapter next turn.
      message: { role: "assistant", content: message },
      text: message.content ?? undefined,
      toolCalls,
      usage: reply.usage
        ? { input: reply.usage.prompt_tokens, output: reply.usage.completion_tokens }
        : undefined,
      model: reply.model,
      details: { finishReason: choice.finish_reason },
    };
  });
};

const toToolChoice = (choice: AgentModelRequest["toolChoice"]) => {
  if (!choice || choice === "auto") return "auto";
  if (choice === "none") return "none";
  if (choice === "required") return "required";

  return { type: "function" as const, function: { name: choice.tool } };
};

// OpenAI's assistant/tool messages don't match ModelMessage's shape
// one-for-one, so this adapter keeps its own history alongside the loop's,
// built fresh from `request.messages` each call. The `assistant` message's
// `content` is whatever this adapter put there last turn (above), so it
// comes back out the same shape it went in.
const toOpenAiMessages = (request: AgentModelRequest) => {
  return request.messages.flatMap((message) => {
    if (message.role === "user") {
      return [{ role: "user" as const, content: toText(message.content) }];
    }

    if (message.role === "assistant") {
      return [message.content as OpenAI.Chat.ChatCompletionAssistantMessageParam];
    }

    // message.role === "tool": one OpenAI message per result, keyed by call id.
    return message.results.map((result) => {
      return {
        role: "tool" as const,
        tool_call_id: result.toolCallId,
        content: result.content,
      };
    });
  });
};

const toText = (content: unknown): string => {
  return typeof content === "string" ? content : JSON.stringify(content);
};
```

- **The tool-call format differs, nothing else does.** OpenAI's `tool_calls` and `tool_choice` shapes aren't Anthropic's, but the loop never sees either — it only sees `AgentModelResponse.toolCalls`, a flat array the adapter is responsible for producing.
- **`message.content` is a pass-through, not a rendering.** The loop stores `message` verbatim and hands it back on the next call unchanged; this is why `toOpenAiMessages` can cast the previous assistant message straight back rather than re-deriving it.
- **Usage is optional per field.** Report `input`/`output` tokens when the provider returns them; a budget or cost calculation downstream reads whatever's there and no more.

### Worked example: a model with no native tool calling

The hard case: a local or self-hosted model (an OpenAI-compatible server such as Ollama or vLLM, or anything else) that has no structured tool-call API at all. The adapter has to ask the model to emit tool calls as text, in a format it then parses — the model doesn't call tools, the adapter does, on the model's behalf.

```typescript {{ title: "inngest/models/local.ts" }}
import { agentModel } from "inngest/experimental/agents";
import type { AgentModelRequest, AgentModelResponse } from "inngest/experimental/agents";

interface LocalOptions {
  baseURL: string; // an OpenAI-compatible completions endpoint
  model: string;
}

// Ask the model to answer in plain text, or to call a tool by writing one
// line of JSON and nothing else. No provider-native tool calling involved.
const toolInstructions = (tools: AgentModelRequest["tools"]): string => {
  if (tools.length === 0) return "";

  const names = tools.map((tool) => `${tool.name}: ${tool.description ?? ""}`);

  return [
    "",
    "You may call one of these tools by replying with exactly one line",
    'of JSON and nothing else: {"tool": "<name>", "input": { ... }}.',
    "Otherwise just answer in plain text.",
    "Tools:",
    ...names,
  ].join("\n");
};

// The model's whole reply is either a JSON tool call or plain text; there is
// no structured split between the two; the adapter has to decide which it got.
const parseReply = (text: string): { toolCall?: { tool: string; input: unknown } } => {
  const trimmed = text.trim();

  if (!trimmed.startsWith("{")) return {};

  try {
    const parsed = JSON.parse(trimmed) as { tool?: string; input?: unknown };

    if (typeof parsed.tool === "string") {
      return { toolCall: { tool: parsed.tool, input: parsed.input ?? {} } };
    }
  } catch {
    // Not a tool call — treat the whole reply as text.
  }

  return {};
};

export const localModel = (options: LocalOptions) => {
  return agentModel(async (request: AgentModelRequest): Promise<AgentModelResponse> => {
    const prompt = buildPrompt(request) + toolInstructions(request.tools);

    const response = await fetch(`${options.baseURL}/v1/completions`, {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ model: options.model, prompt, max_tokens: 1024 }),
    });

    if (!response.ok) {
      throw new Error(`Local model answered ${response.status}`);
    }

    const body = (await response.json()) as {
      choices: { text: string }[];
      usage?: { prompt_tokens: number; completion_tokens: number };
    };

    const text = body.choices[0]?.text ?? "";
    const { toolCall } = parseReply(text);

    return {
      message: { role: "assistant", content: text },
      text: toolCall ? undefined : text,
      toolCalls: toolCall
        ? [{ id: `local-${request.turn}`, name: toolCall.tool, input: toolCall.input }]
        : [],
      // This model doesn't report token counts; leave usage out rather than
      // guess at it. Your own cost tracking for this model needs its own
      // pricing logic, since there's nothing here for it to read.
    };
  });
};

// Renders the whole history as plain text, since there's no structured
// messages API on the other end of this fetch.
const buildPrompt = (request: AgentModelRequest): string => {
  const lines = request.system ? [`System: ${request.system}`] : [];

  for (const message of request.messages) {
    if (message.role === "user") {
      lines.push(`User: ${typeof message.content === "string" ? message.content : JSON.stringify(message.content)}`);
    } else if (message.role === "assistant") {
      lines.push(`Assistant: ${typeof message.content === "string" ? message.content : JSON.stringify(message.content)}`);
    } else {
      for (const result of message.results) {
        lines.push(`Tool result (${result.name}): ${result.content}`);
      }
    }
  }

  return lines.join("\n");
};
```

- **The model never calls a tool — the adapter decides it did.** There's no `tool_calls` field from this provider; `parseReply` is the entire boundary between "the model answered" and "the model wants a tool run," and a model that ignores the formatting instruction just gets a reply forwarded as text instead of a tool call. This is inherently less reliable than a provider with native tool calling, which is exactly why it's the harder of the two examples.
- **No usage reported, and that's honest, not a bug.** Leaving `usage` out entirely (rather than guessing zeros) means a budget or cost dashboard built on `AgentUsage` correctly shows this model as unaccounted-for rather than silently free.
- **Every other primitive — discovery, reports, reliability — works unmodified.** None of them read anything model-specific; they only ever see `AgentModelResponse`, so a model this unlike Anthropic's still composes with the rest of the SDK exactly like `anthropic()` does.

## Your own loop

You want the agent's turns to run your way, or just a little differently. To change the loop's own options, set `loop` on the definition:

{/* not type-checked: loop options on an agent definition */}
```typescript
loop: { maxTurns: 10 },
```

The loop makes at most 10 model calls, down from the default 40. Other options work the same way, such as `toolChoice: "required"` for a small model that answers in chat, or `stop: hasToolCall("finish")` to end once a `finish` tool has run. In a handler, `loop.with({ maxTurns: 10 })` derives that loop from the agent's. For more than options, give `loop` a whole loop of your own:

<AnnotatedCode>

```typescript {{ title: "inngest/agents/parrot.ts" }}
import { agents } from "../client";

export const parrot = agents.agent({
  id: "parrot",
  loop: async (batch) => {
    const heard = typeof batch === "string" ? batch : JSON.stringify(batch);

    return {
      text: heard,
      end: "done",
      unread: [],
      turns: 0,
      noToolCallTurns: 0,
      history: [],
      usage: { input: 0, output: 0 },
      toolCalls: [],
    };
  },
});
```
