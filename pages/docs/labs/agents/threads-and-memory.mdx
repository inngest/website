# Threads and memory

> One key per conversation, and whatever the agent saves under it is still there tomorrow.

Every conversation with an agent is a thread, named by a key you choose. Save the history under that key and the next message picks up exactly where the last one stopped.

<AnnotatedCode>

```typescript {{ title: "inngest/agents/support.ts" }}
import { agent, kv } from "inngest/experimental/agents";
import { agents } from "../client";
import { history } from "../keys";
import { claude } from "../models/claude";

export const support = agents.agent(
  { id: "support" },
  async ({ inbox, control }) => {
    for await (const message of inbox) {
      const result = await agent.loop({
        model: claude,
        prompt: message.content ?? "",
        history: (await kv.thread.get(history)) ?? [],
        ...control,
      });

      await kv.thread.set(history, result.history);
    }
  },
);
```

The run waits here between messages, so a quiet thread uses nothing.
</Annotation>

## Talk to a thread

A thread is a string key. The same key is the same conversation, from any process.

```typescript {{ title: "app/tickets.ts" }}
import { support } from "../inngest/agents/support";

const ticket = support.thread("ticket-42", "acct-9");

await ticket.send("My invoice shows the wrong amount");

await ticket.send("It was due on the 3rd");

const { status, turn, summary } = await ticket.state();
```

The first `send` starts a run. The second joins it, or starts a new one if the first has finished. The second argument names the session the thread belongs to; it defaults to the key.

## Remember across threads

History belongs to one thread. Facts about a customer belong to every thread they open. Give those a wider scope.

<AnnotatedCode>

```typescript {{ title: "inngest/agents/account.ts" }}
import { agent, kv } from "inngest/experimental/agents";
import { agents } from "../client";
import { preferences } from "../keys";
import { claude } from "../models/claude";

export const account = agents.agent({ id: "account" }, async ({ inbox }) => {
  for await (const message of inbox) {
    const known = (await kv.session.get(preferences)) ?? [];
    await agent.loop({
      model: claude,
      system: `What we know about this customer: ${known.join("; ")}`,
      prompt: message.content ?? "",
    });
  }
});
```

<Annotation id="session" lines="8" tease="every thread of the session" title="Session scope" href="#options" linkText="Options">
Shared by all threads that name the same session, such as `acct-9`.
</Annotation>

</AnnotatedCode>

Add `history` as above, `tools: { remember }` and `compaction: { maxTokens: 150_000, keep: 8 }` to the same loop. Past `maxTokens` the start of the history becomes one summary; see [Models and the loop](/docs/labs/agents/models-and-the-loop?ref=docs-labs-agents-threads-and-memory#keep-long-conversations-in-the-window).

```typescript {{ title: "inngest/tools/remember.ts" }}
import { tool } from "inngest/experimental";
import { kv } from "inngest/experimental/agents";
import { z } from "zod";
import { preferences } from "../keys";

export const remember = tool.step({
  description: "Save something to remember about this customer",
  input: z.object({ fact: z.string() }),
  run: async ({ fact }) => {
    await kv.session.update(preferences, (current) => {
      return [...(current ?? []), fact];
    });
    return { saved: fact };
  },
});
```

```typescript {{ title: "inngest/keys.ts" }}
import { kvKey } from "inngest/experimental/agents";
import type { AgentMessage } from "inngest/experimental/agents";

export const history = kvKey<AgentMessage[]>("history");
export const preferences = kvKey<string[]>("preferences");
```

The model saves a fact when it learns one. `update` reads, changes and writes in one safe step, so two threads saving a fact at once never lose one.

## Look inside a thread

`state()` reads a thread's memory without a run, from your app or a script.

```typescript {{ title: "app/inspect.ts" }}
import { account } from "../inngest/agents/account";

const ticket = account.thread("ticket-42", "acct-9");

const { status, turn, usage, lastRun } = await ticket.state();

console.log(status, turn, usage, lastRun);
```

`status` is `running`, `waiting`, `stopped` or `idle`. `usage` sums every model call so far.

List a session's threads with `threads.list()`, most recently messaged first.

```typescript {{ title: "app/list.ts" }}
import { support } from "../inngest/agents/support";

const recent = await support.threads.list({ session: "acct-9", limit: 20 });

for (const thread of recent) {
  console.log(thread.key, (await thread.state()).status);
}
```

## Ask another thread

Give an agent `requests` schemas and another thread can ask it a typed question. The asker gets the reply, or `null` after the timeout.

```typescript {{ title: "inngest/agents/billing.ts" }}
import { z } from "zod";
import { agents } from "../client";

export const billing = agents.agent(
  {
    id: "billing",
    requests: { request: z.object({ orderId: z.string() }), reply: z.object({ refundable: z.boolean() }) },
  },
  async ({ inbox }) => {
    const message = await inbox.next();
    if (message?.kind === "request") {
      await message.reply({ refundable: message.payload.orderId !== "" });
    }
  },
);
```

```typescript {{ title: "inngest/agents/refunds.ts" }}
import { agents } from "../client";
import { billing } from "./billing";

export const refunds = agents.agent({ id: "refunds" }, async ({ inbox }) => {
  const message = await inbox.next();
  const answer = await billing
    .thread("acct-9")
    .request({ orderId: message?.content ?? "" }, { timeout: "5m" });

  return answer?.refundable ? "refund" : "no refund";
});
```

`request` works inside a function and wakes an idle thread.

## When to use what

- Keep the conversation: `kv.thread` with `result.history`.
- Keep facts about a person or account: `kv.session` and a tool that writes it.
- Keep a setting every thread should see: `kv.app` or `kv.env`.
- Keep scratch work for one run: `kv.run`, removed when the run ends.
- Find a thread from outside the agent: `agent.thread(key)` and `state()`.
- Ask another thread a question: `thread.request()`.

## Options

Pick the scope by who should see the value and when it goes away.

```typescript {{ title: "inngest/scopes.ts" }}
import { kv } from "inngest/experimental/agents";

export async function scopes(otherThread: string) {
  await kv.run.set("scratch", { files: ["a.ts"] });
  await kv.thread.set("topic", "refunds");
  await kv.session.set("customer", "acme");
  await kv.app.set("model", "claude");
  await kv.env.set("flag:beta", true);

  return kv.scope("thread", otherThread).get("topic");
}
```

Each scope is wider than the one before. Pass a `store` to `createAgents` for D1 or memory instead of Redis. `kvKey(name, schema)` checks every read, and `update`, `setIfAbsent` and `take` never lose a racing write. `kv.scope(name, id)` reads another instance, such as a different thread.

## Gotchas

- Values are stored as JSON: no `Date`, `Map` or `undefined`.
- The inbox closes when the agent body returns. A message sent after that is dropped, so loop for as long as the thread should live.
- `update` runs your function again if another run wrote first, so keep it pure.
- `threads.list()` uses Insights, which the Dev Server does not serve.

## How it works

- A message is an `agent/message` event. It starts a run when none is live.
- One run is live per thread. Messages sent during a run join its inbox.
- Thread memory lives in the KV store you give `createAgents`.
