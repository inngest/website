# Run CI locally

> Run any pipeline or job on real Sandboxes against your uncommitted changes, before you push.

- **Nothing to push.** Your working tree uploads as is. [Run a pipeline →](#run-a-pipeline-or-job)
- **Guided inputs.** Forms from your schema, saved as fixtures. [Give inputs →](#give-inputs)
- **Pick matrix cells.** Select a value, run every combination. [Matrix →](#choose-matrix-combinations)
- **Skip release steps.** `ci.local` guards side effects. [Skip →](#skip-work-that-must-not-run-from-a-laptop)

```bash
npx inngest-ci
```

```
  inngest-ci pr  pull_request.opened · my-branch @ 70f798f + uncommitted
  Dev Server  http://127.0.0.1:24288

  ◐ pr                                                       41s
  └─ ✓ base     cached                                       0.8s
     ├─ ✓ lint  $ pnpm lint                                  22s
     └─ ◐ test  $ pnpm test                                  41s
```

Press `enter` on a run or job to open its trace.

## Before you start

Finish the [quick start](/docs/labs/ci/quick-start?ref=docs-labs-ci-local), then add a script:

```json {{ title: "package.json" }}
{
  "scripts": {
    "ci": "inngest-ci"
  }
}
```

## Pick what to run

```bash
pnpm run ci
```

```
↑ ↓        move
space      select (on a matrix, selects everything under it)
→ ←        open and close a matrix
enter      run the selection
q, esc     quit
```

The first run saves how to start your app to `inngest.json`. See [Configure](#configure).

## Run a pipeline or job

```bash
pnpm run ci pr
pnpm run ci lint
pnpm run ci release --event push
pnpm run ci pr --pipeline pr --job lint
pnpm run ci pr --event pull_request.opened --no-interactive
```

- `--event` picks a trigger. `--pipeline` or `--job` resolves a name clash.
- A job runs alone, with its [`from`](/docs/labs/ci/base-images?ref=docs-labs-ci-local#start-from-a-job) parents.
- Cron cannot run locally. Add a [`ci.manual()`](/docs/labs/ci/reference?ref=docs-labs-ci-local#triggers) trigger.

```
0   every run passed
1   a run failed or was cancelled
2   setup failed; the message says what to change
```

## Give inputs

<AnnotatedCode>

```typescript {{ title: "ci/jobs/build.ts" }}
import { $, checkout } from "@inngest/ci";
import { z } from "zod";
import { ci } from "../client";

export const build = ci.job(
  {
    id: "build",
    input: z.object({ target: z.enum(["web", "api"]) }),
  },
  async ({ input }) => {
    await checkout();
    await $`pnpm build --target ${input.target}`;
  },
);
```

<Annotation id="schema" lines="8" tease="drives the form" title="Input schema" href="#give-inputs" linkText="Give inputs">
Any JSON Schema library works, such as Zod 4.
</Annotation>

</AnnotatedCode>

```
  build · input

  target  1 of 1 · required
› web
  api

  ↑↓ move · enter pick · esc cancel
```

```bash
pnpm run ci build --input '{"target":"web"}'
pnpm run ci deploy --data '{"env":"preview"}'
pnpm run ci prerelease --data '{"body":"/prerelease"}'
pnpm run ci deploy --fixture nightly-api
```

Flags are checked against the schema. After a run, save the input as a fixture in `.inngest/ci/fixtures/<target>/<name>.json`.

## Skip work that must not run from a laptop

```typescript {{ title: "ci/pipelines/release.ts" }}
import { github } from "@inngest/ci";
import { ci } from "../client";
import { publish } from "../jobs/publish";
import { test } from "../jobs/test";

export const release = ci.pipeline(
  {
    id: "release",
    on: github.push({ branches: ["main"] }),
  },
  async () => {
    await test();

    if (ci.local) {
      return ci.skip("not publishing from a local run");
    }

    await publish();
  },
);
```

## Configure

```json {{ title: "inngest.json" }}
{
  "ci": {
    "start": "tsx server.ts",
    "path": "/api/inngest",
    "dir": ".inngest/ci",
    "devServer": { "bin": "/path/to/inngest" }
  }
}
```

- `start` serves your app on `PORT`. Without it, `inngest-ci` looks for `ci/server.ts`.
- `path` defaults to `/api/inngest`. `dir` holds Dev Server data, fixtures, and logs.
- The Dev Server comes from `INNGEST_CI_DEV_SERVER_BIN`, `devServer.bin`, your project, then `PATH`.

Fix common errors:

```
isn't logged in               npx inngest-cli@latest login
not tied to a single env      npx inngest-cli@latest login --force
can't use Sandboxes yet       ask Inngest to enable Sandbox access
inngest-cli is too old        npm install --save-dev inngest-cli@latest
Could not find a Dev Server   install inngest-cli in your project or globally
No command to start your app  run inngest-ci in a terminal to set it up, or add start to inngest.json
```

## How it works

- Each run starts its own Dev Server and app on free ports.
- `checkout()` uploads your working tree without `.git`, up to 100 MiB. Later jobs upload only changes.
- Jobs run on real [Sandboxes](/docs/sandboxes/overview?ref=docs-labs-ci-local), and checks print in your terminal.
- [`files()`](/docs/labs/ci/base-images?ref=docs-labs-ci-local#add-a-cache-key) hashes local files, so an uncommitted lockfile change rebuilds `base`.
- Sessions older than 10 minutes are cleared by the next one.
