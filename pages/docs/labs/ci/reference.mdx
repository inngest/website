# Inngest CI reference

> Options, triggers, command methods, and limits for `@inngest/ci`.

<Info>
  Inngest CI is an Inngest Labs project: early, moving fast, and shaped by your feedback. [What's Labs?](/docs/labs?ref=docs-labs-ci-reference) APIs may change between 0.x releases.
</Info>

## `createCi`

```typescript {{ title: "TypeScript" }}
const ci = createCi(inngest, {
  github: githubApp(), // githubApp() | githubToken() | consoleReporter() (default)
  machine: { vcpu: 2 }, // default for every job
  runUrl: ({ runId, functionId }) => `https://example.com/${runId}`, // link on checks
  from: image.custom("agent-deps"), // default `from` for jobs without one
});

serve({ client: inngest, functions: ci.functions() }); // pipelines + cache builds, re-runs, local jobs

if (ci.local) {
  return ci.skip("local run"); // true in runs started by inngest-ci
}
```

[Run CI locally →](/docs/labs/ci/local?ref=docs-labs-ci-reference)

## `ci.pipeline`

A [pipeline](/docs/labs/ci/pipelines?ref=docs-labs-ci-reference) is one Inngest function, so every flow control option works.

```typescript {{ title: "TypeScript" }}
export const pr = ci.pipeline(
  {
    id: "pr", // unique in the app; names the function, run, and check
    on: github.pullRequest(), // a trigger, or an array of triggers
    check: false, // or { name?, jobs? }; { jobs: false } keeps only the pipeline check
    machine: { vcpu: 2 }, // default for the pipeline's jobs; a job's own wins
    repo: "acme/app", // "owner/name"; gives crons and manual runs a repository
    singleton: { key: "event.data.pull_request.number", mode: "cancel" },
    concurrency: {
      key: "event.data.repository.owner.login",
      limit: 20,
      scope: "account",
    },
  },
  async ({ event, events, runId, pipelineId, repo, attempt, logger }) => {
    await test();
  },
);
```

Also accepted: `throttle`, `rateLimit`, `debounce`, `priority`, `idempotency`, `batchEvents`, `timeouts`, `cancelOn`, `retries`, `name`, `description`. [Flow control →](/docs/durable-execution/flow-control?ref=docs-labs-ci-reference)

`repo` is `undefined` for triggers with no repository. A malformed `repo` throws. With GitHub credentials, it resolves the default branch and head commit for crons and manual runs.

`ci.skip(reason)` ends the run with a success check carrying the reason.

```typescript {{ title: "TypeScript" }}
const touched = await changed("src/**", "package.json");
// or: changed({ include: ["docs/**"], ignore: ["docs/**/*.png"] })
// patterns: **, *, ?, {a,b}. No `include` means every file.

if (touched === false) {
  return ci.skip("nothing that affects the build changed");
}
```

`changed()` returns `true`, noted on the check, when it cannot tell:

- The run has no repository or no GitHub credentials.
- There is no pull request or push range: cron, manual, merge group, or a push creating a branch.
- A local run cannot find its base branch.
- A compare hits GitHub's 300-file cap.

## Triggers

A [trigger](/docs/labs/ci/pipelines?ref=docs-labs-ci-reference#triggers) starts a pipeline and types its `event`.

```typescript {{ title: "TypeScript" }}
on: github.pullRequest({ branches, types, repo }) // opened, synchronize, reopened by default
on: github.push({ branches, tags, repo }) // exact names: "v*" does not match v1.0.0; deleted branches excluded
on: github.comment({ command, minPermission, repo }) // comment starts with `command`
on: github.mergeGroup({ repo }) // merge queue asks for checks
on: github.checkSuite({ branch, repo }) // a check suite completes
on: { cron: "0 3 * * *" } // schedule; no typed event.data
on: ci.manual({ schema, pipelineId }) // event ci/manual.<pipelineId>, or any ci/manual.*
on: [github.pullRequest(), github.push({ branches: ["main"] })] // union; narrow with "pull_request" in event.data
```

- A pipeline has at most 10 triggers. `pullRequest()` uses one per type.
- `minPermission` is checked after the run starts. A user without it gets a reply and a neutral check. Each `comment()` keeps its own.
- `ci.manual({ schema })` takes any Standard Schema validator, such as Zod.

## `ci.job`

A [job](/docs/labs/ci/jobs?ref=docs-labs-ci-reference) has its own machine and check. Call it like a function.

```typescript {{ title: "TypeScript" }}
const test = ci.job("test", async () => {
  await checkout();
  await $`pnpm test`;
});

const build = ci.job(
  {
    id: "build",
    name: "Build", // trace name; defaults to id
    from: base, // job | job.with(input) | ({ input }) => job.with(input) | image
    machine: { vcpu: 4 },
    cache: { key: files("pnpm-lock.yaml") }, // { key?, refresh?, scope?, maxAge? }
    check: false, // or { name? }
    keepOnFailure: "24h", // snapshot the machine on failure; ID in the pipeline summary under Kept machines
    input: z.object({ target: z.string() }), // Standard Schema; mismatch throws CiUsageError
  },
  async ({ target }) => {
    await $`pnpm build --target ${target}`;
  },
);
```

- A job returns nothing. Each call runs it again on a new machine: a second call shows as `test (2)`.
- The machine starts on the first command. Jobs never share one: use [`from`](#from).
- `job.with(input)` returns the job with an input, for `from`.
- [`inngest-ci`](/docs/labs/ci/local?ref=docs-labs-ci-reference#give-inputs) asks for `input` field by field.
- Durations (`"10m"`, `"1h30m"`) take `ms`, `s`, `m`, `h`, `d`, `w`. A malformed one throws `CiUsageError`.

## Commands

[`` $`…` ``](/docs/labs/ci/commands?ref=docs-labs-ci-reference) runs on the job's machine. A non-zero exit throws `CommandFailedError`.

```typescript {{ title: "TypeScript" }}
await $`pnpm --filter ${pkg} test`; // each value is one argument, unquoted
await $`pnpm test --filter=${pkg}`; // joins the argument when it follows text with no space
await $`pnpm test ${bail && ["--bail", "1"]}`; // arrays spread; false, null, undefined drop
await $.sh`pnpm build && pnpm test | tee test.log`; // /bin/sh -c, values escaped

await $`pnpm test`.retries(2); // up to 2 more runs on the same machine; each attempt is a step
await $`pnpm lint`.nothrow(); // return the result instead of throwing
await $`pnpm test`.env({ CI: "true" });
await $`pnpm test`.cwd("/work/app"); // default /work
await $`pnpm test`.timeout("10m"); // throws CommandTimeoutError
await $`pnpm test`.timeout("10m").onTimeout(async () => $`ps auxf`); // runs fn, then throws
await $`pnpm exec playwright test`.as("e2e"); // names the step

const sha = await $`git rev-parse HEAD`.text();
const tracked = await $`git ls-files`.lines();
const meta = await $`cat package.json`.json<{ name: string }>();

const server = await $`pnpm start`.background(); // ignores retries, timeout, nothrow
server.id;
await server.exited(); // polls for exit
await server.output({ tailBytes: 65536 });
await server.kill(); // SIGTERM, or pass a signal number
```

```typescript {{ title: "TypeScript" }}
type CommandResult = {
  exitCode: number;
  stdout: string; // last 64 KiB
  stderr: string; // last 64 KiB
  truncated: boolean;
  durationMs?: number; // missing for commands with a timeout of 5 minutes or less
};
```

- `$` outside a job throws `CiUsageError`.
- Output arrives when the command ends. A `.timeout()` of 5 minutes or less is exact, and a longer one is approximate.
- Any function can run commands on the calling job's machine.

## Machines

A [machine](/docs/labs/ci/machines?ref=docs-labs-ci-reference) is a Sandbox. Each job gets one on its first command.

```typescript {{ title: "TypeScript" }}
machine: { vcpu: 1 } // 1 GiB
machine: { vcpu: 2 } // 2 GiB, default
machine: { vcpu: 4 } // 4 GiB
```

The first `machine` set wins: job, then pipeline, then `createCi`. Inngest destroys every machine when the pipeline ends. Only `$` runs on the machine.

```typescript {{ title: "TypeScript" }}
await checkout({
  repo: "acme/api", // default: the run's repository
  ref: "main", // branch, tag, or commit; default: the run's commit
  submodules: false,
  history: "shallow", // or "full"
  path: "/work", // commands after checkout({ path }) run there
});
```

- `ref` defaults to the repository's default branch when `repo` is another repository. It resolves to one commit per run.
- `repo` is cloned with your credentials, so never take it from untrusted event data.
- With no repository, as in a cron, `checkout()` throws `CiUsageError`. Pass `repo` or set it on the pipeline.
- Locally, plain `checkout()` uploads your working tree without `.git`, then only changes. It ignores `submodules` and `history`. A `ref` or another `repo` does a real clone.
- On an existing checkout, such as `from` a cached job, `checkout()` moves it to this commit and keeps ignored files like `node_modules`. Locally, deleted files stay.

## `from`

[`from`](/docs/labs/ci/base-images?ref=docs-labs-ci-reference) on [`ci.job`](#ci-job) and [`ci.matrix`](#ci-matrix) starts a job on a copy of another job's machine.

```typescript {{ title: "TypeScript" }}
const base = ci.job("base", async () => {
  await checkout();
  await $`pnpm install`;
});

const build = ci.job({ id: "build", from: base }, fn);
const test = ci.job({ id: "test", from: build }, fn);

from: build.with("web") // the job, run with that input
from: ({ input }) => build.with(input) // parent depends on this job's input
from: image.inngest("base") // an image Inngest maintains
from: image.custom("name") // "name", "name:tag", or "name@sha256:<hex>"
from: image.job("app/job", input) // a job another app defines; input optional
```

- The parent runs once per run, however many jobs start from it. Add a [`cache`](/docs/labs/ci/caching?ref=docs-labs-ci-reference) to share it across runs.
- A cached parent is an image. An uncached one is a run-owned snapshot, cleaned up when the run ends.
- A missing image or snapshot makes each child repeat the parent's commands.
- The parent must use the same CI client. A job or `with(input)` is checked at boot against the parent's `input` schema, and a function when the job runs.
- A cycle fails with its path in the message.
- To choose a parent at run time, define two jobs and choose in the pipeline.
- Jobs defined inside a pipeline build in that run.
- When a cached job's key changes, it and every cached job below it run again.

```typescript {{ title: "TypeScript" }}
await inngest.send(invalidateEvent("node-base")); // ci/base-image.invalidate; job or its ID
await inngest.send(invalidateEvent(base, { scope: "main" })); // branch, pr:<n>, global, or local
```

Without `scope`, every scope is cleared. [Rebuild on demand →](/docs/labs/ci/caching?ref=docs-labs-ci-reference#rebuild-on-demand)

## Extra machines

```typescript {{ title: "TypeScript" }}
const verify = ci.job("verify", async () => {
  await checkout();

  const clean = await sandbox("clean", { vcpu: 1 }); // job's machine settings by default

  await Promise.all([
    $`pnpm test`,
    clean.$.sh`npm install -g my-cli@next && my-cli --version`,
  ]);
});

import { waitForPort, waitForHttp } from "@inngest/ci";

await waitForPort(3000, { timeout: "2m" });
await waitForHttp("http://127.0.0.1:3000/health", { timeout: "2m", status: 200 });
```

- An extra machine starts empty and is destroyed with the pipeline. `checkout()` runs on the job's machine only.
- It appears in the trace with its own sandbox badge.
- `ExtraMachine` has `$`, `$.sh`, `waitForPort()`, and `waitForHttp()`.
- Top-level `waitForPort` and `waitForHttp` run on the job's machine. Both default to `2m`, and throw `CommandFailedError` on giving up.

<Warning>
  Machines cannot reach each other yet. Run servers on the job's machine in the background and use `127.0.0.1`.
</Warning>

## `ci.matrix`

```typescript {{ title: "TypeScript" }}
const compat = ci.matrix(
  {
    id: "compat",
    axes: { node: ["20", "22", "24"], db: ["sqlite", "postgres"] },
    exclude: [{ node: "20", db: "postgres" }],
    include: [{ node: "24", db: "mysql" }],
    concurrency: 3, // default: all at once
    failFast: false, // true: first failure ends the matrix; running ones are not cancelled
    from: base, // job | image | function of the combination
    machine: ({ node }) => ({ vcpu: 2 }), // value or function; cache too
    check: false, // applies to every combination
  },
  async ({ node, db }) => {
    await $`npx -y node@${node} --test`.env({ TEST_DATABASE: db });
  },
);

await compat();
await compat({ node: "22" });
```

- IDs come from the values, as in `compat (node:22, db:sqlite)`. Adding a value leaves the others alone.
- With `failFast` off, failures throw together as an `AggregateError` after every combination finishes.

`shard()` gives this shard `files`: every `total`-th file from `index`. It throws `CiUsageError` outside a job.

```typescript {{ title: "TypeScript" }}
import { $, shard } from "@inngest/ci";

const unit = ci.matrix(
  { id: "unit", axes: { shard: ["0", "1", "2", "3"] }, from: base },
  async ({ shard: index }) => {
    const tests = await $.sh`find src -name '*.test.ts'`.lines();

    await shard({ total: 4, index: Number(index), files: tests }, async (files) => {
      await $`pnpm vitest run ${files}`;
    });
  },
);
```

## Caching

A job's [`cache`](/docs/labs/ci/caching?ref=docs-labs-ci-reference) skips it when nothing it depends on changed. Its input is part of the identity.

```typescript {{ title: "TypeScript" }}
cache: {
  key: files("pnpm-lock.yaml", ".nvmrc"), // string | files() | array | async () => string
  refresh: [{ cron: "0 3 * * *" }], // triggers that build ahead of time
  maxAge: "1d", // string | ms | Temporal.Duration; malformed or zero fails at boot
  scope: "branch", // or "global"
}

key: files("schema.graphql", { repo: "acme/api", ref: "main" })
```

- `files()` hashes matched files in the commit's git tree, or your working tree locally. `ref` defaults to the run's commit, or the other repository's default branch.
- An unchanged key skips the job. A job that started a machine is restored from its image.
- A restored machine keeps its old checkout. Call `checkout()` to move to this commit.
- Set `repo` on a pipeline so a cron has something to check out.
- `durationToMs` from `inngest` converts a duration to milliseconds.
- `"branch"`: a pull request reads its own and its base branch's entries and writes its own. A push reads and writes its branch's. `"global"` shares one set.
- Images are shared by CI, teammates, and local runs. They rebuild on a new key, past `maxAge`, or after `invalidateEvent`. Concurrent misses share one build.
- A cached job also depends on its cached parents. An uncached parent makes it run every time.
- The first run with a new key misses. A job with no commands runs every time. Reused jobs show `Cached <time> ago`.
- Do not cache tests that call the network.

## Checks and reports

[Checks](/docs/labs/ci/checks-and-reports?ref=docs-labs-ci-reference) are one per pipeline and one per job. Require the pipeline check in branch protection.

```text
Running                     In progress, with the current command
Retrying a command          In progress, with the attempt count and last error
Run will be retried         In progress, "Retrying (attempt N of M)"
Passed                      Success, with the duration
Reused from cache           Success, "Cached <time> ago" or "Passed at <sha>, no changes since"
Failed                      Failure, with command, output tail, and annotations
Timed out                   Timed out
Cancelled by other failure  Cancelled
Returned ci.skip()          Success, with the reason
Job never called            No check
```

```typescript {{ title: "TypeScript" }}
await report.summary(`Coverage: **${coverage}%**`); // stacks sections; truncated at 65,000 bytes with a trace note
await report.annotate([{ path: "src/queue.ts", line: 42, message: "Flaky retry here" }]); // batches of 50; entries without path or message drop
```

- `report` targets the current job's check, or the pipeline check outside a job.
- While a run will be retried, checks stay in progress. Command failures, timeouts, usage errors, and matrix failures of only those fail once.
- A GitHub "Re-run" or "Re-run all" sends a new event for the commit. On a pull request it is `pull_request.synchronize`. Otherwise it is a `push`, only if the branch head is that commit.
- Pipelines on other triggers do not rerun. Passed jobs are reused only with a `cache` key.

## Run on GitHub

1. Create a GitHub App with repository permissions: Checks (read and write), Commit statuses (read and write), Contents (read; write for releases or `github.forcePushRef()`), Actions (read, for `github.waitForWorkflow()`), Pull requests (read and write), Issues (read and write), Metadata (read).
2. Subscribe it to: push, pull request, check run, check suite, issue comment, merge group, workflow run.
3. In the Inngest dashboard, create a webhook. Paste `githubWebhookTransform` into its transform, and use its URL as the app's webhook URL.
4. Install the app on your repositories.
5. Set `GITHUB_APP_ID` and `GITHUB_APP_PRIVATE_KEY`, then pass the provider to `createCi`.

```bash
node --input-type=module -e "import { githubWebhookTransform as t } from '@inngest/ci'; console.log(t)"
```

```typescript {{ title: "ci/client.ts" }}
import { Inngest } from "inngest";
import { createCi, githubApp } from "@inngest/ci";

export const inngest = new Inngest({ id: "my-app" });
export const ci = createCi(inngest, {
  github: githubApp({
    appId: process.env.GITHUB_APP_ID,
    privateKey: process.env.GITHUB_APP_PRIVATE_KEY,
  }),
});
```

- `githubApp()` reports checks. `githubToken()` reports commit statuses, with no summaries or annotations.
- `githubApp()` reads `GITHUB_APP_ID` and `GITHUB_APP_PRIVATE_KEY`, falling back to `GITHUB_INSTALLATION_ID` when an event has no installation. `githubToken()` reads `GITHUB_TOKEN`.
- Dev mode prints checks to the terminal. Set `INNGEST_CI_GITHUB=live` to send real ones.

<Warning>
  Inngest does not verify webhook signatures yet. Keep the webhook URL secret.
</Warning>

## GitHub API and helpers

```typescript {{ title: "TypeScript" }}
const created = await github.rest.repos.createRelease({ tag_name: "v1.4.0" }); // every Octokit REST method, one step per call
await github.rest.with({ id: "tag-next" }).git.updateRef({ ref: "heads/next", sha: github.repo().sha, force: true });

await github.stickyComment(key, body); // one PR comment, updated on later runs
await github.upsertPullRequest({ head, base, title, body }); // open or update
await github.forcePushRef(ref, sha); // move or create a branch or tag
await github.canUser(login, permission);
await github.waitForChecks({ names, sha, timeout }); // no machine; default 1h
await github.waitForWorkflow({ workflow, sha, timeout });
await github.paginate(method, params); // every page, typed
await github.graphql(query, variables);
github.repo(); // { owner, repo, sha, number, ref }
github.token(); // short-lived installation token; step.run only
github.octokit(); // plain Octokit client; step.run only
```

- `owner` and `repo` default to the run's repository.
- A call returns the response `data` as JSON, so dates are strings. Keep results small.
- Rate limits retry after the reset, other 4xx errors do not retry, and 5xx errors retry.
- Streaming methods are unsupported: use `github.octokit()` in `step.run`. Inside `step.run`, or outside a pipeline, calls run directly.

<Warning>
  `github.waitForChecks()` can miss a check that finishes between the lookup and the wait. That name then times out.
</Warning>

## Run metadata

Every run is tagged with metadata of kind `userland.inngest-ci`. Commands, output, and secrets are never recorded.

```json
{
  "package": "@inngest/ci",
  "version": "0.1.0",
  "local": false,
  "repo": "my-org/my-app",
  "ref": "feature",
  "sha": "abc1234",
  "pullRequest": 7
}
```

```json
{
  "conclusion": "success",
  "jobs": { "total": 3, "passed": 2, "failed": 0, "cached": 1, "skipped": 0, "cancelled": 0 },
  "apis": { "from": 1, "matrix": 1, "cache": 1, "commands": 6, "githubRest": 0 }
}
```

- `local` is `true` for any Dev Server run. Empty `repo`, `ref`, `sha`, and `pullRequest` are left out.
- `apis` counts calls to `from`, `matrix`, `cache`, `sandbox`, `checkout`, `changed`, `report`, `githubRest`, `githubHelpers`, `waitForChecks`, `waitForWorkflow`, `waitFor`, `commands`, `background`, `shard`, and `skip`, zeros included.
- CI's own steps carry a `{ job, kind }` tag, where `kind` is `job`, `check`, or `cache`.

## Steps inside jobs

```typescript {{ title: "TypeScript" }}
import { step } from "inngest";

const migrations = ci.job("migrations", async () => {
  const db = await step.run("create-db-branch", async () => {
    return neon.branches.create({ parent: "main" });
  });

  await checkout();
  await $`pnpm install`;
  await $`pnpm db:migrate`.env({ DATABASE_URL: db.url });

  await step.run("delete-db-branch", async () => {
    return neon.branches.delete(db.id);
  });
});
```

- Commands are steps and do not rerun. Wrap other side effects in `step.run`.
- Step IDs are scoped to the job.
- `step.waitForEvent`, `step.sleep`, and `step.invoke` work, and a wait holds no worker.
- Throw `RetryAfterError` to retry a step after a delay.

## Errors

```typescript {{ title: "TypeScript" }}
import { CommandFailedError, CommandTimeoutError, CiUsageError } from "@inngest/ci";

class CommandFailedError { command: string[]; exitCode: number; stdoutTail: string; stderrTail: string; jobPath: string } // non-zero exit without .nothrow()
class CommandTimeoutError { command: string[]; timeout: string; jobPath: string } // past .timeout()
class CiUsageError {} // unsupported use, such as $ outside a job; fails the run without retrying
```
