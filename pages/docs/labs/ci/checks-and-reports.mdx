# Checks and reports

> See each pipeline and job as a GitHub check, and add summaries and annotations from code.

<Info>
  Inngest CI is an Inngest Labs project: early, moving fast, and shaped by your feedback. [What's Labs?](/docs/labs)
</Info>

Checks are automatic: one for the pipeline and one for each [job](/docs/labs/ci/jobs). Require the pipeline check in branch protection.

```
✕ pr             test: `pnpm test` exited with 1
✓ pr / base      Passed in 41s
✓ pr / lint      Passed in 22s
✕ pr / test      `pnpm test` exited with 1
```

| State | Check |
| --- | --- |
| Running | In progress, with the current command |
| Retrying a command | In progress, with the attempt count and the last error |
| Run will be retried | In progress, with `Retrying (attempt N of M)` |
| Passed | Success, with the duration |
| Reused from cache | Success, with `Restored, built …` or `Passed at <sha>, no changes since` |
| Failed | Failure, with the command, the output tail, and annotations |
| Returned `ci.skip()` | Success, with the reason |

While a run will be retried, checks stay in progress and complete only on success or the final attempt. Command failures, timeouts, usage errors, and matrix failures made only of those fail once.

Set `check: false` on a pipeline to turn checks off, or `check: { jobs: false }` to keep only the pipeline check.

## Add a summary or annotations

`report` adds to the current job's check. Outside a job it targets the pipeline check.

```typescript {{ title: "TypeScript" }}
await report.summary(`Coverage: **${coverage}%**`);

await report.annotate([
  { path: "src/queue.ts", line: 42, message: "Flaky retry here" },
]);
```

`report.summary()` stacks sections, and `report.annotate()` puts annotations on the diff.

## Read the trace

Every run also opens in the Inngest dashboard as one trace, grouped the way you wrote the pipeline. Each job is one row.

```typescript {{ title: "TypeScript" }}
const test = ci.job({ id: "test", name: "Unit tests" }, async () => {
  await from(base);
  await $`pnpm test`.retries(1);
});
```

- **Collapsed:** one row per job, tagged `JOB`, showing its `name`, or its `id` when it has none. A muted `S1` or `S2` badge marks the [Sandbox](/docs/sandboxes/overview) a job runs on. A second Sandbox from [`sandbox("api")`](/docs/labs/ci/machines#extra-machines) shows its own badge on its row.
- **Expanded job:** Start sandbox (or "Start sandbox from `base`" with [`from()`](/docs/labs/ci/machines#start-a-job-from-another-job)), your commands as `$ pnpm test` rows or their [`.as()`](/docs/labs/ci/commands#options) names, your own `step.run` steps by name, then Save sandbox.
- **Expanded command:** Start process, Wait, Poll process, and Read output, or "Run and read output" for a short captured command. Each retry is Attempt 1, Attempt 2, and so on, and a failed command ends in "Exited with code N".
- **Top level:** a GitHub group holds the check updates, and "Clean up sandboxes" comes last.
- **Dimmed rows:** the work CI does for you is dimmed so your own rows stand out. Failures are never dimmed. Select a dimmed step and the step panel shows "Added by @inngest/ci@<version>".

A job called a second time in the same run shows as `test (2)` and has its own check.

[Commands](/docs/labs/ci/commands#options) shows how `.as()` renames a command row. A GitHub "Re-run" on a check sends a new pull request or push event for the commit, so pipelines on those triggers run again. Passed jobs are reused only when they have a [cache](/docs/labs/ci/caching) key.

![The trace of a pr pipeline in the Inngest Dev Server: a GitHub group, the base and test jobs as one row each, and the test job expanded to show it starting from base, a second api sandbox, a retried command with a failed first attempt, and Save sandbox](/assets/docs/labs/ci/trace.png)

In dev mode, checks print to your terminal. To report on GitHub, see [Run on GitHub](/docs/labs/ci/reference#run-on-github).
