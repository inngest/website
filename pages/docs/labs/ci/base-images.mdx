# Base images

> Start a job on a machine that's already set up.

<Info>
  Inngest CI is an Inngest Labs project: early, moving fast, and shaped by your feedback. [What's Labs?](/docs/labs?ref=docs-labs-ci-base-images)
</Info>

Set `from` on a job to start it with dependencies installed and output built. A base is built once and every run shares it.

| `from` | Starts from |
| --- | --- |
| `base` | [Another job in this app](#another-job) |
| `base.with(input)` | [Another job, built with an input](#another-job) |
| `image.inngest("base")` | [An image Inngest maintains](#an-inngest-image) |
| `image.custom("name")` | [An image published to your workspace](#your-own-image) |
| `image.snapshot("name")` | [A sandbox snapshot you captured](#a-snapshot) |
| `image.job("app/job")` | [A job in another app](#another-app-s-job) |

<AnnotatedCode>

```typescript {{ title: "ci/jobs.ts" }}
import { checkout, files, image, $ } from "@inngest/ci";
import { ci } from "./client";

const base = ci.job(
  { id: "base", cache: { key: files("pnpm-lock.yaml") } },
  async () => {
    await checkout();
    await $`pnpm install`;
  },
);

const test = ci.job({ id: "test", from: base }, async () => {
  await checkout();
  await $`pnpm test`;
});

const e2e = ci.job(
  { id: "e2e", from: image.custom("playwright") },
  async () => {
    await checkout();
    await $`npx playwright test`;
  },
);
```

<Annotation id="key" lines="5" tease="once per lockfile" title="Built once per key" href="/docs/labs/ci/caching?ref=docs-labs-ci-base-images" linkText="Caching">
`base` runs again only when `pnpm-lock.yaml` changes. Every other run starts from its snapshot.
</Annotation>

<Annotation id="from" lines="12" tease="copy of base" title="Start from another job" href="#another-job" linkText="Another job">
`test` starts on its own copy of `base`'s machine, with dependencies already installed.
</Annotation>

<Annotation id="checkout" lines="13" tease="only the changes" title="Catch up to this commit" href="/docs/labs/ci/machines?ref=docs-labs-ci-base-images" linkText="Machines">
The copy has the checkout `base` was built on. `checkout()` moves it to this run's commit and keeps `node_modules`.
</Annotation>

## Another job

```typescript {{ title: "TypeScript" }}
const test = ci.job({ id: "test", from: base }, fn);
const web = ci.job({ id: "web", from: build.with("web") }, fn);
const app = ci.job({ id: "app", from: ({ input }) => build.with(input) }, fn);
```

- The parent runs once in its own run, however many jobs start from it. Each child gets its own copy.
- Give the parent a [`cache`](/docs/labs/ci/caching?ref=docs-labs-ci-base-images) to share it across runs. Without one, it's rebuilt every run.
- `ci.matrix()` takes `from` too.
- A missing parent, a bad input, or a job that starts from itself fails when your app starts.

## An Inngest image

```typescript {{ title: "TypeScript" }}
const lint = ci.job({ id: "lint", from: image.inngest("base") }, fn);
```

`base` has Node.js, Python, Ruby and common tools. [See what's included](/docs/sandboxes/features/base-images?ref=docs-labs-ci-base-images). Jobs without `from` start on it.

## Your own image

```typescript {{ title: "TypeScript" }}
const e2e = ci.job({ id: "e2e", from: image.custom("playwright") }, fn);
```

An image published to your workspace, like a browser toolchain your team maintains. Use an image for a base you reuse across many runs: each job starts fresh on it, at its own size.

Cached jobs on it rebuild when you publish a new version.

## A snapshot

```typescript {{ title: "TypeScript" }}
const e2e = ci.job({ id: "e2e", from: image.snapshot("browser-ready") }, fn);
```

A [snapshot you captured](/docs/sandboxes/features/snapshots-and-restore?ref=docs-labs-ci-base-images) from a sandbox, with its memory and running processes:

```typescript {{ title: "TypeScript" }}
await sandbox.snapshot({ name: "browser-ready" });
```

Use a snapshot to start exactly where a machine left off, like a browser already open. Snapshots expire, so for a long-lived base, use an image.

## Another app's job

```typescript {{ title: "TypeScript" }}
const test = ci.job({ id: "test", from: image.job("platform/node-base") }, fn);
```

The other app builds its job once, from the commit it's deployed from, for every app that asks.

- Both apps run `@inngest/ci` in the same Inngest environment.
- The other app must be deployed from Vercel, Netlify, Render, Railway, GitHub Actions, or a git checkout, so it knows its repository.

## Every job

```typescript {{ title: "TypeScript" }}
const ci = createCi(inngest, { from: image.custom("agent-deps") });
```

Jobs without their own `from` start on it.

## How it works

A cached job's snapshot is named after its [key](/docs/labs/ci/caching?ref=docs-labs-ci-base-images#choose-the-key), its input, and the exact snapshot it started from. Jobs look their base up by that name before they start.
