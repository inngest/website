# Base images

> Start a job on a machine that's already set up.

<Info>
  Inngest CI is an Inngest Labs project: early, moving fast, and shaped by your feedback. [What's Labs?](/docs/labs?ref=docs-labs-ci-base-images)
</Info>

Set `from` on a job to start it with dependencies installed and output built. A cached base is published as an image, built once, and shared by every run. An uncached base is built for the run that needs it and cleaned up when the run ends.

| `from` | Starts from |
| --- | --- |
| `base` | [Another job in this app](#another-job) |
| `base.with(input)` | [Another job, built with an input](#another-job) |
| `image.inngest("base")` | [An image Inngest maintains](#an-inngest-image) |
| `image.custom("name")` | [An image published to your workspace](#your-own-image) |
| `image.job("app/job")` | [A job in another app](#another-app-s-job) |

<AnnotatedCode>

```typescript {{ title: "ci/jobs.ts" }}
import { checkout, files, image, $ } from "@inngest/ci";
import { ci } from "./client";

const base = ci.job(
  { id: "base", cache: { key: files("pnpm-lock.yaml") } },
  async () => {
    await checkout();
    await $`pnpm install`;
  },
);

const test = ci.job({ id: "test", from: base }, async () => {
  await checkout();
  await $`pnpm test`;
});

const e2e = ci.job(
  { id: "e2e", from: image.custom("playwright") },
  async () => {
    await checkout();
    await $`npx playwright test`;
  },
);
```

<Annotation id="from" lines="12" tease="copy of base" title="Start from another job" href="#another-job" linkText="Another job">

## Another job

```typescript {{ title: "TypeScript" }}
const test = ci.job({ id: "test", from: base }, fn);
const web = ci.job({ id: "web", from: build.with("web") }, fn);
const app = ci.job({ id: "app", from: ({ input }) => build.with(input) }, fn);
```

- The parent runs once in its own run, however many jobs start from it. Each child gets its own copy.
- Give the parent a [`cache`](/docs/labs/ci/caching?ref=docs-labs-ci-base-images) to share it across runs as an image. A cached parent's children can set their own `machine` size and secrets, because they boot fresh from the image.
- Without a `cache`, the parent is built for this run and kept as a snapshot that belongs to it. [Sandboxes and snapshots a run creates are cleaned up when it ends](/docs/sandboxes/features/run-owned?ref=docs-labs-ci-base-images), however it ends, so there's nothing for CI to leave behind.
- `ci.matrix()` takes `from` too.
- A missing parent, a bad input, or a job that starts from itself fails when your app starts. A cycle names its path, like `a → b → a`.
- A job defined inside a pipeline function, rather than at the top of a file, builds in the run that defined it. Defining the same job ID twice in a run throws `CiUsageError`.

## An Inngest image

```typescript {{ title: "TypeScript" }}
const lint = ci.job({ id: "lint", from: image.inngest("base") }, fn);
```

`base` has Node.js, Python, Ruby and common tools. [See what's included](/docs/sandboxes/features/base-images?ref=docs-labs-ci-base-images). Jobs without `from` start on it. Pin a language version with a [runtime image](/docs/sandboxes/features/base-images?ref=docs-labs-ci-base-images#runtime-images), such as `image.inngest("node-22")`.

## Your own image

```typescript {{ title: "TypeScript" }}
const e2e = ci.job({ id: "e2e", from: image.custom("playwright") }, fn);
```

An image published to your workspace, like a browser toolchain your team maintains. Use an image for a base you reuse across many runs: each job starts fresh on it, at its own size.

Cached jobs on it rebuild when you publish a new version.

## Another app's job

```typescript {{ title: "TypeScript" }}
const test = ci.job({ id: "test", from: image.job("platform/node-base") }, fn);
```

The other app builds its job once, from the commit it's deployed from, as an image every app that asks shares.

- Both apps run `@inngest/ci` in the same Inngest environment.
- The other app must be deployed from Vercel, Netlify, Render, Railway, GitHub Actions, or a git checkout, so it knows its repository.

## Every job

```typescript {{ title: "TypeScript" }}
const ci = createCi(inngest, { from: image.custom("agent-deps") });
```

Jobs without their own `from` start on it.

## How it works

A cached job's image is named after its [key](/docs/labs/ci/caching?ref=docs-labs-ci-base-images#choose-the-key), its input, and the exact image it started from. Jobs look their base up by that name before they start.
