# Jobs

> Split a pipeline into units that each get a machine and a check.

- **Call it like a function.** `await test()`. [Define a job →](#define-and-call-a-job)
- **Parallel or in order.** `Promise.all` and `await`. [Machines →](/docs/labs/ci/machines?ref=docs-labs-ci-jobs)
- **Matrices.** One job per combination. [Matrix →](#run-a-job-for-every-combination)
- **Inngest steps inside.** Wait, sleep, invoke. [Steps →](#use-inngest-steps-in-a-job)

import { $, checkout } from "@inngest/ci";

## Define and call a job

Jobs never share a machine. Use [`from`](/docs/labs/ci/base-images?ref=docs-labs-ci-jobs#start-from-a-job) to build on one. Put each job in its own file. [Project structure →](/docs/labs/ci/structure?ref=docs-labs-ci-jobs)

```typescript {{ title: "ci/pipelines/release.ts" }}
export const release = ci.pipeline({ id: "release", on: github.push({ branches: ["main"] }) }, async () => {
  const build = ci.job(
    { id: "build", cache: { key: files("pnpm-lock.yaml") } },
    async () => {
      await checkout();
      await $`pnpm install && pnpm build`;
    },
  );

  const publish = ci.job({ id: "publish", from: build }, async () => {
    await $`pnpm publish`;
  });

  await publish();
});
```

## Run a job for every combination

```typescript {{ title: "ci/jobs/compat.ts" }}
const compat = ci.job(
  {
    id: "compat",
    matrix: {
      axes: { node: ["20", "22", "24"], db: ["sqlite", "postgres"] },
      exclude: [{ node: "20", db: "postgres" }],
      concurrency: 3,
    },
    from: base,
  },
  async ({ matrix }) => {
    await $({ env: { TEST_DATABASE: matrix.db } })`npx -y node@${matrix.node} --test`;
  },
);

await compat();
await compat({ node: "22" });
```

## Use Inngest steps in a job

```typescript {{ title: "ci/jobs/migrations.ts" }}
import { step } from "inngest";

const migrations = ci.job("migrations", async () => {
  const db = await step.run("create-db-branch", async () => {
    return neon.branches.create({ parent: "main" });
  });

  await checkout();
  await $({ env: { DATABASE_URL: db.url } })`pnpm db:migrate`;
});
```

`step.waitForEvent`, `step.sleep`, and `step.invoke` work too.

## How it works

- A job has no return value. `name` defaults to `id`.
- The machine starts on a job's first command.
- Code outside commands can rerun on resume, so wrap side effects in `step.run`.
- A job defined inside a pipeline builds in that run. Its ID is unique per run.
