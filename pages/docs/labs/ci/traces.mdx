# Read CI traces

> See one row per job and per command, and open a row to see everything it did.

<Info>
  Inngest CI is an Inngest Labs project: early, moving fast, and shaped by your feedback. [What's Labs?](/docs/labs)
</Info>

A run's [trace](/docs/platform-and-operations/traces) groups steps by what your pipeline did, so you read it the way you wrote it.

```typescript {{ title: "TypeScript" }}
const test = ci.job({ id: "test", name: "Unit tests" }, async () => {
  await from(base);
  await $`pnpm test`.retries(1);
});
```

## What you see

- **A row per job.** A `[JOB]` tag marks each job. The row shows the job's `name`, or its `id` when it has none.
- **A row per command.** Each command reads as `$ pnpm test`, or as its [`.as()`](/docs/labs/ci/commands#options) name. Open it to see each attempt and the wait between attempts.
- **CI's own work, dimmed.** Starting a Sandbox, saving it, and updating GitHub checks sit in groups such as Start sandbox, Save sandbox, and GitHub, so your commands stand out. Select a dimmed step and the step panel says "Added by @inngest/ci".
- **The Sandbox each row ran on.** A muted `S1`, `S2` badge shows which [Sandbox](/docs/sandboxes/overview) ran a row. The badge appears when a row runs on a different Sandbox than the row above it, as with a job started [`from()`](/docs/labs/ci/machines#start-a-job-from-another-job) another job.
- **Why a command failed.** A failed command's step reads "Exited with code N".
