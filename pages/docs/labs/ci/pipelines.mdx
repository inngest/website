# Pipelines and triggers

> Define what starts a pipeline, which jobs it calls, and how runs are limited.

- **Plain TypeScript.** Branch, loop, and run jobs in parallel. [Define a pipeline →](#define-a-pipeline)
- **Typed triggers.** Pull requests, pushes, comments, cron. [Triggers →](#triggers)
- **Skip a run.** Success with a reason. [Skip →](#skip-a-run)
- **Flow control.** Cancel, cap, and debounce. [Flow control →](#flow-control)

## Define a pipeline

<AnnotatedCode>

```typescript {{ title: "ci/pipelines.ts" }}
export const pr = ci.pipeline(
  {
    id: "pr",
    on: github.pullRequest(),
    singleton: { key: "event.data.pull_request.number", mode: "cancel" },
    concurrency: {
      key: "event.data.repository.owner.login",
      limit: 20,
      scope: "account",
    },
  },
  async () => {
    await Promise.all([lint(), test()]);
  },
);
```

<Annotation id="on" lines="4" tease="typed event" title="Trigger" href="#triggers" linkText="Triggers">
Starts the run and types `event`.
</Annotation>

<Annotation id="singleton" lines="5" tease="cancels stale runs" title="Singleton" href="#flow-control" linkText="Flow control">
A newer push cancels the older run.
</Annotation>

<Annotation id="concurrency" lines="6-10" tease="caps parallel runs" title="Concurrency" href="/docs/durable-execution/flow-control?ref=docs-labs-ci-pipelines" linkText="Flow control">
At most 20 per account.
</Annotation>

</AnnotatedCode>

## Triggers

```typescript {{ title: "TypeScript" }}
export const merged = ci.pipeline(
  {
    id: "merged",
    on: github.pullRequest({ types: ["closed"] }),
  },
  async ({ event }) => {
    if (event.data.pull_request.merged === false) {
      return ci.skip("closed without merging");
    }

    await release();
  },
);
```

```typescript {{ title: "TypeScript" }}
on: github.comment({ command: "/deploy" })
on: github.mergeGroup()
on: { cron: "0 3 * * *" }
on: ci.manual({ pipelineId: "deploy", schema })
```

## Skip a run

```typescript {{ title: "TypeScript" }}
const touched = await changed("src/**", "package.json");

if (touched === false) {
  return ci.skip("nothing that affects the build changed");
}
```

## Flow control

`throttle`, `rateLimit`, `debounce`, and `priority` work like `singleton` and `concurrency`. [Flow control →](/docs/durable-execution/flow-control?ref=docs-labs-ci-pipelines)

## How it works

- A pipeline is one Inngest function. The handler gets `event`, `events`, `runId`, `pipelineId`, `repo`, `attempt`, and `logger`.
- `ci.skip()` completes the check as success, so required checks never wait.
- `changed()` returns `true` when it cannot tell: no repo, no credentials, no push or pull request range, or over 300 files.
